## 已确认的通用帧事实

- 支持 RS485、RS232、UART；默认 9600 bps，其他速率可能为客户定制；所有 16 位数值大端。
- 请求：`DD A5|5A CMD LEN DATA... CHECKSUM_H CHECKSUM_L 77 [CALLBACKID 4B]`。
  `A5` 是读、`5A` 是写；可选 callback ID 位于 `77` 后，接收端需依长度和超时断帧。
- 正常响应：`DD CMD 00 LEN DATA... CHECKSUM_H CHECKSUM_L 77 [CALLBACKID 4B]`；错误状态包含
  `80`（命令不存在）、`81`（无效操作）、`82`（校验错误）。
- 请求校验和覆盖 `CMD + LEN + DATA`，逐字节求和后取反加一，高字节在前。原件中的
  `DD A5 03 00 FF FD 77`、`DD A5 04 00 FF FC 77`、`DD A5 05 00 FF FB 77`、
  `DD A5 0F 00 FF F1 77`、`DD A5 AA 00 FF 56 77` 与现有只读 Driver 向量一致。
- 响应的文字说明将命令码列入校验范围，但原件 0x04 响应示例的 `F9F9` 只能由 `LEN + DATA`
  得到（若包含 `CMD=04` 会是 `F9F5`）。因此当前严格解析以示例为准；零长度错误响应的
  `LEN + DATA` 校验和为 `0000`，并允许 `77` 后的 callback ID。

## 0xE1 MOS：事实与限制

原件第 9--10 页定义：`DD 5A E1 02 YY XX CHECKSUM_H CHECKSUM_L 77`，成功响应为
`DD E1 00 00 CHECKSUM_H CHECKSUM_L 77`。

- `XX bit0`：1=软件关闭充电 MOS，0=打开；`XX bit1`：1=软件关闭放电 MOS，0=打开。
- `XX=00/01/02/03` 分别为解除、仅关闭充电、仅关闭放电、同时关闭。
- `YY=00` 为终端用户优先级，`YY=AA` 为运营优先级；运营锁定不能由用户优先级解除。
- 原件没有把 0xE1 列为工厂模式前置条件；工厂模式要求属于参数读写与容量配置流程。

这消除了“0xE1 必须工厂模式”的文档误述，但**不**授权启用 MOS 动作：尚无真实 BMS 的 wake、
优先级、ACK、读回 `fet_status` 和双 bit policy 现场证据。未来 Action 必须一次提交两个关闭位和
优先级，不能用两个独立布尔 write 互相释放另一 bit。

## F2/F3 参数：仍保持不可用

原件明确给出读/写参数流程：进入工厂模式 `DD 5A 00 02 56 78 FF 30 77`，操作后以
`DD 5A 01 02 00 00 FF FD 77`（读）或 `DD 5A 01 02 28 28 FF AD 77`（写）退出。并给出
CRC16 例程：初值 `FFFF`、多项式 `A001`、LSB-first；该 CRC 仅用于参数数据块，不能替代通用帧
校验和。

但原件仍有阻断编译/启用的内部歧义：第 18--19 页 F2/F3 小节标题与帧命令号相互矛盾，且参数块
长度写为 53/52 字节时，CRC 覆盖却写成 `BYTE0~BYTE96`。没有真实设备的完整 F2/F3 请求/响应
黄金向量、CRC 字节序或读回捕获前，不实现参数写入、batch 或工厂模式物理动作。

## 当前准入结论

1. 可将本文件作为嘉佰达协议来源与 hash 证据；不再把本机“参考笔记”当作唯一来源。
2. 原件与现有解析器共同覆盖的 `0x03/0x04/0x05/0x0F/0xAA` 已注册为统一 Action Catalog 的
   `read/low` 动作；它们带请求/响应命令号绑定 verifier，全部默认禁用，等待真实 BMS 设备灰度。
   所有 BMS 写、reset、清零和工厂模式操作继续不进入 Action Catalog。
3. 0xE1 的未来实现需在真实测试 BMS 上完成双 bit 编译向量、ACK、`fet_status` 读回、优先级和恢复测试。
4. F2/F3 需要先消除上述原件歧义，并在真实设备上完成进入、操作、finally 退出和 readback 的整套证据。

### C6 UART0 模拟传输证据（非真实 BMS）

2026-07-19，专用 C6 的 UART0/GPIO16/17 临时配置为 9600 8N1，`/dev/ttyUSB0` 只识别并回复
上述五条读取帧。C6 ResourceReport 先实报临时 channel 1 enabled；随后 API 创建五条 Operation，
均经 Outbox → ChannelCmdV2 → UART0 → Final → action-aware verifier 成功：

| Action | 请求命令 | verified result 项数 | 发布至 Final |
| --- | --- | ---: | ---: |
| `read_basic_info` | `0x03` | 10 | 179 ms |
| `read_cell_voltage` | `0x04` | 5 | 96 ms |
| `read_hardware_version` | `0x05` | 1 | 167 ms |
| `read_comprehensive` | `0x0F` | 10 | 163 ms |
| `read_protection_count` | `0xAA` | 12 | 184 ms |

模拟响应覆盖了 53.61 V、23.39 A、FET status、单体电压、`V19` 版本、综合状态和 12 项保护次数。
为确保测试只由 Action 触发，临时 EdgeDevice 的五条 legacy polling interval 均显式设为 0；仅清空
channel `template_ids` 不足以阻止 Driver 的默认轮询模板。该行为已记录，未将它视为 BMS 控制授权。
随后临时设备/配置已软删除，UART0 恢复禁用，C6 恢复 Manifest 成功并实报仅有 SN-3001 channel 3。
因此该结果只证明统一链路和 V19 模拟帧解析，不能替代真实 BMS 的型号、接线、wake、callback、固件
兼容性或任何控制动作证据。
