# 二进制帧协议规范

## 模型层级说明（v2.2 起）

v2.2 引入三层模型:

| 层级 | 概念 | 说明 |
|------|------|------|
| Node | 节点 | 物理边缘设备 (ESP32-C6/S3), MQTT 通信主体 |
| EdgeDevice | 边缘设备 | Node + Channel + DeviceConfig 的实例化 |
| DeviceConfig | 设备配置 | 设备型号的协议无关定义 |

MQTT topic 使用 `nodes/{id}/up|down`, 不再使用 v2.1 的 `devices/{id}/up|down`。

## 帧格式

```
┌──────────┬─────────────────────────────────────┐
│  type    │  fields...                          │
│  (1 B)   │  (key-value pairs, proto-style)     │
└──────────┴─────────────────────────────────────┘

type:    1 字节消息类型 (0x01-0x1A)
fields:  每个 field = [tag] [value]

tag = varint((field_number << 3) | wire_type)
  field_number ≤ 15 时 tag 为 1 字节（向后兼容旧版单字节 tag）
  field_number ≥ 16 时 tag 为多字节 varint（v2.7+）
  wire_type 0 = varint (整数/bool/enum)
  wire_type 2 = length-delimited (string/bytes/packed repeated)
```

## 各消息详细定义

### Hello (0x01) — ESP→SVR

启动握手，节点上线后首条消息。

```
field 1 (string): node_id          — 节点自报标识（兼容字段；服务端路由身份以 MQTT topic 为准）
field 2 (string): firmware_version — 固件版本
field 3 (string): model            — 硬件型号（如 "ESP32-S3", "ESP32-C6"）
field 4 (varint): channel_count    — 当前通道数
field 5 (varint): config_epoch     — 本地配置 epoch（v2.1+）
field 6 (varint): nvs_has_config   — NVS 是否持有配置，0/1（v2.1+）
field 7 (string): last_manifest    — 当前 manifest_id（v2.1+）
field 8 (string): protocol_version — 节点支持的协议版本（v2.1+）
field 9 (varint uint32): handshake_nonce — 可选握手关联值（v2.6+）
```

`handshake_nonce` 缺失或为 0 时按旧版握手处理；非零时服务端必须在
HelloAck field 3 原样回显。该值只用于把 ACK 与本次 Hello 关联，**不是认证信息**，
也不得替代 MQTT topic、连接身份或授权检查。field 9 重复、wire type 非 varint、
超过 `uint32` 或编码损坏时，服务端拒绝该 Hello 且不发送 HelloAck。合法未知字段
必须忽略，以保持前向兼容。

节点的连接握手 supervisor 每次发送（包括超时重试）都必须生成新的非零 nonce；
普通 `sync_manager` 配置同步 Hello 使用 legacy 模式并省略 field 9。v2.6 节点只允许
与当前 MQTT `connection_generation` 下已 armed nonce 完全相等的 HelloAck 完成连接握手，
无 field 3、field 3 为 0 或旧/未来 nonce 均不得完成握手。

### StatusRpt (0x02) — ESP→SVR

周期性心跳/状态上报。

```
field 1 (varint): uptime_sec      — 运行时长 (秒)
field 2 (string): status          — 运行状态字符串 (如 "running")
field 3 (varint): channel_count   — 当前活跃通道数
field 4 (varint): config_epoch    — 本地配置 epoch
field 5 (varint): sync_state      — 同步状态枚举 (0=idle, 1=in_sync, ...)
field 6 (string): config_hash     — 当前 manifest_id（可选）
field 7 (bytes):  channel_health  — 通道健康状态 (嵌套子消息, repeated, 可选)
field 8 (string): sync_id         — 同步 ID（可选）
field 9 (bytes):  runtime_perf    — 运行时性能快照 (嵌套子消息, 可选, v2.7+)
field 10 (bytes): control_stats   — V2 控制聚合计数 (嵌套子消息, 可选, v2.7+)

ChannelHealth 子消息 (field 7, repeated):
  field 1 (varint): channel_id
  field 2 (bytes):  edge_device_health (repeated)

  EdgeDeviceHealth 子消息:
    field 1 (varint): edge_device_id
    field 2 (varint): command_index
    field 3 (varint): error_count
    field 4 (varint): comm_status — 0=OK, 1=TIMEOUT, 2=CRC_ERROR, 3=FAULT

RuntimePerf 子消息 (field 9):
  field 1  (varint): free_heap             — 当前剩余堆 (字节)
  field 2  (varint): min_free_heap         — 历史最小堆 (字节)
  field 3  (varint): sched_stack_hwm       — scheduler 任务栈高水位 (words)
  field 4  (varint): worker_stack_hwm      — bus worker 最小栈高水位 (words)
  field 5  (varint): min_queue_spaces      — 采样队列最小剩余空间
  field 6  (varint): report_drop_count     — 遥测报告丢弃计数
  field 7  (varint): report_queue_hwm      — 报告队列高水位
  field 8-12  (varint): queue_current_spaces[0..4]  — 5 条队列当前剩余
  field 13-17 (varint): queue_high_water[0..4]      — 5 条队列已用高水位
  field 18-22 (varint): queue_skipped[0..4]         — 5 条队列跳过采样计数
  field 23-27 (varint): queue_rejected[0..4]        — 5 条队列拒绝采样计数
  队列索引: 0=UART0, 1=UART1, 2=UART2, 3=SPI, 4=I2C

ControlStats 子消息 (field 10):
  field 1 (varint): accepted   — 已接纳命令数
  field 2 (varint): rejected   — 已拒绝命令数
  field 3 (varint): completed  — 已完成命令数
  field 4 (varint): replayed   — 重放命令数
```

### DataRpt (0x03) — ESP→SVR

传感器数据或 WriteCmd 读响应。每帧表示一个通道事件。

```
field 1 (varint): channel_id          — 通道 ID
field 2 (varint): timestamp_us        — ESP 启动后的微秒时间戳
field 3 (varint): sequence            — 序列号
field 4 (bytes):  raw_data            — 原始数据（可选）
field 5 (varint): error_code          — 非零表示采集/读响应失败（可选）
field 6 (varint): request_id          — 关联 WriteCmd；周期采集为 0/省略
field 7 (varint): edge_device_id      — 具体 EdgeDevice（可选）
field 8 (varint): command_index       — 设备命令索引（可选）
field 9 (varint): command_template_id — 后端 ConfigTemplate ID（可选）
```

### ConfigMfst (0x04) — SVR→ESP

全量配置下发。节点收到后必须回复 ConfigRslt (0x05)。

```
field 1 (string): manifest_id  — 配置清单 ID (版本号)
field 2 (bytes):  templates    — 设备模板列表 (嵌套子消息, repeated)
field 3 (bytes):  channels     — 通道配置列表 (嵌套子消息, repeated)
field 5 (bytes):  dma_channel_configs — DMA 通道配置 (嵌套子消息, repeated, v2.4+)

Template 子消息:
  field 1 (varint): template_id
  field 2 (string): name
  field 3 (string): parser         — 解析器 ID (如 "bosch.bmp280")
  field 4 (varint): interval_ms    — 采集间隔
  field 5 (bytes):  init_commands  — 初始化命令列表 (repeated)

ChannelConfig 子消息:
  field 1 (varint): channel_id
  field 2 (varint): bus_type       — 1=UART, 2=I2C, 3=SPI, 4=GPIO, 5=ADC
  field 3 (varint): hardware_id    — 硬件资源索引 (hw_tables 中的索引)
  field 4 (varint): interval_ms    — 采集间隔
  field 5 (varint): enabled        — 1=启用, 0=禁用
  field 6 (bytes):  bus_config     — 总线特定配置 (如波特率/I2C地址)
  field 7 (varint): template_ids   — 关联模板 ID (repeated)
  field 8 (varint): dma_enabled    — 是否启用 DMA (v2.4+)

DmaChannelConfig 子消息 (v2.4+):
  field 1 (varint): dma_id         — DMA 通道 ID
  field 2 (varint): enabled        — 1=启用, 0=禁用
  field 3 (bytes):  bind_to        — 绑定到硬件资源 (如 "UART1")
```

### ConfigRslt (0x05) — ESP→SVR

配置应用确认。

```
field 1 (varint): success       — 1=成功, 0=失败
field 2 (varint): error_code    — 错误码 (失败时)
field 3 (string): error_msg     — 错误描述 (失败时)
```

### WriteCmd (0x06) — SVR→ESP

legacy 交互命令。只保留受控 read 和内部初始化兼容；新的业务控制使用 ChannelCmdV2。

```
field 1 (varint uint32): request_id       — 非零请求 ID
field 2 (varint uint32): channel_id       — 非零目标 Channel DB ID
field 3 (bytes, max 128): data            — TX 字节，可为空
field 4 (varint, 0..256): read_size       — 期望 RX 长度；0/省略表示仅写
field 5 (varint uint32): edge_device_id   — DataReport 路由身份（可选）
field 6 (varint, 1..30000): rx_timeout_ms — UART RX timeout；省略默认 1000ms
```

严格规则：required field 1/2/3 必须各出现一次；已知字段 wire type 必须匹配；重复、未知字段、dirty EOF、channel 0、TX/RX/timeout 越界均拒绝。超长 TX 不得截断，Channel/bus 不存在不得回退 UART0。`channel_id=0 + FC00` 不再是 factory reset 入口。

### WriteRsp (0x07) — ESP→SVR

ESP32 admission/TX 结果；不代表目标厂商协议 ACK 或业务验证成功。读数据通过 DataRpt field 6 request_id 返回。

```
field 1 (varint uint32): request_id — 对应 WriteCmd
field 2 (varint bool): success      — ESP32 是否接纳/完成 TX
field 3 (varint uint32): error_code — 非零错误码（可选）
field 4 (string): error_msg         — 脱敏错误描述（可选）
```

### ChannelCmdV2 (0x15) — SVR→ESP

版本化、单步、受限的物理通道事务信封。它替代新的业务控制对 `WriteCmd` 的依赖；
不承载驱动语义或高风险动作。当前仅当节点的 `ResourceReport.command_engine`
明确声明支持时，服务端才可下发。

```
field 1  (bytes, 16): command_id          — 全局命令标识
field 2  (bytes, 16): payload_digest      — 不含传输可变字段的请求摘要
field 3  (varint u32): attempt            — 非零尝试序号
field 4  (string, 1..32): boot_id         — 必须等于节点当前启动实例
field 5  (varint u32): edge_device_id     — 非零目标设备 ID
field 6  (varint u32): channel_id         — 非零目标通道 ID
field 7  (varint u64): deadline_unix_ms   — 非零绝对截止时间
field 8  (bytes, 1..128): tx_data         — 待发送原始字节
field 9  (varint, 0..256): read_size      — 期望响应长度；0 表示仅写
field 10 (varint, 1..30000): rx_timeout_ms
field 11 (varint, 0..30000): post_tx_delay_ms
field 12 (varint): risk_class             — Phase 2 固定为 0（low）
field 13 (varint): flags                  — Phase 2 固定为 0
field 14 (varint): protocol_version       — 固定为 1
field 15 (varint, 0..8): batch_step       — 批次步骤索引（可选，0=非批次）
```

field 1-14 必须恰好出现一次，field 15 可选（缺省为 0）；未知或重复字段、wire type 不符、dirty EOF、超界值均拒绝。
节点必须将 `boot_id` 与当前启动实例精确匹配，拒绝陈旧实例的命令。Go 与 C 共享
golden vector，协议升级必须新增版本而不能改变本版字段含义。

### ChannelCmdV2Ack (0x16) — ESP→SVR

节点对信封的接纳结果，不表示总线事务已经完成。

```
field 1 (bytes, 16): command_id
field 2 (bytes, 16): payload_digest
field 3 (varint u32): attempt
field 4 (string): boot_id
field 5 (varint u64): event_sequence
field 6 (varint bool): accepted
field 7 (varint u32): error_code  — 0 成功；1001 不支持/陈旧 boot；1002 信封非法
```

### ChannelCmdV2Final (0x17) — ESP→SVR

每个已接纳事务恰好一个终态回执。field 1..7 与 Ack 相同，field 6 为成功布尔值；
可选 `field 8 (bytes)` 为有长度上限的原始响应，`field 9 (varint bool)` 表示重放。
节点在 Phase 2 能力未启用时不得发送 Final。

### ResourceReport (0x19) — ESP→SVR  (v2.4+)

硬件资源上报。Hello 后或收到 QueryResources (0x1A) 时发送。

协议层定义意愿，节点层决定现实：节点根据硬件约束上报实际资源。

```
field 1 (string): platform          — 平台标识 ("ESP32-S3", "ESP32-C6", "Linux-RK3576")
field 2 (varint): resource_count    — 资源总数
field 3 (bytes):  buses_blob        — 总线列表 (嵌套子消息)
field 4 (bytes):  channels_blob     — 通道列表 (嵌套子消息)
field 8 (bytes):  dma_channels      — DMA 通道列表 (嵌套子消息, repeated, v2.5+)
field 9 (bytes):  command_engine    — V2 控制引擎能力（Phase 2）
field 10 (bytes): manifest_capacity — ConfigManifest 存储上限 (v2.7+)

Buses 子消息 (field 3):
  field 1 (bytes): uart_entry (repeated)
  field 2 (bytes): i2c_entry (repeated)
  field 3 (bytes): spi_entry (repeated)
  field 4 (bytes): gpio_entry (repeated)
  field 5 (bytes): adc_entry (repeated)
  field 6 (bytes): pwm_entry (repeated)

  每个 bus_entry 包含:
    field 1 (string): id            — 硬件标识 ("UART0", "I2C0")
    field 2 (varint): unit          — 单元号
    field 3 (varint): ...           — 总线特定字段 (引脚/频段等)

  pwm_entry:
    field 1 (string): id                  — PWM 硬件标识 ("PWM0")
    field 2 (varint): channel             — LEDC 输出通道索引
    field 3 (varint): timer_count         — 目标芯片共享 LEDC timer 数量
    field 4 (varint): max_resolution_bits — 目标芯片最大 PWM 分辨率位数

  GPIO 与 PWM 是独立资源类型：GPIO entry 表示物理引脚，PWM entry 表示可经
  GPIO matrix 路由到合法输出引脚的 LEDC 通道。不得由 GPIO 数量推导 PWM 数量。

Channels 子消息 (field 4):
  field 1 (bytes): channel_entry (repeated)

  channel_entry:
    field 1 (varint): id            — 通道 ID
    field 2 (varint): bus_type      — 1=UART, 2=I2C, 3=SPI, 4=GPIO, 5=ADC
    field 3 (varint): hardware_id   — 硬件索引
    field 4 (varint): interval_ms   — 采集间隔
    field 5 (varint): enabled       — 1=启用, 0=禁用
    field 6 (bytes):  bus_config    — 总线配置
    field 7 (varint): template_ids  — 关联模板 (repeated)
    field 8 (varint): dma_enabled   — DMA 是否启用 (v2.5+)

DmaChannel 子消息 (field 8, repeated):
  field 1 (varint): dma_id          — DMA 通道 ID (平台唯一)
  field 2 (string): name            — 名称 ("GDMA_CH0")
  field 3 (varint): dma_type        — 0=GDMA, 1=EDMA, 2=DMA2D
  field 4 (varint): capabilities    — bit mask: bit0=TX, bit1=RX, bit2=burst
  field 5 (varint): max_burst       — 最大突发传输长度 (bytes)
  field 6 (varint): state           — 0=free, 1=allocated, 2=disabled
  field 7 (string): bound_to        — 当前绑定的硬件 ("UART1" / "" = 未绑定)
  field 8 (varint): compatible_bus  — 兼容总线: bit0=UART, bit1=I2C, bit2=SPI

CommandEngine 子消息 (field 9):
  field 1 (varint u32): revision              — 非零实现修订
  field 2 (string):      boot_id               — 当前启动实例，1..32 字节
  field 3 (varint bool): supports_channel_cmd_v2
  field 4 (varint bool): supports_bounded_batch — Phase 2 固定 false
  field 5 (varint bool): supports_finally       — single-step Final 能力
  field 6 (varint u32): max_batch_steps         — Phase 2 固定 0
  field 7 (varint u32): max_tx_bytes            — 当前为 128
  field 8 (varint u32): max_rx_bytes            — 当前为 256
  field 9 (varint u32): max_step_timeout_ms     — 当前为 30000
  field 10(varint u32): ram_dedup_entries       — RAM replay 容量（当前为 4）

所有字段必须恰好一次、bool 必须 canonical 0/1。`supports_channel_cmd_v2=true`
时必须同时 `supports_finally=true`；服务端只以成功持久化且未过期的本报告作为下发依据。

ManifestCapacity 子消息 (field 10):
  field 1 (varint u32): max_templates    — ConfigManifest 最大模板数
  field 2 (varint u32): max_channels     — ConfigManifest 最大通道数
  field 3 (varint u32): max_template_ids — 每通道最大关联模板 ID 数
```

### OtaCmd (0x0A) — SVR→ESP

```
field 1 (string): ota_id        — OTA 任务 ID
field 2 (string): url           — 固件下载 URL
field 3 (string): checksum      — SHA256 hex 校验和
field 4 (varint): size          — 固件大小 (bytes)
field 5 (string): version       — 固件版本
field 6 (varint): sequence      — 非零命令序号，用于重投去重
```

### OtaProg (0x0B) — ESP→SVR

```
field 1 (string): ota_id        — OTA 任务 ID
field 2 (varint): status        — 0=下载中, 1=安装中, 2=成功, 3=失败, 4=校验中
field 3 (varint): progress      — 进度 (0-100)
field 4 (string): error_message — 失败信息（可选）
```

### ScanReq (0x0D) / ScanRpt (0x0C)

```
ScanReq: field 1 (varint): bus_type — 1=I2C (仅 I2C 实现)
ScanRpt: field 1 (bytes): devices   — 扫描结果 (I2C 地址列表, repeated varint)
```

### HelloAck (0x12) — SVR→ESP  (v2.1+)

Hello 的确认包。v2.6 起可回显本次握手的关联值。

```
field 1 (varint): server_time    — 服务端 Unix 时间（毫秒）
field 2 (varint uint32): features — 服务端功能位
field 3 (varint uint32): handshake_nonce — Hello field 9 的原样回显（仅非零时发送，v2.6+）
```

Legacy Hello（nonce 缺失或为 0）的 HelloAck 必须省略 field 3，并保持 field 1、2
的既有字节和字段兼容性。

### ConfigSyncReq (0x13) / ConfigSyncRsp (0x14)  (v2.1)

配置同步机制。用于确保服务端离线恢复后能重推配置。

```
ConfigSyncReq:  (空消息, 无字段)
ConfigSyncRsp:
  field 1 (varint): has_config   — 1=需要配置下发
```

### QueryReq (0x0E) / QueryRsp (0x0F)  (v2.1+)

通用查询/响应，用于扩展查询。

```
QueryReq:
  field 1 (varint): query_type  — 查询类型
  field 2 (bytes):  payload     — 查询参数

QueryRsp:
  field 1 (varint): query_type  — 对应查询类型
  field 2 (bytes):  payload     — 查询结果
```

### ConfigQuery (0x10) / ConfigReport (0x11)  (v2.1+)

用于服务端查询节点当前持有的配置版本。

```
ConfigQuery:
  field 1 (string): manifest_id — 期望的配置 ID

ConfigReport:
  field 1 (string): manifest_id — 节点当前配置 ID
```

### QueryResources (0x1A) — SVR→ESP  (v2.4+)

请求节点上报硬件资源。

```
(空消息, 无字段)
```

## 编码 API (frame_codec)
