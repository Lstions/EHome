## 1. 通用帧事实

- 帧分隔：DD 5A 头 + 长度 + 命令 + 数据 + CRC（校验和算法按原件）。
- 读指令（当前实现确认可用）：基础信息、单体电压、综合数据（client mode 参数同步等 5+ 读）。
- ReadSize 语义：响应总帧长（不足须 0x00 填充，否则 err=3 长度不足）。

## 2. 已确认可用指令（驱动实现现状）

| 指令 | 类别 | 状态 |
|------|------|------|

## 3. F2/F3 工厂模式（冻结原因）

- F2 写保护参数 53 字节块；F3 写系统参数。写序列须先进工厂模式、写完退出（RequiresFinally）。
- **原件内部歧义**：部分字段语义有两种互斥解释，无黄金向量无法裁决 → 当时 gate 的直接原因。
- 冻结政策：F2/F3 保持不可用（协议文档 §F2/F3 现状），直到实机证据补齐 + 字段级对账实现（技术债 T3）。

## 4. 门禁政策（现行）

**fail-closed + 证据门禁 + 默认启用原则**（2026-08-14 全线统一后的组合语义）：

1. **实现即默认启用**的前提是 `verifier != nil && Verification != "" && AvailabilityCode == ""`。
2. **证据门禁**：未实机验证的动作挂 `AvailabilityCode = protocol_unverified` → 目录可见但不可执行（分区：schema 冻结、执行待证据）。
3. 15 个未实机验证动作处于 protocol_unverified：包括 F2/F3 整块、0xE1 MOS 写、SN 写、保护/系统参数写、强制均衡、寻车、工厂模式等。
4. **解冻条件**（每个动作逐个满足）：
   - 真实 BMS 实机（C6 UART0 模拟传输不算实机）；
   - 黄金向量（发送帧 + 期望响应帧）；
   - 字段级对账（非整块 bytes.Equal，见技术债 T3）；
   - ACK 校验和验证（T4）；
   - 需 finally 的动作验证失败路径退出工厂模式。

## 5. 五读指令模拟证据（C6 UART0 模拟传输）

此前"已确认"的五读指令含 C6 UART0 模拟传输证据（非真实 BMS）——只佐证字节级收发链路，不构成实机门禁证据。真实 BMS 实机未接入过。

## 6. 与驱动实现的对应

- 驱动：backend/internal/drivers/jiabaida.go（1929 行）——读取路径质量 8/10、安全门禁 9.5/10（评审）。
- 动作目录经由 deviceaction 动态装配（Action Schema v1），门禁常量定义在 drivers/definition.go。
- 解冻动作 = 补 Verification + 移除 AvailabilityCode + 实机验证记录（协议文档本文件 §4 登记）。
