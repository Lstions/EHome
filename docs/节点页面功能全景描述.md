# 前端「节点页面」功能全景描述

> 用途：给 AI 重新设计节点页面（NodeList + NodeDetail）时作为功能基线。
> 范围：`frontend-shared/src/views/node/`（NodeList.vue、NodeDetail.vue）+ 其子组件
> （ChannelPanel.vue、QuickCreateDeviceDialog.vue、LogPanel.vue、LogRealtimeViewer.vue、LogHistoryPanel.vue）
> + 通道侧（ChannelManager.vue、ChannelTerminal.vue）+ OTAForm.vue + node store / node API。
> 代码基线：main 分支（含 2026-08-09 前的移动端响应式 P0 修复与批次 A/B 合入）。

---

## 一、路由与页面骨架

- `/node` → NodeList.vue（节点列表页），路由 title「节点」，菜单图标 Connection，鉴权保护。
- `/node/:id` → NodeDetail.vue（节点详情页），路由 title「节点详情」，`hidden: true`（不出现在菜单）。
- 列表页/详情页均由 MainLayout 承载（顶部顶栏 + 左侧菜单），页面自身不再含二级导航。

## 二、节点列表页（NodeList.vue，约 909 行）

### 2.1 顶部统计卡片（4 张 StatCard）
- 「本页节点」（总数，主色）、「本页在线」（绿色）、「本页离线」（红色）、「本页告警」（黄色，warning 状态计数）。
- 数值用 CountUp 数字滚动动画；前 3 张可点击，点击后设置状态筛选（全部/在线/离线），第 4 张不可点。
- 统计基于**当前页已加载列表**实时计算（不是全库统计）。
- 布局：桌面 4 列；≤1200px 2 列；≤768px 单行 4 列紧凑小卡（图标 22px / 数值 16px / 标签 10px，纵向堆叠，标签 keep-all 防逐字竖排）。

### 2.2 工具栏
- 搜索框：`placeholder="搜索名称/型号"`，前缀 Search 图标，可清除，输入即过滤（本地过滤当前页）。
- 状态筛选下拉：全部 / 在线 / 离线（`el-select`，可清除，change 后重置页码=1）。
- 型号筛选下拉：选项来自当前列表去重的 model 集合，可清除。
- 视图切换按钮组：卡片视图（Grid）/ 表格视图（List），高亮当前模式。
- 「添加节点」主按钮：`router.push('/node?action=add')`——**目前只有跳转，没有任何接收 action=add 的落地页面/对话框**（路由无 add 处理，页面无监听），即该按钮是"跳转占位"，重设计时可一并处理（补对话框或删除）。
- 「刷新」按钮：loading 态，强制重新拉取（force=true），成功提示"数据已刷新"，失败提示"获取节点列表失败"。
- 活动筛选区：有关键词/状态/型号任一筛选时显示「当前筛选：」+ 可关闭的 el-tag + 「清除全部」文字按钮。

### 2.3 卡片视图（默认）
每张卡片（el-card，hover 阴影，点击整卡进详情）：
- 头部：左侧 CPU 图标（在线=绿色渐变底/离线=灰色渐变底）+ 名称 + 型号（未知型号兜底）；右侧状态胶囊（圆点 + 在线/离线，在线圆点呼吸动画）。
- 主体 info-row 四行：
  - 设备ID：`node_id`（物理序列号，如 F0F5BDFFFE02）；
  - 固件版本：el-tag，未知显示「未知」；
  - 连接质量：仅在线显示进度条（6px 细条，颜色按质量分档）+ 百分比数值，离线显示 `-`；
  - 上线时间：相对时间（刚刚 / N分钟前 / N小时前 / N天前 / 超出 7 天显示日期）。
- 底部三个文字小按钮（click.stop，不触发卡片跳转）：配置（→ `/node/:id?tab=config`，同样无接收方，占位跳转）、升级（→ `/firmware?node=:id`）、删除（危险色，二次确认）。
- 离线卡片整体 opacity 0.8。

### 2.4 表格视图
- el-table：stripe、loading、行点击进详情、行悬浮指针。
- 列：节点（图标+名称+型号，min-width 200）/ 设备ID（100）/ 固件（el-tag，100）/ 状态（圆点+文字，100）/ 连接质量（进度条，150）/ 延迟（`latency_ms`，>0 显示 `N ms` 且按延迟分档着色，否则 `-`，100）/ 上线时间（相对时间，160）/ 操作（固定右侧：详情按钮 + 删除文字按钮，180）。
- 分页（el-pagination）：total + sizes(10/20/50) + prev/pager/next/jumper；更改页码或每页条数重新拉取。

### 2.5 空状态
- 加载完成后无数据：EmptyState（Connection 图标、标题"暂无节点"、描述"开始添加第一个节点来监控您的设备"、快捷操作按钮"添加节点"→ 仅 ElMessage.info('跳转添加页面')，同样是占位）。

### 2.6 数据与状态逻辑（重设计需保留的交互契约）
- Store：`useNodeStore`（Pinia，`stores/node.ts`）：
  - 列表缓存：按 `(status, page, page_size)` 为 key 的 Map 缓存，TTL 15s；`hasCachedList` / `getCachedList` / `fetchNodes(params, force)`；
  - in-flight 去重：同 key 并发请求合并，只保留最新请求生效（latestRequestByKey 序列号裁判，旧响应丢弃）；
  - 强制刷新（force=true）绕过 TTL；刷新成功后写缓存；
  - 详情缓存：`fetchDetail(id, force)`，TTL 15s，缓存同时以「数字 id」和「node_id 字符串」双 key 登记；
  - `updateNode(id, {name})`：改本地列表缓存 + 详情缓存、使 list/detail 缓存失效（detailEpoch/cacheEpoch 递增）；
  - `deleteNode(id)`：乐观移除 + 清空全部列表/详情缓存 + 递增 epoch；
  - `clearCache()`：登出会话变更时清空（registerSessionCacheClearer）。
- 页面初次加载：优先读缓存（有缓存不显示骨架屏直接渲染），无缓存显示骨架屏（4 个 stat 骨架 + 8 个卡片骨架）。
- WebSocket 订阅 `WS_EVENT.NODE_STATUS`：
  - 已有节点：就地更新 status（离线时把连接质量清零），**不整页重拉**（防闪屏）；
  - 新节点（列表中没有的 node_id）：500ms 防抖静默刷新（silent=true，不显示骨架屏）。
- 所有异步操作带"请求序列号"防过期；切换/卸载时旧响应不落地。
- 搜索/筛选都是**本地过滤**当前页数据（不重新请求后端）。

### 2.7 删除流程
- ElMessageBox.confirm（"确定要删除节点 X 吗？此操作不可恢复。"，type=warning）→ 调 `nodeStore.deleteNode(row.id)` → 本地移除 + total-1 + 统计更新 + 成功提示 → 后台静默强制刷新（失败则警告"节点已删除，但列表刷新失败"）；取消不提示。

## 三、节点详情页（NodeDetail.vue，约 1248 行）

### 3.1 页面头部
- 面包屑：首页 / 节点管理 / 当前节点（名称优先，未命名显示设备 ID 前 8 位 + `…`）。
- PageHeader：返回按钮（router.back）、标题=节点名称（未命名时与面包屑一致）。
- 右上操作按钮组（**节点离线时全部禁用**，禁用态统一灰色 + tooltip"设备离线，无法操作"）：
  - 「同步配置」（RefreshRight 图标）：调 `nodeApi.syncConfig(id)`，成功提示"配置同步成功"；
  - 「OTA 升级」（Upload 图标，primary）：打开 OTAForm 对话框；
  - 「测延迟」（Connection 图标）：调 `nodeApi.ping(nodeId)`，然后**等 WS 推回 latency_ms**（5s 超时提示"延迟测量超时，采集器可能离线"，收到后提示"延迟: N ms"并清 ping 中态）。
- 移动端：标题独占一行（最多两行省略），按钮区换行到第二行右对齐。

### 3.2 基本信息卡
- el-descriptions（border，桌面 2 列 / 移动端 1 列），字段：
  - 节点名称：**行内编辑**——点击铅笔图标进入编辑（el-input，Enter 保存 / Esc 取消），保存调 `nodeStore.updateNode(id, {name})`，更新本地 collector 状态；带序列号防过期；
  - 设备ID（node_id）；
  - 型号（model）；
  - 固件版本（el-tag type=info）；
  - 状态（StatusBadge 组件）；离线时连接质量/延迟显示灰色 `-` 加 tooltip"设备离线，暂无数据"；
  - 连接质量：进度条（颜色分档），undefined 显示 `-`；
  - 延迟：`ping_latency_ms` >0 显示 `N ms`（按延迟着色），否则 `-`；
  - 上线时间：`formatTime`（绝对时间，1970/0001 边界显示 `-`）；
  - 在线时长：**每秒刷新的会话时长**（从 last_online_time 到当前时间的差值，显示 N天 N小时 N分钟，不足 1 分钟显示秒；离线显示 `-` 且 tooltip"设备离线，暂无数据"）。注意：数值一致性由用户心算校验（上线时间 + 在线时长 ≈ 当前时间）。

### 3.3 配置同步状态卡
- 协议版本、Last Manifest（等宽 code）、Last Sync（绝对时间）、Last Sync ID（整行占位,有值才显示）。
- 状态标签：header 内 el-tag——离线强制显示"离线"（info），在线按 `config_sync_state` 映射：in_sync=已同步(success) / syncing=同步中(warning) / lag=落后(danger) / error=错误(danger) / 其它=未知(info)。

### 3.4 总线配置卡（ChannelPanel，约 1971 行，最大子组件）
整体是两个 Tab：
- **Tab1「硬件资源」**：
  - 头部操作：刷新（refreshAll=并行拉 buses+channels+periph）/ 保存配置（put 硬件配置，**仅在线可点**）/ 新建通道（打开 ChannelManager 对话框，仅在线可点）；
  - 按总线类型分组（I2C / UART / SPI / ADC）折叠面板，每类显示「类型 tag + 中文名 + N 个资源」徽标：
    - 每个硬件资源行：名称/类型 tag/引脚徽章（PinBadges：TX/RX/SDA/SCL/MOSI/MISO/SCLK/CS/GPIO/CH 角色 + 引脚号，按总线类型配色）+ 参数信息（频率/波特率/方向/主从）+ **DMA 开关**（仅 uart/spi/i2c：从 dmaStore 读该硬件兼容的 DMA 通道，开关状态=是否有 DMA 绑定到该硬件，切换走 dmaStore.toggle→写 dma-config API；互斥：一个硬件只能绑一个 DMA）+ enabled 复选框（只读展示）；
    - 该硬件下的**通道标签**（可点→打开 ChannelManager 编辑该通道；可关→删除通道并确认）；无通道时显示虚线"无通道 + 创建通道"按钮；
    - UART 特有：「改波特率」按钮→对话框（选 UART 通道 + 波特率 9600~115200，调 channelApi.reconfigure）；
    - I2C / RS485-UART 特有：「地址扫描」按钮（i2c 走 i2c scan，uart 且 bus_config 含 rs485 模式或可解析时走 modbus scan，提示"扫描完成: 发现 N 个设备"）；
  - **GPIO 分组**（GPIOResourceList 子组件）：显示 ESP32 上报的 GPIO 引脚资源，支持添加（选方向 OUTPUT/INPUT/INPUT_PULLUP/INPUT_PULLDOWN + 初始电平(输出时) + 标签）、编辑、删除；占用引脚映射（总线已占用 + PWM 输出）在界面标记/防冲突；运行态电平变化通过 WS PERIPH_RESULT 事件实时刷新；
  - **PWM 分组**（PWMResourceList 子组件）：显示 PWM 硬件资源，支持添加（选输出引脚=未占用 GPIO + 频率 + 占空比 0-10000(即 0.00%-100.00%) + 分辨率 4~max + 自动启动 + 标签）、编辑、删除；运行态（running/duty）通过 WS 实时刷新；
  - 全部空时 EmptyState"等待节点硬件资源上报"；
  - 加载：先下发 QueryResources → 等 2s 采集器上报回填 DB → 拉 capabilities（硬件能力）+ hardware config（用户配置）合并渲染，避免闪烁。
- **Tab2「通道终端」（ChannelTerminal 子组件）**：
  - 实时总线数据流查看终端：TX/RX 日志分区（可展开详情），HEX/ASCII 显示切换；
  - 发送区：HEX / ASCII 两种输入模式、间隔（ms）、波特率设定、发送按钮（调通道发送 API）；
  - 终端日志：暂停/继续、导出、清空。
  - 说明：这里是"通道级"调试工具，与传感器数据无关，属于底层总线排查。

### 3.5 DMA 通道卡（NodeDetail 内独立卡）
- 只读展示 dmaStore.mergedChannels（DMA 通道列表）：名称 + 状态 tag（FREE=未使用 / ALLOCATED=未绑定(黄) / 已绑定(绿) / DISABLED=已禁用(红)）、类型（GDMA/类型N）、能力（TX/RX/Burst 位掩码）、最大突发（字节）、绑定对象、兼容总线（UART/I2C/SPI 位掩码）。
- 头部「刷新」按钮；**DMA 的绑定/解绑只能在 ChannelPanel 的开关操作**，此卡仅展示。
- 空数据 → el-empty"暂无 DMA 数据"。

### 3.6 关联设备卡
- 头部：「创建设备」（primary，**collector 无 node_id 时禁用**）→ 打开 QuickCreateDeviceDialog；「刷新」（重拉设备+通道）。
- 设备表格（stripe，行点击→跳 `/edge-device/:id`，移动端横向滚动 + 提示条）：
  - 设备名称（min-width 140，溢出省略）/ 类型（getDeviceTypeLabel 映射）/ 地址（`hardware_id`，等宽 code，空显示 `-`）/ 通道（**可点击的通道 tag**：硬件类型大写 + hardware_id，点击→NodeDetail 转发给 ChannelPanel 打开 ChannelManager 编辑该通道；无通道显示灰字"无"）/ 最新数据（**最多 3 个键值对**：传感器中文名: 数值+单位，过滤 error_code/raw_data，<10 保留 2 位小数否则取整；空显示 `-`）/ 状态（StatusBadge）/ 最后数据时间（绝对时间）/ 操作（固定右列："查看"文字按钮）。
- 通道数据来自 `channelApi.getList(node_id 序列号)`；设备来自 edgeDeviceStore.fetchList(`{node_id: 序列号, page:1, page_size:100}`)。**注意：必须用物理序列号 node_id 查询，不能用路由数字 id**。
- 创建成功后：edgeDeviceStore.invalidateLists() + 重拉设备列表。

### 3.7 快速创建设备对话框（QuickCreateDeviceDialog.vue）
- 入口：详情页「创建设备」按钮；预填节点（step-tip 显示"在节点 X 上直接创建设备，无需预先创建设备模板"）。
- 表单：
  - 设备型号（解析器）下拉：可选=有 hardware_types 的 parser；选项显示 `名称 (id)` + 各总线类型小 tag；选择后重置已选通道；校验必填；
  - 通道下拉：按所选型号的总线类型过滤该节点已有通道（大小写归一），显示 `UART xxx` 格式；加载中显示"正在加载通道…"，加载完无匹配显示引导"该节点暂无匹配 X 的通道，请先在下方总线配置中创建"；校验必填；
  - 设备名称：必填；
  - 采集间隔（ms）：100~3600000，步进 100；**若型号驱动声明了可调度轮询指令，则隐藏此字段并提示"该设备型号按下方'轮询指令'逐条设置间隔（0=禁用）"**；
  - 逐指令轮询间隔（CreateWizardCommandIntervals 子组件）：选定型号后拉取驱动 schedulable 指令模板，逐条设置间隔；加载失败拦截提交（"驱动轮询指令未成功加载…"）；提交时冻结一致快照；
  - 「继承历史数据（可选）」折叠区（默认折叠）：若为更换/重建的同一台物理设备，可选择继承的历史逻辑设备（LogicalDeviceCandidateSelect：按类型+节点+硬件ID+通道过滤候选，展开时才发请求），已选显示"已选择" tag；提交时带 `logical_device_id`（未选不传）。
- 提交：调 `edgeDeviceApi.create({name, node_id, channel_id, hardware_id, type: parser.id, interval_ms, command_intervals?, logical_device_id?})`（不传 device_config_id → driver-backed 创建）；成功提示 + 关窗 + 重置表单 + emit('created')。
- 关闭/取消时重置表单，避免下次残留。

### 3.8 OTA 升级对话框（OTAForm.vue）
- 字段：固件版本下拉（仅 active 固件，显示版本+说明，展示当前版本对比）、当前版本静态展示、选中固件的信息展示区。
- 「开始升级」按钮：校验选中固件后调 `nodeApi.startOTA(collectorId, firmware_id)`；之后轮询真实进度（进度条 + 状态；completed/failed 停止轮询并提示）。
- 取消/关闭按钮：升级进行中（completed 前）可点「取消」中止；关闭后 `emit('success')` 由详情页刷新固件版本 + OTA 历史。
- 对话框宽度 560px（受全局 92vw 移动端约束）。

### 3.9 OTA 升级历史卡
- 头部「刷新」；表格（移动端横向滚动 + 提示条）：
  - 升级版本（`from → to`）/ 状态（el-tag：pending=等待中 info / downloading=下载中 warning / installing=安装中 warning / success=成功 success / failed=失败 danger / cancelled=已取消 info）/ 进度（el-progress，success=成功状态 / failed=exception）/ 开始时间 / 完成时间（空显示 `-`）/ 操作（仅 pending/downloading 显示「取消」红色文字按钮）。
- 取消：ElMessageBox 确认 → `nodeApi.cancelOTA(id, record.id)` → 成功提示 + 重拉历史。

### 3.10 系统日志卡（LogPanel + LogRealtimeViewer + LogHistoryPanel）
**控制条：**
- 「日志流」开关：读/写 nodeApi.getLogConfig/updateLogConfig（stream_enabled）；开/关成功提示；
- 「级别」下拉：日志级别（禁用态=日志流关闭时），改级别走 updateLogConfig；
- 「持久化」开关：updateLogPersist；**若持久化开但日志流关，显示黄条警告"持久化已开启但日志流未开启，ESP32 不会产生日志。请同时开启日志流。"**。
**实时日志区（LogRealtimeViewer）：**
- 终端风格黑色区域（JetBrains Mono 等宽，高度 clamp 420px~720px，58vh；移动端 320~560px）：每行 = 运行时间(ESP uptime 微秒转可读) + 级别(颜色分级) + tag + 消息；
- 数据源：WS `WS_EVENT.NODE_LOG`（按 node_id 过滤），上限 5000 行环形保留；
- 工具栏：搜索框（Tag/消息/级别实时过滤，搜索时显示"命中数/总数"）、暂停/继续（暂停时新日志不滚动）、清屏、导出文本、导出 CSV；
- 「N 条新日志 · 回到底部」悬浮按钮：未读计数（基于 receivedCount 相对上次已读位置，搜索态按搜索语义计数），点击回到底部并确认已读；
- 虚拟滚动（vue-virtual-scroller RecycleScroller，行高 28px）。
**历史日志区（LogHistoryPanel）：**
- 工具栏：查询 / 导出当前结果(CSV) / 全部清理（危险，二次确认"确认清理该节点全部历史日志？此操作不可恢复。"）；

- 空数据显示 el-empty"暂无历史日志"。

### 3.11 详情页数据与状态逻辑（重设计需保留的契约）
- 初次加载：collector 详情 + OTA 历史 + DMA 通道并行拉取；无 collector 显示骨架屏；
- **fetchDevices 只能在 collector 详情成功且拿到序列号后触发**（用数字路由 id 查会查空且闪烁）；collector 加载失败时兜底关 loading；
- 采集器上线时（离线→在线 watch）：自动刷新 ChannelPanel 的通道/总线（refreshChannels + refreshBuses）；
- WebSocket NODE_STATUS：收到本节点延迟 → 更新 latency + 收尾测延迟流程并提示；其它状态变更 → 重新拉详情；
- 在线时自动测延迟（若详情里无延迟数据）；
- 路由 id 变更（同页复用）：重置所有状态、清定时器、重新拉全部数据；卸载时递增所有序列号 + 清理定时器 + 退订 WS；
- 会话切换保护：所有写操作带 getSessionGeneration/assertSessionGeneration + 组件 generation，防跨会话/跨路由竞态落地。

## 五、页面级交互约束与易错点（重设计必读）

1. **node_id 是物理序列号**：凡查设备/通道/日志必须用 `collector.node_id`，路由 `:id` 是数字主键，二者不可混用（前端历史 bug 类）。
2. **离线即只读**：详情页三个顶栏操作、总线配置保存/新建通道/通道编辑/删除、DMA 开关等全部在 `collector.status !== 'online'` 时禁用（灰色 + tooltip"设备离线，无法操作"）；但列表/日志查看不限制。
3. **硬件类型大小写**：后端存大写（UART/I2C/SPI/ADC），前端表单小写，任何比较需归一化。
4. **在线时长数学一致性**：上线时间 + 在线时长 ≈ 当前时间，重设计不得破坏每秒刷新的在线时长计算。
5. **WS NODE_STATUS 驱动实时性**：列表就地更新不重拉；详情延迟靠 WS 回包收尾（测延迟按钮是"发 ping → 等回包 → 提示 N ms"）。
6. **WS NODE_LOG 驱动实时日志**；PERIPH_RESULT 驱动 GPIO/PWM 运行态。
7. **缓存**：列表 15s TTL / 详情 15s TTL，双 key（数字 id + 序列号）；删除节点后清全缓存；写操作递增 epoch 防止旧响应落地。
8. **移动端适配现状**：统计卡 4 列紧凑、描述列表单列、宽表格横向滚动+提示、对话框 92vw、日志终端高度降档、页头按钮换行——重设计后仍需保留这些断点行为（768/1200）。
9. **确认类操作**：删除节点 / 删除通道 / 取消 OTA / 清理历史日志 / 清理指定时间前日志，全部二次确认。
10. **空状态**：节点列表 EmptyState、关联设备空、DMA 空、OTA 历史空、日志空（"等待日志..." / "无搜索命中" / "暂无历史日志"）均需保留。
11. **加载骨架屏**：列表页首载（4 stat + 8 card 骨架）、详情页各卡骨架（基本信息 5 行 / 总线 6 行 / DMA 3 行 / 设备 4 行 / OTA 4 行）。
12. **「添加节点」与卡片「配置」是未落地占位跳转**（`/node?action=add`、`/node/:id?tab=config` 无接收方），重设计要么补功能要么移除。
13. **通道终端是底层总线调试工具**（HEX/ASCII 收发），不是数据面板——重设计时注意与"传感器数据展示"区分定位。
