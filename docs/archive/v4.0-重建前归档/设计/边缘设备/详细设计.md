> **实现**: [实现/边缘设备.md](../../实现/边缘设备.md)
> **验收**: [验收标准.md](验收标准.md)
> **关联**: [00-术语表.md §2.4](../00-术语表.md) | [00-概念模型.md](../00-概念模型.md) | [节点/详细设计.md](../节点/详细设计.md) | [设备配置/详细设计.md](../设备配置/详细设计.md)

## 1. 功能概述

**边缘设备** = **节点** (物理整机) + **通道** (物理端点) + **设备配置** (型号定义) 三元组的**实例化**。

它是数据采集的**实际载体**,每个边缘设备在中心端是一个 DB 记录,通过 sync 机制把配置下发到节点(节点的 channel 持有"挂的设备"信息,但不感知"边缘设备"概念)。

### 1.1 与 v2.1 "设备" 的区别

| 维度 | v2.1 "Device" | v2.2 "EdgeDevice" |
|------|----------------|------------------|
| **关注点** | 物理设备 (无 Node 概念) | 节点+通道+型号 三元组实例 |
| **type 字段** | `Type` (重复了 DeviceConfig.DeviceType) | 不存, 通过 `device_config_id` 查 |
| **parser_id 字段** | `ParserID` (重复了 DeviceConfig.ParserID) | 不存, 通过 device_config 查 |
| **init flow** | 不存 | 通过 device_config.init_flow 查 |
| **协议下发** | 直接下发 device 记录 | 不下发 (节点只接收 channel + parser) |

### 1.2 端点

| 端点 | 方法 | 权限 | 用途 |
|------|------|------|------|
| `/api/v1/edge-devices` | GET | 登录 | 列表 (分页 + 过滤) |
| `/api/v1/edge-devices/:id` | GET | 登录 | 详情 |
| `/api/v1/edge-devices` | POST | admin | 创建设备 (1 个 node + 1 个 channel + 1 个 device_config) |
| `/api/v1/edge-devices/:id` | PUT | admin | 编辑 (interval_ms / enabled) |
| `/api/v1/edge-devices/:id` | DELETE | admin | 删除 |
| `/api/v1/edge-devices/:id/init` | POST | admin | 触发设备初始化 (v2.1 G6 修复: sendAndWait) |
| `/api/v1/edge-devices/:id/data` | GET | 登录 | 历史数据 (sensor_name / time_range) |
| `/api/v1/edge-devices/:id/latest` | GET | 登录 | 最新数据 |
| `/api/v1/edge-devices/:id/operations` | POST | admin | 远程操作 (PWM/雨量/...) |
| `/api/v1/edge-devices/:id/operations/history` | GET | 登录 | 操作历史 |

> **v2.2 新增端点说明**:
>
> - `GET /:id/latest-data` — 获取边缘设备最新一条数据 (等价于 `/latest` 的语义别名, 返回 unified_data 最新记录)
> - `GET /:id/data` — 获取边缘设备历史数据 (等价于已有 `/data` 端点, 支持 sensor_name / time_range 过滤)
> - `POST /:id/operations` — 远程操作 (PWM/雨量重置/...), 发送 WriteCommand 到节点
> - `GET /:id/operations/history` — 查询该设备的操作历史记录
> - `POST /:id/init` — 触发设备初始化 (v2.1 G6 修复: sendAndWait), 重新执行 device_config.init_flow 步骤

> v2.1 兼容: `/api/v1/devices` 同样可用 (双路径, 见 [命名迁移设计.md §3.3](../../archive/命名迁移设计-v2.2.md)

## 2. 数据模型 (v2.2)

```sql
CREATE TABLE edge_devices (
  id                  SERIAL PRIMARY KEY,
  name                VARCHAR(64) NOT NULL,            -- 业务名 (e.g. "BMP280 现场 A 屋顶")
  node_id             INTEGER NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  channel_id          INTEGER NOT NULL REFERENCES channels(id) ON DELETE RESTRICT,
  device_config_id    INTEGER NOT NULL REFERENCES device_configs(id) ON DELETE RESTRICT,
  hardware_id         INTEGER NOT NULL DEFAULT 0,      -- 通道上的地址 (I2C 0x76 / SPI 0 / GPIO pin)
  interval_ms         INTEGER NOT NULL DEFAULT 5000,
  enabled             BOOLEAN NOT NULL DEFAULT true,
  status              VARCHAR(20) NOT NULL DEFAULT 'active',  -- active/error/disabled/initializing
  error_code          INTEGER NOT NULL DEFAULT 0,
  last_data_at        TIMESTAMPTZ,
  last_error          VARCHAR(256),
  config_version      VARCHAR(64),                     -- v2.1 同步: 该设备应用到的 manifest_id
  init_state          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- pending/in_progress/done/failed
  init_last_step      INTEGER NOT NULL DEFAULT 0,
  init_total_steps    INTEGER NOT NULL DEFAULT 0,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at          TIMESTAMPTZ,
  UNIQUE (node_id, channel_id, hardware_id)            -- 同一通道同一地址不能重复
);

CREATE INDEX idx_edge_devices_node_id ON edge_devices(node_id);
CREATE INDEX idx_edge_devices_channel_id ON edge_devices(channel_id);
CREATE INDEX idx_edge_devices_device_config_id ON edge_devices(device_config_id);
CREATE INDEX idx_edge_devices_status ON edge_devices(status);
```

**关键字段**:

| 字段 | 含义 | 备注 |
|------|------|------|
| `node_id` | 节点 (FK) | 物理整机 |
| `channel_id` | 通道 (FK) | 节点的物理通信端点 |
| `device_config_id` | 设备配置 (FK) | 型号定义 (协议无关) |
| `hardware_id` | 通道上的地址 | I2C 0x76 / SPI 0 / GPIO pin 等 |
| `interval_ms` | 采集间隔 | 来自边缘设备 (而非设备配置) |
| `enabled` | 启用 | 来自边缘设备 |
| `status` | 当前状态 | active/error/disabled/initializing |
| `init_state` | 初始化状态 | pending/in_progress/done/failed |

**v2.1 → v2.2 迁移**:
- 旧 `devices` 表 → 新 `edge_devices` 表
- 旧 `devices.Type` 和 `devices.ParserID` 删除 (从 `device_configs` 推导)
- 旧 `devices.ChannelID` 保留, 改名 `channel_id`
- 新增 `device_config_id` (FK) ← 关键
- 新增 `node_id` (FK, 通过 channel_id 推导或显式存)

## 3. 状态机 (v2.2 强化)

### 3.1 边缘设备状态

```
       创建
        ↓
    ┌─────────┐ 触发 init     ┌──────────────┐
    │ pending ├───────────────►│ initializing │
    └────┬────┘                └──────┬───────┘
         │                            │
         │ 首次采集成功 (data 来了)    │ init 完成
         │                            ▼
         │                      ┌──────────┐
         └─────────────────────►│  active  │◄────┐
                                └─────┬────┘     │
                                      │          │ 错误恢复
                                      ▼          │
                                ┌──────────┐     │
                                │  error   ├─────┘
                                └─────┬────┘
                                      │ 手动禁用
                                      ▼
                                ┌──────────┐
                                │ disabled │
                                └──────────┘
```

### 3.2 状态转移触发

| 从 | 到 | 触发 |
|----|----|----|
| pending | initializing | 节点上线 + triggerDeviceInit (在 Hello 时) |
| pending | active | 首次数据成功 (init 跳过或没 init 流程) |
| initializing | active | InitDevice sendAndWait 全成功 |
| initializing | error | InitDevice 失败 (超时/超时 3 次) |
| active | error | DataReport error_code != 0 |
| error | active | 收到正常数据 (自动恢复) |
| active | disabled | 手动 PUT enabled=false |
| disabled | active | 手动 PUT enabled=true |
| any | pending | 重新初始化 (v2.2 新增) |

### 3.3 初始化状态机 (v2.1 G6 修复)

```
pending (1) → in_progress (2) → done (4) or failed (5)
                              │
                              ├─→ timeout (3 次重试) → failed
                              └─→ step 失败 → failed
```

**关键**: v2.2 **必须用 sendAndWait**,不再用 `time.Sleep`

## 4. 关键流程

### 4.1 创建边缘设备 (POST /edge-devices)

**v2.2 强制 3 要素**: node + channel + device_config

```json
POST /api/v1/edge-devices
{
  "name": "BMP280 现场 A 屋顶",
  "node_id": 1,
  "channel_id": 2,
  "device_config_id": 5,
  "hardware_id": 0x76,
  "interval_ms": 1000
}
```

**后端流程**:
1. 验证 node 存在
2. 验证 channel 存在且属于该 node
3. 验证 device_config 存在
4. 验证 (node_id, channel_id, hardware_id) 唯一
5. 创建 edge_device 记录
6. **EmitConfigChange** (v2.1 同步机制): 通知节点拉新配置
7. 节点收到 ConfigManifest → apply → 启动该 edge_device 的采集
8. 节点触发 init (如果有 init_flow)
9. 节点发 ConfigResult

### 4.2 节点侧采集流程

节点不知道"edge_device"概念,只接收 channel 配置。采集流程:

```
sync_manager 启动
  ↓
config_mgr_apply_manifest (收到 ConfigManifest)
  ├─ 解析 channels
  ├─ 对每个 channel:
  │   ├─ hw_pin_setup(channel.bus_config)
  │   ├─ bus_init(channel.bus_type)
  │   └─ 启动该 channel 的 scheduler task
  │         ├─ 对该 channel 上挂的所有 edge_devices:
  │         │   ├─ edge_device_1: interval 1000ms, parser A
  │         │   ├─ edge_device_2: interval 2000ms, parser B
  │         │   └─ ...
  │         └─ 周期触发:
  │               ├─ bus_xfer(channel_id, hardware_id, parser)
  │               ├─ parser.parse(raw_bytes) → sensor_data
  │               └─ msg_handler_send_data_report(...)
  └─ send_config_result
```

**关键**: 节点从 ConfigManifest 拿到的不是 edge_device 列表,而是:
- channel 配置 (bus_type + bus_config + template_refs)
- parser 注册表 (从 device_config 推导)
- edge_device 的 (channel_id, hardware_id, interval_ms, parser_id) 关联表

> 节点侧的"edge_device"是逻辑概念,由 parser + channel 共同实现,不需要单独的 struct

### 4.3 设备初始化 (G6 修复)

```go
// deviceinit.go InitDevice (v2.2 改用 sendAndWait)
func (o *Orchestrator) InitDevice(deviceID string, channelID uint32, deviceType string) error {
    steps := o.GetInitSequence(deviceType)
    for i, step := range steps {
        resp, err := o.pendingWrite.SendAndWait(
            deviceID, channelID, step.Data, step.ReadSize, step.Timeout*3)
        if err != nil {
            return fmt.Errorf("step %d %s failed: %w", i, step.Name, err)
        }
        if !resp.Success {
            return fmt.Errorf("step %d %s nack: %s", i, step.Name, resp.ErrorMsg)
        }
        if step.Name == "read_calib" {
            o.saveCalibData(deviceID, deviceType, resp.Data)
        }
    }
    return nil
}
```

### 4.4 远程操作 (PWM/雨量/...)

```go
// handler_edge_device.go operations
func (m *Manager) ExecuteOperation(edgeDeviceID uint, op *Operation) error {
    edge := m.getEdgeDevice(edgeDeviceID)
    
    // 找到节点和通道
    channel := m.getChannel(edge.ChannelID)
    
    // 构造 WriteCommand
    writeCmd := buildWriteCommand(op, channel, edge.HardwareID)
    
    // 发送并等待响应 (sendAndWait)
    resp, err := m.pendingWrite.SendAndWait(
        edge.Node.NodeID, channel.ID, writeCmd.Data, writeCmd.ReadSize, 5*time.Second)
    
    if err != nil {
        m.recordOpLog(edgeDeviceID, op, "failed", err.Error())
        return err
    }
    
    m.recordOpLog(edgeDeviceID, op, "success", string(resp.Data))
    return nil
}
```

### 4.5 数据采集 (DataReport)

```
节点 scheduler 周期触发 (每 edge_device.interval_ms)
  ↓
读取 (channel_id, hardware_id) 物理值
  ├─ bus_xfer(channel.bus_type, channel.bus_config, cmd)
  └─ raw_bytes
  ↓
解析 (使用 device_config.parser 注册的 parser)
  ↓
sensor_data { name: "temperature", value: 23.5, unit: "°C" }
  ↓
DataReport (上行, 含 edge_device_id 在 channel_id 字段)
  ↓
中心端 handler_data:
  ├─ 解析
  ├─ 写 unified_data 表 (关联 edge_device_id)
  └─ 推 WS data_update
```

## 5. 协议层 (v2.2 扩展)

### 5.1 协议字段

**DataReport (0x03) v2.2 字段 1 (channel_id)** 复用为 `edge_device_id`:
- v2.1 字段含义: channel 的 id
- v2.2 字段含义: edge_device 的 id (中心端 PK)
- 兼容: 老节点发 channel_id, 中心端按 channel_id 找该 channel 上的 edge_device(s), 默认取第一个

**ConfigManifest (0x04) v2.2 字段 5 (channel_info)**:
```json
{
  "channel_id": 1,
  "bus_type": "SPI",
  "bus_config": "{...}",
  "edge_devices": [
    {
      "edge_device_id": 10,        // 中心端 PK (节点侧不感知)
      "hardware_id": 0,
      "parser_id": "bosch.bmp280",
      "interval_ms": 1000,
      "enabled": true
    }
  ]
}
```

**ConfigQuery (0x13) v2.2 字段 4 (filter_by_edge_device_id)**:
```
SVR 收到 ConfigQuery, 可按 edge_device_id 过滤 (如果该 edge 改了 config)
```

### 5.2 不下发 EdgeDevice 概念到节点

**原因**: 节点不知道 edge_device 概念,这是中心端业务抽象

**节点侧存储**:
```c
// ESP32 NVS 不存 edge_device, 只存 channel + (hardware_id, parser_id, interval_ms) 列表
NVS:
  cfg_epoch, manifest_id
  channels[]:
    channel_id, bus_type, bus_config
    edge_devices[]:        // 这里用 edge_devices[] 命名只是为了清晰,实际是 "channel 上挂的子设备"
      hardware_id, parser_id, interval_ms, enabled
```

## 6. 容错设计 (v2.2 强化)

| 场景 | 行为 | 修复 |
|------|------|------|
| 创建设备时 (channel_id, hardware_id) 冲突 | UNIQUE 约束 + 返回 409 | - |
| 创建设备时 node_id 不存在 | 404 | - |
| 创建设备时 device_config 已被删除 | 404 | - |
| Init 步骤超时 | sendAndWait 内部重试 3 次, 失败 fail | G6 |
| Init 步骤 NACK | step 失败, 整个 init 失败 | - |
| 节点不在线时创建设备 | 创建 DB 记录, ConfigChange 触发, 节点上线时拉取 | - |
| 节点在线时删除设备 | EmitConfigChange → 节点停止该 edge 采集 | - |
| 节点不在线时删除设备 | 同上, 节点上线时拉取最新 config (无该 edge) | - |
| 设备配置 device_config 被删除 (有 edge 引用) | RESTRICT 约束阻止, 返回 409 | - |
| 节点侧 init 失败 | 节点发 ConfigResult success=false + error_code | - |

## 8. 安全 (v2.2)

- 创建/编辑/删除 edge_device: admin role
- 查询: 登录即可
- 设备配置 (device_config) 引用: RESTRICT 防止误删
- 操作审计: OperationLog 记录所有 admin 操作
