## 1. 功能概述

EHomeSystem 使用 JWT (HS256) + 三级 RBAC 控制前后端所有访问入口。

### 1.1 角色定义

| 角色 | 描述 | 权限 |
|------|------|------|
| **admin** | 管理员 | 全部 + 用户管理 |
| **operator** | 操作员 | 节点/边缘设备/通道/固件/配置, 不可见系统监控 |
| **viewer** | 观察者 | 只读 |

### 1.2 端点清单

| 端点 | 方法 | 权限 |
|------|------|------|
| `/api/v1/auth/login` | POST | 公开 |
| `/api/v1/auth/refresh` | POST | 持有 refresh_token |
| `/api/v1/auth/logout` | POST | 持有任意 token (前端清 storage) |
| `/api/v1/firmwares/:filename/download` | GET | 公开 (ESP32 无 JWT, 路由在认证外注册) |
| `/api/v1/users` | GET/POST | admin |
| `/api/v1/users/:id` | GET/PUT/DELETE | admin |
| `/api/v1/users/me/change-password` | POST | 任意登录用户 |

## 2. 数据模型

```sql
CREATE TABLE users (
  id            SERIAL PRIMARY KEY,
  username      VARCHAR(64)  UNIQUE NOT NULL,
  email         VARCHAR(128),
  password_hash VARCHAR(128) NOT NULL,  -- bcrypt cost 10
  role          VARCHAR(16)  NOT NULL CHECK (role IN ('admin','operator','viewer')),
  enabled       BOOLEAN      DEFAULT true,
  last_login_at TIMESTAMPTZ,
  created_at    TIMESTAMPTZ  DEFAULT NOW(),
  updated_at    TIMESTAMPTZ  DEFAULT NOW()
);

CREATE INDEX idx_users_role ON users(role);
```

### 2.1 密码哈希

- 算法: bcrypt (cost 10)
- 库: `golang.org/x/crypto/bcrypt`
- 验证: `bcrypt.CompareHashAndPassword(stored, input)`
- 失败: 统一返回 `invalid username or password` (不区分用户名/密码错, 防止用户枚举)

## 3. JWT 设计

### 3.1 Token 结构

```json
{
  "sub": 1,              // user_id
  "username": "admin",
  "role": "admin",
  "iss": "ehome",
  "iat": 1703491200,
  "exp": 1703577600
}
```

- 签名: HS256, 密钥从 `EHOME_JWT_SECRET` 环境变量
- 有效期: 24h (生产) / 7d (开发)
- 存储: localStorage (记住我) / sessionStorage (临时)

### 3.2 签发流程

```
POST /auth/login {username, password}
  ↓
[bcrypt 验证]
  ↓ (通过)
[签发 JWT]
  ├─ 主 token (24h)
  ├─ refresh token (7d, 单独表存)
  └─ 更新 last_login_at
  ↓
{ token, refresh_token, user: {id, username, role} }
```

### 3.3 鉴权流程

```
请求带 Authorization: Bearer ***
  ↓
[middleware/jwt] 解析 + 验证 + 写 ctx.Set("user_id")
  ↓
[handler] 从 ctx 取 user_id
  ↓
[role 检查] (路由级)
  ├─ 需要 admin → user.role != "admin" → 403
  └─ 需要登录 → user 未登录 → 401
```

## 4. 状态机

### 4.1 登录失败锁定 (前端)

```
[空] ──→ 输入密码 ──→ 校验失败 ──→ attempts++
                                  ↓
                            attempts < 5? ─→ 否 ─→ [locked 5min]
                                  ↓ 是
                            attempts = 0? ─→ 是 ─→ 清零 + 成功
                                  ↓ 否
                            继续提示 "还剩 N 次机会"
```

- 状态持久化: `localStorage` (key: `login_lockout`)
- 锁定 5 分钟后自动清零
- 默认 5 次, 可通过 `VITE_LOGIN_MAX_ATTEMPTS` 调整

### 4.2 服务端强制锁定 (TODO P2)

> 当前只在客户端做锁定, 服务端**未做** IP 维度的 brute-force 防护

## 5. API 契约

### 5.1 POST /api/v1/auth/login

**Request**:
```json
{ "username": "admin", "password": "xxx" }
```

**Response 200** (注意: 不在 envelope 内, 直返):
```json
{
  "token": "eyJhbG...NiIs...",
  "user": { "id": 1, "username": "admin", "role": "admin" }
}
```

**Response 401**:
```json
{ "error": "invalid username or password" }
```

### 5.2 GET /api/v1/users

**Headers**: `Authorization: Bearer *** token>`

**Response 200**:
```json
{
  "code": 200,
  "data": {
    "list": [
      { "id": 1, "username": "admin", "email": "a@x.com",
        "role": "admin", "enabled": true,
        "created_at": "2026-06-03T...",
        "last_login_at": "2026-06-03T..." }
    ],
    "total": 1
  }
}
```

## 6. 容错设计

| 场景 | 行为 |
|------|------|
| 过期 token | 401 + 前端跳 login (无感) |
| 错误签名的 token | 401 + 日志 WARN |
| 角色不足 | 403 + 前端 v-permission 隐藏 |
| bcrypt 错误 | 500 + 通用错误 (不暴露细节) |
| DB 不可达 | 500 + "服务暂时不可用" |

## 7. 可观测性

| 事件 | 字段 | 触发 |
|------|------|------|
| `auth.login.success` | user_id, ip | 登录成功 |
| `auth.login.failure` | username, ip, reason | 登录失败 |
| `auth.token.expired` | user_id, exp | 401 触发 |
| `auth.user.created` | new_user_id, role | admin 建用户 |
| `auth.password.changed` | user_id, forced | 改密 |
