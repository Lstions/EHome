## 1. 系统定位

EHomeSystem 是家庭数字化 IoT 平台：以 ESP32 为边缘节点，通过 MQTT 接入中心端（Go 后端），完成多协议传感器采集、电池（BMS）监控、逆变器管理、外设直控与固件 OTA 升级，并提供 Vue3 Web 管理界面供单管理员使用。

四层模型（详见 [00-概念模型.md](00-概念模型.md)）：

```
平台层 EHomeSystem
  └─ 中心端 Center（Go：业务核心/状态机/持久化/协议解析）
       └─ 节点 Node（ESP32-S3/C6：无业务逻辑，只做协议/驱动/上报）
            └─ 边缘设备 Edge Device（节点+通道+设备配置三元组的实例，逻辑抽象在中心端）
```

## 2. 用户与权限

- 单主体模式：单管理员账户，所有菜单仅由登录状态保护（早期 RBAC 三角色已收敛为 API 层语义）；未登录仅可访问登录页与首次初始化引导页。
- 首次使用初始化引导：检测未初始化状态，引导创建管理员账户（`/initialize`）。
- JWT 认证：默认 24h，勾选"记住我"签发 7 天令牌；支持重新认证（reauthenticate）、修改密码、远程登出所有会话（logout-all）。
- 登录防爆破：失败限流锁定；前端区分"登录接口 401"（不清会话）与其他 401（跳转登录）；429 解析 Retry-After。

## 4. 功能需求详述

### 4.1 认证与账户

- 需求：管理员可登录/登出、记住登录态、修改密码与资料；密码 ≥8 位 bcrypt 存储。
- 支撑 API：`/auth/*`、`/account`、`/account/password`、`/account/reauthenticate`、`/account/logout-all`。
- 边界：登录 401 不清会话；非登录 401 才跳转登录页。

### 4.2 仪表盘

- 需求：一屏掌握系统健康——节点在线/离线统计、异常摘要（采集错误）、按分类的数据趋势图、节点状态变化记录。
- 支撑 API：`/overview`。

### 4.3 节点管理

节点是物理整机（ESP32），本域覆盖其接入、资源、运维全流程：

- 基本信息：节点列表/详情、在线状态、uptime、固件版本、ping、状态历史。
- 总线配置 TAB：按总线类型（I2C/UART/SPI/ADC/GPIO）子页配置通道；I2C 扫描（ScanRequest/Report）、通道重配置、通道写入；在线可改配置、离线只读已上报配置。
- DMA 通道 TAB：只读资源视图（DMA 编号/类型/能力/最大突发/绑定/兼容总线），绑定操作在总线配置 TAB 完成。
- 关联设备 TAB：该节点下边缘设备列表/卡片双视图。
- OTA 历史 TAB：该节点历次升级记录。
- 系统日志 TAB：ESP32 日志流（Log V2）查看与持久化配置。
- 通道终端 TAB：进入 WebSocket 透明管道终端。
- 资源发现：`query-resources`/`capabilities`/`hardware/config`/`config/sync`（手动触发同步）。
- 硬约束：硬件资源完全来自节点 ResourceReport 上报，后端不得硬编码任何型号的 GPIO/PWM/UART fallback；未上报返回空资源集。
- 支撑 API：`/nodes*`、`/:id/dma-channels`、`/:id/dma-config`、`/:id/bus/i2c/scan`、`/:id/query-resources`、`/:id/status-history`、`/:id/logs`、`/:id/log-config`、`/:id/log-persist`。

### 4.4 通道管理与通道终端

- 通道是节点的物理通信端点（UART/I2C/SPI/GPIO/ADC）。
- 通道列表：查看各节点通道、地址、速率、模式。
- 通道终端：WebSocket（`/api/v1/ws/terminal`）对指定通道做十六进制透明管道读写，用于现场调试协议帧；支持清空终端日志。
- 支撑 API：`/channels/:channel_id/terminal`、`/channels/:channel_id/terminal/write`。

### 4.5 GPIO/PWM 外设直控

- 需求：对节点 GPIO 引脚直接置位/读取，对 PWM 通道调频率/占空比/启停/查状态。
- 架构约束：GPIO/PWM 不走通道系统（只有可数据交互、有协议帧的资源才进通道），通过独立 PeriphCmd(0x1B)/PeriphRsp(0x1C) 协议直控；前端为行式资源控制面板。
- 支撑 API：`/nodes/:id/gpio[/:pin[/set|read]]`、`/nodes/:id/pwm[/:hardware_id[/duty|freq|start|stop|state]]`。

### 4.6 设备配置模板

- 需求：定义一种设备型号的协议无关配置——parser 解析规则、init_flow 初始化序列、operations 操作集；可设为某设备类型的默认配置；提供树视图与解析器在线测试。
- 支撑 API：`/device-configs*`、`/:id/test-parser`、`/:id/init-flow`、`/:id/operations`、`/:id/default`、`/tree`。

### 4.7 边缘设备

边缘设备 = 节点 + 通道 + 设备配置 的实例，是采集与控制的基本单元：

- 通用能力：CRUD、批量删除、初始化（init）、执行动作（execute）、改地址（change-address）、最新数据/历史数据查询、候选设备推荐（candidates，接入前发现总线上可实例化的设备）、创建时校验 (node, channel, hardware_id) 唯一。
- 动作执行链：驱动动作 → dry-run 预览 → 确认后执行（危险动作二次确认对话框）；critical 类动作（如 bms.reboot）at_most_once 限频 + 设备互斥锁。
- 类型化详情页（按驱动注册的能力渲染）：
  - **BMS 详情页（嘉佰达 Jiabaida）**：电芯电压图（含历史对比）、MOS 状态、保护状态网格、SOC、温度探头分档展示（>60°C 高温档等）；写动作覆盖 MOS 策略设置、充/放电 MOS 测试、强制均衡、寻车（find_car）、进出工厂模式与工厂参数读写、BMS 重启、清除告警、充放电时间窗、上报间隔、内阻/SN/自定义属性写入等 17+ 动作；critical 类动作（如 bms.reboot）限频 at_most_once。
  - **逆变器详情页（Techfine）**：功率流向图、MPPT 通道、发电量统计、温度与风扇、电池信息、告警清单。
  - **通用设备详情**：共享控制面板、历史图表区、指令频率区、动作确认对话框（危险动作二次确认）。
- 驱动体系（`backend/internal/drivers/`，注入式 Registry + 动作 schema + 命令模板）：
  - 内置传感器驱动：BMP280 / LKTH01 / SN3000 / PRS3001。
  - 通用驱动：generic_modbus / generic_i2c（任意协议设备接入）。
  - 厂商驱动：嘉佰达 BMS、Techfine 逆变器（含 BMS 协同充电控制）。
- 支撑 API：`/edge-devices*`、`/:id/init`、`/:id/execute`、`/:id/latest-data`、`/:id/data`、`/:id/change-address`、`/batch-delete`；驱动命令另经 `/drivers` 注册表路由。

### 4.8 逻辑设备与数据生命周期（v3.3）

- 需求：多个边缘设备可合并为一个逻辑设备并保持数据可追溯；数据保留期可配（默认 365 天）；删除设备时可同时删数据；每日 purge 任务清理过期数据。
- 关键规则：合并走预览 → 发起 → 后台搬迁（merge job）；合并门控要求 ≥2 个可合并候选；合并中/已合并/purge 中的实例拒绝重复操作（409）；被合并方保留 logical_device_id 身份链（merge_chain）。
- 支撑 API：`/logical-devices*`、`/merge/preview`、`/merge`、`/merge-jobs/:id`；后端 `internal/datalifecycle/`（merge/merge_chain/retention/purge/backfill/indexes）。

### 4.9 数据面板

- 需求：选设备 + 时间范围后查看历史趋势图表与历史数据表格；可开启实时数据接收（WebSocket 推送）；历史数据导出 CSV；大数据量走服务端降采样（max_points）保证图表流畅。
- 支撑 API：`/unified-data/historical[-batch]`、`/unified-data/categories`、`/devices/:id/history`、`/devices/:id/sensor-data`、`/nodes/:id/latest`；实时事件 `data_update`。

### 4.10 固件管理与 OTA

- 固件仓库：上传/列表/单个与批量删除/下载（下载走一次性 ticket 防盗链）。
- OTA 任务：创建（start/tasks）、进度查询（progress）、取消（cancel）；升级流为 OtaCommand(0x0A 含 SHA256) → 节点 HTTPS 下载（TLS 校验，Mozilla CRT bundle）→ OtaProgress(0x0B) 回报 → 分区校验 → 重启 → Hello 上线自动标记完成。
- 可靠性：A/B 分区 + 30s mark valid 自动回滚；同节点并发 OTA 走 supersede 模式；生产模式 HTTPS 不可降级。
- 支撑 API：`/firmwares*`、`/ota/*`。

### 4.11 数据源健康管理

- 需求：对采集数据源做激活/停用、健康检查、重置，并提供故障切换日志（failover-logs）供排障。
- 支撑 API：`/data-sources/:id[activate|deactivate|health|reset]`、`/devices/:id/failover-logs`。

### 4.12 厂商与型号目录

- 需求：维护厂商、设备分类、设备型号及型号字段元数据，作为设备配置与驱动的字典支撑。
- 支撑 API：`/vendors*`、`/device-models*`、`/device-categories`。

### 4.13 Home Assistant 集成

- 需求：将节点/设备以 MQTT Discovery 方式同步到 Home Assistant（单设备/单节点/全量三个粒度）；节点 Hello 上线时自动推送 retained discovery。
- 遥测隔离：HA 状态遥测走 best-effort 有界 latest-value 队列，HA 故障不阻塞采集主链路（已实测故障隔离）。
- 支撑 API：`/ha/sync/:deviceId`、`/ha/sync/node/:nodeId`、`/ha/sync/all`。

### 4.14 通知中心

- 需求：站内通知（配置同步失败、OTA 结果、合并任务结果等）统一呈现；未读计数、单条已读、全部已读。
- 支撑 API：`/notifications*`、`/unread-count`、`/read-all`；实时事件 `notification`。

### 4.15 系统监控

- 需求：运行指标页，自动刷新间隔可选 5s/10s/30s；展示含"能力快照超过有效期未上报的节点数"等健康指标。
- 支撑 API：`/metrics`、`/metrics/prometheus`（Prometheus 抓取端点）。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|------|------|
| 数据采集入库延迟 P99 | ≤ 200ms |
| MQTT 消息吞吐 | ≥ 100 msg/s |
| WebSocket 并发客户端 | ≥ 50 |
| CRUD → 节点收到 P99 | ≤ 5s |
| SyncGate 决策延迟 P99 | ≤ 1ms |
| OTA 升级耗时（10MB） | ≤ 5min |
| 前端首屏加载（gzip） | ≤ 300KB |

高频数据交互实测基线（2026-08-15 复测）：S1 场景丢率 0%（修复前 84%）、处理量提升 5.2–6.8×、PG 写入提升 8.3×、RSS 52MB、30min soak 零丢失。

### 5.2 安全

- API：JWT(HS256)；MQTT：用户名密码 + ACL（节点只能 pub/sub 自己的 topic）。
- 密码 bcrypt(cost 10)；登录 5 次失败锁定 5 分钟。
- OTA：SHA256 校验 + A/B 分区 + 自动回滚；HTTPS 默认开且生产不可降级。

### 5.3 容错与自愈（Fail-Open）

| 场景 | 行为 |
|------|------|
| 未知 wire code | WARN + 保留当前状态 |
| OTA 进度帧丢失 | Hello 上线时按 firmware_version 自动补完 OTA |
| 配置下发失败 | 退避重试 3 次 + 失败进通知 |
| 节点 90s 无心跳 | offline detector 判离线并推事件 |
| WS 断开 | 自动重连 + 顶部 banner 提示 |
| 中心端重启丢内存态 | 启动 5s 后向所有 online 节点 push |
| 节点恢复出厂（NVS 空） | SyncGate 检测后强制下发配置 |
| ConfigEventBus 满 | drop + 告警 |

### 5.4 可观测性

- 结构化 JSON 日志，同步操作携带 sync_id 链路追踪。
- Prometheus 指标族 `ehome_*`（节点在线数、数据接收计数、同步决策/时长、OTA 失败原因等）。
- WebSocket 事件规范：`node_status`、`data_update`、`edge_device_status`、`ota_progress`、`notification`、`node_config_synced`。

## 6. 平台约束（功能实现的硬约束）

1. 四层分离：任一层可独立替换；节点层无业务逻辑。
2. 协议优先：二进制帧协议（v2.5/v2.7，20 种消息类型）是中心端↔节点唯一契约，变更必须走版本化流程（`scripts/check_protocol_fields.sh` 门禁）。
3. 显式状态机：OTA/数据源切换/节点连接/边缘设备等跨时间流程全部显式状态机，状态字面量入库。
4. 资源上报制：硬件资源只来自 ResourceReport，禁止后端硬编码 fallback。
5. GPIO/PWM 引脚直控，不入通道系统。
6. 单主体模式：菜单仅由登录状态保护。
