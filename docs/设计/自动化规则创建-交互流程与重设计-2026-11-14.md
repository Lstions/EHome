## 1. 原交互流程（改造前）

### 1.1 主流程

```text
规则列表「创建规则」
  → 对话框（640px，单页滚动）
      ① 名称
      ② 触发器类型（传感器阈值 / 时间窗 / 日出日落；事件驱动禁用）
      ③ 触发器字段组（按类型切换；日出日落含位置来源与试算）
      ④ 附加条件（仅传感器阈值；行模式 ↔ JSON 源码）
      ⑤ 动作卡片（1..N，按顺序执行；风险动作带徽标与参数编辑）
      ⑥ 需人工确认（规则级开关）
      ⑦ 冷却时间 / 每日上限（数字框 + 常用档位）
      ⑧ 启用
      ⑨ 保存前诊断（仅保存后出现）
  → 点「保存」
      → 前端校验（toast 首条错误）
      → POST /automation-rules/precheck（blocking / warnings / risk_actions）
          · blocking 非空 → 诊断区逐条列出，拒绝保存
          · warnings 非空 → 第一次点击只展示，按钮变「我已了解，仍然保存」
          · risk_actions 非空 → 风险清单弹窗，逐项勾选后才能提交
      → POST/PUT 落库 → 关闭对话框、刷新列表
```

### 1.2 控件清单与职责

| # | 控件 | 作用 | 关键约束 / 联动 |
|---|------|------|-----------------|
| 1 | 名称 | 规则标识，列表与触发历史回链 | 必填；仅前端非空校验 |
| 2 | 触发器类型 | 决定下方字段组：传感器阈值 / 时间窗 / 日出日落 | 切换时清空互斥字段；`event` 占位禁用 |
| 3 | 数据来源 | 传感器阈值的数据来自「单设备」还是「来源组」 | 来源组时隐藏设备、改传 `source_group_id`，锚点由后端双写 |
| 4 | 边缘设备 / 来源组 | 选择被监测对象 | 单设备必填；来源组必填 |
| 5 | 传感器选择器 | 选择字段（支持族 `cell_*:max`、@别名） | 必填；带出单位/精度用于阈值展示；可试算 |
| 6 | 比较符 / 阈值 / 持续秒 | 条件本体：连续满足时长达到才触发 | 阈值按字段类型校验；持续 0 = 瞬时 |
| 7 | 时间窗开始/结束/边沿 | 每日窗口触发（进入/离开/窗口内） | HH:mm；跨零点有提示；存量 `8:00` 自动补零 |
| 8 | 日出/日落 + 偏移分钟 | 相对天文事件触发 | 偏移 [-720,720]；实时文案「日落前 30 分钟」 |
| 9 | 位置来源（2026-11-14） | 坐标/时区唯一入口：外网 IP 自动定位 / 手动城市 | 两项必选其一；时区随位置回填，**不可手填**；未选不能保存 |
| 10 | 试算（传感器阈值） | 用近 24h 数据预览「会不会触发」 | 只读接口；不自动请求 |
| 11 | 附加条件 | AND 条件列表；可切 JSON 源码 | 仅传感器阈值求值；行模式空行即报错 |
| 12 | 动作卡片 | 1..N 个动作，顺序即执行顺序 | 设备动作需设备+动作 ID+参数；通知需级别；风险动作需授权 |
| 13 | 需人工确认 | 触发后只生成待确认通知 | 与动作级风险徽标语义不同，二者并存 |
| 14 | 冷却时间 / 每日上限 | 防抖与日熔断 | 0-86400s / 0-1000；常用档位 chips 写回数值 |
| 15 | 启用 | 保存后是否立即生效 | 关闭保留配置 |
| 16 | 保存前诊断 | 展示 blocking / warnings | 仅保存后出现；warnings 需二次确认 |
| 17 | 取消 / 保存 | 关闭 / 提交 | 保存中 loading；风险弹窗打开时禁止再次保存 |

### 1.3 改造前的问题

1. **一屏塞不下**：640px 宽、单列滚动，PC 需要 2~3 屏；移动端弹窗 92vh 内再套滚动，
   动作卡片与冷却设置经常在首屏之外。
2. **没有进度感**：用户不知道「还差什么」，只能反复点保存看 toast。
3. **错误不定位**：校验只弹首条 toast，出错控件可能在当前视口之外；用户要来回滚。
4. **信息架构混杂**：附加条件嵌在「触发条件」内部，动作之后又出现冷却/每日上限，
   「触发 → 做什么 → 怎么执行」的因果被拉平成一条长列表。
5. **移动端底部操作拥挤**：取消/保存两个全宽按钮，加上弹窗内滚动，拇指区不稳定。

## 2. 重设计目标

- **一步一问**：每一步只回答一个问题，顺序符合用户心智：
  叫什么 → 什么时候触发 → 做什么 / 怎么执行 → 核对并保存。
- **错误可达**：点「下一步」只校验当前步骤；点「保存」校验全部并**跳到第一个出错的步骤**。
- **双端同构**：PC 用左侧步骤栏（可回看/跳转）；移动端全屏 + 顶部步骤条，单列、44px 触控目标。
- **零语义变化**：所有字段、校验、提交体、风险确认、warnings 二次确认、诊断区**行为不变**，
  只改变呈现与导航。

## 3. 新交互流程

### 3.1 步骤划分

| 步骤 | 标题 | 内容 | 进入下一步的条件 |
|---|---|---|---|
| 1 | 基本信息 | 名称、启用 | 名称非空 |
| 2 | 触发条件 | 触发器类型 / 阈值 / 时间窗 / 日出日落 + 位置 + 附加条件 + 试算 | 该类型的必填项 + 附加条件格式 |
| 3 | 动作与策略 | 动作卡片、需人工确认、冷却、每日上限 | 动作字段完整、参数 JSON 合法、策略边界 |
| 4 | 检查与保存 | 触发/位置/动作/策略摘要 + 保存前诊断 | 无（保存时执行全量校验 + 后端预检） |

- **任意步骤可点左侧步骤栏跳转**（移动端只能按「上一步/下一步」），不强制线性；
  真正的门禁在「下一步」与「保存」。
- **保存按钮始终存在**：非最后一步为次要样式（主操作是「下一步」），最后一步为主按钮。
  这样既保留熟手的「直接保存」路径，也避免向导把保存藏起来。
- **保存成功路径**：校验通过后自动切到第 4 步再发请求，用户能在摘要与诊断区旁看到
  precheck 的 blocking/warnings 与风险弹窗，而不是在某个字段步骤上"背后"弹窗。

### 3.2 校验与错误定位

```text
下一步 → validateStep(当前步)
保存   → validate()（全量，顺序与改造前一致）
         失败 → firstInvalidStep() 定位并切到对应步骤 + toast 首条错误
         通过 → 切到第 4 步 → precheck → warnings 二次确认 / 风险清单 → 提交
```

校验函数按域拆分（`useRuleForm.ts`）：`validateBasic` / `validateTriggerType` /
`validateConditions` / `validateActions` / `validatePolicy`，`validate()` 仅做顺序组合，
**不复制判据**。

### 3.3 PC 布局（≥768px）

```text
┌──────────────────────────────────────────────────────────────┐
│ 创建规则                                                   × │
├───────────────┬──────────────────────────────────────────────┤
│ ① 基本信息  ✓ │  基本信息                                    │
│ ② 触发条件  ✓ │  先给规则起个名字…                           │
│ ③ 动作与策略 ✓ │  ┌ 名称 ────────────────────────────────┐  │
│ ④ 检查与保存 ● │  │                                        │  │
│               │  └────────────────────────────────────────┘  │
├───────────────┴──────────────────────────────────────────────┤
│ 取消                              上一步   下一步   保存     │
└──────────────────────────────────────────────────────────────┘
```

- 对话框宽度 980px、最高 88vh；左栏 232px；右侧内容独立滚动（最大 62vh）。
- 步骤状态：当前蓝色、已完成绿色对勾、未开始灰色；可点击跳转。
- 底部按钮固定，不随内容滚动。

### 3.4 移动端布局（<768px）

```text
┌─────────────────────────────┐
│ 创建规则                 ×  │
│ 步骤 2/4        触发条件     │
│ ████████░░░░░░░░░░░░░░░░░░  │
│                             │
│ 触发条件                    │
│ 选择什么情况下触发…         │
│ ┌ 触发器类型 ────────────┐  │
│ └────────────────────────┘  │
│ …（单列，label 在控件上方） │
│                             │
│ [  上一步  ] [  下一步  ]   │
└─────────────────────────────┘
```

- `:fullscreen` 全屏，标题栏保留关闭 ×；内容区独立滚动。
- 顶部显示「步骤 n/4 + 当前步骤名」+ 25% 进度条。
- 表单项 `label-position="top"`，避免 92px 标签挤压 390px 宽度。
- 底部只保留 1~2 个按钮：前 3 步为「上一步/下一步」，第 4 步为「上一步/保存」；
  不再重复放「取消」（关闭走 ×），触控高度 ≥44px。
- 实测 390×844：`scrollWidth == innerWidth == 390`，无横向溢出。

### 3.5 控件在新布局中的位置

| 步骤 | 控件 |
|---|---|
| 1 | 名称、启用 |
| 2 | 触发器类型、数据来源、设备/来源组、传感器选择器、比较符/阈值/持续、时间窗、日出日落、位置来源、试算、附加条件 |
| 3 | 动作卡片（类型/设备/动作 ID/参数/级别/顺序/删除）、需人工确认、风险提示、冷却时间、每日上限 |
| 4 | 触发摘要、位置摘要、动作摘要、策略摘要、保存前诊断 |

## 4. 状态与边界

| 状态 | 行为 |
|---|---|
| 打开新建/编辑 | 步骤重置为 1；编辑时回填全部字段（含位置来源；旧规则降级为 city +「已配置坐标（历史规则）」） |
| 切换步骤 | 已填内容保留（所有步骤常驻 DOM，`v-show`），不重新挂载组件 |
| 下一步校验失败 | toast 首条错误，停留当前步骤 |
| 保存校验失败 | 切到第一个出错步骤 + toast |
| 保存进行中 | 保存按钮 loading；风险弹窗打开时再次保存被拒（既有护栏） |
| warnings | 第一次保存只展示诊断，按钮变「我已了解，仍然保存」；同一内容指纹再点才提交 |
| 风险动作 | 与改造前一致：勾选风险清单后提交 `risk_acknowledged` |

## 6. 后续可做（未实施）

- 步骤内锚点定位：保存失败时除了切步，还滚动到具体字段并聚焦。
