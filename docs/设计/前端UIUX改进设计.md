# 前端 UI/UX 改进设计

> **状态**: P0、P1、P2、P3 已实施；待完成全量浏览器矩阵与项目级回归
> **创建日期**: 2026-07-13
> **范围**: Vue 3 + Element Plus 前端（`frontend-shared/`）
> **依据**: 全页面源码审查与本地 CDP 实机访问（仪表盘、节点、边缘设备、数据面板、权限页；桌面与 390px 移动视口）
> **不在本轮范围**: 生产部署、后端接口重构、ESP32 固件改动

## 1. 背景与问题定义

当前前端已覆盖节点、边缘设备、通道、数据、OTA、配置、监控、用户与日志等核心流程，具备统一布局、主题、实时 WebSocket、图表和基础空状态能力。但页面实现以功能迭代为主，尚未完全收敛到统一设计系统，主要问题为：

1. 小屏响应式只覆盖部分页面；仪表盘四个 KPI 在 390px 视口被压缩到约 69px 宽，无法有效阅读或点击。
2. 顶部“全局搜索”通过关键词猜测页面跳转，列表页面未消费 `route.query.search`，与页面内搜索重复且语义不真实。
3. Dashboard 状态时间线由当前快照临时构造，却标记为“模拟数据”，不应作为运维事实呈现。
4. 主题变量已存在，但核心页面仍硬编码亮色背景、边框和文本色，暗色主题存在视觉不一致风险。
5. 节点、边缘设备、设备配置的统计卡混用全量总数和当前页统计，在线/离线数字不闭合。
6. 通道管理不在侧栏入口；`PageHeader` 插槽只支持 `extra`，而通道页使用了 `actions`，导致刷新操作不渲染。
7. 图标按钮缺少 `aria-label` 和 tooltip，移动端用户与辅助技术难以理解。
8. 数据面板写死温度、气压和比较类别，无法适配 BMS、逆变器及动态传感器类别。

## 2. 目标与非目标

### 2.1 目标

- 在不改变既有业务能力的前提下，建立统一的页面、统计、筛选、空状态与响应式模式。
- 确保核心资源列表在桌面、平板和手机视口下都可阅读、可操作、无横向页面溢出。
- 让导航、筛选、统计和数据标签准确反映实际数据范围与权限。
- 将颜色、按钮、图标和可访问性要求收敛到项目既有 UI 标准。
- 每项前端改动至少完成单元测试、类型检查和真实浏览器访问验证。

### 2.2 非目标

- 不把 GPIO/PWM 作为通道继续扩展；其后续 UI 归入独立外设控制域。
- 不用虚构数据补足真实运维数据缺口。
- 不在本设计中重写后端数据聚合 API；前端先准确标识当前数据范围，后端聚合能力作为后续接口任务。

## 3. 信息架构

### 3.1 目标导航

```
仪表盘
资源管理
  ├── 节点
  ├── 边缘设备
  └── 通道
数据中心
  └── 数据面板
配置与发布
  ├── 配置模板
  └── 固件管理
系统管理
  ├── 系统监控（管理员）
  └── 用户管理（管理员，从用户菜单进入）
```

首轮不强制引入嵌套菜单，但必须把“通道管理”放入可发现的主导航。角色不可用的入口不显示，直接访问受路由守卫保护。

### 3.2 页面模板

| 模板 | 适用页面 | 固定结构 |
|---|---|---|
| 资源列表 | 节点、边缘设备、通道、配置、固件、用户 | PageHeader → 筛选/操作栏 → 统计（可选）→ 列表或卡片 → 分页/空状态 |
| 资源详情 | 节点详情、边缘设备详情 | 返回 + 实体名称/状态/操作 → 概览 → 分区卡片 |
| 数据分析 | 仪表盘、数据面板、系统监控 | PageHeader → 时间/对象筛选 → KPI → 图表 → 明细 |

外层内容留白由 `MainLayout` 统一负责；页面组件不得再默认增加重复的 24px 外边距。

## 4. 分阶段实施

### 阶段 P0：可信与可用

#### P0-1 移动端 KPI 栅格

**目标**：390px 下 KPI 卡最小宽度不低于 150px，主要按钮最小可触达高度 40px。

**实现**：
- 抽取或统一使用响应式统计栅格；窄屏为两列，桌面为四列。
- Dashboard、DataPanel、Monitor、Profile 同步检查固定 `el-col :span`。
- KPI 数值禁止换行，标签允许最多两行并截断。

**验收**：
- CDP 设置 390px、768px、1440px 三档；`scrollWidth === innerWidth`。
- Dashboard KPI 在 390px 下每张宽度不少于 150px。

#### P0-2 顶部搜索语义收敛

**目标**：避免“搜索”实际仅关键词跳转。

**实现**：
- 首轮将顶部入口定义为“快速跳转”，仅展示明确页面入口；不再从自然语言中猜测资源类型。
- 节点与边缘设备列表读取 `route.query.search` / `route.query.status` 作为初始筛选条件。
- 用户修改筛选条件后同步更新 URL 的双向状态管理留至 P1 列表筛选收敛。
- 后续版本再建设真正的 Command Palette（资源检索、最近访问、快捷操作）。

**验收**：
- 直接访问带 `search` / `status` 的节点和边缘设备 URL 时，页面级筛选可恢复。

#### P0-3 Dashboard 运维事实

**目标**：不以模拟时间线表达真实运维状态。

**实现**：
- 删除当前临时构造的“设备状态时间线”区域，或改为“当前状态概览”，不得附带“模拟数据”标签。
- 真实状态历史仅在后端提供事件流接口后重建。

**验收**：
- Dashboard 不再出现“模拟数据”标签。
- 空数据时展示明确的真实数据引导，而非伪造记录。

#### P0-4 页面头部与主导航修复

**目标**：恢复通道管理入口及其刷新操作。

**实现**：
- `PageHeader` 只保留并统一 `extra` 插槽；修正 ChannelList 的插槽名。
- 在主导航加入“通道管理”。
- 为 PageHeader 返回、视图切换、通知、主题等图标按钮补充 `aria-label`；统一 tooltip 留至 P2 可访问性收敛。

**验收**：
- `/channel` 可以从主导航到达。
- ChannelList 页面标题右侧显示刷新按钮。
- 无文字按钮均可由辅助技术读取名称。

### 阶段 P1：资源管理一致性

#### P1-1 统计口径

- 将资源列表统计明确分为“全局聚合”或“当前页/筛选集”；不能混用。
- 后端聚合接口尚未提供前，卡片标签必须使用“当前页”或“本次加载”。
- 展示统计更新时间与筛选影响范围。

#### P1-2 筛选、分页与视图切换

- 搜索统一 300ms 防抖，重置页码。
- 卡片与表格共享筛选、排序、分页和选中状态。
- 大数据量筛选转服务端；当前页本地过滤不得假装全局搜索。
- 筛选后显示条件 chips 与“清除全部”。

#### P1-3 空状态

- 区分初始、过滤无结果、无权限、加载失败四类。
- DataPanel 未选设备时显示“先选择设备”的初始状态。
- 日志未启用时显示开关影响与明确行动入口。

### 阶段 P2：主题与组件系统

#### P2-1 主题令牌

- 在 `styles/theme.css` 补充并统一语义 token：surface、surface-raised、border-subtle、text-primary、text-secondary、status-*。
- 移除页面 CSS 中硬编码亮色背景、边框、文本颜色。
- 图表颜色保留在 `utils/theme.ts`，不得在组件内重复硬编码。

#### P2-2 图标和可访问性

- 指标和设备信息改用 Element Plus 图标映射，移除 emoji 作为业务图标。
- 状态表达使用文字 + 色彩 + 图形，不仅依赖颜色。
- 所有 icon-only 控件具有 tooltip、`aria-label`、焦点可见样式和键盘可操作性。

#### P2-3 工程调试 UI 响应式

- `LogPanel` 在小屏改为纵向控制布局。
- `ChannelTerminal` 在小屏改为 TX/RX 上下布局或 Tabs，避免双栏压缩。
- 日志消息允许折行；长帧可展开、复制、导出。

### 阶段 P3：数据分析深化

- DataPanel 的 KPI 和类别改为由设备可用传感器类别动态驱动。
- 多设备比较只允许具有共同单位的指标。
- 提供数据新鲜度、采样质量、错误码说明和时间范围一致性提示。
- 真实状态事件接口完成后，重建可筛选的状态历史和告警中心。

## 5. 组件契约

### 5.1 PageHeader

```ts
interface PageHeaderProps {
  title: string
  subtitle?: string
  showBack?: boolean
}
```

- 仅提供 `extra` 操作插槽。
- 窄屏允许标题与操作区换行，主操作优先保留。
- 返回按钮必须有“返回上一页”可访问名称。

### 5.2 统计卡

```ts
interface StatItem {
  label: string
  value: string | number
  unit?: string
  icon: Component
  tone?: 'primary' | 'success' | 'warning' | 'danger' | 'info'
  scope?: 'global' | 'filtered' | 'page'
  onClick?: () => void
}
```

- 卡片只有在存在明确导航结果时可点击。
- `scope` 用于显示统计范围，防止数字误导。
- 交互卡使用 button/link 语义或完整键盘处理，不能只用 `div @click`。

### 5.3 空状态

```ts
interface EmptyStateProps {
  kind: 'initial' | 'filtered' | 'error' | 'permission' | 'empty'
  title: string
  description?: string
  actions?: EmptyAction[]
}
```

每一类都有不同插图、文案和允许的操作；不再把所有情况统一成“暂无数据”。

## 7. 已知实现约束

1. `client.ts` 响应拦截器已解包一次，调用方必须按已有项目模式读取返回值，避免二次 `.data`。
2. 前端测试中 Canvas/ECharts 不可靠，图表行为须由数据转换单测 + 浏览器渲染验证共同保证。
3. 当前开发验证仅使用开发基础设施、后端 `:8090` 与 Vite `:5174`；禁止操作生产 `/opt/EHomeSystem` 或 `ehome-*` 容器。
4. GPIO/PWM 不属于通道系统；后续 UI 从通道筛选和模板类别中迁出。
