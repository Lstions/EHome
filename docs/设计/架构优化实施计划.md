评估报告（架构评估与优化路线图.md）确认当前架构为"良好解"，7 处偏离最优。本计划将其中的 4 项细化为可实施任务（评估 §5 的步骤 1-4）：

| 任务 | 内容 |
|------|------|
| A | unified_data 时序化：月分区 + rollup + retention 改 DROP partition |
| B | Redis 退役：心跳/限流/去重进程内化 |
| C | 阈值告警引擎：规则 CRUD + 解析后回调求值 + 前端规则页 |
| D | 文档一致性修正（EMQX/Mosquitto 矛盾）+ broker 选型留档 |

**非目标**：微服务化、换协议、换前端栈、多租户、handler 全面下沉、驱动表驱动化。

## 1. 全局约束

1. 测试基线不回退：`make test` 全绿；PG 特性走 `make test-integration`。
2. 方言兼容：单测 SQLite，PG-only DDL 以 `db.Dialector.Name() != "postgres"` 分支。
3. API 兼容：/api/v1 既有响应形状不变；新增字段只增不改。
4. 每任务独立提交序列；A/B 文件集不重叠可并行；C 依赖确认接口边界后独立。
5. 凭据不入文档不入代码。

## 2. 任务 A — unified_data 时序化

### 现状事实（多轮审查实证）

- models.UnifiedData：ID/SensorName(32)/Value/Unit/Timestamp/CreatedAt/EdgeDeviceID/LogicalDeviceID，b-tree 索引 4 个
- 全仓零 FK 引用 unified_data.id → 主键改复合不破坏任何外键
- persist consumer 显式设 Timestamp=now → 分区键恒有值
- merge 是 UPDATE logical_device_id 原地改写 → rollup 无需合并后重算（rollup 保持 device 维度）
- 最新值查询面：DISTINCT ON (device_id) 无时间谓词 → v0.2 补 latestValueCache 改造

### 设计要点

- **月分区**：PG 声明式 RANGE，分区键 (timestamp)；主键 (id, timestamp)；DDL 走手写迁移（AutoMigrate 移除 UnifiedData 加注释）；SQLite 不分区走同构路径
- **迁移**：unified_data_new 建表 → 按批搬迁（10K/批断点续跑）→ RENAME legacy 观察一个 retention 周期不删
- **RollupConsumer**：挂在 persist 之后，UPSERT ON CONFLICT；独立邮箱 fail-open；丢率 >0.1% 降级微批（rollup.batch_ms 开关）
- **查询**：historical API 加 precision=rollup|raw（auto：>48h 强制 rollup；仅 device 过滤允许 rollup，logical scope 强制 raw）
- **retention**（2026-09-12 更新）：raw 系统级默认 90 天，可经 EHOME_DATA_RETENTION_DAYS 覆盖（30 天仅作推荐配置示例）；rollup 保留 365 天，为独立策略，与 raw 默认解耦（当前代码未见自动清理路径，待确认）
- **latestValueCache**：概览/最新值 API 改内存缓存（persist 旁路更新 + 启动回填 + miss 回落 SQL）

### 验收

- [ ] PG 集成：EXPLAIN 分区裁剪、跨月查询、3 个月数据搬迁行数一致 id 无重复
- [ ] retention RunOnce 产生 DROP partition
- [ ] latest-value 缓存命中/回落双路径一致
- [ ] SQLite 单测全绿；auto 模式 >48h 返回 rollup
- [ ] 性能冒烟：100 万行 rollup 查询 < 200ms（留档 docs/测试/）

## 4. 任务 C — 阈值告警引擎

### 数据模型

```go
AlertRule  { ID, TargetType(edge_device|logical_device), TargetID, SensorName,
             Comparator(gt|gte|lt|lte|eq|neq), Threshold, DurationSec(0=立即),
             SilenceSec(默认300), Level(info|warning|critical), Enabled, Name }
AlertEvent { ID, RuleID, State(firing|resolved), Value, FiredAt, ResolvedAt, NotifiedAt }
```

### 求值引擎（挂接点裁决 v0.4：解析后回调）

DataEvent 只携带 RawData 字节，物理量在 SensorParserConsumer 内解析为 []parser.Field。独立 consumer 方案=每事件重复解析（10000 evt/s 基线 CPU 翻倍，不可接受）。**改法**：SensorParserConsumer 增加 alertCallback（复用 deviceActivity 回调先例），分片模式天然并行。

- 规则缓存：CRUD 写路径直接失效+重载（30s 刷新仅兜底）
- 状态机：normal → firing（连续满足 DurationSec）→ resolved；抑制：firing 未 resolved 不重发
- Notification 复用：Source="alert_rule"、SourceID=ruleID、Type 映射（critical→error 图标）
- 超载保护：ring buffer 1000 规则×窗口，超出丢弃计数暴露 metrics

### API 与前端

- /api/v1/alert-rules（CRUD + PATCH enabled）；/api/v1/alert-events（list + read）
- 权限对齐现状：单主体模式下登录即可
- 前端：/alerts 页（规则表格 + 创建/编辑对话框 + 事件时间线）；复用 LogicalDeviceCandidateSelect 模式

### 验收

- [ ] 状态机单测全覆盖（直通/持续窗口/恢复/静默/抑制）
- [ ] 集成：超阈值序列 → firing + Notification + WS；回落 → resolved
- [ ] 前端 vitest：表单校验 + 列表渲染；CDP 走查创建→触发→通知可见
- [ ] make test 全绿

## 7. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 分区迁移数据丢失 | 双表并存 + 断点续跑 + 行数校验门禁；legacy 保留 |
| 主键变更破坏引用 | 零 FK 引用已实证；id 序列全局不变 |
| rollup/raw 口径跳变 | auto 边界（48h）前后端同参数；logical scope 强制 raw 消除第三口径 |
| 最新值查询退化 | latestValueCache + miss 回落双路径断言 |
| Redis 删除离线检测变化 | checkDBLastSeen 本就是 L3 兜底，阈值不变 |
| 告警风暴 | SilenceSec 300s + firing 抑制 + 过载丢弃计数 |
