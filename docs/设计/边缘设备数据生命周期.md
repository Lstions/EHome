> **状态**: 已实现（v3.3 交付：逻辑设备身份 + 合并追溯 + retention + purge；v1→v3.3 五轮评审闭环后实施）
> **版本**: v3.3
> **日期**: 2026-08-22
> **关联**: [概念模型.md](概念模型.md) | [边缘设备.md](边缘设备.md) | [功能需求总览.md](功能需求总览.md)

## 1. 背景与需求

删除边缘设备后，其数据（unified_data / device_data / calibration_cache）成为孤儿。需求约束：

1. 数据有业务价值，删除设备后**默认保留数据**。
2. 历史数据继承/合并是**可选行为**，用户显式触发。
3. 数据保留期**可配置**，默认 1 年（365 天）。
4. **跨节点**也能继承/合并；合并对象可能多个，用户自选。

## 2. 备选方案裁决

| 方案 | 做法 | 结论 |
|------|------|------|
| A. 数据迁移 | UPDATE unified_data SET device_id=新id | 否决：单值无法表达 N:1 多源血缘、跨节点无法回答采集来源、误合并不可恢复 |
| B. 逻辑身份（现行） | 数据挂 logical_device_id，实例可增删 | **采纳**：血缘保留（device_id 原值不动）+ 归属可追溯（merged_into 链）+ 删除/重建连续 |

**关键原则**：不改写 unified_data/device_data 的 device_id 原值（血缘）；只新增 logical_device_id（归属）。合并是 **UPDATE logical_device_id 原地改写**，不是 INSERT 搬迁。

## 3. 数据模型

```sql
CREATE TABLE logical_devices (
    id SERIAL PRIMARY KEY,
    identity_key VARCHAR(64) UNIQUE NOT NULL,  -- 创建后只读：type:hardware_id（空地址时 type:{uuid}）
    name VARCHAR(128) NOT NULL,
    device_type VARCHAR(32) NOT NULL,
    retention_days INTEGER DEFAULT 365,
    merged_into INTEGER REFERENCES logical_devices(id),
    merge_status VARCHAR(16),                 -- NULL / pending / done
    purge_requested BOOLEAN DEFAULT FALSE,    -- 删除时勾选"同时删除数据"
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

ALTER TABLE edge_devices ADD COLUMN logical_device_id INTEGER;
ALTER TABLE unified_data ADD COLUMN logical_device_id INTEGER;   -- 纯追加时序表，不加 GORM 软删
ALTER TABLE device_data   ADD COLUMN logical_device_id INTEGER;

-- 索引（CRITICAL）
CREATE INDEX CONCURRENTLY idx_unified_logical_ts ON unified_data(logical_device_id, timestamp DESC);
CREATE INDEX CONCURRENTLY idx_devdata_logical_ts ON device_data(logical_device_id, timestamp DESC);
```

不变量：

- 大表（unified_data/device_data）**不引入 GORM 软删**：项目内 Raw SQL（handler_data/handler_overview）绕过 GORM scope，软删条件不生效；保留 DELETE 硬删语义，retention 本就硬删。
- logical_device_id 不带 GORM FK 级联：删除 logical_device 只准在数据清理完成后由清理任务执行。

## 4. 核心流程

### 4.1 创建（候选匹配）

- 创建边缘设备时匹配既有逻辑设备候选（`Unscoped`，含已软删实例）；按权重排序由用户显式选择，**不做自动继承**：
  - 同 node + 同 channel + 同 hardware_id + 同 type = 100
  - 同 node + 同 type + 同 hardware_id（通道不同）= 80
  - 同 node + 同 type = 60

### 4.2 合并（追溯链）

- `POST /logical-devices/merge/preview`：预览多源合并（时间轴/重叠/数据量）。
- `POST /logical-devices/merge`：发起后台合并任务（乐观占位，返回 job_ids），数据 UPDATE logical_device_id → 新身份。
- **追溯链**：被合并方保留 merged_into 链；查询沿链解析（followMergeChain）。
- **保形去重**：重叠时段数据保留 MAX(id) 行（另行结构契约不变，行语义保形）。
- **门控**：合并中/已合并/purge 中的实例拒绝重复操作（409）。

### 4.3 删除与清理

- 删除边缘设备：软删 + 数据默认保留；勾选"同时删除数据"→ purge_requested。
- 批量删除：/edge-devices/batch-delete，每项同样可选"同时删除数据"。
- retention：retention_days 每逻辑设备可配；每日 purge 任务清理过期数据（v3.4 起 unified_data 改整分区 DROP，因数据层时序化）。
- 删除 logical_device 仅在数据清理完成后由任务执行。

## 5. API 摘要

| 端点 | 用途 |
|------|------|
| /logical-devices | 列表/创建 |
| /logical-devices/:id | 详情/编辑（仅 name） |
| /logical-devices/merge/preview | 合并预览（多源） |
| /logical-devices/merge | 发起合并（返回 job_ids） |
| /merge-jobs/:id | 合并任务状态 |
| /edge-devices/:id（DELETE） | 删除（可选同时删数据） |
| /edge-devices/batch-delete | 批量删除 |

## 7. 验收标准（已达成的现行验证）

- [x] 合并门控：pending/done 状态 409。
- [x] retention 到期清理；purge_requested 清理。

## 8. 已知限制与评审遗留

- calibration_cache 无 DeletedAt 且唯一索引 idx_calibration_edge_kind 会阻塞同型设备重建（关联：配置走 CalibrationAwareDriver 缺校准即拒收样本）——已知问题，删除确认对话框中提示。
- config_templates 孤儿不回收，累积超 ESP32 16 模板上限会致 ConfigManifest rejected → 需 SQL 清理（运维手册条目）。
- merge 任务无乐观锁并发控制（单实例单管理员下低风险，评审记录在案）。
