## 1. 四层概念模型

```
┌─ Layer 4: 平台 (Platform) ────────────────────────────┐
│   整个系统（EHomeSystem）                                │
└──────────┬──────────────────────────────────────────────┘
           ▼
┌─ Layer 3: 中心端 (Center) ────────────────────────────┐
│   Go 后端 + Web 前端 + PostgreSQL + MQTT Broker         │
│   权威源：节点/通道/设备配置/边缘设备/数据                 │
└──────────┬──────────────────────────────────────────────┘
           ▼ MQTT / HTTP / WebSocket
┌─ Layer 2: 节点 (Node) ────────────────────────────────┐
│   ESP32-S3 / ESP32-C6 物理整机，运行 EHomeSystem 固件    │
│   只做：总线 IO / 协议 / 采集执行 / 资源上报 / OTA        │
└──────────┬──────────────────────────────────────────────┘
           ▼ 总线 (UART/I2C/SPI/ADC + GPIO/PWM 直控)
┌─ Layer 1: 边缘设备 (Edge Device) ─────────────────────┐
│   节点 + 通道 + 设备配置 三元组的实例化                    │
│   e.g. "Node A 的 UART1 上挂的 SN-3001"                  │
└──────────────────────────────────────────────────────────┘
```

**关键**：每一层只与直接上下层对话。节点不感知"边缘设备/设备配置"概念（中心端抽象）；中心端不直接控制节点硬件（通过协议间接控制）。

## 2. 核心术语

### 2.1 节点 Node

现场部署的**物理嵌入式设备**（ESP32-S3/C6），运行 EHomeSystem 固件，经 MQTT 与中心端通信。

- 唯一身份：`node_id`（eFuse Wi-Fi MAC 派生的 12 位大写十六进制）
- 协议模型：Hello 握手（handshake_nonce 关联 v2.6）、StatusReport 心跳（5 秒周期）、ResourceReport 硬件资源上报
- 节点**不感知**边缘设备/设备配置概念；节点只接收 Channel 配置 + 模板 + 日志流/GPIO/PWM 配置

**易混点**：❌ 不是"采集器"（旧名，已废弃）；❌ 不是"边缘设备"。

### 2.2 通道 Channel

节点上的**物理通信端点**：UART / I2C / SPI / ADC。

- 只描述物理（引脚、速率、模式、地址范围），不描述上面挂什么型号
- **GPIO/PWM 不入通道系统**（v3.0 裁决）：只有"可数据交互、有协议帧"的总线才入通道；GPIO 是引脚直控，PWM 是 LEDC 直控，走独立 PeriphCmd/PeriphRsp 协议
- 通道有 `hardware_id`（从机地址，如 I2C 0x76）；EdgeDevice 也存 `hardware_id`——两者的关系以 unique (channel_id, hardware_id, type) 约束为准

**易混点**：✅ 通道 = 物理；❌ 通道 ≠ 挂在总线上的设备（那是边缘设备）。

### 2.3 设备配置 DeviceConfig

一种**设备型号**的协议无关定义："这个型号是什么 / 怎么初始化 / 怎么解析"。

- 三部分：connection（连接参数）、parser（解析器）、init_flow（初始化序列）
- 一个型号一份，可在多个节点复用；由中心端统一管理
- 操作集（operations）与驱动（Driver）共同定义该型号可执行的受控操作

**易混点**：❌ 不是"设备模板"（旧名）；❌ 不是具体设备（那是边缘设备）。

### 2.4 边缘设备 EdgeDevice

**节点 + 通道 + 设备配置 + hardware_id** 的实例化，数据采集的实际载体。

- 唯一性约束：同一通道 + 同一从机地址 + 同一型号 不可重复（允许同通道不同地址的多从机）
- 数据归属：`unified_data.edge_device_id` 记实例血缘；数据身份归属另有逻辑设备标识（§2.5）
- 初始化：创建即通过 SyncGate 下发 → 节点启动采集 + init_flow 初始化（sendAndWait）

**易混点**：❌ 不是"设备配置"（实例 vs 型号）；❌ 不是"节点"。

### 2.5 逻辑设备 LogicalDevice（v3.3）

**数据身份**概念：设备删除后数据仍归属的稳定身份。

- `logical_device_id` 挂在 unified_data / device_data 上，创建边缘设备时建立
- 支持设备间的数据继承/合并（merge 链可追溯，merge_chain）
- retention 保留期可配置（默认 90 天，可经 EHOME_DATA_RETENTION_DAYS 覆盖）；purge 每日任务清理过期数据
- EdgeDevice 可增删，数据血缘保持（device_id 原值不重写）

### 2.6 中心端 Center

服务端的 Go 后端 + Vue 前端。是节点/通道/设备配置/边缘设备/数据的**权威源**。

- 配置同步唯一入口：SyncGate（ConfigEventBus + EpochGenerator）
- 数据链：DataEventBus → 分片消费者（解析 → persist → WS 推送 → 告警求值）
- 单主体模式：唯一管理员（AuthenticateSingleUser）

### 2.7 协议 Protocol

中心端 ↔ 节点的**自研二进制帧**协议（protobuf-wire 兼容编码，无 protobuf 依赖）。

- Magic 0xEB，消息类型 0x01-0x1D（Hello → LogStream）
- MQTT topic：`nodes/{id}/up`（QoS1）、`nodes/{id}/down`（QoS0）、`nodes/{id}/control`（QoS1）
- 控制面：ChannelCmdV2（0x15/0x16/0x17）为业务控制主协议；WriteCmd（0x06）仅保留受控 read 与内部初始化兼容
- 变更必须走版本化流程（scripts/check_protocol_fields.sh 门禁）

### 2.8 模板 Template / ConfigTemplate

节点的"如何读寄存器"的**二进制命令序列**。

- 逐指令 ConfigManifest（v2.5.16+）：采集指令按频率编排、随 ConfigManifest 下发
- 与 DeviceConfig 不同：Template 是低层命令（hex 字节），DeviceConfig 是高层型号描述
- 固件容量上限：16 模板 / 8 通道 / 每通道 5 边缘设备 / 每设备 3 命令

## 3. 术语映射表（权威）

| 旧命名（v2.1 及以前） | 新命名（v2.2+） | 类型 | 备注 |
|---------------------|---------------|------|------|
| 采集器 / Collector | **节点 / Node** | 物理设备 | 全文档统一 |
| 设备模板 / Device Template | **设备配置 / DeviceConfig** | 型号定义 | 避免与具体设备混淆 |
| 设备 / Device | **边缘设备 / EdgeDevice** | 实例化 | 区分型号 vs 实例 |
| 通道 / Channel | **通道 / Channel** | 物理端点 | 不变（GPIO/PWM 已剥离） |
| 中心端 / Center | **中心端 / Center** | 服务层 | 不变 |
| WriteCommand 业务控制 | **受控操作（ChannelCmdV2）** | 控制协议 | v2.7 起主协议 |
| 设备数据身份 | **逻辑设备 / LogicalDevice** | 数据归属 | v3.3 引入 |

## 4. 禁止的命名（反模式）

| ❌ 禁止 | ✅ 替代 |
|--------|--------|
| 采集器 | 节点 |
| 设备（单独使用，有歧义） | 边缘设备 / 设备配置（具体化） |
| 设备模板 | 设备配置 |
| 设备类型 | 设备型号 |
| GPIO 通道 / PWM 通道 | GPIO/PWM 外设直控（不入通道系统） |
| 边缘（单独使用） | 边缘设备 |

## 6. 术语自检

每篇文档 / 每段代码自问：

- [ ] "节点"准确？（不是"采集器"不是"边缘设备"）
- [ ] "设备配置"准确？（不是"设备模板"不是"边缘设备"）
- [ ] "边缘设备"准确？（不是"设备"不是"节点"）
- [ ] GPIO/PWM 表述为"外设直控"，未说成"通道"？
- [ ] 数据归属区分了血缘（edge_device_id）与身份（logical_device_id）？
