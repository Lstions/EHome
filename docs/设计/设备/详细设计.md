## 1. 功能概述

设备 (Device) 是传感器/执行器的 Server 侧抽象, 属于 node 之下。一个 device 关联:
- 一个 channel (物理通道, 如 I2C-0 0x76)
- 一个 parser (驱动, 如 bosch.bmp280)
- 采集间隔 (interval_ms)
- 所属 node (device_id)

### 1.1 端点

| 端点 | 方法 | 权限 | 用途 |
|------|------|------|------|
| `/api/v1/devices` | GET | 登录 | 列表 |
| `/api/v1/devices/:id` | GET | 登录 | 详情 |
| `/api/v1/devices` | POST | operator+ | 创建 |
| `/api/v1/devices/:id` | PUT | operator+ | 更新 |
| `/api/v1/devices/:id` | DELETE | operator+ | 删除 |
| `/api/v1/devices/:id/latest-data` | GET | 登录 | 最新数据 |
| `/api/v1/devices/:id/data` | GET | 登录 | 历史数据 (分页) |
| `/api/v1/devices/:id/operations` | POST | operator+ | 远程操作 (PWM/雨量重置/...) |

## 2. 数据模型

```sql
CREATE TABLE devices (
  id              SERIAL PRIMARY KEY,
  node_id    INTEGER REFERENCES collectors(id),
  channel_id      INTEGER REFERENCES channels(id),
  name            VARCHAR(64) NOT NULL,
  device_type     VARCHAR(32) NOT NULL,    -- bmp280 / npk_sensor / inverter
  protocol        VARCHAR(16),            -- modbus / stream / custom
  hardware_type   VARCHAR(16),            -- uart / i2c / spi / gpio / adc
  parser_id       VARCHAR(64),            -- bosch.bmp280 / renke.npk
  interval_ms     INTEGER DEFAULT 1000,
  enabled         BOOLEAN DEFAULT true,
  status          VARCHAR(16) DEFAULT 'unknown', -- online/offline/unknown/error
  last_data       JSONB,                  -- 最新一次数据
  last_data_at    TIMESTAMPTZ,
  error_code      INTEGER DEFAULT 0,      -- HAL 错误码
  config          JSONB,                  -- 设备特定配置
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_devices_collector ON devices(node_id);
CREATE INDEX idx_devices_channel ON devices(channel_id);
CREATE INDEX idx_devices_type ON devices(device_type);
```

## 3. 状态机

### 3.1 Device 状态

```
   创建
    ↓
 unknown ──→ online ──→ error
              │  ↑       │
              ↓  └───────┘ (错误恢复)
           (设备离线/数据错误)
```

- `unknown`: 等待第一次 DataReport
- `online`: 60s 内有数据
- `error`: 解析错误 (error_code != 0)
- `offline`: 10min 内无数据 (P3 计划)

### 3.2 设备操作 (WriteCommand type=0x06)

| device_type | operation | 效果 |
|-------------|-----------|------|
| rain | reset | 雨量清零 |
| battery | restart | 重启保护板 |
| gpio.digital | set_high / set_low / toggle | GPIO 电平 |
| gpio.pwm | set_duty | PWM 占空比 + 频率 |
| inverter | query_state | 查询逆变器状态 |

```
前端 → POST /api/v1/devices/:id/operations
  ↓
[server] 发 WriteCommand (0x06) 到 mqtt.down
  ↓
[ESP32] 执行 → 发 WriteResponse (0x07)
  ↓
[server] 收到 → 解析 success + 推送 frontend
```

## 5. 设备操作示例

### 5.1 PWM 设置

```json
POST /api/v1/devices/123/operations
{
  "operation": "set_pwm",
  "params": { "channel": 0, "duty_pct": 50, "frequency_hz": 1000 }
}
```

→ Server 发 WriteCommand (0x06):
```c
frame.payload[0] = WRITE_OP_PWM;  // op_type
frame.payload[1] = 0;            // channel
frame.payload[2..3] = 50;        // duty_pct (uint16)
frame.payload[4..7] = 1000;      // frequency_hz (uint32)
```

→ ESP32 收到 → 设置 PWM → 发 WriteResponse (success=true) → Server 推 frontend

## 6. 容错设计

| 场景 | 行为 |
|------|------|
| 设备离线 | 10min 无数据 → status=offline + notification |
| 解析错误 | 原始数据进 notifications (level=error) + error_code 标记 |
| 操作超时 | WriteResponse 30s 内未回 → error_code=ETIMEDOUT + 通知 |
| 并发操作 | 同一设备同时操作 → 串行队列, 防止 race |
| 采集间隔 < 100ms | 服务端拒绝, 最低 100ms |
