# 方案 D 详细设计：plan 改指针（复用槽位缓冲，保留原子性）

> 状态：**待评审** | 日期：2026-10-10 | 替代方案 C（已被自审否决）
> 核心：**不拆命令**，而是让命令元素不再内联 512 B 的 plan 副本。

---

## 1. 为什么方案 C 被否决（结论摘要）

```
C 的两条路线都不可行:
  F1 拆成 N 条命令 => 破坏原子性（后端崩溃时后续步骤永不执行）
  F2 事务锁     => 槽位是池式分配，与 channel 无关，锁不到
⇒ 详见《方案C-自审报告-2026-10-10.md》
```

## 2. 方案 D 的核心洞察

```
原子性的来源是「一个命令内执行完整序列」:
  bus_worker.c:1338  execute_uart_batch(ch_idx, ctx, cmd, raw, raw_len, error_code)
  ⇒ 一个 bus_cmd_t 携带完整 plan，worker 在一次调用里跑完全部步骤

所以不该拆命令，而应该【让命令元素不再内联 plan 副本】。

现有机制恰好提供了零成本的落点:
  ① msg_handler 槽位 s_slots[slot].cmd 已持有 plan_data[512]
     （msg_handler_internal.h:230  channel_cmd_v2_t.plan_data）
  ② 槽位在 QUEUED 期间**独占**
     （handler_channel_cmd_v2.c:170  reserve_slot 只取 state==FREE 的槽）
  ③ QUEUED **跨越整个执行期**
     （handler 桥接成功后 send_ack(true) 保持 QUEUED；
       worker 完成才 queue_control_final -> complete_slot -> FINAL）
  ⇒ 槽位的 plan_data 在命令执行期间天然有效且稳定
  ⇒ 命令元素只需存【指针】，不需要 512 B 副本
```

## 3. 改动清单（7 处，每处附依据）

### 改动 1：`bus_cmd_t` 定义（`components/bus_dma/include/cmd_queue.h`）
```c
/* 改造前 */
typedef struct {
    BUS_CMD_COMMON
    uint8_t plan_data[CMD_PLAN_MAX];   /* 512 B */
    size_t  plan_len;
    uint8_t plan_step_count;
} bus_cmd_t;                              /* = 700 B */

/* 改造后 */
typedef struct {
    BUS_CMD_COMMON
    const uint8_t *plan_ptr;           /* 指向槽位的 plan_data，不拥有 */
    size_t  plan_len;
    uint8_t plan_step_count;
} bus_cmd_t;                              /* ≈ 192 B */
```

**尺寸核算**（独立计算，非照抄）：
```
  sample_cmd_t（公共前缀，pahole 实测） = 180 B
  + plan_ptr (4) + plan_len (4) + plan_step_count (1) = 189 B
  对齐到 4                                  = 192 B
  ✅ 192 < 256（满足用户约束）
```

⚠ **注意**：`_Static_assert` 需要更新 ——
   原断言 `offsetof(plan_data) == offsetof(type)+sizeof(type)` 不再成立，
   改为 `offsetof(plan_ptr) == offsetof(type)+sizeof(type)`。

### 改动 2：⚠⚠ **关键** —— 桥接必须传槽位副本（`handler_channel_cmd_v2.c:352`）
```c
/* 改造前（危险）*/
channel_cmd_v2_t cmd;            /* 栈局部 */
... 解析进 cmd ...
if (!on_channel_cmd_v2_received(&cmd, (uint8_t)slot)) {
    /* ⇒ 若 plan_ptr = cmd.plan_data，则命令入队后栈被回收 => **悬垂指针** */
}

/* 改造后 */
v2_control_slot_t *entry = &s_slots[slot];
/* 解析进 entry->cmd（槽位副本），而不是栈局部 */
if (!on_channel_cmd_v2_received(&entry->cmd, (uint8_t)slot)) { ... }
```

**依据**：槽位在 QUEUED 期间独占且跨越整个执行期（见 §2 的 ② ③），
所以 `entry->cmd.plan_data` 在整个执行期间有效。

⚠ 这处改动**最容易出错**，必须配 host 测试覆盖。

### 改动 3：`bus_manager.c:1359` 消除 512 B 拷贝
```c
/* 改造前 */
if (plan_len > 0) memcpy(cmd.plan_data, plan_data, plan_len);

/* 改造后 */
cmd.plan_ptr = plan_data;      /* 直接引用调用者的缓冲 */
```

### 改动 4：读取端（`bus_worker.c:1358,1362`）
```c
/* 改造前 */
uint16_t step_len = (uint16_t)cmd->plan_data[cursor] | ((uint16_t)cmd->plan_data[cursor + 1] << 8);
if (!decode_batch_step(cmd->plan_data + cursor, step_len, &step)) { ... }

/* 改造后 */
uint16_t step_len = (uint16_t)cmd->plan_ptr[cursor] | ((uint16_t)cmd->plan_ptr[cursor + 1] << 8);
if (!decode_batch_step(cmd->plan_ptr + cursor, step_len, &step)) { ... }
```

⚠ 需补空指针检查：`if (!cmd->plan_ptr && cmd->plan_step_count > 0) => fail`

### 改动 5：`scrub_plan_tail`（`bus_worker.c:473-478`）
```c
/* 现状：尾部 520 B（旧 plan_data + plan_len + step_count）需清零 */
static void scrub_plan_tail(bus_cmd_t *cmd) {
    if (cmd->channel_cmd_v2) return;
    memset((uint8_t *)cmd + sizeof(sample_cmd_t), 0,
           sizeof(bus_cmd_t) - sizeof(sample_cmd_t));   /* 520 B */
}

/* 改造后：尾部仅 12 B（plan_ptr 4 + plan_len 4 + step_count 1 + 对齐 3）*/
/* 函数可保留（代价从 520 B memset 降到 12 B），语义不变 */
```

⇒ **副作用收益**：每条 SAMPLE 命令的 memset 从 520 B 降到 12 B（100Hz × 5 通道）。

### 改动 6：`same_identity`（`handler_channel_cmd_v2.c:136-137`）—— **无需改**
```c
/* 幂等比较仍比槽位自己的 plan_data（未改）*/
a->plan_len == b->plan_len && memcmp(a->plan_data, b->plan_data, a->plan_len) == 0
⇒ channel_cmd_v2_t 未变，此处不动 ✅
```

### 改动 7：host 测试同步（`host_tests/`）
```
所有直接访问 bus_cmd_t.plan_data 的测试需改为 plan_ptr。
预计影响：bus_worker_rx_tests.c / cmd_queue 相关测试。
⚠ 编译期暴露，不会静默漏改。
```

## 4. 收益（独立核算）

| 项 | 改造前 | 改造后 | 变化 |
|---|---|---|---|
| `bus_cmd_t` 元素 | 700 B | **192 B** | −508 B |
| 3 个 control 队列 | 17,112 B | **4,920 B** | **−12,192 B = −11.9 KiB** |
| `scrub_plan_tail` 每次 memset | 520 B | 12 B | −508 B/命令 |
| 新增静态开销 | — | **0** | 复用槽位已有缓冲 |
| wire 协议 | — | **无变更** | ✅ |
| 后端 | — | **无变更** | ✅ |
| **原子性** | — | **保留** | ✅ |

**与方案 C 对比**：
| | 方案 C | **方案 D** |
|---|---|---|
| 收益 | ~14.1 KiB | **11.9 KiB** |
| 原子性 | ❌ 破坏 | ✅ 保留 |
| 协议变更 | 需升版本 | **无** |
| 后端改动 | 新表 + 逐条下发 | **无** |
| 风险 | 高 | **中（1 处关键改动）** |
| 符合 ≤256 B | ✅ | ✅ |

⇒ **方案 D 用 2.2 KiB 的收益差，换掉全部协议/后端改动与原子性风险**。

## 5. 风险与缓解（逐条已验证）

| # | 风险 | 缓解 | 验证 |
|---|---|---|---|
| R1 | **悬垂指针**：槽位被提前复用 | `reserve_slot` 只复用 FREE / 最旧 FINAL；QUEUED 不可复用 | ✅ 已读 `handler_channel_cmd_v2.c:166-172` |
| R2 | 命令被丢弃时指针悬垂 | `discard_command_queue:2388-2392` 会 `complete_control` 置 FINAL | ✅ 已读 |
| R3 | 桥接失败时槽位泄漏 | handler 失败路径直接置 FINAL（`:353-360`）| ✅ 已读 |
| R4 | 改动 2 漏改（仍传栈局部）| **必须配 host 测试**；且悬垂会表现为 plan_len 异常 | ⚠ 待实现 |
| R5 | 跨组件耦合（bus_dma 指向 msg_handler 缓冲）| **已有先例**：`control_slot` 就是这个耦合 | ✅ |
| R6 | S3P 上 plan 在 PSRAM 时 cache 禁用访问 | ⚠ **需核实**：worker 是否在 cache-disable 期间读 plan | ⚠ **待验证** |
| R7 | host 测试影响面 | 编译期暴露 | ⚠ 待评估 |

### ⚠ 5.1 R6 是唯一未验证的关键风险
```
若 S3P 的槽位 plan_data 在 PSRAM（当前在 .bss 内部 RAM），
而 worker 在 cache 禁用期间（如 spi_flash 操作）读 plan_ptr => 崩溃。

现状：channel_cmd_v2_t 在 s_slots[] 里，是 **.bss 内部 RAM**（实测）
  nm 验证: s_slots 在 0x3fca0120（内部 DRAM）
⇒ **当前无此风险**；但若将来把 s_slots 移到 PSRAM，必须重新评估。
⚠ 需在设计中明确记录这条约束。
```

## 8. 独立评审反馈与设计修正（2026-10-10）

### 8.1 ✅ 评审确认的部分
```
F1（方案 C 破坏原子性）的**事实基础正确**:
  · execute_uart_batch (bus_worker.c:1338-1395) 在单次调用内 for 循环跑完全部
    plan_step_count 步（:1356-1385），中途不返回
  · 整条 plan 由一个 bus_cmd_t 承载并整条入队（bus_manager.c:1347-1359, :1378）
  · worker 一取到即整批执行（bus_worker.c:1456-1466）
  ⇒ "一个命令内执行完整序列"为真

方案 D 的可行性前提（槽位 QUEUED 期不可复用）也经独立确认:
  · handler_channel_cmd_v2.c:167-208 仅 FREE/最旧 FINAL 可复用
  · FINAL 由 worker 完成回调后才到达
    (bus_worker.c:1463 complete_control -> :837 queue_control_final
     -> main.c:661 注册 handler_channel_cmd_v2_complete)
  · 槽位自持完整 plan_data[512] 副本（msg_handler_internal.h:230）
```

### 8.2 ⚠ 评审指出我的表述错误（已接受）
```
我写的「改动点 2：必须改为传 &s_slots[slot].cmd，否则悬垂」表述有误。

事实:
  · 传的确实是栈局部 &cmd（channel_cmd_v2_t cmd 定义于
    handler_channel_cmd_v2.c:283，调用在 :352）
  · **但 plan 在 bus_manager.c:1359 被 memcpy 进队列元素**，
    栈指针并未逃逸  ⇒  **今天不存在悬垂**

⇒ 修正表述：「改传 &s_slots[slot].cmd」是**方案 D 的前置条件**，
   而不是方案 C 的缺陷。**现状无 bug**。
```

### 8.3 🔴 评审提出的最大风险（认真对待）

> 所有权倒置且无强制手段 —— bus_dma 队列元素长期持有 msg_handler
> 静态槽内缓冲的裸指针，无引用计数、无断言、无状态钩子；
> 「FINAL 可复用 ≠ reader 已释放引用」这一等号只靠当前执行顺序成立。
> 一旦把完成提前发布（完成回调已走 s_control_final_q **异步队列**，
> bus_worker.c:837-850），或新增取消/重发/重试路径，立即变成 use-after-free。

**我的评估**：
```
① 当前顺序是**严格有序**的（不是"偶然"）:
   uart_cmd_loop 内: receive_prioritized_command(取命令)
                     -> execute_uart_batch(读 plan)      [读]
                     -> complete_control                  [发布 FINAL]
   即"读 plan" 与 "发布 FINAL" 在**同一任务内串行**，读在前。

② 但评审指出的**未来风险成立**:
   s_control_final_q 是异步队列 ⇒ 若将来有人把"发布 FINAL"移到
   执行之前（或并行），裸指针立刻 UAF，且**没有任何机制会报警**。

③ ⇒ 设计必须**把隐式不变量变成显式强制**。
```

### 8.4 ✅ 设计修正：从「裸指针」改为「带校验的访问器」

**修正后的方案 D-prime**（消除裸指针，把不变量显式化）:

```c
/* 不再把裸指针放进队列元素。改为：
 * 队列元素只带 control_slot（**已有字段**），worker 通过 msg_handler
 * 的**访问器**取 plan。 */

/* msg_handler_hooks.h 新增 */
/* 返回 true 表示: slot 存在且 state==QUEUED，out_ptr/out_len 有效。
 * 该函数内部做状态断言 —— 把"FINAL 不可复用"的不变量**变成运行时校验**。 */
bool channel_cmd_v2_borrow_plan(uint8_t slot, const uint8_t **out_ptr,
                                size_t *out_len, uint8_t *out_steps);

/* 实现（handler_channel_cmd_v2.c）*/
bool channel_cmd_v2_borrow_plan(uint8_t slot, const uint8_t **out_ptr,
                                size_t *out_len, uint8_t *out_steps) {
    if (slot >= CHANNEL_CMD_V2_SLOT_COUNT || !out_ptr || !out_len || !out_steps)
        return false;
    v2_control_slot_t *e = &s_slots[slot];
    uint32_t st = __atomic_load_n(&e->state, __ATOMIC_ACQUIRE);
    if (st != V2_SLOT_QUEUED && st != V2_SLOT_COMPLETING) {
        /* 不变量被破坏: worker 在读一个已被释放的槽 */
        ESP_LOGE(TAG, "borrow_plan: slot %u state=%u (expected QUEUED) -- "
                      "invariant violated, refusing to hand out plan",
                 (unsigned)slot, (unsigned)st);
        return false;
    }
    *out_ptr = e->cmd.plan_data;
    *out_len = e->cmd.plan_len;
    *out_steps = e->cmd.plan_step_count;
    return true;
}
```

**收益对比**：

| | 裸指针方案 D | **访问器方案 D-prime** |
|---|---|---|
| 不变量 | 隐式（靠顺序）| **显式运行时校验** |
| UAF 后果 | 静默崩溃/数据损坏 | **打印错误并拒绝执行** |
| 队列元素尺寸 | 192 B | **180 B**（连指针都省了）|
| 省内存（3 队列）| 12,192 B | **12,384 B = 12.1 KiB** |
| 跨组件耦合 | 裸指针（无约束）| **函数调用（有契约）** |

⇒ **D-prime 比 D 更好**：尺寸更小、约束更明确、失败可见。

### 8.5 ⚠ 修正后的残留风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| R7 | **TOCTOU**（校验通过后被复用）| 访问器校验 QUEUED 后返回指针，理论上仍有极短窗口 | 当前执行顺序下同一任务串行，不可能；跨任务时需注意 |
| R8 | 借出后槽位被复用 | 需要"借出期"约定 | 设计明确写：**borrow 只在单任务内有效，不可跨任务/不可长持有** |
