### 2.2 字段验证 (v2.2 三大部分)

- [ ] `connection.protocol` 在白名单 (UART/I2C/SPI/GPIO/ADC)
- [ ] `connection.default_params` 是合法 JSON
- [ ] `parser.id` 在 parser_registry 注册
- [ ] `parser.options` 是合法 JSON
- [ ] `init_flow.steps[]` 长度 0-50
- [ ] `init_flow.steps[].data` 是合法 hex string
- [ ] `init_flow.steps[].name` 不重复
- [ ] `init_flow.steps[].timeout_ms` 范围 10-10000

### 2.3 CRUD 行为

- [ ] 创建成功 → 推 notification 事件
- [ ] 创建时 vendor_id 不存在 → 422
- [ ] 创建时 (device_type, name) 重复 → 409
- [ ] 编辑 → EmitConfigChange → 引用此 device_config 的所有 edge_devices 重新 init
- [ ] 删除时 (有 edge_devices 引用) → 409, 提示迁移路径
- [ ] 删除时 (无引用) → 软删除

### 2.4 Parser 测试 (v2.2 新增)

- [ ] `POST /test-parser` 接受 raw_data (hex string)
- [ ] 调 driver.ParseData(raw_data)
- [ ] 返回 parsed_result (sensor_data 数组)
- [ ] parser 不存在 → 404
- [ ] 单元测试: 正常解析路径
- [ ] 单元测试: 解析失败 (不抛 panic)

## 四、集成验收 (E2E)

### 4.1 端到端 (v2.2 设备配置 + 边缘设备 + 节点)

- [ ] 创建设备配置 (BMP280) → 创建边缘设备 (引用此 device_config) → 节点收到 → 触发 init → 校准成功 → 开始采集
- [ ] 改设备配置的 init_flow (加 soft_reset 步骤) → 引用此 device_config 的所有 edge_devices 5s 内重新 init
- [ ] 改设备配置的 parser.id (换另一个 parser) → 所有引用此的 edge_devices 切换解析器
- [ ] 删除设备配置 (有引用) → 返回 409, 提示先迁移
- [ ] 删除设备配置 (无引用) → 软删除

### 4.2 同步场景 (v2.1 同步机制)

- [ ] 创建设备配置 → 5s 内相关节点收到 (如果有 edge_devices 引用)
- [ ] 改设备配置 → 5s 内相关节点收到
- [ ] 节点重启 → 自动恢复 (从 NVS 读 cfg_epoch)
- [ ] 中心端重启 → 启动 push 在线节点

### 4.3 协议兼容 (v2.1/v2.2)

- [ ] v2.1 设备配置 (无 init_flow) → v2.2 中心端兼容 (init_flow=[])
- [ ] v2.2 设备配置 → v2.1 中心端只能取 parser.id 和 connection, 忽略 init_flow
