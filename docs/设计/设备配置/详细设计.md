# 设备配置 (Device Config) — 详细设计 (v2.2)

> **模块**: 设备配置 (Device Config) — 一种设备型号的协议无关元数据定义
> **版本**: v2.2 (2026-06-04 从"设备模板"改名为"设备配置", 强化字段)
> **实现**: [实现/设备配置.md](../../实现/设备配置.md)
> **验收**: [验收标准.md](验收标准.md)
> **关联**: [00-术语表.md §2.3](../00-术语表.md) | [00-概念模型.md](../00-概念模型.md) | [边缘设备/详细设计.md](../边缘设备/详细设计.md)

## 1. 功能概述

**设备配置** (Device Config) = 一种**设备型号**的协议无关元数据定义,描述"这个型号是什么 / 怎么初始化 / 怎么解析数据"。

**核心内容 (v2.2 三部分)**:
1. **设备连接参数** (Connection): 协议 / 默认参数
2. **数据解析器** (Parser): 注册的解析器 ID
3. **业务配置流程** (Init Flow): 校准 / 初始化步骤序列

> **v2.2 关键变化**: "设备模板" → "设备配置"。字段强化, 三部分结构化。

### 1.1 与 v2.1 "设备模板" 的区别

| 维度 | v2.1 "Device Template" | v2.2 "Device Config" |
|------|------------------------|---------------------|
| 关注点 | "创建设备时的模板" | "型号的协议无关定义" |
| connection 字段 | `Config` (JSON, 不分类) | `connection` (结构化) + `connection.default_params` |
| parser 字段 | `ParserID` (string) | `parser.id` + `parser.options` |
| init 流程 | 不存 (在 Device.init_sequence) | `init_flow.steps[]` (中心端统一管理) |
| 业务流 | 模糊 | 明确三部分: 连接 / 解析 / 初始化 |

### 1.2 端点 (v2.2 保持路径, 强化语义)

| 端点 | 方法 | 权限 | 用途 | 兼容 |
|------|------|------|------|------|
| `/api/v1/device-configs` | GET | 登录 | 列表 (按厂商/型号/协议过滤) | v2.1 路径保留 |
| `/api/v1/device-configs/:id` | GET | 登录 | 详情 | v2.1 |
| `/api/v1/device-configs` | POST | admin | 创建设备配置 (含 init_flow) | v2.1 |
| `/api/v1/device-configs/:id` | PUT | admin | 编辑 (v2.1: 触发 ConfigChange, 影响所有 edge_devices) | v2.1 |
| `/api/v1/device-configs/:id` | DELETE | admin | 删除 (RESTRICT, 阻止有 edge_devices 引用) | v2.1 |
| `/api/v1/device-configs/default/:device_type` | GET | 登录 | 获取该 device_type 的默认配置 | v2.1 |
| `/api/v1/device-configs/:id/init-flow` | GET | 登录 | 仅获取 init_flow 步骤 | **v2.2 新增** |
| `/api/v1/device-configs/:id/test-parser` | POST | admin | 测试 parser (mock raw_data → parsed) | **v2.2 新增** |

## 2. 数据模型 (v2.2 强化)

```sql
CREATE TABLE device_configs (
  id                  SERIAL PRIMARY KEY,
  name                VARCHAR(128) NOT NULL,           -- e.g. "BMP280 大气压传感器"
  device_type         VARCHAR(64) NOT NULL,            -- e.g. "bmp280"
  vendor_id           INTEGER REFERENCES vendors(id) ON DELETE SET NULL,  -- v2.2: 关联厂商
  device_model_id     INTEGER REFERENCES device_models(id) ON DELETE SET NULL, -- v2.2: 关联型号
  
  -- v2.2 新增三部分结构化字段 ↓
  connection          JSONB NOT NULL,                  -- 设备连接参数
    -- e.g. {"protocol":"SPI", "default_params":{...}}
  
  parser              JSONB NOT NULL,                  -- 数据解析器
    -- e.g. {"id":"bosch.bmp280", "options":{...}}
  
  init_flow           JSONB NOT NULL DEFAULT '[]',     -- 业务配置流程
    -- e.g. {"steps":[{"name":"reset","data":"\\xE0","read_size":0,"timeout_ms":100}, ...]}
  
  -- 元数据
  description         TEXT,
  protocol            VARCHAR(32),                     -- 兼容 v2.1: modbus/stream/custom
  hardware_type       VARCHAR(32),                     -- 兼容 v2.1: uart/i2c/spi/gpio/adc
  is_default          BOOLEAN NOT NULL DEFAULT false,
  status              VARCHAR(20) NOT NULL DEFAULT 'active',
  
  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at          TIMESTAMPTZ,
  
  UNIQUE (device_type, name)                           -- 同型号同名不重复
);

CREATE INDEX idx_device_configs_device_type ON device_configs(device_type);
CREATE INDEX idx_device_configs_vendor_id ON device_configs(vendor_id);
CREATE INDEX idx_device_configs_status ON device_configs(status);

-- v2.1 兼容视图 (3 个月)
CREATE VIEW device_templates AS
  SELECT
    id, name, device_type, description, protocol, hardware_type,
    parser->>'id' AS parser_id, connection AS config, is_default, status
  FROM device_configs;
```

### 2.1 关键字段 (v2.2)

| 字段 | 类型 | 必填 | 含义 |
|------|------|------|------|
| `connection` | JSONB | ✓ | 设备连接参数 (协议 + 默认参数) |
| `parser` | JSONB | ✓ | 解析器 (id + options) |
| `init_flow` | JSONB (数组) | - | 业务配置流程 (步骤序列) |

### 2.2 connection 结构

```json
{
  "protocol": "SPI",                    // 总线协议
  "default_params": {                    // 默认参数 (可被 channel.bus_config 覆盖)
    "clock_hz": 10000000,
    "mode": 0,
    "bit_order": "MSB"
  },
  "optional": {                          // 可选配置
    "interrupt_pin": 0
  }
}
```

### 2.3 parser 结构

```json
{
  "id": "bosch.bmp280",                  // 必填: 注册的解析器 ID
  "options": {                            // 可选: 解析器特定参数
    "temperature_unit": "celsius",
    "pressure_unit": "pascal"
  }
}
```

### 2.4 init_flow 结构 (v2.2 强化)

```json
{
  "steps": [
    {
      "name": "soft_reset",
      "data": "\\xE0",
      "read_size": 0,
      "timeout_ms": 100,
      "description": "软复位"
    },
    {
      "name": "read_chip_id",
      "data": "\\xD0",
      "read_size": 1,
      "timeout_ms": 50,
      "expected_value": "0x58",           // 期望返回值 (校验)
      "description": "读芯片 ID (BMP280 应该是 0x58)"
    },
    {
      "name": "read_calib",
      "data": "\\x88",
      "read_size": 26,
      "timeout_ms": 100,
      "store_as": "calibration",          // 响应数据存为 calibration (后续使用)
      "description": "读校准数据 (26 字节)"
    },
    {
      "name": "set_config",
      "data": "\\xF4\\x27",
      "read_size": 0,
      "timeout_ms": 20,
      "description": "设置 ctrl_meas 寄存器"
    },
    {
      "name": "verify_ready",
      "data": "\\xF3",
      "read_size": 1,
      "timeout_ms": 50,
      "description": "验证状态就绪"
    }
  ]
}
```

**关键变化 (v2.2)**:
- 加 `expected_value`: 校验返回, 失败 → step 失败
- 加 `store_as`: 命名存储响应 (后续 step 可引用)
- 加 `description`: 运维友好

## 3. 状态机 (v2.2)

### 3.1 设备配置状态

```
  创建
   ↓
 active ──→ inactive (admin 禁用) ──→ active
   ↓
 archived (软删除, 6 个月后清理)
```

### 3.2 引用关系

- 设备配置 被 edge_devices.device_config_id 引用
- 设备配置 引用 vendors (可选)
- 设备配置 引用 device_models (可选)

**RESTRICT 删除**: 有 edge_devices 引用时不允许删除, 需先迁移引用

## 4. 关键流程 (v2.2)

### 4.1 创建设备配置 (POST /device-configs)

**v2.2 强制 3 字段**: connection / parser / init_flow

```json
POST /api/v1/device-configs
{
  "name": "BMP280 大气压传感器",
  "device_type": "bmp280",
  "vendor_id": 1,                          // 关联 bosch
  "connection": {
    "protocol": "SPI",
    "default_params": { "clock_hz": 10000000, "mode": 0 }
  },
  "parser": {
    "id": "bosch.bmp280"
  },
  "init_flow": {
    "steps": [
      { "name": "soft_reset", "data": "\\xE0", "read_size": 0, "timeout_ms": 100 },
      ...
    ]
  },
  "is_default": true
}
```

**后端流程**:
1. 验证 vendor_id 存在 (如指定)
2. 验证 connection.protocol 在白名单
3. 验证 parser.id 在 parser_registry 注册
4. 验证 init_flow.steps[] 格式正确
5. 创建 device_configs 记录
6. **EmitConfigChange** (v2.1 G1 修复) — 注意: 此时还没 edge_devices 引用, 实际不触发 sync, 但记录审计
7. 推 notification 事件 (新设备配置可用)

### 4.2 节点侧应用 (节点不知道 device_config 概念)

节点从 ConfigManifest 拿到:
- channel.bus_config (物理参数, 可能被 device_config.connection.default_params 合并)
- edge_device.parser_id (引用 parser_registry)
- edge_device.init_flow (从 device_config 拷贝过来)

**节点 NVS**:
```c
// NVS 存 edge_device 关联的 parser 和 init_flow, 不存 device_config_id
{
  "edge_devices": [
    {
      "hardware_id": 0,
      "parser_id": "bosch.bmp280",      // 从 device_config.parser.id
      "init_flow": [...],               // 从 device_config.init_flow.steps
      "interval_ms": 1000,
      "enabled": true
    }
  ]
}
```

### 4.3 修改设备配置 (v2.1 G1 修复)

```
PUT /api/v1/device-configs/:id
{
  "init_flow": {
    "steps": [...]    // 加了 soft_reset 步骤
  }
}
```

**后端流程**:
1. 更新 device_configs 记录
2. **EmitConfigChange** (v2.1 G1 修复)
3. **影响范围分析**: 找出所有引用该 device_config_id 的 edge_devices
4. **SyncGate.OnConfigChange** → 对每个 online node 推 ConfigManifest
5. 节点收到 ConfigManifest → 重新 apply 该 device_config 的新 init_flow
6. 重新触发 edge_devices 的 init (如果 init_flow 变了)
7. 推 node_config_synced 事件

### 4.4 设备配置删除 (RESTRICT)

```
DELETE /api/v1/device-configs/:id
```

**后端流程**:
1. 查询引用: `SELECT COUNT(*) FROM edge_devices WHERE device_config_id = :id`
2. 如果 > 0 → 返回 409 Conflict, 提示"请先迁移引用"
3. 如果 = 0 → 软删除 (deleted_at = NOW())
4. 6 个月后自动清理 (cron job)

## 5. 协议层 (v2.2)

### 5.1 协议字段 (ConfigManifest 扩展)

**v2.2 ConfigManifest 包含**:
- 中心端的 device_config 完整定义 (v2.2 init_flow) **不下发到节点**
- 节点只收到 edge_devices[] (含 parser_id 和 init_flow 步骤)

**v2.1 兼容**:
- 老固件只解析 channels + templates
- 新固件解析 channels + edge_devices
- 字段共存: 同一 Manifest 同时包含 channels (v2.1) + edge_devices (v2.2)

### 5.2 ConfigQuery (0x13) v2.2 扩展

```
SVR 收到 ConfigQuery:
  filter_by_edge_device_id: 10  // 选填
    ↓
  返回该 edge_device 的最新 config (含 init_flow)
```

## 6. 设备配置 vs 配置模板 (Template) 的关系

> **关键澄清**: device_configs (v2.2) 和 config_templates (v2.1 模板池) 是**两件事**

| 维度 | DeviceConfig (v2.2) | Template (v2.2 模板池) |
|------|---------------------|------------------------|
| 关注点 | 型号的协议无关元数据 | "怎么读寄存器" 的二进制命令 |
| 用户 | 业务方 (产品经理) | 嵌入式工程师 |
| 内容 | 业务配置 (init flow, parser id) | 二进制命令序列 (hex) |
| 粒度 | 一个型号一个 | 多设备可共享一个 |
| 实例化 | 边缘设备 (N:1) | edge (N:1) |
| 协议下发 | 通过 channel.edge_devices | v2.2 计划 TemplatePoolSync (0x15) |

**示例 (BMP280)**:
- DeviceConfig: `{parser:"bosch.bmp280", init_flow: 5 步}`
- Template (注册到 template_pool): `{id: 1, write_data:"\\x88", read_length:26}`

**使用流程**:
```
1. 中心端读 device_config.init_flow
2. 中心端解析每个 step 的 data 字段 → 找到对应 Template
3. 节点收到 ConfigManifest 时, init_flow 步骤已展开为 binary command 序列
4. 节点执行 (使用 sendAndWait, 校准数据存 NVS)
```

## 7. 容错设计 (v2.2)

| 场景 | 行为 | 修复 |
|------|------|------|
| 创建设备配置时 parser.id 不存在 | 404 (parser registry 查不到) | - |
| 创建设备配置时 vendor_id 不存在 | 422 | - |
| 删除有 edge_devices 引用的设备配置 | 409, 提示"先迁移引用" | - |
| 修改 init_flow 步骤格式错误 | 422, Zod schema 校验 | - |
| 修改 init_flow → 节点收到 → init 失败 | 节点回 ConfigResult success=false | - |
| vendor / device_model 软删除 | device_configs 保留 (SET NULL) | - |
| 设备配置重复 (device_type + name) | UNIQUE 约束, 409 | - |

- 创建设备配置: admin
- 查询: 登录
