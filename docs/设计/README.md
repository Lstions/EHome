## 🎯 设计原则

EHomeSystem 整体遵循 5 大设计原则 (按重要性排序)：

### 1. 三层分离 (Three-Layer Separation)
- **采集层**: ESP32 边缘节点 (无业务逻辑, 只做协议/驱动/上报)
- **服务层**: Go 后端 (业务核心, 状态机, 持久化, 协议解析)
- **展示层**: Vue3 Web 前端 (无业务逻辑, 只做交互/可视化)
- 边界清晰, 任一层可独立替换

### 2. 协议优先 (Protocol-First)
- 二进制帧协议 (`backend/pkg/frame/`) 是后端 <-> ESP32 的唯一契约
- 协议变更是 break change, 必须走 [设计/总体设计.md §3 协议规范](总体设计.md#3-协议规范) 的版本化流程
- ESP32 端跟后端强类型共用头文件 (无 protobuf, 直接 C struct + 手写 encode/decode)

### 3. 状态机显式 (Explicit State Machines)
- 所有跨时间的业务流程 (OTA/数据源切换/设备连接) 都用显式状态机
- 状态字面量持久化到 DB 字符串字段, 不存魔法数字
- 状态转移图必须在 [设计/<功能>/详细设计.md] 中画出

### 4. 容错优先 (Fail-Open / Graceful Degradation)
- 任何超时/重试/丢帧必须显式处理, 不能"卡死等"
- 关键场景示例: [设计/固件OTA/详细设计.md §6.4.3](固件OTA/详细设计.md) 的 Hello 自动完成
- 后端任何不可信输入必须有 fail-open 默认行为 (见 [总体设计 §4.2](总体设计.md#42-容错设计))

### 5. 可观测性 (Observability by Default)
- 任何状态转移/边界事件都进 logger
- 任何业务异常都进 `notifications` 表
- Prometheus 指标 + 结构化日志 + WebSocket 推送三件套
- 设计稿必须包含"可观测性"小节 (错误码、关键事件、Metrics)
