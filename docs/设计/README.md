## 🎯 设计原则（五大铁律）

### 1. 三层分离
- 平台层 → 中心端（业务核心）→ 节点（无业务逻辑）→ 边缘设备（逻辑抽象）。
- 边界清晰，任一层可独立替换。GPIO/PWM 直控经独立协议，不入通道系统。

### 2. 协议优先
- 二进制帧协议是中心端 ↔ 节点唯一契约（`backend/pkg/frame/`，[../协议/二进制帧协议.md](../协议/二进制帧协议.md)）。
- 变更是 break change，走版本化流程 + CI 校验。
- Go 与 C 共享 golden vector 语义。

### 3. 状态机显式
- 跨时间流程（OTA/同步/初始化/控制执行）全部显式状态机，状态字面量入库。

### 4. 容错优先（Fail-Open）
- 超时/重试/丢帧必须显式处理；三重兜底：Hello 决策 + 中心端重启 push + 节点周期 sync。

### 5. 可观测性
- 结构化日志（sync_id 链路追踪）+ Prometheus + WS 事件三件套；任何业务异常进通知中心。
