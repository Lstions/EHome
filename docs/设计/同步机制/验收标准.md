# 同步机制 v2 — 验收标准

> **模块**: 同步机制 (Sync Mechanism)
> **协议**: v2.1
> **对应设计**: [详细设计.md](详细设计.md)

## 一、设计目标验收

| # | 目标 | 验收项 | 状态 |
|---|------|--------|------|
| D1 | 中心端是配置唯一权威源 | 任何配置变更 5s 内推到所有相关设备 | [ ] |
| D2 | 节点可恢复 | 任意时刻节点可从中心端拉取完整状态 | [ ] |
| D3 | 多通道同步 | Hello/StatusReport/Startup/ConfigChange 都能触发同步 | [ ] |
| D4 | 可观测同步 | 每次同步带 sync_id 贯穿全链路 | [ ] |
| D5 | 协议向后兼容 | v2.0 固件可与 v2.1 中心端互通 | [ ] |

## 二、GAP 修复验收 (从 v2.0 → v2.1)

| GAP | 描述 | 修复点 | 验收项 | 状态 |
|-----|------|-------|--------|------|
| **G1** | 中心端改配置不通知 | SyncGate.OnConfigChange + ConfigEventBus | 改 channel 后 5s 内 ESP32 收到 | [ ] |
| **G2** | 中心端重启丢同步 | main.go 启动 push | Center restart 后 10s 内所有在线设备收到 | [ ] |
| **G3** | 恢复出厂卡死 | SyncGate.OnHello 检查 nvs_has_config | 长按 BOOT 5s → 重启 → 30s 内收到 ConfigManifest | [ ] |
| **G4** | WS 事件名错位 | events.go + events.ts 共享常量 | 前端订阅 node_status, 后端推送 node_status | [ ] |
| **G5** | StatusReport 不触发重发 | SyncGate.OnStatusReport | offline→online 后 30s 内收到 ConfigManifest | [ ] |
| **G6** | device init 用 Sleep | 改用 sendAndWait | BMP280 5 步初始化, 每步有 WriteResponse 匹配 | [ ] |
| **G7** | hashMgr.Reset 死代码 | ConfigEventBus 替代 | 不再需要 Reset (事件驱动) | [ ] |

## 四、中心端架构验收

### 4.1 ConfigEventBus

- [ ] bufferSize = 1024 (配置化)

- [ ] 集成测试: CRUD → Event → SyncGate 链路

### 4.2 EpochGenerator

- [ ] Next() 单调递增 (并发安全)
- [ ] Restore() 从 DB 恢复
- [ ] 单元测试: 并发 100 个 Next() 无重复
- [ ] 单元测试: 重启后 epoch 不丢

### 4.3 SyncGate

#### 4.3.1 OnHello

- [ ] nvs_has=false → 强制全量
- [ ] epoch < server → 强制全量
- [ ] manifest_id 不匹配 → 强制全量
- [ ] hash 一致 + dedup 窗口内 → 不发
- [ ] hash 一致 + dedup 过期 → 不发 (默认行为)
- [ ] 决策带 sync_id

#### 4.3.2 OnStatusReport

- [ ] epoch < server → 推 ConfigManifest
- [ ] in_sync → 不发
- [ ] 决策带 sync_id

#### 4.3.3 OnConfigChange

- [ ] 一事件 → 一决策 (单 node)
- [ ] 一事件 → 多决策 (批量改 templates 影响多 node)
- [ ] 决策带 sync_id

#### 4.3.4 OnCenterStartup

- [ ] 启动 5s 后触发
- [ ] 推所有 status=online 的 node
- [ ] 推不存在的 node (DB 有, MQTT 未连) 不阻塞

#### 4.3.5 OnConfigQuery

- [ ] 收到 ConfigQuery → 比对 epoch
- [ ] in_sync → 返回 SyncResponse(in_sync=true)
- [ ] out_of_sync → 返回 ConfigManifest

#### 4.3.6 OnOfflineReconnect

- [ ] StatusReport 触发, oldStatus=offline → 决策
- [ ] epoch 检查通过
- [ ] 同时触发 triggerDeviceInit

#### 4.3.7 OnFactoryReset

- [ ] WriteCmd 0xFC 0x00 触发 (后端可选, 不强制)
- [ ] 主动重置 hashMgr

### 4.4 CRUD 接入事件总线

- [ ] handler_device.go channel CRUD 末尾调用 EmitConfigChange
- [ ] handler_node.go node CRUD 末尾调用 EmitConfigChange
- [ ] handler_ota.go firmware CRUD (如适用) 调用 EmitConfigChange
- [ ] 单元测试: 改 channel → 收到 ConfigChangeEvent
- [ ] 集成测试: 改 channel → ESP32 收到 ConfigManifest

### 4.5 main.go 启动 push

- [ ] 启动 5s 后触发
- [ ] 遍历所有 status=online node
- [ ] 推 ConfigManifest 给每个
- [ ] 单元测试: 模拟重启 + 在线设备 → 收到 ConfigManifest

## 七、错误处理验收

### 7.1 中心端错误兜底

| 错误 | 兜底 | 验收 |
|------|------|------|
| ConfigEventBus 满 | drop + alarm | [ ] |
| Epoch 持久化失败 | 不阻塞, 内存用 | [ ] |
| Collector DB 找不到 | skip + 不报错 | [ ] |
| ConfigManifest 编码失败 | log + 跳过该设备 | [ ] |
| MQTT 发送失败 | 退避 3 次 + notifications | [ ] |

### 7.2 节点端错误兜底

| 错误 | 兜底 | 验收 |
|------|------|------|
| ConfigManifest 解码失败 | WARN + 不写 NVS + ConfigResult fail | [ ] |
| apply 失败 | 重试 1 次 | [ ] |
| NVS 写失败 | 重试 3 次 | [ ] |
| ConfigQuery 发送失败 | 退避重试 | [ ] |

### 7.3 兜底机制 (关键)

- [ ] 任何同步失败都不能让设备"卡死等"
- [ ] 30s 后周期 sync 兜底
- [ ] MQTT 断自动重连触发新 Hello
- [ ] 单元测试: 各种失败场景
