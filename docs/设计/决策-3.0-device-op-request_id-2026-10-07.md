# 决策：0x22/0x23 的 `request_id` 保留（结清 §93.4，2026-10-07）

> 状态：**保留 request_id**。本文把"它是实现者加的、需设计确认"这一悬挂项**结清**。
> 依据是**可执行的证据**，不是"我觉得需要"。

## 一、§93.4 原本的问题
> "`request_id` 是**我加的**，需要设计确认。设计从未规定关联 id。"

## 二、裁决：保留。三条证据

### 证据 1：它防的**不是假想风险，而是已被测出的真实故障**
`backend/internal/nodemgr/device_op_tracker_test.go:95` 的 `TestStaleAckIsRejected`
**逐字写明了失效链**：

| 步骤 | 发生的事 |
|---|---|
| 1 | 第一次 reboot 下发 |
| 2 | **ACK 丢失** ⇒ 第一次超时（`Fail`） |
| 3 | 第二次 reboot 下发（单飞已释放） |
| 4 | **第一次的迟到 ACK 到达** |
| 5 | ❗ 若按"谁在飞就归谁"关联 ⇒ 它**解掉第二次** |

后果（测试注释原话）：**"the operator would be told the reboot succeeded based on an ACK
that belonged to an operation that already timed out"** ——
即**把已经超时失败的操作报成成功**。
而操作员据此决定**要不要跑一趟现场**，所以这不是显示问题，是**决策依据被污染**。

> **这条把"实现者觉得需要"变成了"有一个测试证明少了它会报错成功"。**

### 证据 2：两端都**已经**在强制这条契约（删它要同时改两端）
- **后端**：`device_op_tracker.go:141` —— `if !ok || p.requestID != ack.RequestID { return false }`
  （不匹配 ⇒ 拒不解析 + 计数，且**不当失败刷日志**：那条请求已经不在了，没什么可报的）；
- **固件**：`handler_device_op.c` 文件头明写
  "request_id 必须**原样回显**：服务端用它把 ACK 配到具体那一次请求上"，
  且 `device_op.h` 的 `request_id` 上限**与后端 `MaxDeviceOpRequestIDBytes` 对齐**；
- **共享向量**：`protocol/vectors/wire_primitives.txt` 的 `device_op_reboot` /
  `device_op_ack_ok` 等用例**已经把 field 2 的编号与字节固定**；
- **跨语言对锚**：`device_e2e_firmware_test.go` 断言后端解出的 `request_id` 与发来的一致。

⇒ 删掉它要**同时**改 4 处（两端实现 + 向量 + 对锚），而收益是"少一个字段"。

### 证据 3：单飞**不能**替代它
一个自然的反驳是"每节点同时只有一次在飞（`Begin` 拒绝第二个），
所以'迟到的 ACK'不可能归错"。**不成立**，因为**单飞槽位会被释放**：
- 超时/失败会 `Fail` ⇒ 释放槽位（这正是 `TestStaleAckIsRejected` 的第 2-3 步）；
- 于是"旧 ACK"到达时，槽位里**已经坐着一个新的请求** —— 正是归错的那一刻。

⇒ 单飞解决的是"**同时**两个"，`request_id` 解决的是"**先后**两个"。**两者不可互替。**

## 三、这条与我此前两次裁决的一致性
本仓已有两次同类裁决（都是"用证据结清一个挂着的问题"）：
- **§120 帧类型双写**：保留双写 + 两端强制一致性校验（向量已钉死形状）；
- 本文 `request_id`：保留（已钉死且有测试证明缺它会报成功）。

两次的共同判据：**改它要动几处 / 不改它的后果是否已有测试证明**。
- 改的代价大（多处契约）**且**不改的后果已被证明 ⇒ 保留。

## 四、仍然**没有**被定下来的（如实列出，不因为本文而改变）
1. **发送窗口大小**：设计 §4.1 → §5.2 之间**始终没有给出数字**；
2. **QoS2 → ACK 的时点**；
3. **端序**：§42.3 同类"实现者选了"的问题（本文只结清 `request_id`，不结清端序）；
4. **NTP 服务器地址**：`CONFIG_EHOME_NTP_SERVER` 默认空 ⇒ sntp_mgr 进 DISABLED。

⇒ 本文**只**结清 `request_id`，**不**顺带把上面这些"一起决定"。

## 五、证据边界
- 证据来自**源码与测试**（本机可复现），**不是**真机实测；
- **未在真机上构造过"ACK 丢失 + 重发"场景**（本卡禁刷设备）；
  ⇒ "这台设备会重发 ACK"这一前提**我未能直接实测**，它是设计文档的说法
  （§93.4 "设备**会重发 ACK**"）。**但裁决不依赖它** ——
  即使设备从不重发，`TestStaleAckIsRejected` 的第 2-4 步（超时后释放槽位 + 迟到 ACK）
  在**自动重试**或**人为重试**下同样成立。
