## 1. 原交互流程

```text
边缘设备列表「创建边缘设备」
  → 对话框（760px，el-steps simple）
      ① 选择设备型号：配置模板（可选）+ 解析器卡片
      ② 节点与通道：所属节点 + Tab（选择已有通道 | 创建新通道）
      ③ 基本信息：名称 + 采集间隔 / 逐指令轮询间隔 + 配置确认
  → 「下一步」受 canGoNext 门禁；最后「创建边缘设备」提交
编辑模式：跳向导，单页显示「名称/节点/通道/采集间隔」+ 保存修改
```

**步骤门禁（`useCreateWizardSelection.canGoNext`）**

| 步骤 | 可进入下一步的条件 |
|---|---|
| 0 设备型号 | 已选解析器 |
| 1 节点与通道 | 已选节点，且（已有通道被选中 **或** 新通道选了硬件 ID 且节点上报了该总线资源） |
| 2 基本信息 | 设备名称非空 |

## 2. 控件清单与职责

| 步骤 | 控件 | 作用 / 约束 |
|---|---|---|
| ① | 配置模板（可选） | 选中后自动套用设备类型、推荐解析器与硬件类型；可清空 |
| ① | 解析器卡片 | 决定原始字节解析方式与可用总线（`hardware_types`）；键盘可达；未选不能下一步 |
| ② | 解析器徽标 | 回显当前型号（名称 + id），提醒后续通道必须匹配其总线 |
| ② | 所属节点 | 只列在线节点；切换节点会清空已选通道并重载通道列表/能力 |
| ② | Tab：选择已有通道 | 卡片展示通道名、硬件类型、总线 ID；选中态 + 绿勾；无匹配时提示新建 |
| ② | Tab：创建新通道 | 硬件类型（解析器支持的总线）、硬件 ID（节点 capabilities 上报的资源）、I2C 从机地址、SPI CS、采集间隔；节点未上报总线时禁用并说明 |
| ③ | 边缘设备名称 | 必填；创建后作为列表/详情标题 |
| ③ | 采集间隔 / 轮询指令 | 无 schedulable 指令时用全局 interval_ms；有则逐条设置（0 = 禁用），失败必须拦截提交 |
| ③ | 配置确认 | 解析器、通道、总线、轮询指令数或采集间隔的只读摘要 |
| 底部 | 上一步 / 下一步 / 创建 | 下一步受 canGoNext 门禁；创建中 loading，关闭按钮禁用 |
| 编辑 | 名称 / 节点 / 通道 / 间隔 | 不重新选择型号、不传 type；换节点必须重选通道（历史数据仍连续） |

## 3. 改造前的问题

1. **宽度与步骤条**：760px 固定宽 + `el-steps simple`，390px 下三个标题挤成一行、被压缩；
   步骤条只是装饰，不能回看/跳转。
2. **移动端不堆叠**：新通道表单用 `el-col :span="12"`，窄屏仍两列并排，硬件类型/ID 被压窄。
3. **逐指令轮询行裁切（实测）**：`200px 名称 + 描述 + 150px 数字框 + 开关` 单行不换行、
   容器 `overflow:hidden` ⇒ 390px 下数字框只剩半截、开关完全不可见。
4. **操作区偏小**：footer 按钮默认 32px，低于移动端 44px 触控目标。
5. **信息重复**：每步顶部还有一条 `.step-tip`，与新增的步骤说明重复，挤占首屏。
6. **全屏被全局样式截断**：`theme.css` 的 `.el-dialog { max-width: 92vw }` 会把
   `is-fullscreen` 对话框压成左右各留 15px（高度对、宽度不对）。

## 4. 重设计

### 4.1 与规则向导统一的壳

- **PC（≥768px）**：900px 对话框、左侧 220px 步骤栏（已完成打勾、当前高亮、只允许回看
  已完成步骤）、右侧独立滚动、固定 footer。
- **移动端（<768px）**：全屏、顶部「步骤 n/3 + 当前步骤名」+ 进度条、单列、固定 footer、
  44px 按钮、右上角 × 关闭（不再重复「取消」）。
- 删除三个重复的 `.step-tip`，说明统一放在每步标题下的一句描述。
- 全屏对话框显式解除 `.el-dialog { max-width:92vw }`（width/max-width/margin 归零）。

### 4.2 分步布局

| 步骤 | 内容 |
|---|---|
| 1 设备型号 | 面板头 + 配置模板 + 解析器卡片列表（列表在壳内滚动） |
| 2 节点与通道 | 面板头 + 解析器徽标 + 节点下拉 + Tabs（已有通道卡片 / 新通道表单） |
| 3 基本信息 | 面板头 + 名称 + 采集间隔/轮询指令 + 配置确认 |

### 4.3 响应式细节

- 新通道表单：`el-col :xs="24" :sm="12"`，390px 下硬件类型/硬件 ID 各占一行。
- 配置模板行：窄屏由横向 flex 改为纵向（标签在上、下拉占满）。
- 逐指令轮询行：窄屏改为两行 —— 第一行「名称 + 类型 + 命令字」，第二行描述，
  第三行右对齐「数字框 + ms + 开关」；容器不再 `overflow:hidden`。
- 通道列表在移动端取消固定 `max-height`，交给外层滚动。
- footer 按钮移动端内联 `min-height:44px`（不再依赖可能被覆盖的 scoped 样式）。

## 6. 未改变的行为（刻意保留）

- `canGoNext` 门禁、节点在线过滤、切换节点清空通道、节点能力上报缺失时禁止创建该总线通道；
- 创建/编辑三条提交分支、inline 建通道、逐指令间隔加载失败拦截；
- 编辑模式不走向导、不重新提交 type；
- 所有 data-test 与既有交互入口（便于既有测试与自动化脚本继续使用）。
