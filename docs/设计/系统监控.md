## 1. 功能概述

运行指标页（自动刷新可选 5s/10s/30s），健康检查端点，Prometheus 抓取端点，平台总览 API。

## 2. 端点

| 端点 | 用途 |
|------|------|
| /metrics | JSON 业务指标（前端监控页数据源） |
| /metrics/prometheus | Prometheus 抓取（ehome_* 15+ 族） |
| /health | 健康检查 |
| /overview | 平台总览（统计聚合 + 异常摘要 + 趋势分类） |

## 3. 指标

### 3.1 业务指标（/metrics，前端卡片）

- 节点在线/离线/总数。
- 边缘设备总数（按状态）。
- 数据接收计数/速率。
- 能力快照超期节点数（ResourceReport 超过有效期未上报的节点——健康指标）。
- 同步在途数、告警活跃数（v3.4）。

### 3.2 Prometheus 指标族（核心）

| 指标 | 含义 |
|------|------|
| ehome_node_online_count | 在线节点数 |
| ehome_data_received_total | 数据接收计数 |
| ehome_sync_decisions_total | 同步决策（reason/action） |
| ehome_sync_duration_seconds | 同步耗时 |
| ehome_config_epoch | 当前配置 epoch |
| ehome_event_bus_dropped_total | 事件总线丢弃 |
| ehome_edge_device_total | 边缘设备数（status） |
| ehome_https_ota_failures_total | OTA 失败（reason） |

## 4. 容错设计

- 监控页数据源失败：显示错误态 + 重试，不影响其他页面。
- 自动刷新暂停：页面不可见时停止轮询，返回时恢复（避免空轮）。
- 指标聚合 Go 侧完成（不压 DB）。

## 5. 前端

- views/monitor/Monitor.vue：指标卡 + 自动刷新选择器（5/10/30s）+ 健康状态区。
- 卡片规范：透明底 + tone 图标（遵守前端规范 §4.3 统计卡）。

## 9. 监控部署（可选 profile）

Prometheus + Alertmanager 以 Docker Compose profile `monitoring` 内嵌于根
`docker-compose.yml`（单一真源），**默认不启动**：

```bash
docker compose --profile monitoring up -d                            # 主栈 + 监控
docker compose --profile monitoring up -d prometheus alertmanager    # 仅监控
```

- **可选、不拖慢主栈**：监控服务声明 `profiles: ["monitoring"]`，不带该 profile 时
  `docker compose up -d` 完全不会创建/启动监控容器，主栈启动零额外开销。
- **与主栈同网络**：profile 服务仍加入主栈默认网络，`prometheus.yml` 的抓取目标
  `ehome-web:8080` 可直接解析（旧独立 compose 项目无法解析，已收敛到单一真源）。
- **端口**：宿主端口由 `.env` 控制 —— `PROMETHEUS_PORT`（默认 9090）、
  `ALERTMANAGER_PORT`（默认 9093）。
- **数据卷**：`ehome-prometheus-data` / `ehome-alertmanager-data`，在根 compose 末尾声明。
- **配置挂载**：`deploy/monitoring/{prometheus.yml,alert_rules.yml,alertmanager.yml}`，
  路径相对仓库根，从仓库根运行 compose 即成立。
- **只读校验**：`docker compose config --quiet` 与
  `docker compose --profile monitoring config --quiet`；规则用 `promtool check config/rules`。

## 10. 告警规则清单

告警规则位于 `deploy/monitoring/alert_rules.yml`；指标唯一真源为
`backend/pkg/metrics/metrics.go`，规则内注释逐条标注指标定义行号与递增点。

| 规则名 | 严重级 | 触发条件 | 排查方向 |
|--------|--------|----------|----------|
| EhomeDataConsumerDBWriteFailures | warning | `rate(ehome_data_consumer_db_write_failures_total[1m]) > 1` 持续 2m | PostgreSQL 连接池 / 磁盘 / 表状态 |
| EhomeDataConsumerDBWriteFailuresSustained | critical | `increase(...[10m]) > 100` 持续 1m | PostgreSQL 可用性 / 表损坏 / 磁盘满 |
| EhomeDataEventBusDropped | critical | `rate(ehome_data_event_bus_dropped_total[5m]) > 0` 持续 2m | 消费者阻塞、队列容量、DB 反向背压 |
| EhomeConfigEventBusDropped | warning | `rate(ehome_event_bus_dropped_total[5m]) > 0` 持续 5m | 配置事件消费阻塞、总线上游速率 |
| EhomeLogEventBusDropped | warning | `rate(ehome_log_event_bus_dropped_total[5m]) > 0` 持续 5m | 日志落库阻塞、DB 延迟、消费并发 |
| EhomeWorkerPoolQueueBacklog | warning | `ehome_worker_pool_queue_size > 100` 持续 5m | DB 写入慢、worker 不足、上报突发 |
| EhomeWorkerPoolOverflow | critical | `rate(ehome_worker_pool_overflow_total[5m]) > 0` 持续 2m | DB 可用性 / 慢查询、池容量 |
| EhomeWorkerPoolBackpressureBlock | warning | `rate(ehome_worker_pool_backpressure_block_total[5m]) > 0` 持续 5m | 摄入快于消费、MQTT 消费循环受阻 |
| EhomeDataReportErrors | warning | `rate(ehome_data_report_errors_total[5m]) > 0` 持续 5m | 报文解析 / 字段校验、设备映射 |
| EhomePendingWriteTimeouts | warning | `rate(ehome_pendingwrite_timeout_total[5m]) > 0` 持续 5m | 设备离线、MQTT 下行、超时配置 |
| EhomeMqttPublishFailures | warning | `rate(ehome_mqtt_publish_failures_total[5m]) > 0` 持续 2m | EMQX 连通 / 认证、QoS、TLS / ACL |
| EhomeAllNodesOffline | critical | `ehome_nodes_online == 0`（有历史上报）持续 15m | EMQX 连接、离线判定逻辑、网络 |

**未覆盖**：retention / purge / 分区任务失败 —— `backend/internal/datalifecycle`
（含 `partition_mgr.go`）当前未暴露 Prometheus 指标，不编造指标名。
`ehome_mqtt_publish_failures_total` 已定义但当前无递增点，对应规则为前向兼容。

## 11. 指标清单补充

> 本节为追加小节：记录本轮补齐的 MQTT 发布失败递增值，以及数据生命周期
> 任务失败/清理行数/分区 DROP 指标。指标定义唯一真源仍为
> `backend/pkg/metrics/metrics.go`。
>
> 说明：§10 末尾“retention / purge / 分区任务失败未暴露指标”“ehome_mqtt_publish_failures_total
> 无递增点”的表述由本节取代；原文按“仅追加、不改动 §9/§10”的要求保留。

### 11.1 MQTT 发布失败

| 指标名 | 类型 | 标签 | 埋点位置（文件:行） | 用途 |
|--------|------|------|---------------------|------|
| ehome_mqtt_publish_failures_total | CounterVec | topic | backend/internal/mqtt/mqtt.go:460 | Publish 失败（Publish 返回 error / client 为 nil / 未连接 / token error）按 topic 计数 |

### 11.2 数据生命周期任务

| 指标名 | 类型 | 标签 | 埋点位置（文件:行） | 用途 |
|--------|------|------|---------------------|------|
| ehome_lifecycle_task_failures_total | CounterVec | task | backend/internal/datalifecycle/retention_task.go:156,168；purge.go:165,178；partition_mgr.go:75,124,149,173,192 | 生命周期任务失败次数 |
| ehome_lifecycle_purged_rows_total | CounterVec | task | backend/internal/datalifecycle/retention_task.go:171；purge.go:181 | 成功硬删除的行数（unified_data + device_data） |
| ehome_lifecycle_dropped_partitions_total | Counter | 无 | backend/internal/datalifecycle/partition_mgr.go:153 | retention 清理中整分区 DROP 的数量 |

`task` 标签取值（仅取已存在执行路径）：

| task | 对应执行体 | 递增条件 |
|------|------------|----------|
| retention | RetentionTask.RunOnce / processOne | 扫描逻辑设备失败，或单个逻辑设备处理返回 error |
| purge | Purger.RunOnce / purgeOne | 扫描 purge_requested 失败，或单个逻辑设备 `PurgeFailed` |
| partition | PartitionManager.EnsurePartitions / DropPartitionsBefore | 建分区失败、列出分区失败、DROP 分区失败 |
| rollup | EnsureRollupTable | rollup 表存在性检查或建表失败 |

### 11.3 未纳入本轮的 rollup 聚合失败

分钟级 rollup 聚合写入 `RollupConsumer.Upsert`（`backend/internal/databus/rollup_consumer.go`）
在包白名单之外，未新增埋点；仅 `EnsureRollupTable`（建表/存在性检查，属
datalifecycle）以 `task="rollup"` 计数。若需覆盖聚合 UPSERT 失败，需另开
databus 包的埋点工作。

### 11.4 告警规则建议（供后续 §10 扩展，不自动新增规则）

| 指标 | 建议触发条件 | 排查方向 |
|------|--------------|----------|
| ehome_lifecycle_task_failures_total | `rate(ehome_lifecycle_task_failures_total[5m]) > 0` 持续 5m | retention/purge/partition 任务失败日志、DB 可用性 |
| ehome_lifecycle_dropped_partitions_total | `increase(ehome_lifecycle_dropped_partitions_total[1h]) > 0` | 仅提示，正常 retention 行为；异常放量查 cutoff 计算 |
| ehome_lifecycle_purged_rows_total | 作为清理吞吐观测，不单独告警 | 长期为 0 但有待删数据时查任务调度 |
