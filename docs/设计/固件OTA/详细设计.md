# 固件 OTA — 详细设计

## 1. 功能概述

固件 OTA (Over-The-Air) 是 ESP32 端 A/B partition + Server 端状态机的完整升级链路。

## 2. 数据模型

```sql
CREATE TABLE firmwares (
  ID         SERIAL PRIMARY KEY,
  Version    VARCHAR(32) NOT NULL,
  Checksum   VARCHAR(64) NOT NULL,  -- SHA256 hex
  Filename   VARCHAR(256),
  SizeBytes  BIGINT,
  StoragePath VARCHAR(512),
  Changelog  TEXT,
  TargetModel VARCHAR(64),
  CreatedAt  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE ota_tasks (
  ID           SERIAL PRIMARY KEY,
  OtaID        VARCHAR(64) UNIQUE NOT NULL,
  CollectorID  INTEGER REFERENCES collectors(id),
  FirmwareID   INTEGER REFERENCES firmwares(id),
  Status       VARCHAR(20) DEFAULT 'pending',  -- 6 态
  Progress     INTEGER DEFAULT 0,
  ErrorMsg     VARCHAR(256),
  ToVersion    VARCHAR(32),
  StartedAt    TIMESTAMPTZ,
  CompletedAt  TIMESTAMPTZ,
  CreatedAt    TIMESTAMPTZ,
  UpdatedAt    TIMESTAMPTZ
);

CREATE INDEX idx_ota_tasks_collector ON ota_tasks(collector_id);
CREATE INDEX idx_ota_tasks_status ON ota_tasks(status);
```

## 4. 状态机 (6 态 + 1 cancelled)

```
   创建
    ↓
 pending ──→ downloading ──→ verifying ──→ installing ──→ success
    │              ↓             ↓            ↓
    └──────────→ failed ←──────┴────────────┘
                   (任意阶段失败)
    
    用户取消: * → cancelled (任何非终态)
```

### 4.1 6 字符串字面量 + cancelled

| wire code | 字符串 | 说明 |
|-----------|--------|------|
| 0 | downloading | 正在下载 (0-99%) |
| **1** | **installing (or verifying)** | 当前 ESP32 把 verifying 和 installing 都映射到 1 |
| 2 | success | 真正完成 (status=2, progress=100) |
| 3 | failed | 失败 + error_msg |
| 4 | verifying (server-side 扩展) | 未来 ESP32 升级使用 |
| (无) | cancelled | 用户主动取消 (P3 计划) |

## 5. 关键流程

### 5.1 创建 OTA 任务

详见 [总体设计 §2.3](../总体设计.md#23-ota-升级流-完整-详见-固件ota详细设计md)

```
POST /api/v1/ota/tasks {collector_id, firmware_id}
  ↓
[server] 同一 collector 的旧 in-flight 任务 supersede (mark failed)
  ↓
[DB] INSERT ota_tasks (status=pending)
  ↓
[server] 发 OtaCommand (0x0A) 到 devices/{id}/down/v2
  ↓
[server] 推 ota_progress 事件 (status=pending, progress=0)
```

### 5.2 接收 OtaProgress

```
[server] 收 OtaProgress (0x0B) → 解析 status
  ↓
[DB] UPDATE ota_tasks
  ├─ WireDownloading(0) → status=downloading
  ├─ WireInstalling(1) → status=installing
  ├─ WireVerifying(4) → status=verifying (扩展)
  ├─ WireSuccess(2) → status=success, progress=100, completed_at=NOW
  └─ WireFailed(3) → status=failed, error_msg=...
  ↓
[server] 推 ota_progress 事件
```

### 5.3 Hello 自动完成 (关键)

```
[server] 收 Hello → 查该 collector 最新 ota_tasks
  ↓
若 status 非终态:
  ├─ device.firmware_version == to_version → 标 success
  └─ started_at > 10min → 标 failed
  ↓
推 ota_progress 事件
```

10 分钟超时推算: 10MB 固件 × 1Mbps = 80s + 1-5s 校验 + 30-60s 刷写 = 150s, 10min = 6× 余量

## 6. ESP32 端 9 步流程

```
1. 收 OtaCommand → 解析字段, 启动 ota_updater_task
2. 创建 HTTP client 连接 firmware_url
3. esp_ota_begin(update_partition, OTA_SIZE_UNKNOWN) → ota_handle
4. 边读 HTTP 边 esp_ota_write
5. 下载完成 → esp_ota_end(ota_handle) → SHA256 校验
   - 校验失败 → esp_ota_abort + status=3, error="Hash mismatch"
6. esp_ota_set_boot_partition(update_partition) 切换 boot 分区
7. 发 status=2 (success), progress=100, msg="Success, rebooting"
   - 注意: status=2 不是 status=1 (跟 §5.2 mapping 一致)
8. vTaskDelay(1000ms) 确保 progress 帧经 MQTT 发出
9. esp_restart()

main.c 启动早期 → esp_ota_mark_app_valid_cancel_rollback() (30s 内)
```

## 7. 容错设计

| 场景 | 行为 |
|------|------|
| 未知 wire code | WARN + 保留当前状态 (fail-open) |
| checksum 长度非 64 | WARN + 跳过 hash 校验 (不卡死) |
| 同 collector 并发 OTA | supersede 旧任务 |
| 消息丢失 (esp_restart 丢 success 帧) | Hello 自动完成 |
| 30s 内未 mark valid | ESP32 自动 rollback |
| 10min 无响应 | failed (10× 最坏情况) |
| 损坏固件 (checksum 不匹配) | status=3, error="Hash mismatch" |
| 同版本升级 | 拒绝: "firmware version is the same" |
