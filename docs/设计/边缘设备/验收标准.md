- [ ] 创建时 node_id 存在 → 200

- [ ] 创建时 channel_id 不属于 node_id → 422

- [ ] 删除 → EmitConfigChange, 节点停止该 edge

- [ ] 成功 → init_state=done

- [ ] 单元测试: sendAndWait 正常路径
- [ ] 单元测试: sendAndWait 超时路径

## 三、节点端验收

### 3.1 配置接收

- [ ] 收到 ConfigManifest 包含 channel.edge_devices[] 列表
- [ ] 节点 NVS 存 (channel_id, hardware_id, parser_id, interval_ms) 列表
- [ ] 不存 edge_device_id (节点不感知)
- [ ] 节点 Scheduler 收到后启动各 edge 的 task

### 3.2 初始化触发

- [ ] 节点收到 edge 带 init_flow → 调 InitDevice (sendAndWait)
- [ ] 每步 WriteCommand + 等 WriteResponse
- [ ] 校准数据 (read_calib 步骤) 上行到 center
- [ ] center 写 calib_cache
- [ ] 失败上报 ConfigResult success=false + error_msg

### 3.3 数据上报

- [ ] DataReport field 1 (channel_id) 填 edge_device 对应的 channel_id
- [ ] 不下发 edge_device_id 字段 (节点不感知)
- [ ] 周期 = edge.interval_ms (来自 ConfigManifest)
- [ ] 错误时 error_code 上行

## 四、集成验收 (E2E)

### 4.1 端到端

- [ ] 创建 edge_device (BMP280 模板) → 节点收到 → 触发 init → 校准成功 → 开始采集温度气压
- [ ] 暂停 edge_device (enabled=false) → 节点停止采集 → 中心端 status=disabled
- [ ] 启用 edge_device (enabled=true) → 节点恢复采集
- [ ] 删除 edge_device → 节点停止采集 → 中心端记录

### 4.2 同步场景 (v2.1 同步机制 + v2.2 边缘设备)

- [ ] 创建设备 → 5s 内节点收到 ConfigManifest
- [ ] 改 device_config → 引用该 device_config 的所有 edge_devices 重新 init
- [ ] 节点重启 → 自动恢复 (从 NVS 读 cfg_epoch, 跟中心端比对)
- [ ] 中心端重启 → 启动 push, 在线节点收到

### 4.3 协议兼容 (v2.1/v2.2 互操作)

- [ ] **Server=v2.2 + Device=v2.1**: 节点发 channel_id, 中心端按 channel_id 找 edge_device, 默认取第一个
- [ ] **Server=v2.1 + Device=v2.2**: 中心端不下发 edge_devices 字段, 节点不感知
- [ ] 降级日志有明确标识
