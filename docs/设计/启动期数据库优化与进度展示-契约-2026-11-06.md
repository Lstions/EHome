# 启动期数据库优化 + Web 进度展示 —— 实施契约（2026-11-06）

> 状态：已裁决，可实施
> 工作树：`/mnt/storage/WorkSpace/EHome/.agents/worktrees/telemetry-storage`（分支 `feat/telemetry-storage`）
> 前置：遥测存储优化 L1/L2/L3 已落地（commit 86897a1a）

---

## 1. 问题（现状实测）

当前 `backend/cmd/server/main.go` 的启动序列是**同步阻塞**的：

```
database.Connect → AutoMigrate → MigrateUnifiedDataToPartitioned(Fatal) → MigrateTableToPartitioned(device_data)(Fatal)
→ MigrateTelemetryRollup1mToPartitioned(Warn) → ensurePartitions() → reapRollupPartitions()
→ GPIO 迁移 → purger → retention → …→ api.SetupRoutes → **此刻才 ListenAndServe**
```

后果：
1. 生产首次升级时，`ensurePartitionParentIndexes` 会补建 F-10 两条复合索引（实测 +4.51 GB / 69.6M 行，分钟级 DDL），
   `retireDeadTimeseriesIndexes` 会 DROP 索引（ACCESS EXCLUSIVE）—— 这段时间**端口根本没监听**，浏览器只会看到连接失败/网关超时；
2. `/health` 是静态 `{"status":"ok"}`，没有任何阶段信息；
3. 进度只写 slog（容器 stdout），前端拿不到；
4. `copyMonthBatched` 死表搬迁**一条进度日志都没有**（每批算了 `remaining` 但从不输出）。

## 2. 架构裁决：**维护引擎 → 全量引擎 的原子切换**

不采用"边跑边注册路由"（gin 在 Serve 期间 AddRoute 是数据竞争）。采用外层 handler 持有 `atomic.Pointer[gin.Engine]`：

```
                    ┌──────────────────────────────────────────┐
http.Server ───────▶│ rootHandler (atomic.Pointer[gin.Engine]) │
                    └───────────────┬──────────────────────────┘
                          nil ──────┴────── non-nil
                           │                    │
                 维护引擎(小)                 全量引擎(现有 r)
                 · /health (含阶段)          · 全部业务路由
                 · /api/v1/system/maintenance
                 · /readyz
                 · 静态资源 + SPA 回退
                 · 其余 → 503 MAINTENANCE_IN_PROGRESS
```

**监听时机提前**：`logger.Init` 之后、`database.Connect` **之前**就 `ListenAndServe`。
这样 DB 连不上也能在网页上看到"连接数据库…失败"。

**切换时机**：`api.SetupRoutes(r, …)` + `setupStaticRoutes(r, …)` 完成之后 → `rootHandler.SetEngine(r)`。

## 3. 后端接口契约

### 3.1 新包 `backend/internal/bootstrap`（只依赖标准库 + time）

```go
package bootstrap

type StepState string
const (
    StepPending StepState = "pending"
    StepRunning StepState = "running"
    StepDone    StepState = "done"
    StepFailed  StepState = "failed"
    StepSkipped StepState = "skipped"
)

type Step struct {
    ID         string    `json:"id"`          // 稳定标识，前端可依赖
    Label      string    `json:"label"`       // 中文展示名
    Weight     int       `json:"weight"`      // 进度权重（相对值，不必和为 100）
    State      StepState `json:"state"`
    Progress   float64   `json:"progress"`    // 步骤内 0..100
    Detail     string    `json:"detail,omitempty"`
    Error      string    `json:"error,omitempty"`
    StartedAt  *time.Time `json:"started_at,omitempty"`
    FinishedAt *time.Time `json:"finished_at,omitempty"`
}

type Snapshot struct {
    Ready        bool      `json:"ready"`
    Failed       bool      `json:"failed"`
    Percent      float64   `json:"percent"`        // 0..100，按 Weight 加权
    CurrentStep  string    `json:"current_step"`  // 当前 step ID，全部完成时为空
    CurrentLabel string    `json:"current_label"`
    StartedAt    time.Time `json:"started_at"`
    ElapsedMS    int64     `json:"elapsed_ms"`
    Steps        []Step    `json:"steps"`
    Version      string    `json:"version"`
    BuildCommit  string    `json:"build_commit,omitempty"`
}

type Tracker struct{ /* 并发安全 */ }

func NewTracker(steps []Step) *Tracker
func DefaultSteps() []Step
// 方法：Begin/StepProgress/Done/Fail/Skip/Snapshot/Ready/Failed
func (t *Tracker) Begin(id string)
func (t *Tracker) StepProgress(id string, pct float64, detail string)
func (t *Tracker) Done(id, detail string)
func (t *Tracker) Fail(id string, err error)
func (t *Tracker) Skip(id, detail string)
func (t *Tracker) Snapshot() Snapshot
func (t *Tracker) Ready() bool
func (t *Tracker) Failed() bool
func (t *Tracker) SetBuildCommit(c string)
```

**步骤清单（DefaultSteps，权重合计 100）**：

| ID | Label | Weight |
|---|---|---:|
| `db_connect` | 连接数据库 | 3 |
| `auto_migrate` | 数据库结构迁移 | 10 |
| `partition_unified_data` | unified_data 分区迁移 | 25 |
| `partition_device_data` | device_data 分区迁移 | 15 |
| `partition_rollup` | 聚合表分区就绪 | 2 |
| `ensure_partitions` | 滚动分区保障 | 3 |
| `parent_indexes` | 补齐父表索引 | 25 |
| `retire_dead_indexes` | 退役死索引 | 5 |
| `warmup` | 缓存预热 | 7 |
| `startup_tasks` | 后台任务启动 | 5 |

### 3.2 进度回调注入（避免大改函数签名）

在 `backend/internal/datalifecycle` 增加：

```go
// MigrationProgress 是迁移/索引维护的进度回调（可为 nil）。
type MigrationProgress interface {
    StepProgress(stepID string, pct float64, detail string)
}
func SetMigrationProgress(p MigrationProgress)   // 全局，启动期一次性注入
```

**必须埋点的位置**（只在 PG 路径且确有耗时处）：
- `MigrateTableToPartitioned`：按月循环 `i/totalMonths`，detail 形如 `"202611 第 3/7 批 已搬 41,000 行"`
- `copyMonthBatched`：每批结束上报一次（用 `remaining`/已搬行数构造 detail）
- `ensurePartitionParentIndexes`：每建一条索引前后上报
- `retireDeadTimeseriesIndexes`：每条 DROP 前后上报

stepID 映射：unified_data → `partition_unified_data`；device_data → `partition_device_data`；
ensure 索引 → `parent_indexes`；退役 → `retire_dead_indexes`。

### 3.3 HTTP 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/v1/system/maintenance` | **免鉴权** | 返回 `{"code":0,"data":Snapshot}`；只暴露阶段/进度/耗时，不含任何业务数据 |
| GET | `/health` | 免鉴权 | 保留 `status`/`commit` 字段（向后兼容），**新增** `ready`(bool)、`phase`(string)、`percent`(float) |
| GET | `/readyz` | 免鉴权 | ready=200 `{"ready":true}`；否则 503 `{"ready":false,"phase":...,"percent":...}` |

维护期业务响应：HTTP 503 + `Retry-After: 5` + body
`{"code":503,"error_code":"MAINTENANCE_IN_PROGRESS","message":"服务正在执行启动期数据库优化，请稍候"}`

**免鉴权白名单（维护引擎必须放行）**：`/health`、`/readyz`、`/api/v1/system/maintenance`、`/ping`、`/assets/*`、`/favicon.svg`、`/metrics`（保持现状免鉴权）、以及**所有 GET 到 SPA 入口的非 API 路径**（返回 index.html）。

### 3.4 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `EHOME_STARTUP_MAINTENANCE_PAGE` | `true` | 关掉则退化为旧行为（同步阻塞后再监听），用于排障 |
| `EHOME_STARTUP_FAIL_FAST_SECONDS` | `0` | >0 时，若启动超过该秒数仍未就绪，进程以非 0 退出（可选） |

## 4. 前端契约

- 新路由 `/maintenance`（`meta.requiresAuth: false`，不进菜单）
- `App.vue` 顶层门禁：应用启动时先探一次 `/api/v1/system/maintenance`；
  - `ready=false` → 渲染维护页（**不经过 router-view**，避免登录跳转与懒加载干扰）
  - 轮询 2s，就绪后自动 `location.reload()` 回到正常路由
  - 维护页必须能在**未登录**状态显示（该接口免鉴权）
- 维护页内容：总体进度条 + 阶段列表（当前阶段高亮、已完成打勾、失败标红）+ 已耗时 + 失败时给"失败原因 + 重试"按钮（重试=刷新页面）
- 组件：`views/maintenance/Maintenance.vue`、api：`api/system.ts` → `getMaintenanceStatus()`
- 文案示例："系统升级中，正在优化数据库，请勿关闭…"

## 5. 兼容与回滚

- 三个开关默认值保证：**不改变任何业务语义**，只改变"何时开始监听"。
- 排障开关 `EHOME_STARTUP_MAINTENANCE_PAGE=false` 一键回退旧行为。
- 失败语义保持：`unified_data`/`device_data` 迁移失败仍 **Fatal**；`telemetry_rollup_1m` 仍只 Warn。
  Fatal 时维护页应显示 failed 状态（在 Fatal 前先 `tracker.Fail`）。
