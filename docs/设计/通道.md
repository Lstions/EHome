## 1. 功能概述与端点

**通道 (Channel)** = 节点上的**物理通信端点**，是物理总线的逻辑抽象。每个通道属于一个节点，对应一种传输总线类型：**UART / I2C / SPI / ADC**。通道**只描述物理**（引脚、速率、模式、从机地址范围），不描述上面挂什么型号——挂在总线上的东西是[边缘设备](边缘设备.md)。

> **v3.0 裁决：GPIO/PWM 不在通道系统内**。只有"可数据交互、有协议帧"的总线才入通道；GPIO 是引脚直控、PWM 是 LEDC 直控，走独立 PeriphCmd/PeriphRsp 协议，见[GPIO与PWM外设控制.md](GPIO与PWM外设控制.md)。因此本模块**不含 GPIO 通道**（历史 GPIO/ADC 共栖段落已随剥离移除；ADC 保留为通道类型）。

通道还承载两块能力：

- **通道终端**：中心端 ↔ 节点通道的**透明字节管道**（WebSocket + 历史 + 直写），调试/诊断用，有审计与门禁。
- **DMA 通道视图**：节点 DMA 通道的配置 API 与"总线配置"只读视图；DMA 资源分配设计见[DMA资源管理设计.md](DMA资源管理设计.md)。

## 2. 数据模型

模型：`backend/internal/models/models.go` 的 `Channel`（表 `channels`）。

```text
channels:
  id            SERIAL PK
  node_id       VARCHAR(32) NOT NULL (index)   -- 所属节点物理 ID
  hardware_type VARCHAR(20)   -- "SPI"/"I2C"/"UART"/"ADC"（大写存储）; GPIO/PWM 拒绝
  hardware_id   VARCHAR(16) DEFAULT ''         -- 总线上的硬件地址 (e.g. I2C 0x76)
  interval_ms   INT DEFAULT 5000               -- 0 = 显式禁止调度
  bus_type      VARCHAR(20) DEFAULT 'I2C'      -- 总线类型，须与 hardware_type 等值; legacy GPIO/PWM 拒绝
  bus_config    TEXT                            -- JSON/hax 引脚路由与速率配置
  template_ids  TEXT                            -- 逗号分隔的模板 ID 列表
  config        TEXT                            -- JSON bus 配置（兼容旧字段）
  enabled       BOOLEAN DEFAULT true
  dma_enabled   BOOLEAN DEFAULT false          -- DMA 启用（节点总线配置 TAB 开关）
  created_at / updated_at / deleted_at          -- 软删除 (P3)
  （关联）EdgeDevices []EdgeDevice (FK ChannelID)
```

### 2.1 传输通道校验（gpio/pwm 排除）

```text
validateTransportChannelType（handler_device.go，权威实现）
  ├─ isPeripheralChannelType(hardware_type | bus_type)：GPIO/PWM（含历史数字枚举 "4"/"6"）
  │    → 拒绝："GPIO and PWM are peripheral resources, not channels"
  ├─ hardware_type / bus_type 必填（TrimSpace 非空）
  └─ EqualFold(hardware_type, bus_type) 不匹配 → 拒绝
```

历史数字枚举 "4"/"6" 保留仅因**存量行兼容**：`MigrateGPIOChannels` / `RetireLegacyPWMChannels` 启动时把这类行禁用（不删）。

### 2.2 外设冲突检测

创建/更新携带 `bus_config`（引脚路由，hex 编码）时执行 `validateChannelPeripheralConflicts`：解析引脚并与 GPIO/PWM 外设配置比对，引脚冲突 → 409（`channel route conflicts with GPIO/PWM configuration`）。内联创建路径（边缘设备向导）缺省不带 bus_config，则跳过该门（无路由可校验）。

### 2.3 总线参数默认值

**UART**：baudrate 115200 / data_bits 8 / stop_bits 1 / parity none / flow_control none / rx·tx_buffer_size 1024
**I2C**：clock_hz 400000 / sda_pin 21 / scl_pin 22 / pullup_enabled true
**SPI**：clock_hz 1000000 / mosi_pin 23 / miso_pin 19 / sclk_pin 18 / cs_pin 5 / mode 0
**ADC**：channel 0 / attenuation 0dB·2.5dB·6dB·11dB / sample_time 100ms / voltage_range 0-3.3V

## 3. 状态机

通道无独立业务状态机；关键状态位：

- `enabled`：调度开关（禁用通道上的边缘设备停止采集）
- `dma_enabled`：DMA 通道启用（与节点 DMA 配置、设备上报状态三方合并展示）
- 软删除（deleted_at）：被边缘设备引用时 DELETE 拒绝（409）

DMA 通道状态合并规则（handler_node.go `GET /:id/dma-channels`）：

```text
上报状态（ResourceReport field 8）  ⊕  配置意图（node.Config.dma_configs）
  ├─ 意图 enabled 且上报 disabled(2) → 显示 free(0)（配置已推、设备未回报）
  └─ 意图 disabled 且上报非 disabled → 显示 disabled(2)
```

## 4. 关键流程

### 4.1 创建通道

```text
POST /api/v1/channels
  1. interval_ms 显式 0 与缺省区分（0 = 有意禁用调度）
  2. enabled 从 payload 读取（缺省 true）
  3. validateTransportChannelType（GPIO/PWM 拒绝；bus_type 等值校验）
  4. 事务：节点行锁 → validateChannelPeripheralConflicts（引脚冲突 409）→ INSERT
  5. EmitConfigChange(CfgChangeChannel, Create) → 节点拉取
  6. 节点写 NVS → ConfigResult
```

### 4.2 更新 / 删除

```text
PUT /:channel_id（DTO 仅允许 hardware_type/bus_type/enabled/bus_config/dma_enabled/...）
  事务内行锁 → 候选值组装 → type/冲突/绑定校验全部通过才 Updates → EmitConfigChange(Update)
  ├─ validateChannelBindings：通道类型变更影响已挂边缘设备的绑定校验
  └─ 失败 → 500 + 不入库（显式避免静默覆盖）
DELETE /:channel_id
  事务内引用检查：有 edge_devices 引用 → 409（cannot delete channel referenced by
  edge devices）；无引用 → 软删 + EmitConfigChange(Delete)
```

### 4.3 I2C / Modbus 扫描

```text
POST /:channel_id/scan { scan_type: "i2c"|"modbus", start_addr?, end_addr?, timeout_ms? }
  ├─ 通道 lookup（不存在 404；非 transport/禁用 400）
  ├─ i2c → SendScanRequest（ScanRequest 0x0D；节点扫描 0x01-0x7F → ScanReport 0x0C）
  ├─ modbus → SendModbusScanRequest（地址区间）
  └─ 响应 { channel_id, scan_type, request_id }（结果经事件总线推前端）
```

### 4.4 通道直写（WriteCommand 10s 超时）

```text
POST /:channel_id/write { data, hex_mode }
  ├─ 门禁 rawWritesEnabled 关闭 → 410
  ├─ 通道 lookup + validateTransportChannel
  └─ PendingWrite.SendWriteCommand（10s）→ { success, error_code, error_msg }
     （受控审计的终端入口另见 terminal/write）
```

### 4.5 通道终端（透明管道）

```text
GET /:channel_id/terminal?count= → TerminalMgr.GetHistory（内存滚动历史）
POST /:channel_id/terminal/write { device_id, data_hex, read_size }
  ├─ 门禁 rawWritesEnabled 关闭 → 410
  ├─ loadTransportChannel 校验 + hex 解码
  └─ SendWriteCommand → 上行经终端流事件推送
前端 ChannelTerminal.vue：TX/RX 双面板、HEX/ASCII 切换、按通道分组、时间戳 + 错误码、
  虚拟滚动、清空；事件经统一 WS（终端与通用 WS 共用单主体会话语义）
```

### 4.6 通道重配置

`POST /:channel_id/reconfigure { baudrate?, clock_hz? }`：返回 `status: reconfigured` + request_id；总线参数落地走 Manifest/Template 下发链（结合[设备配置.md](设备配置.md) connection.default_params 与采集模板），物理层以节点端总线 HAL 实际重配为准。

## 5. 协议与外部契约

- **ConfigManifest（0x04）**：通道配置随节点清单下发（bus_type + bus_config + channel 挂载 edge_devices 表）；变更由 SyncGate 触发。字段与版本约束见[../协议/二进制帧协议.md](../协议/二进制帧协议.md)与[同步机制.md](同步机制.md)。
- **ScanRequest（0x0D）/ ScanReport（0x0C）**：I2C 扫描契约（0x01-0x7F 地址 + 发现地址列表上行）。
- **ResourceReport field 8 / ConfigManifest field 5**：DMA 通道资源上报与配置下发（见[DMA资源管理设计.md](DMA资源管理设计.md)）。
- **WS**：终端流事件与通用事件共用 `/api/v1/ws`（`?token=` 会话校验，见[认证授权.md](认证授权.md) §5.2）。
- **控制域边界**：通道直写属**诊断/收紧路径**（生产 410）；受控操作一律走[边缘设备控制.md](边缘设备控制.md)。

## 8. 已知限制与债务

| 限制/债务 | 说明 |
|-----------|------|
| hardware_type 大小写坑（实机记录） | 后端存储为**大写**（SPI/I2C/UART/ADC，ToUpper 归一），前端必须 `toLowerCase()` 后才能与 `Parser.hardware_types`（契约小写）及表单值比较——ChannelManager/parser.ts 均已按此实现；任何新前端比较点须复读此坑，否则类型匹配静默失败 |
| hardware_id 语义 | 通道与边缘设备都存 hardware_id（VARCHAR：地址/名称/""），以应用层约定为准（见[边缘设备.md](边缘设备.md) §2.1）；无独立跨表外键 |
| SPI/GPIO/ADC 扫描未实现 | SPI 扫描、外设扫描 P3 未做；扫描能力以 I2C + Modbus 为界 |
| 通道冲突检测增强 | DMA 冲突自动降级（P2）未完成，资源池降级策略受节点端三级分配约束 |
| bus_config 双格式 | 引脚路由为 hex 编码透传（前端展示/编辑约束多）；JSON 与 hex 两态并存，无统一 schema |
| ~~reconfigure 端点语义浅~~ **2026-09-16 已修复（且原描述低估了严重性）** | 原文说「返回占位 status，实际物理重配经 Manager 下发链落地」——**实测并非如此**：端点只做 `ShouldBindJSON` 后直接返回 `{"status":"reconfigured"}`，**既不解析 baudrate、也不查通道、更不下发**；而前端「修改波特率」对话框会提示**「重配置命令已发送」** ⇒ 用户以为硬件已改，**实际什么都没发生**（**谎报成功**）。**修法**：按 UART `bus_config` 的真实 hex 布局（波特率在字节 2..5 big-endian，与 `nodemgr/handler_channel_cmd_v2.go` 的 `set_baud_rate` 同布局）改写、写库、并 `EmitConfigChange` 触发下发；同值时返回 `status=unchanged` 而非谎称已改；`clock_hz`（SPI）显式 **501**；非 UART **400**；坏 hex **400**。回归测试 `internal/api/channel_reconfigure_test.go`（5 用例），变异自证：跳过写库 ⇒ 红。**剩余边界**：仍无端到端确认闭环（下发结果不回执到本端点）。 |
| 直写门禁依赖控制策略 | rawWritesEnabled 关闭时终端与直写均 410；审计覆盖以[边缘设备控制.md](边缘设备控制.md)台账为准 |
| 终端历史为内存滚动 | TerminalMgr 历史不持久化，重启清空（调试场景可接受） |

> **修复记录**（文档体系 v3.4 重建时核对）：GPIO/ADC 共栖段落已随 v3.0 GPIO 剥离移除；`bus_type=4 GPIO` 等历史数字枚举仅存活于存量行兼容注释，已不在任何设计流程中产生。
