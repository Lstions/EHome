## 1. 系统定位与用户

### 1.1 定位

家庭数字化 IoT 平台：通过 ESP32 边缘节点采集多协议传感器/电池/逆变器数据，中心端（Go）统一管理、存储与可视化，并支持远程控制与固件升级。

### 1.2 三层模型（需求作用对象）

| 层 | 说明 | 需求视角 |
|----|------|---------|
| 中心端 (Center) | Go 后端 + Web 前端，业务核心 | 人机交互的全部功能面 |
| 节点 (Node) | ESP32-S3/C6 物理整机 | 接入、采集执行、资源上报、OTA 受体 |
| 边缘设备 (EdgeDevice) | 节点+通道+设备配置三元组实例 | 采集、控制、数据归属 |

### 1.3 用户角色

- **单主体模式**：唯一管理员（AuthenticateSingleUser），所有菜单仅由登录态保护。
- **访客**：未登录仅可访问登录页与初始化引导页。

## 4. 非功能需求（摘要）

| 类别 | 需求 | 来源 |
|------|------|------|
| 容错 | Fail-open：未知 wire code / 配置失败退避重试 / 中心端重启 push 兜底 / 节点周期 sync 兜底 | 总体设计 §4.2 |
| 安全 | JWT + 登录锁定 + bcrypt；OTA TLS 不可降级；写操作限管理员 | 总体设计 §4.4 |
| 性能 | 入库延迟 P99 ≤200ms；CRUD→节点生效 P99 ≤5s；SyncGate P99 ≤1ms；MQTT ≥100 msg/s | 总体设计 §6 |
| 部署 | 单机 Docker 单容器（v3.4 起 4 服务→3：去 Redis）；≥10 节点扩展路径 | 架构优化实施计划 |

## 5. 明确不做（非目标，持续有效）

- 多用户/多角色管理界面（单主体模式是产品决策）。
- GPIO/PWM 走通道系统（v3.0 裁决）。
- 中心端硬编码任何型号的 GPIO/PWM/UART 资源（必须来自 ResourceReport）。
- 微服务化、protobuf/gRPC、多租户、K8s（家庭规模无收益）。
