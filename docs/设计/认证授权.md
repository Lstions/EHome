> **日期**: 2026-08-22
> **关联**: [总体设计.md](总体设计.md) | [术语表.md](术语表.md) | [节点.md](节点.md) | [../操作/认证与账户运维指南.md](../操作/认证与账户运维指南.md)

## 1. 功能概述与端点

系统采用**唯一管理员主体认证（单主体）**模式，不再提供多用户 CRUD 与角色权限矩阵：旧 RBAC 三级角色（admin/operator/viewer）已从 UI 移除，`role` 列仅在 API 层保留 `admin` 语义。核心安全原则：**单用户 ≠ 无鉴权**——除公开白名单外，全部 REST 与 WebSocket 必须经过有效会话认证，且每次请求都对照数据库权威状态复核。

- 身份与状态：`subject_key = system_admin` 是唯一可登录主体；`AuthState`（`system_auth` 行）是系统认证状态权威。
- 会话撤销：JWT 携带会话版本 `sv`；改密 / logout / logout-all 原子递增 `session_version`，全部旧 Token 立即失效。
- 登录限流：进程内滑动窗口限流（5 次失败 / 15 分钟窗口，v3.4 无 Redis）。
- 初始化：全新数据库不 seed 默认账户，走 `ehomectl` 引导 + 一次性初始化凭据流程。

### 1.1 端点

公开端点（无 JWT；backend/internal/api/routes.go）：

| 端点 | 方法 | 说明 |
|---|---|---|
| `/health` | GET | 健康检查 |
| `/metrics` | GET | Prometheus 抓取（仅计数标签，无载荷/PII） |
| `/api/v1/auth/initialization` | GET | 查询 AuthState；`uninitialized` 时顺手落库状态行 |
| `/api/v1/auth/initialize` | POST | 用一次性初始化凭据创建唯一管理员（仅在 `uninitialized` 可用） |
| `/api/v1/auth/login` | POST | 登录（限流保护） |
| 固件下载路由 | GET | ESP32 无 JWT 拉取（部署边界须另做隔离/签名） |

受保护端点（`/api/v1` 组统一挂 `JWTAuthWithDB`，按主体有效会话校验）：

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v1/account` | GET/PATCH | 查看/更新用户名、邮箱 |
| `/api/v1/account/password` | POST | 改密（成功后旧 Token 全部失效，返回 `reauthenticate:true`） |
| `/api/v1/account/reauthenticate` | POST | 会话内再认证（与登录共用限流） |
| `/api/v1/account/logout-all` | POST | 撤销该主体全部会话 |
| `/api/v1/auth/logout` | POST | 同 logout-all |
| 旧 `/api/v1/users/**` | — | 认证后一律返回 **410 Gone**（兼容期） |

## 2. 数据模型

### 2.1 用户（models.User，backend/internal/models/models.go）

```text
users 表（兼容期保留表名）：
  id                SERIAL PK          -- 主体 ID（JWT sub 用数字 ID）
  username          VARCHAR            -- 可配置，不作为权限依据
  password_hash     VARCHAR            -- bcrypt（DefaultCost）强哈希
  email             VARCHAR
  role              VARCHAR            -- 恒为 "admin"（API 层兼容语义）
  enabled           BOOLEAN            -- 仅 AuthState=initialized 时决定能否登录
  subject_key       VARCHAR            -- 活动主体固定 "system_admin"
  session_version   INTEGER            -- 会话代际（≥1，JWT sv 来源）
  password_changed_at TIMESTAMP
  initialized_at    TIMESTAMP
  last_login_at     TIMESTAMP
  retired_at        TIMESTAMP NULL     -- 历史账户归档标记；非 NULL 一律不能登录
```

不变量：任一时刻**有且仅有一个活动主体**（`subject_key=system_admin AND retired_at IS NULL`）；初始化时以事务强制单行约束；历史账户退休后保留审计关联但禁止登录。

### 2.2 认证状态（models.AuthState，backend/internal/models/auth_state.go）

```text
key = "system_auth"（SystemAuthStateKey）——固定单行：
  state: uninitialized | initialized | migration_required | disabled
  security_version, initialized_at, created_at, updated_at
```

- 缺行视为全新安装：`LoadAuthState` 返回合成 `uninitialized` 不落库；落库只由 `GET /initialization`、`ehomectl auth bootstrap-database` 或服务启动引导路径显式完成。
- 认证校验硬条件：`AuthState == initialized`，否则所有会话无效。运行时请求不得自行修复缺失行。

### 2.3 初始化令牌（models.InitializationToken）

一次性凭据：`id`、随机 `credential`（VerifyInitializationCredential 校验，错误容忍度 5）、`expires_at`（CLI 生成默认 10 分钟）、`consumed_at`。使用条件：AuthState 为 `uninitialized`、令牌未消费、未过期、无活动主体；成功即标记 `consumed_at` 并永久关闭初始化入口。

## 3. 状态机

### 3.1 AuthState 生命周期

```text
（全新库，无行）
   │ ehomectl auth bootstrap-database / GET /initialization
   ▼
uninitialized ── POST /initialize（一次性凭据）──► initialized
   │                                                  │
   │ 旧版数据库检测（升级场景）                          │ 运维动作
   ▼                                                  ▼
migration_required ◄──────────────（禁用登录，走迁移指南）   disabled（停止签发/校验）
```

- `uninitialized`：只有 `GET /initialization`、`POST /initialize` 可用；登录一律 401。
- `migration_required`：旧库升级未完成单主体迁移时的状态，完整步骤见 [../操作/认证与账户运维指南.md](../操作/认证与账户运维指南.md)。
- `disabled`：管理员运维性停用认证，全部会话校验失败。

### 3.2 账户登录可行性

`enabled=true` 且 `retired_at IS NULL` 且 AuthState=initialized 才可登录；任一不满足即 401（错误信息不暴露具体原因）。

## 4. 关键流程

### 4.1 管理员初始化（一次性）

```text
1. ehomectl auth bootstrap-database   # 前置：users 计数=0 且 state=uninitialized，创建 system_auth 行
2. ehomectl auth create-initialization-token   # 输出一次性凭据（10min 内有效）
3. POST /api/v1/auth/initialize {credential, username, password, email}
     └─ 事务内：校验 uninitialized → 校验令牌未消费未过期 → 无活动主体
        → bcrypt 存密码 → 建 subject_key=system_admin、SessionVersion=1、Role=admin、Enabled=true
        → 标记令牌 consumed_at → 写审计 auth.initialized → state=initialized
```

成功后入口永久关闭；`initialize` 再次调用返回 409 `AUTH_INITIALIZATION_REJECTED`。密码最小长度 8；审计不记录密码与完整一次性令牌。

### 4.2 登录 / 再认证

```text
POST /api/v1/auth/login {username, password, remember_me}
  ├─ 认证失败 → limiter.AllowFailure(IP, username)
  │     ├─ 超限 → 429 + Retry-After（进程内滑动窗口，5 次/15min，IP 与用户名双键）
  │     └─ 未超限 → 401 "用户名或密码错误"（登录接口 401 不清会话不跳转）
  └─ 认证成功 → limiter.Reset → SignSessionToken（TTL：24h；remember_me 7d）
        → 200 {token, user}
```

`/account/reauthenticate` 复用同一限流器与鉴权逻辑；**坏密码不会吊销仍然有效的会话**，调用方可在限流窗口内重试。

### 4.3 会话验证（每次请求）

```text
JWTAuthWithDB（middleware.go，挂 /api/v1 全部路由）
  ├─ 提取 Bearer header 或 ?token=（WS 场景）
  ├─ ParseSessionToken：HS256 强制、iss=ehome、aud=ehome-api；sub/iat/exp/jti/sv 齐备
  └─ ValidateSessionClaims（对照 DB）：
       AuthState==initialized
       AND user(id=sub AND subject_key=system_admin AND retired_at IS NULL AND enabled=true)
       AND user.session_version == claims.sv       ← 改密/登出后旧 Token 立即失效
  → ctx 注入 subject_id / session_version / token_expires_at / token_jti
```

### 4.4 撤销

`POST /account/password`（改密）与 logout / logout-all 均**原子递增 `session_version`**，随后全部旧 Token（含其他端）在下一请求即 401；改密成功后返回 `reauthenticate:true`，前端引导重新登录。

### 4.5 初始化之外的主机本地命令

- `ehomectl auth bootstrap-database`：空库创建 `system_auth` 行（拒绝已存在用户/已初始化）。
- `ehomectl auth create-initialization-token`：生成一次性凭据（仅 uninitialized）。
- `ehomectl auth reset-password`：`EHOME_NEW_ADMIN_PASSWORD`（≥12 字符）主机本地重置，并吊销现存会话。

## 5. 协议与外部契约

### 5.1 前端契约

- 登录串用 Pinia user store；Token 存储：remember_me → localStorage，否则 sessionStorage。
- 401 分类（frontend-shared/src/api/client.ts）：**非登录接口** 401 且存在本地会话 → 清 Token 跳 `/login`；**登录接口** 401 保留当前页并把错误信息展示给用户（用例见 `client.spec.ts`）。
- 路由守卫（src/router/index.ts）：`requiresAuth` 路由未登录 → 跳 `/login?redirect=...`；已登录访问 `/login` → 跳 `/dashboard`。
- 登录锁定 UI（src/utils/loginLockout.ts）解析 429/Retry-After 展示倒计时。
- 前端不再渲染角色标签、用户管理、`v-permission`、`/403` 角色分支（已移除）。

### 5.2 WebSocket 契约

```text
升级前：URL 携带 ?token=<jwt>，经 JWTAuthWithDB 校验（同 REST 契约）
HandleWebSocket：从 gin ctx 写入 Client{SubjectID, SessionVersion, ExpiresAt, JTI}
  ├─ SubjectID==0 → 直接拒绝升级
  └─ Hub.SetSessionValidator(fn) 复核会话（DB 权威）：发送敏感命令前检查
     撤销（改密/登出）后该主体连接按会话代际断开
```

连接不读取 role；通用与终端 WebSocket 共用同一单主体会话语义。

### 5.3 节点侧契约

- ESP32 / MQTT broker 会话**不持有 JWT**：节点身份由 EMQX ACL 绑定（`nodes/${clientid}/up`/`down`，见 [节点.md](节点.md) §5.1），中心端以 topic 路由身份，与 HTTP 会话域正交。
- 固件下载端点免鉴权设计上供节点拉取，生产部署须以签名 URL/网络隔离收紧。

## 8. 已知限制与债务

| 限制/债务 | 说明 |
|---|---|
| 限流为进程内实现 | Redis 已退役（方案 v3.4 §4 任务B），滑动窗口存内存；重启清零可接受（窗口仅 15 分钟），多实例部署需分布式实现 |
| 恢复口令仅主机本地 | `reset-password` 依赖本机环境变量，不提供远程无会话入口（有意为之）；运维步骤见迁移与运维指南 |
| 初始化凭据一次性 | 凭据丢失且 AuthState 仍 uninitialized 时可重新生成；一旦 initialized 无该恢复通道 |
| 审计广度 | 登录/改密等事件审计链路在单主体迁移后持续扩展中，覆盖清单以运维指南为准 |
| role 列残留 | API 层保留 `role=admin` 兼容语义，后续数据库版本逐步裁撤 |
| 429/401 前端文案 | 后端统一"用户名或密码错误"与 429 的 Retry-After 到 UI 的倒计时逻辑由 `loginLockout.ts` 负责，多语言化不在本版范围 |
| 固件下载免鉴权 | 属部署边界问题，未在代码层收紧（详见 §5.3） |
