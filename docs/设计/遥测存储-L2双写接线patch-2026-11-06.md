## 1. 目标（一句话）

把「解析成功的一帧」额外编码进 `telemetry_frame`。**默认关闭**，开启后失败不影响主写入。

L2 侧已全部实现并测试通过（`backend/internal/telemetry/`）。本 patch 只改 `backend/internal/databus/consumers_heavy.go` 一个文件、共 3 处、约 12 行 + 注释。

---

## 2. 为什么要接在「解析成功路径」而不是「写库成功分支」

这是本 patch 唯一的**设计判断**，请勿按直觉改成"写库成功后再双写"：

| 接法 | 后果 |
|---|---|
| ❌ 接在 `Create(&records)` 成功的 else 分支里 | L1 开启 `write_on_change` 后，**被跳过的帧不进帧表** ⇒ 帧表的增量链出现空洞。⌈每设备每 slot 最多 60s 一个关键帧⌉，60s 内的变化值**永久丢失**（不是压缩损失，是数据损失）。 |
| ✅ 接在解析成功处（`now` 算好之后、写库之前） | 帧表记录的是**设备真实采样**，与 L1 是否跳过入库完全解耦。L1 决定"旧表写哪些行"，L2 决定"这一帧怎么编码"——方案 §2 明说「L1 与 L2 不是二选一」。 |

同理适用于 L3 rollup 的旁路聚合：**它也必须挂在解析成功路径上**（否则跳过入库的帧不会进分钟桶，rollup 的 avg/min/max 会漏掉真实样本）。两处可以写在同一个位置、共享同一批 `readings`，一次改完。

## 3. 精确改动（3 处）

### 3.1 导入（`consumers_heavy.go:3-20` 的 import 块）

### 3.2 结构体字段 + setter（`consumers_heavy.go:133` 起；setter 加在 `:259` 附近，`HasSourceHealthSink` 之前）

```go
type SensorParserConsumer struct {
	// ...既有字段保持不动...

	// telemetrySink 是 L2 帧级编码的双写旁路（设计/遥测存储-L2双写接线patch-2026-11-06.md）。
	//
	// nil 安全：未接线时整条旁路不存在，行为与改造前逐字节相同。
	// 接线方构造方式：telemetry.SinkOrNil(dualWriter) —— 开关关闭时得到 nil。
	telemetrySink telemetry.Sink
}

// SetTelemetrySink 注入 L2 双写旁路（方案 §7 阶段 2 第 2 步）。
//
// 为什么是 setter 而不是构造函数参数：与既有 4 个 Set*Sink 同一范式
// （SetLatestSink / SetAlertSink / SetAutomationSink / SetSourceHealthSink）。
// 为什么默认 nil：双写默认关闭，由 EHOME_TELEMETRY_DUAL_WRITE 控制；
// 未开启时必须完全零成本（不要在这里做任何构造/查库）。
func (c *SensorParserConsumer) SetTelemetrySink(sink telemetry.Sink) {
	c.telemetrySink = sink
}
```

### 3.3 调用点（`consumers_heavy.go:397` `now := time.Now()` 之后、`records` 构造之前）

```go
	now := time.Now()

	// ============ L2 双写旁路（方案 §7 阶段2 第2步）============
	// 接在**解析成功路径**上，而不是写库成功分支：L1 开启 write_on_change 后，
	// 被跳过入库的帧仍然是一次真实采样，必须进帧表（否则增量链出现空洞，
	// 60s 内的变化值永久丢失）。见 patch 文档 §2 的对照表。
	//
	// 三条不变量：
	//   1. sink 为 nil ⇒ 完全跳过（默认关闭，零成本）；
	//   2. sink 内部是**有界队列 + 异步落库**，绝不阻塞本函数、绝不反压采集；
	//   3. sink 失败（编码/落库）只计数 + 日志，不返回错误、不影响主写入。
	// 因此这里不需要 defer/recover，也不需要判返回值。
	if c.telemetrySink != nil && len(sensorData) > 0 {
		readings := make([]telemetry.Reading, len(sensorData))
		for i := range sensorData {
			readings[i] = telemetry.Reading{Name: sensorData[i].Name, Value: sensorData[i].Value}
		}
		c.telemetrySink(device.ID, now, int64(evt.CommandTemplateID), readings)
	}
```

> **注意 `now` 的口径**：必须是 `unified_data.timestamp` 用的**同一个** `now`（此处正是它）。
> 两张表时间戳不同源的话，影子校验（逐帧比对 解码值 vs unified_data 值）会全量误判。

## 4. main.go 的装配（`cmd/server/main.go`，可与 rollup 装配合并）

放在 `database.AutoMigrate()` 与分区迁移之后、`nodemgr.NewManager(...)` 之前：

```go
	// L2 帧级编码双写（方案 §7 阶段2）：默认关闭（EHOME_TELEMETRY_DUAL_WRITE=false）。
	// 表由 partition_mgr 建（partitionParentDDL 已登记 telemetry_frame），
	// 因此这里只做"构造 + 注入"，不建表。
	var telemetryDual *telemetry.DualWriter
	{
		dict := telemetry.NewDBSlots(db)
		if err := dict.WarmUp(); err != nil {
			logger.Warnf("telemetry: slot warmup failed (dual write degraded): %v", err)
		}
		telemetryDual = telemetry.NewDualWriterFromEnv(db, dict)
		if telemetryDual != nil {
			defer telemetryDual.Close()
			logger.Infof("telemetry: L2 dual write ENABLED (frames go to telemetry_frame; old tables unchanged)")
		}
	}
```

注入点（`nodeMgr.SetLatestSinkFn(...)` 之后即可，nodemgr 内部会推给所有 shard consumer）：

```go
	// 若 nodemgr 尚无该方法，按既有 SetAlertEvaluator 的范式加一个透传：
```

## 5. 开启前置条件（缺一不可）

| # | 条件 | 为什么 |
|---|---|---|
| 1 | 先跑过一次启动（或手工执行 `datalifecycle.MigrateTableToPartitioned(db, "telemetry_frame", "telemetry_frame_legacy")`） | 表不存在时 `NewDualWriter` 返回 `ErrTablesMissing`，`NewDualWriterFromEnv` 打 Warn 后返回 nil ⇒ **安静不双写**，不报错。 |
| 2 | `EHOME_TELEMETRY_DUAL_WRITE=true` | 默认 false。开关关闭时 `NewDualWriterFromEnv` 直接返回 nil，零成本。 |
| 3 | 磁盘余量（方案 §7 阶段 0 先腾 ≥6 GB） | 双写期两份数据并存。 |
| 4 | `EHOME_TELEMETRY_HEARTBEAT_SECONDS`（默认 60）与 L1 同源 | 关键帧间隔即增量链的最大错位窗口（§8）。 |

观测（`telemetry.DualWriter.Stats()`）：`Encoded` / `Dropped` / `Failed` / `PayloadSum`。
**影子校验要求 Dropped == 0 且 Failed == 0**（Dropped > 0 说明落库跟不上采集；Failed > 0 说明编码或写库有问题）。

## 6. 与 L3 rollup 接线的关系

两处**必须挂在同一位置**（解析成功、`now` 之后）：

```go
	now := time.Now()
	// L2 帧级编码（本 patch）
	if c.telemetrySink != nil && len(sensorData) > 0 { ... }
	// L3 分钟桶旁路聚合（reviewer 的接线，同样在这里）
	if c.rollupSink != nil && len(sensorData) > 0 { ... }
```

原因相同：**跳过入库的帧仍是真实采样**。分两次解决会让第二次改动又要重新理解 L1 的门控语义。

## 7. 不要做的事（防回归）

- ❌ 不要在 `SensorParserConsumer` 里直接 `import gorm` 写 frames 表 —— 那会让 databus 直接依赖帧表 schema。
- ❌ 不要把 sink 调用放进 `if err := c.db.Create(...); err != nil { } else { ... }` 分支。
- ❌ 不要在 sink 里做同步 DB 写 —— `DualWriter.Observe` 已经保证非阻塞；若未来替换实现，这条不变量必须保持。
- ❌ 不要复用 `sensorData` 切片传引用给异步侧：本 patch 已逐元素拷贝成 `[]telemetry.Reading`。
