# 系统监控 — 详细设计

## 1. 功能概述

系统监控 (Monitor) 面向管理员 (admin only), 展示服务自身的健康状态 + 资源使用 + 业务指标。

## 2. 端点

| 端点 | 方法 | 权限 |
|------|------|------|
| `/api/v1/overview` | GET | admin |
| `/api/v1/metrics/summary` | GET | admin |
| `/api/v1/metrics/prometheus` | GET | (无 auth, 给 Prometheus 抓取) |

## 3. 指标 (Metrics)

### 3.1 业务指标
- 采集器总数/在线/离线
- 设备总数/在线
- 今日数据点
- OTA 进行中/成功/失败
- 通知数 (未读/总计)

### 3.2 资源指标
- CPU 使用率 (Prometheus process)
- 内存使用
- 协程数
- DB 连接池
- Redis 连接
- MQTT broker 连接

### 3.3 Prometheus
- `/api/v1/metrics/prometheus` 标准格式
- 配置 scrape_interval=15s
- Grafana dashboard (P3)

## 4. 容错设计

| 场景 | 行为 |
|------|------|
| DB 查询超时 | 返回缓存值 + WARN |
| Redis 不可达 | 跳过缓存, 直查 DB |
| Prometheus 端点异常 | 不影响主业务 |
| 指标聚合慢 (>5s) | 超时返回部分结果 |

## 5. 可观测性

> 监控系统自身的可观测性是元级别的。

| 事件 | 字段 |
|------|------|
| `monitor.metrics_collected` | duration_ms, success_count |
| `monitor.health_check` | component, status, latency_ms |

| 指标 | 类型 | 标签 |
|------|------|------|
| `ehome_monitor_scrape_duration_seconds` | histogram | - |
| `ehome_monitor_health_status` | gauge | component |
