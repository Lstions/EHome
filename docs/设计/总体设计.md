## 1. 系统架构 (v2.2 三层模型)

### 1.1 中心端 / 节点 / 边缘设备 (v2.2 重定义)

```
┌─────────────────────────────────────────────────────────────────────┐
│                          平台层 (Platform)                            │
│  EHomeSystem 整个系统, 跨节点集中管理                                  │
└─────────────────────────────────────────────────────────────────────┘
                              ▲
┌─────────────────────────────┴───────────────────────────────────────┐
│                          中心端 (Center)                             │
│  Go 1.23 + Gin + GORM + PostgreSQL + Redis + Mosquitto                │
│  - 节点 (Node) 管理: 列表/状态/OTA                                    │
│  - 设备配置 (Device Config) 管理: 型号定义/init_flow/parser          │
│  - 边缘设备 (Edge Device) 管理: 实例化/状态/操作                      │
│  - 业务核心: ConfigEventBus + SyncGate (v2.1 同步)                  │
│  - MQTT broker: nodes/{id}/up|down/v2                               │
│  - WebSocket: node_status / edge_device_data / ...                  │
│  - Prometheus + 结构化日志 + sync_id 链路追踪                        │
└─────────────────────────────────────────────────────────────────────┘
                              ▲ MQTT + HTTP
┌─────────────────────────────┴───────────────────────────────────────┐
│                          节点 (Node) [v2.2]                          │
│  ESP-IDF v5.x + FreeRTOS                                             │
│  - 12 个 component (+ sync_manager v2.1)                            │
│  - 5 种硬件总线 (UART/I2C/SPI/GPIO/ADC)                              │
│  - 通道 (Channel) 物理端点: 引脚/速率/模式                            │
│  - 边缘设备 (Edge Device) 逻辑抽象: parser/interval/init_flow        │
│  - OTA HTTPS (Mozilla CRT bundle, v2.1)                             │
│  - 周期 sync task (60s 检查, 10min ConfigQuery)                      │
└─────────────────────────────────────────────────────────────────────┘
                              ▲ 总线 (UART/I2C/SPI/GPIO/ADC)
┌─────────────────────────────┴───────────────────────────────────────┐
│                          边缘设备 (Edge Device) [v2.2]               │
│  物理传感器 / 执行器 (BMP280/SHT30/SN3000/继电器/...)                │
│  - 数据采集 (周期性)                                                  │
│  - 远程操作 (PWM/雨量/重置/...)                                      │
│  - 通过节点的通道接入                                                 │
└─────────────────────────────────────────────────────────────────────┘
```

> **关键概念区分** (v2.2):
> - **节点 (Node)**: 物理整机 (ESP32)
> - **通道 (Channel)**: 节点的物理通信端点 (UART/I2C/SPI/GPIO/ADC)
> - **设备配置 (Device Config)**: 一种设备型号的协议无关定义
> - **边缘设备 (Edge Device)**: 节点 + 通道 + 设备配置 三元组的实例化
> - 完整定义见 [00-术语表.md](00-术语表.md)

## 2. 核心数据流

### 2.1 节点接入流 (v2.2 命名)

```
Node (ESP32) 上电
  ↓
[sync_manager] init
  ↓
[wifi_mgr]  连接 WiFi
  ↓
[msg_handler]  发 Hello (type=0x01) — v2.1 字段:
  - node_id (v2.2 字段名, 数值同 v2.1 device_id)
  - firmware_version, model, channel_count
  - config_epoch, nvs_has_config, last_manifest
  - protocol_version = "2.2"
  ↓ (MQTT up: nodes/{id}/up/v2)
[center/node/handler_v2] 收 Hello
  ├─ 解析 + upsert nodes 表
  ├─ **SyncGate.OnHello()** 决策 (v2.1)
  │     ├─ NVS 空 → 强制下发
  │     ├─ Epoch 落后 → 强制下发
  │     ├─ Hash 不匹配 → 强制下发
  │     └─ 否则 dedup 决定
  ├─ 触发 HandleHelloOTACompletion
  ├─ 触发 [offline_detector] 重置离线计时
  ├─ HA Discovery (retained)
  └─ 推 node_status 事件 (v2.2 替代 node_status)
  ↓
[node/manager] 解析 ConfigManifest (含 channels[].edge_devices[])
  └─ 写 NVS + 启动 edge_devices 采集
```

### 2.2 数据采集流 (v2.2 节点+边缘设备)

```
[scheduler] 周期触发 (每 edge_device.interval_ms)
  ↓
[bus] 读物理层 (I2C/SPI/UART/...)  ← 由 channel.bus_config 决定
  ↓
[parser] 解析 raw_data → 物理量      ← 由 edge_device.parser_id 决定
  ↓
[msg_handler] 打包 DataReport (type=0x03)
  - channel_id (= edge_device 对应的 channel_id)
  ↓ (MQTT up: nodes/{id}/up/v2)
[center/node/handler_v2] 收 DataReport
  ├─ 解析 raw_data (使用 device_config.parser.id)
  ├─ 写 unified_data 表 (关联 edge_device_id)
  ├─ 推 edge_device_data 事件
  └─ 触发 [dataSource/healthy] 记录
```

### 2.3 边缘设备创建流 (v2.2 新流程)

```
前端 → POST /api/v1/edge-devices
       { name, node_id, channel_id, device_config_id, hardware_id, interval_ms }
  ↓
[center/api/handler_edge_device.go]
  1. 验证 node / channel / device_config 存在
  2. 验证 (node, channel, hardware_id) UNIQUE
  3. 创建 edge_devices 记录
  4. **EmitConfigChange** (v2.1 G1 修复)
  ↓
[SyncGate] fanout 到 online 节点
  ↓
[Node] 收到 ConfigManifest
  └─ 解析 channels[].edge_devices[] 列表
  └─ 启动该 edge 的 scheduler task
  └─ 触发 init (如果 device_config.init_flow 存在)
       └─ InitDevice (sendAndWait, v2.1 G6 修复)
  └─ 发 ConfigResult
  ↓
[center] 推 node_config_synced + edge_device_status 事件
```

### 2.4 OTA 升级流 (v2.1 HTTPS + SHA256)

```
前端 → POST /api/v1/ota/tasks {node_id, firmware_id}
  ↓
[center/api/handler_ota] 创建 OTA 记录
  ↓
[ota/manager] 发 OtaCommand (0x0A) 含 SHA256
  ↓
[Node/ota] HTTPS 下载 (Mozilla CRT bundle)
  ├─ TLS 验证 (不再 skip)
  ├─ 期间发 OtaProgress (0x0B)
  └─ 完成: esp_partition_get_sha256() → 校验 → finish + restart
  ↓
[Node 重启 → Hello] → HandleHelloOTACompletion 标 success
```

### 2.5 配置同步流 (v2.1 多通道)

**所有配置同步入口走 SyncGate 同一管道**:

```
                        ┌─────────────────────────────────┐
                        │   ConfigEventBus (Go chan)      │
                        │   + EpochGenerator (DB 持久化)   │
                        └────────────────┬────────────────┘
                                         │
   ┌────────────────────┬────────────────┼────────────────┬──────────────┐
   ↓                    ↓                ↓                ↓              ↓
┌─────────┐      ┌─────────────┐  ┌──────────┐   ┌──────────┐  ┌──────────┐
│   CRUD  │      │  Server     │  │  Hello   │   │  Status  │  │ Config   │
│ Handler │      │  Startup    │  │ (节点)   │   │  Report  │  │  Query   │
└────┬────┘      └──────┬──────┘  └─────┬────┘   └─────┬────┘  └─────┬────┘
     │                  │               │              │              │
     └──── EmitChange ──┴── OnStartup ──┴── OnHello ──┴── OnStatus ──┴── OnQuery
                              ↓
                    ┌──────────────────┐
                    │     SyncGate     │ (统一决策中心)
                    └────────┬─────────┘
                             ↓
                  m.SendConfigManifest(deviceID, with sync_id)
                             ↓
                            MQTT
                             ↓
                    Node config_mgr_apply_manifest()
```

## 3. 协议规范 (v2.2)

### 3.1 协议层定位

EHomeSystem v2.0 **完全废弃** v1.x 的 protobuf 协议, 采用精简**二进制帧**:
- 体积: ~50 字节 vs protobuf ~150 字节 (-67%)
- 解析: 手写 decode (~200ns) vs protobuf 反射 (~10μs) (-50x)
- 可调试: 16 进制 dump 可读
- 缺点: 不向后兼容 (v1.x 不可升级, 必须烧 v2.0 固件)

**v2.2 在 v2.0/v2.1 基础上扩展, 向后兼容** (v2.2 节点 + v2.1 中心端 降级路径 OK)

### 3.2 帧格式 (Frame Format) - 不变

```
┌──────────┬──────────┬──────────────┬─────────────────┐
│ Magic 1B │ Length 2B│ Type 1B      │ Payload N-4B    │
│ 0xEB     │ LE uint16 │ see §3.3     │ type-specific   │
└──────────┴──────────┴──────────────┴─────────────────┘
```

### 3.3 消息类型 (20 种, v2.2 兼容 v2.0/v2.1)

| Type | 名称 | 方向 | 用途 | 版本 |
|------|------|------|------|------|
| 0x01 | Hello | Node→Center | 上线握手 (v2.1 加 epoch/nvs_has) | v2.0+ |
| 0x02 | StatusReport | Node→Center | 心跳 (v2.1 加 epoch) | v2.0+ |
| 0x03 | DataReport | Node→Center | 采集数据 (channel_id) | v2.0+ |
| 0x04 | ConfigManifest | Center→Node | 配置下发 (channels[].edge_devices[] v2.2) | v2.0+ |

| 0x06 | WriteCommand | Center→Node | 远程操作 | v2.0+ |

| 0x08 | Ping | 双向 | 延迟测量 | v2.0+ |
| 0x09 | Pong | 双向 | 延迟响应 | v2.0+ |
| 0x0A | OtaCommand | Center→Node | 固件升级 | v2.0+ |

### 3.4 MQTT Topic 设计 (v2.2 + v2.1 兼容)

| Topic | 方向 | 用途 | 版本 |
|-------|------|------|------|
| `nodes/{node_id}/up/v2` | Node→Center | 上行 (v2.2 命名) | v2.2 |
| `nodes/{node_id}/down` | Center→Node | 下行 (v2.2 简化) | v2.2 |
| `devices/{device_id}/up/v2` | Node→Center | 上行 (v2.1 兼容, 6 个月) | v2.1 |
| `devices/{device_id}/down/v2` | Center→Node | 下行 (v2.1 兼容) | v2.1 |

> **关键**: v2.2 节点用 `nodes/...` topic, v2.1 节点继续用 `devices/...` topic, 中心端双订阅, 灰度 6 个月

### 3.5 协议变更流程 (v2.2 强化)

任何对 frame / message format 的修改必须:
1. 在 [总体设计 §3.3](#33-消息类型-20-种-v22) 表里更新
2. 在 [同步机制/详细设计 §3](同步机制/详细设计.md) 详细定义新字段
3. 标注版本 (v2.0+ / v2.1+ / v2.2+) 和兼容性
4. 在 CI 中验证: `scripts/check_protocol_fields.sh`

### 4.2 容错设计 (Fail-Open, v2.1+v2.2 强化)

| 场景 | 行为 | 参考 |
|------|------|------|
| 未知 wire code | WARN + 保留当前状态 | [固件OTA §6.3](固件OTA/详细设计.md) |
| MQTT 帧丢失 | Hello 上线时通过 firmware_version 自动完成 OTA | [固件OTA §6.4.3](固件OTA/详细设计.md) |
| OtaChecksum 长度非 64 | WARN + 跳过 hash 校验 (不卡死) | [固件OTA §6.2](固件OTA/详细设计.md) |
| 同节点并发 OTA | supersede 模式 | [固件OTA §6.4.1](固件OTA/详细设计.md) |
| 配置下发失败 | 退避重试 3 次 + 失败进 notifications | [节点/详细设计 §3](节点/详细设计.md) |
| 节点 90s 无心跳 | offline detector 触发 → 推 node_status 事件 | [节点/详细设计 §6](节点/详细设计.md) |
| WS 连接断开 | 自动重连 + 顶部 banner 提示 | §3 |
| **中心端重启丢内存态** | **启动 5s 后 push 所有 online 节点 (G2 修复)** | **[同步机制 §4.6](同步机制/详细设计.md)** |
| **节点恢复出厂 (NVS 空)** | **SyncGate 检测 nvs_has_config=false → 强制下发 (G3 修复)** | **[同步机制 §4.4](同步机制/详细设计.md)** |
| **ConfigEventBus 缓冲区满** | **drop + alarm** | **[同步机制 §8.1](同步机制/详细设计.md)** |
| **采集器周期 sync 失败** | **退避重试, 下个 60s 周期兜底** | **[同步机制 §5.4](同步机制/详细设计.md)** |
| **设备初始化用 Sleep** | **改用 sendAndWait (G6 修复)** | **[边缘设备 §4.3](边缘设备/详细设计.md)** |
| **边缘设备 NVS 空** | **节点 fallback: 主动查 device_config** | **[边缘设备 §6](边缘设备/详细设计.md)** |

### 4.4 安全设计 (v2.1+v2.2 强化)

## 5. 部署架构

### 5.1 单机部署 (开发/小规模生产)

```

          10-100 个 ESP32 节点
```

## 6. 性能基线 (v2.2 目标)
