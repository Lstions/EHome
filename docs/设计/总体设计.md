## 1. 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                    中心端 (Center)                             │
│  Go 后端（Gin + GORM + PostgreSQL 16）                        │
│  ├─ API 层（REST /api/v1 + WebSocket）                        │
│  ├─ 配置同步：ConfigEventBus + EpochGenerator + SyncGate       │
│  ├─ 数据链：DataEventBus（分片 + 轻重消费者分离）               │
│  ├─ 控制域：Driver Registry + deviceaction + ChannelCmdV2     │
│  ├─ 数据生命周期：datalifecycle（逻辑设备/retention/purge）     │
│  └─ 可观测：结构化日志 + sync_id 追踪 + Prometheus             │
└───────────────┬──────────────────────────────┬────────────────┘
                │ MQTT (nodes/{id}/up|down|control)│ HTTPS (OTA 下载)
┌───────────────▼──────────────────────────────▼────────────────┐
│                     节点 (Node)                                │
│  ESP32-S3 / ESP32-C6 双目标（ESP-IDF, FreeRTOS）               │
│  ├─ 总线：UART/I2C/SPI/ADC（事件驱动 RX，v2.7 动态租约）         │
│  ├─ 外设直控：gpio_ctrl + pwm_ctrl（PeriphCmd/PeriphRsp）       │
│  ├─ 采集：scheduler（逐指令 ConfigManifest）                    │
│  ├─ 控制：ChannelCmdV2（幂等/重放/boot_id 绑定）                │
│  ├─ OTA：HTTPS + SHA256 + A/B + 30s mark-valid                 │
│  └─ 日志流：Log V2（有界 ring + QoS0）                          │
└────────────────────────────────────────────────────────────────┘
```

## 2. 核心数据流

### 2.1 节点接入（Hello 握手 + SyncGate）

```
Node 上电 → Wi-Fi 连接 → 订阅 nodes/{id}/down + control
  → 发 Hello (0x01: node_id, firmware_version, model, channel_count,
                epoch, has_active_manifest, last_manifest, proto_version="2.6",
                handshake_nonce)
  → 中心端收 Hello:
      ├─ upsert nodes 表 + node_id 身份绑定
      ├─ 回 HelloAck (0x12: server_time_ms, features, 同 nonce)
      ├─ SyncGate.OnHello() 决策: NVS空/Epoch落后/manifest不匹配 → 强制下发
      ├─ HandleHelloOTACompletion / offline detector 重置
      ├─ HA Discovery (retained)
      └─ 推 node_status 事件
  → Node 应 QueryResources(0x1A) 或自发 ResourceReport(0x19)
  → 需要配置时中心端发 ConfigManifest(0x04) → Node 事务化应用 → ConfigResult(0x05)
```

### 2.2 数据采集链

```
scheduler（interval_ms 周期）→ bus_worker（事件驱动 RX）
  → DataReport (0x03: channel_id, request_id, edge_device_id, command_index,
                 raw_data, error_code)
  → MQTT up → 中心端 consumers_heavy:
      ├─ 统一解析器 pkg/parser（按 DeviceConfig.parser 规则）
      ├─ unified_data 入库（血缘 edge_device_id + 归属 logical_device_id）
      ├─ WS 推 data_update
      ├─ 告警求值回调（v3.4，SensorParserConsumer 内）
      └─ RollupConsumer 写 1min rollup（v3.4, PG-only）
```

### 2.3 边缘设备创建

```
POST /api/v1/edge-devices {node_id, channel_id, device_config_id, hardware_id, interval_ms}
  → 校验 (channel, hardware_id, type) 唯一
  → 创建并绑定 logical_device
  → EmitConfigChange → SyncGate 下发 ConfigManifest
  → 节点: 事务化应用（挂起 worker → 校验 → 应用 → 激活）
     → 启动 scheduler → init_flow 初始化（sendAndWait）
  → ConfigResult success → 推 node_config_synced + edge_device_status
```

### 2.4 受控操作（ChannelCmdV2 主路径）

```
前端 DeviceControlPanel → 驱动 Action 定义 → dry-run 预览（CompilePlan）
  → POST /edge-devices/:id/operations（Idempotency-Key）
  → deviceaction 九项门禁（catalog available → verifier → CurrentEngineAllows）
  → CommandExecution: Outbox 持久化 → MQTT control topic QoS1
  → Node: 校验（deadline/boot_id/目标资源/重放记录）→ 0x16 ACK → 执行 → 0x17 Final
  → 中心端: 身份四元组去重（command_id+digest+attempt+boot_id）；replayed=1 返回缓存终态
```

### 2.5 配置同步（SyncGate 统一入口）

```
CRUD Handler / Server Startup / Hello / StatusReport / ConfigQuery
        └──► ConfigEventBus ──► SyncGate 决策 ──► SendConfigManifest(sync_id)
                                                  └─► Node config_mgr_apply → ConfigResult
决策矩阵: NVS 空 | Epoch 落后 | manifest 不匹配 | 周期 60s/10min 兜底 → 全量下发
```

### 2.6 OTA 升级

```
POST /ota/tasks → OtaCommand(0x0A: ota_id,url,checksum,size,version,sequence)
  → Node HTTPS 下载（TLS 不可降级）→ SHA256 校验 → OtaProg(0x0B) 进度
  → A/B 分区切换 → 重启 → Hello 上线自动标记完成（frame 丢失兜底）
  → 30s mark-valid；失败自动回滚；同节点并发 supersede
```

## 3. 协议规范

权威定义见 [../协议/二进制帧协议.md](../协议/二进制帧协议.md)。此处只列总体设计约束：

1. **帧格式**：魔数 0xEB + 2B 长度 + 1B 类型 + type-specific payload（protobuf-wire 兼容 varint/length-delimited 编码）。
2. **消息全集**：0x01 Hello, 0x02 StatusRpt, 0x03 DataRpt, 0x04 ConfigMfst, 0x05 ConfigRslt, 0x06 WriteCmd(legacy), 0x07 WriteRsp, 0x08 Ping, 0x09 Pong, 0x0A OtaCmd, 0x0B OtaProg, 0x0C ScanRpt, 0x0D ScanReq, 0x0E QueryReq, 0x0F QueryRsp, 0x10 ConfigQuery, 0x11 ConfigReport, 0x12 HelloAck, 0x13 ConfigSyncReq, 0x14 ConfigSyncRsp, 0x15 ChannelCmdV2, 0x16 ChannelCmdV2Ack, 0x17 ChannelCmdV2Final, 0x18 PongAck, 0x19 ResourceReport, 0x1A QueryResources, 0x1B PeriphCmd, 0x1C PeriphRsp, 0x1D LogStream。
3. **变更流程**：任何字段变更 → 协议文档登记 + version bump + CI `scripts/check_protocol_fields.sh` 校验。
4. **兼容原则**：fail-open 处理未知 wire code；严格拒绝已知字段的 wire type 不符/重复。

## 4. 通用设计

### 4.1 容错设计（Fail-Open / 自愈）

| 场景 | 行为 |
|------|------|
| 未知 wire code | WARN + 保留当前状态 |
| OTA 帧丢失 | Hello 上线时按 firmware_version 自动补完成 |
| 配置下发失败 | 退避重试 + 失败进通知；节点周期 sync 兜底 |
| 节点 90s 无心跳 | offline detector 判离线 + node_status 事件 + notification |
| 节点恢复出厂（NVS 空） | SyncGate 检测 has_active_manifest=0 → 强制下发 |
| 中心端重启 | 启动后 push 所有 online 节点 |
| ConfigEventBus 满 | drop + alarm 指标 |
| 数据消费者过载 | 独立邮箱 + fail-open（丢弃计数暴露为 metrics） |
| x 死元组/日志噪声 | GORM logger IgnoreRecordNotFoundError；死代码 chan 删除 |

### 4.2 可观测性

- **结构化日志**：timestamp/level/component/message/sync_id；关键事件带 event 字段。
- **Prometheus**：ehome_sync_decisions_total、ehome_data_received_total、ehome_event_bus_dropped_total、ehome_edge_device_total 等 15+ 族。
- **WS 事件**：node_status / data_update / edge_device_status / ota_progress / notification / node_config_synced / ping_result。
- **Health**：/health、/overview（平台总览）。

### 4.3 安全设计

| 层 | 措施 |
|----|------|
| API | JWT(HS256) + session_version；登录 5 次失败锁定；进程内限流（v3.4） |
| MQTT | 账号密码 + ACL（节点仅能 pub/sub 自己 topic） |
| OTA | HTTPS + SHA256 + A/B + rollback + 下载一次性票据 |
| 凭据 | bcrypt(cost 10)；单主体唯一管理员 |
| 前端 | 路由守卫 + 401 分类处理；敏感操作后端鉴权 |

### 4.4 数据模型分层

```
视图层(views/) → API 层(handlers) → 业务/服务层(service,
  internal/{nodemgr,datalifecycle,deviceaction,commandexec} → Repository(GORM) → Model
（v3.4 架构优化目标：handler=transport 强制 <300 行/文件，业务下沉 service，渐进实施）
```

## 5. 部署架构

### 5.1 单机（开发/家庭生产，默认）

```
1 台 Linux 服务器
├─ ehome-web 单容器（API + SPA 静态，多阶段构建）
├─ postgres 16（ehome + ehome_test 双库）
├─ emqx（MQTT broker）
└─ redis（v3.4 退役中，进程内化）
```

### 5.2 扩展路径（≥10 节点）

```
多实例 backend 时再引入 Redis（心跳共享）与 broker 集群；接口不变
（当前单实例无共享状态需求，不提前建设）
```
