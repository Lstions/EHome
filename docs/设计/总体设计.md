## 1. 系统架构

### 1.1 三层分离

```
┌─────────────────────────────────────────────────────────────────────┐
│                          展示层 (Presentation)                         │
│  Vue 3 + Vite + Element Plus + Pinia + vue-router                    │
│  - 15 个页面 (Dashboard / Collector / Device / Data / ...)            │
│  - WebSocket 实时事件推送                                              │
│  - JWT 鉴权 (admin/operator/viewer 三级 RBAC)                          │
│  - i18n (zh-CN / en-US)                                               │
└─────────────────────────────────────────────────────────────────────┘
                              ▲ HTTP REST + WebSocket
                              │ (Vite proxy: /api/* → :8080)
┌─────────────────────────────┴───────────────────────────────────────┐
│                          服务层 (Server)                                │
│  Go 1.23 + Gin + GORM + PostgreSQL + Redis + Mosquitto                │
│  - REST API (74+ 端点)                                                │
│  - 业务核心: 状态机 / 持久化 / 协议解析 / 离线检测 / 离线写              │
│  - MQTT broker 中转: devices/{id}/up|down/v2                          │
│  - WebSocket 推送: collector_status / data_update / ota_progress ...  │
│  - Prometheus 指标 + 结构化日志                                        │
└─────────────────────────────────────────────────────────────────────┘
                              ▲ MQTT v3.1.1 QoS 0/1
                              │ (binary frame protocol, 11 种消息)
┌─────────────────────────────┴───────────────────────────────────────┐
│                          采集层 (Edge)                                  │
│  ESP-IDF v5.x + FreeRTOS                                             │
│  - 11 个 component (wifi_mgr / mqtt / frame / scheduler / bus ...)     │
│  - 5 种硬件总线 (UART / I2C / SPI / GPIO / ADC)                       │
│  - OTA 自升级 (A/B partition + 30s mark valid 兜底)                    │
│  - RGB LED 状态指示 (11 种状态)                                        │
│  - FreeRTOS 多任务 + 异步消息队列                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 核心数据流

### 2.1 设备接入流 (Hello 握手)

```
ESP32 上电
  ↓
[wifi_mgr]  连接 WiFi
  ↓
[proto_engine]  发 Hello (type=0x01)
  - device_id, firmware_version, model, channel_count, hardware_types
  ↓ (MQTT up: devices/{id}/up/v2)
[server/mqtt/handler_v2] 收 Hello
  ├─ 更新 collectors 表 (last_seen, firmware_version, status=online)
  ├─ 发 HelloAck (type=0x12) 含 ConfigManifest (type=0x04)
  ├─ 触发 [HandleHelloOTACompletion] (§6.4.3)
  ├─ 触发 [offline_detector] 重置离线计时
  └─ 推 collector_status 事件到前端 WebSocket
  ↓
[device/manager] 解析 ConfigManifest
  └─ 写 device/channels/unified_data
```

### 2.2 数据采集流 (周期性)

```
[scheduler] 定时触发 (每 device.interval_ms)
  ↓
[bus] 读物理层 (I2C/SPI/UART/...)
  ↓
[driver] 解析 raw_data → 物理量
  ↓
[proto_engine] 打包 DataReport (type=0x03)
  - device_id, channel_id, raw_data, parsed_data
  ↓ (MQTT up: devices/{id}/up/v2)
[server/mqtt/handler_v2] 收 DataReport
  ├─ 解析 raw_data
  ├─ 写 unified_data 表
  ├─ 推 data_update 事件到前端
  └─ 触发 [dataSource/healthy] 记录
```

### 2.3 OTA 升级流 (完整, 详见 [固件OTA/详细设计.md](固件OTA/详细设计.md))

```
前端 → POST /api/v1/ota/tasks {collector_id, firmware_id}
  ↓
[server/api/handler_ota] 创建 OTA 记录 + supersede 旧 in-flight
  ↓
[ota/manager] 发 OtaCommand (type=0x0A) 到 devices/{id}/down/v2
  ↓
[esp32/ota_updater] 下载 + 校验 + 刷写
  ├─ 期间发 OtaProgress (type=0x0B) status=0..3
  └─ 刷写完成发 status=2 (success) + progress=100 → esp_restart()
  ↓
[server/mqtt/handler_v2] 收 OtaProgress → 更新 OTA 记录
  ↓
[设备重启 → 发 Hello (type=0x01)]
  ↓
[HandleHelloOTACompletion] §6.4.3
  ├─ 若 firmware_version == to_version → 标 success
  └─ 否则若 started_at 超过 10min → 标 failed
  ↓
推 ota_progress 事件到前端 (进度条 0%→100%→完成)
```

## 3. 协议规范

### 3.1 协议层定位

EHomeSystem v2.0 **完全废弃** v1.x 的 protobuf 协议, 采用精简**二进制帧**:
- 体积: ~50 字节 vs protobuf ~150 字节 (-67%)
- 解析: 手写 decode (~200ns) vs protobuf 反射 (~10μs) (-50x)
- 可调试: 16 进制 dump 可读
- 缺点: 不向后兼容 (v1.x 不可升级, 必须烧 v2.0 固件)

### 3.2 帧格式 (Frame Format)

```
┌──────────┬──────────┬──────────────┬─────────────────┐
│ Magic 1B │ Length 2B│ Type 1B      │ Payload N-4B    │
│ 0xEB     │ LE uint16 │ see §3.3     │ type-specific   │
└──────────┴──────────┴──────────────┴─────────────────┘
```

- Magic: `0xEB` (固定, 用于帧同步)
- Length: 整个帧的总字节数 (含 magic + length + type)
- Type: 1 字节消息类型 (0x00-0xFF)
- Payload: 类型相关的字段, 长度 = Length - 4

### 3.3 消息类型 (11 种)

| Type | 名称 | 方向 | 用途 |
|------|------|------|------|
| 0x01 | Hello | ESP→SVR | 上线握手 |
| 0x02 | StatusReport | ESP→SVR | 心跳 (60s/次) |
| 0x03 | DataReport | ESP→SVR | 采集数据 |
| 0x04 | ConfigManifest | SVR→ESP | 配置下发 |
| 0x05 | ConfigResult | ESP→SVR | 配置确认 |
| 0x06 | WriteCommand | SVR→ESP | 远程操作 |
| 0x07 | WriteResponse | ESP→SVR | 操作响应 |
| 0x08 | Ping | 双向 | 延迟测量 |
| 0x09 | Pong | 双向 | 延迟响应 |
| 0x0A | OtaCommand | SVR→ESP | 固件升级 |
| 0x0B | OtaProgress | ESP→SVR | 升级进度 |
| 0x0C | ScanReport | ESP→SVR | I2C 扫描结果 |
| 0x0D | ScanRequest | SVR→ESP | I2C 扫描请求 |
| 0x0E | QueryRequest | SVR→ESP | 资源/通道查询 |
| 0x0F | QueryResponse | ESP→SVR | 查询响应 |
| 0x10 | ConfigQuery | SVR→ESP | 配置同步查询 |
| 0x11 | ConfigReport | ESP→SVR | 配置同步响应 |
| 0x12 | HelloAck | SVR→ESP | Hello 确认 (含 ConfigManifest) |

### 3.4 MQTT Topic 设计

| Topic | 方向 | 用途 |
|-------|------|------|
| `devices/{device_id}/up/v2` | ESP→SVR | 上行 (Hello/Status/Data/Progress/...) |
| `devices/{device_id}/down/v2` | SVR→ESP | 下行 (Config/Write/OTA/Ping/Scan/Query) |
| `ehome/internal/+/up` | ESP→SVR | 内部广播 (固件库同步等) |

### 3.5 协议变更流程

任何对 frame / message format 的修改必须:
1. 在 [总体设计 §3.3](总体设计.md#33-消息类型-11-种) 表里更新 (递增 type 号, 不复用)
2. 在 [对应模块详细设计 §3](README.md#功能模块清单) 里描述
3. 在 [ESP32_FLASH_GUIDE.md](../../ESP32_FLASH_GUIDE.md) 里标注不兼容

## 4. 通用设计

### 4.1 数据模型分层

```
┌─────────────────────────────────────────────┐
│ 视图层 (View): 纯渲染, 不直接查 DB         │
├─────────────────────────────────────────────┤
│ API 层 (Handler): 参数校验 + 调用 service   │
├─────────────────────────────────────────────┤
│ Service 层: 业务逻辑 + 状态机              │
├─────────────────────────────────────────────┤
│ Repository 层: GORM CRUD                    │
├─────────────────────────────────────────────┤
│ Model 层: GORM struct + 索引 + 关系         │
└─────────────────────────────────────────────┘
```

> 前端目录的 `api/` 模块对应后端 `handler/`, `stores/` 对应 service 层
> 视图组件不直接调 api, 必须经 stores (保证状态/订阅/错误统一)

### 4.2 容错设计 (Fail-Open)

| 场景 | 行为 | 参考 |
|------|------|------|
| 未知 wire code | WARN + 保留当前状态, 不写 DB | [固件OTA §6.3](固件OTA/详细设计.md) |
| MQTT 帧丢失 (esp_restart 丢最后一帧) | Hello 上线时通过 firmware_version 自动完成 OTA | [固件OTA §6.4.3](固件OTA/详细设计.md) |
| OtaChecksum 长度非 64 | WARN + 跳过 hash 校验 (不卡死) | [固件OTA §6.2](固件OTA/详细设计.md) |
| 同 collector 并发 OTA | supersede 模式: 旧任务标 failed, 新任务 pending | [固件OTA §6.4.1](固件OTA/详细设计.md) |
| 配置下发失败 | 重试 3 次, 失败进 notifications 中心 | [采集器/详细设计 §3](采集器/详细设计.md) |
| 设备 10min 无心跳 | offline detector 触发 → 推 frontend 事件 | [采集器/详细设计 §6](采集器/详细设计.md) |
| WS 连接断开 | 自动重连 + 顶部 banner 提示 | [设计/网络/可观测性](#3-状态机显式-explicit-state-machines) |

### 4.3 可观测性

#### 4.3.1 结构化日志
- 所有 logger 调用必须 JSON 化, 含 `timestamp / level / component / message / request_id`
- 关键事件 (状态机转移/重试/supersede) 必须带 `event` 字段
- 示例: `{"event":"ota_status_change","task_id":"abc","from":"downloading","to":"success"}`

#### 4.3.2 Prometheus 指标
| 指标名 | 类型 | 标签 |
|--------|------|------|
| `ehome_collector_online_count` | gauge | - |
| `ehome_ota_active_count` | gauge | status |
| `ehome_data_received_total` | counter | device_id, status |
| `ehome_mqtt_publish_failures_total` | counter | topic |
| `ehome_http_request_duration_seconds` | histogram | method, route, status |

#### 4.3.3 WebSocket 事件
| 事件名 | payload | 触发场景 |
|--------|---------|----------|
| `collector_status` | `{collector_id, status, last_seen}` | 上线/离线 |
| `data_update` | `{device_id, data, timestamp}` | 新采集数据 |
| `ota_progress` | `{task_id, status, progress, error_msg}` | OTA 进度 |
| `notification` | `{id, level, message, timestamp}` | 新通知 |
| `device_status` | `{device_id, status, error_code}` | 设备状态变化 |

#### 4.3.4 错误码
HAL 错误码: 9 种, 见 [设备/详细设计 §6](设备/详细设计.md)

### 4.4 安全设计

| 层 | 措施 |
|----|------|
| API | JWT (HS256) + 角色 RBAC (admin/operator/viewer) |
| MQTT | 用户名密码 + ACL (device_id 限制只能 pub/sub 自己的 topic) |
| 前端 | 路由守卫 + 按钮级 v-permission 指令 |
| OTA | SHA256 校验 + A/B partition + 30s mark valid 自动 rollback |
| 密码 | bcrypt (cost 10) |
| 登录 | 5 次失败锁定 5 分钟 (前端, [认证授权/详细设计 §4](认证授权/详细设计.md)) |

## 5. 部署架构

### 5.1 单机部署 (开发/小规模生产)

```
1 台 Linux 服务器 (Ubuntu 22.04+)
├─ backend (Go 静态编译 ~30MB)
├─ frontend-shared (Nginx 静态文件)
├─ PostgreSQL 15
├─ Redis 7
├─ Mosquitto 2.x
└─ Prometheus + Grafana (可选)
```

### 5.2 分布式 (≥10 节点)

```
LB (Nginx) → 3× backend (Go)
                 ↓
        PostgreSQL 主从 + Redis 集群 + Mosquitto 集群
                 ↓
          10-100 个 ESP32 节点
```

详细部署: 参考 `docs/ESP32_FLASH_GUIDE.md` + `scripts/deploy/`
