## 1. 背景、目标与非目标

### 1.1 问题

`sensor_name` 是设备数据、规则引擎、数据源三者共同依赖的"数据身份证"，但它是一根**裸字符串**：同一根字符串在 5 处各写一遍（驱动产出 / `unified_data` / `alert_rules` / `automation_rules` / `data_sources` / 前端两套 map），无注册表、无校验、无单一事实源（详见评估 §2–§7）。

**两类结构性缺陷**（纯枚举词表解决不了，这是本方案存在的理由）：

1. **动态索引字段无法穷举**：`cell_voltage_1..N`、`temperature_1..N` 的 N 由设备上报的 `cell_count`/`ntcCount` 决定（`jiabaida_parse.go:248/289`），每台设备不同。
2. **厂商同义字段无法归一**：`rsoc`（嘉佰达）/ `battery_capacity`（Techfine）/ `bms_soc`（逆变器 BMS 段）是同一物理量的不同物理名；规则绑定物理名 ⇒ 换型号即失效。

### 1.2 事实口径（v0.2 修订：**不写死数字**）

v0.1 用"169 个字段名字面量"作分母，评审实测为 **170**（含 18 个动作参数名 `ControlParameter{Name:...}` 与 6 个 `*_ack` 回读伪量），且**仓库处于并发改动中**（同日有提交变更驱动字段）。因此：

> **本文件不写死任何字段名计数。** 所有"字段名集合"由 CI/脚本按 §12.3 定义的**口径**从代码推导，分母随代码自动更新。
> 已核实的结构性事实（评审三方独立复核，基线 `dea94e4d`，2026-10-21）：
> - `Driver.GetSensorDefinitions()` 声明并集 = **91** 个名字（三方一致）；
> - 源码中 `Name:` 字面量总数 = 170，其中 `ControlParameter` 参数名 18 个、`*_ack` 回读伪量 6 个；
> - 生产库 `unified_data` 实际出现 **13** 个 sensor_name（2 台设备）；`device_models`/`device_configs` = 0 行；`alert_rules`/`automation_rules`/`data_sources` = 0 行；
> - `unified_data.edge_device_id` **全表 NULL**（179,532/179,532，台账 **DS-14 未修复**）⇒ 真实设备身份在 `unified_data.device_id`（= EdgeDevice.ID）。

### 1.3 目标

| # | 目标 | 验收口径（可证伪） |
|---|---|---|
| G-1 | 新设备接入零中心端配置：首帧后规则编辑器即可见其字段 | 新建 BMS（不碰中心端配置）→ 首帧后 ≤90s，`GET /sensor-fields?edge_device_id=X` 返回 ≥1 |
| G-2 | 规则不绑物理名：换厂商/换型号不改规则 | 同一 `@soc < 30` 规则在 jiabaida_bms 与 techfine_inverter 上均能命中 |
| G-3 | 动态索引字段可表达 | `temperature_* > 45` 在 2 探头与 4 探头设备上都正确求值 |
| G-4 | 静默失效清零 | 配错的 selector 24h 内被 `never_resolved` 标记并通知 |
| G-5 | 数据面零新增依赖 | `go list -deps ./internal/databus \| grep sensorfield` → 空；`unified_data` 无新增列/FK |
| G-6 | 存量字面量规则行为不变 | 现有 automation/alert 全量测试**零修改**通过；纯字面量走与今天逐字节相同的比较路径 |
| G-7 | 可回滚（**限定语义**，见 §14.3） | 关闭开关并**重启**后：特殊 selector 规则不触发 + 落审计；纯字面量照旧 |

### 1.4 非目标

- **不改协议、不改固件**：不向节点下发字段字典（概念模型 §4 裁决不变）。
- **不引入表达式语言**：D3 只做受限函数式（§6.2）。
- **不做跨帧聚合**：`TriggerDurationSec` 滑窗语义不变。
- **不做单位换算**：单位仅展示/分轴。
- **不改 `unified_data` 表结构**（不加列、不加 FK）。
- **一期 `data_sources.category` 不支持 selector**（仅字面量 + 存在性校验）——见 §9.4 的评审裁决。
- **一期 `alert` 与 `automation conditions` 必须同步支持 selector**（不能只支持 trigger，否则静默失效；见 §9.2）。

## 2. 术语与核心概念

| 术语 | 定义 | 例子 |
|---|---|---|
| **物理名** | 驱动解析产出的原样字段名 | `rsoc`、`cell_voltage_3` |
| **语义名** | 跨厂商归一后的业务量名 | `soc`、`dc_power` |
| **字段族** | `前缀_数字后缀`，**严格匹配 `^<prefix>_[0-9]+$`** | `temperature_*` → `temperature_1..N` |
| **派生字段** | 本帧多字段计算出的只读虚拟量 | `virtual:cell_delta` |
| **选择器** | 持久化在规则里的唯一契约字符串 | `rsoc` / `temperature_*:max` / `@soc` / `virtual:dc_power` |
| **解析** | selector → (物理字段集合, 聚合方式) | — |
| **声明** | 驱动静态声明 | `GetSensorDefinitions()` |
| **观测** | 该设备实际入库过的字段 | `sensor_field_obs` |
| **已知集合** | 解析期该设备的 声明 ∪ 观测 | 用于判断 unbound |
| **本帧集合** | 求值时该帧实际解析出的字段 | 用于求值 |

> ⚠ **v0.2 关键修订**：family **不采用纯前缀匹配**。v0.1 的纯前缀会让 `cell_voltage_*` 命中 `cell_voltage_max/min/avg`（`jiabaida_parse.go:309-311`），导致 `sum/avg` 重复计数、`all/min` 把派生归约量当原始测点。改为**数字后缀严格匹配**后，族成员恰为 `cell_voltage_1..N`，语义自洽。

## 3. 总体架构

### 3.1 分层与包布局（v0.2 修订：HTTP 与领域分离，避免包环）

```
internal/sensorfield/            ← 领域层（无 HTTP、无 GORM 模型定义）
    selector.go   语法解析 + 错误码
    registry.go   内存快照（decl/obs/alias/virt）+ epoch
    resolve.go    控制面 Resolve（family 展开、聚合）
    eval.go       数据面 Eval（编译产物，零 DB）
    alias.go      别名加载与冲突检测
    virtual.go    派生函数集 + 环检测
    observe.go    观测计数（内存）+ projector
internal/models/sensor_field.go  ← 两张新表的 GORM 模型（放 models，保持其叶子性）
internal/api/handler_sensor_fields.go ← HTTP handler（复用 api envelope）
internal/api/handler_automation.go     ← 增加 precheck 端点
```

> **为什么 handler 不放 sensorfield**：`sensorfield/api.go` 若要复用 `internal/api` 的 envelope，会形成 `sensorfield → api → automation → sensorfield` 环（评审 arch H-1 指出的两个真实成环点之一）。领域包必须保持对 `api` 零依赖。

### 3.2 依赖方向

```
internal/models  （叶子）
internal/drivers （叶子：仅 pkg/logger + pkg/parser）
        ▲
internal/sensorfield      （依赖 models、drivers、logger、metrics）
        ▲                    ▲                    ▲
internal/automation   internal/alert      internal/api
   （仅控制面：编译 selector、保存校验；**仅 evaluator.go/planner.go 允许 import**）
        ▲
internal/datasource  ← 一期**不**依赖 sensorfield（category 不做 selector）

**硬禁令**：internal/databus → sensorfield（数据面）；sensorfield → internal/api / automation / alert / datasource（反向）
```

### 3.3 数据面如何做到"零依赖"（v0.2 修订）

| 需求 | 现状可行性 | 方案 |
|---|---|---|
| 每帧知道出现了哪些字段（观测） | 已有旁路钩子：`main.go:280` `nodeMgr.SetLatestSinkFn(api.SetLatestValue)` → databus 对每条记录调 `latestSink(records[i])` | 在 **main.go** 把注入包装成 `func(rec){ api.SetLatestValue(rec); sensorfield.Observe(rec) }`。**databus 零改动、零 import** |
| 求值用编译产物 | automation/alert 的 `rule` 结构体不挂编译字段（否则 models 破叶子性） | 在 automation/alert 包内维护**旁路 map**：`map[ruleID]*plan`，key 含 `deviceID/selectorHash/epoch/ruleVersion` |
| 观测落库 | 无 | 进程内计数器 + 60s 批量 UPSERT（projector goroutine） |

> 这是评审 **C1/B-1** 的处置：**观测采集点 = 既有注入 sink**，不是 ingest 侧新代码。

## 4. 数据模型

### 4.1 内存 Registry

```go
type Registry struct {
    snap atomic.Pointer[snapshot]   // 读无锁
    enabled atomic.Bool
}
type snapshot struct {
    decl  map[string][]FieldDecl   // device_type → 声明
    obs   map[uint][]FieldObs      // **deviceID（= unified_data.device_id）**
    alias map[string][]AliasCand   // semantic → 候选（有序）
    virt  map[string]VirtualDef
    epoch uint64                   // 任一来源变更即 +1
}
type FieldDecl struct { Name, Unit, ValueType string }
type FieldObs  struct { Name, Unit string; FirstSeen, LastSeen time.Time; Samples int64 }
```

**命名口径（v0.2 写死，防 DS-14 陷阱）**：
> 本方案所有"设备 ID"一律指 **`EdgeDevice.ID`**，即 `unified_data.device_id` 列的值。
> ⚠ `unified_data.edge_device_id` 当前全表 NULL（DS-14 未修复），**禁止**用它做投影或聚合。

### 4.2 观测投影表

```sql
CREATE TABLE sensor_field_obs (
  device_id   BIGINT      NOT NULL,          -- = unified_data.device_id
  sensor_name VARCHAR(64) NOT NULL,
  unit        VARCHAR(16) NOT NULL DEFAULT '',
  first_seen  TIMESTAMPTZ NOT NULL,
  last_seen   TIMESTAMPTZ NOT NULL,
  samples     BIGINT      NOT NULL DEFAULT 0,
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (device_id, sensor_name)
);
CREATE INDEX idx_sfo_last_seen ON sensor_field_obs (last_seen);
```

**采集路径（v0.2 修订，处置 B-1）**：

```go
// cmd/server/main.go —— 既有注入点，只加一行
nodeMgr.SetLatestSinkFn(func(rec models.UnifiedData) {
    api.SetLatestValue(rec)                 // 既有行为
    fieldResolver.Observe(rec.DeviceID, rec.SensorName, rec.Unit, rec.Timestamp) // 新增：纯内存
})
```

- `Observe` 只做 `sync.Map` + `atomic.Int64` 自增，**无 DB、无锁竞争、无分配**（值类型入参）。
- projector 每 60s 把增量 UPSERT 一次（`ON CONFLICT DO UPDATE SET last_seen=excluded.last_seen, samples=samples+excluded.samples`）。
- 冷启动：`SELECT * FROM sensor_field_obs`（小表）灌 snapshot。

**回填 SQL（v0.2 修订，补齐 first_seen/samples，处置 B-3）**：

```sql
INSERT INTO sensor_field_obs (device_id, sensor_name, unit, first_seen, last_seen, samples)
SELECT device_id, sensor_name, max(unit), min(timestamp), max(timestamp), count(*)
FROM unified_data
WHERE device_id IS NOT NULL
GROUP BY device_id, sensor_name
ON CONFLICT (device_id, sensor_name) DO UPDATE
SET first_seen = LEAST(sensor_field_obs.first_seen, EXCLUDED.first_seen),
    last_seen  = GREATEST(sensor_field_obs.last_seen, EXCLUDED.last_seen),
    samples    = sensor_field_obs.samples + EXCLUDED.samples;
```

（分批执行，复用 `datalifecycle/backfill_jobs` 的**水位表**；runner 需新写——评审 impl 指出既有 runner 是 logical_id 专用，不能直接复用。）

### 4.3 丰富层 `sensor_field_meta`

同 v0.1（`sensor_name PK / label_zh / unit / value_type / precision / status`）。缺行不影响功能，前端降级显示物理名。唯一消费者是展示 API。

### 4.4 存量数据处置（v0.2 新增，处置 F9）

升级前必须跑**一次性扫描**（M0），把既有自由文本值分类：

| 类别 | 判据 | 处置 |
|---|---|---|
| literal | 匹配 `^[a-z][a-z0-9_]*$` 且不是特殊文法 | 原样保留，行为不变 |
| special | 匹配 family/`@`/`virtual:` 文法 | **标记 `needs_review`**：不自动生效；UI 红标；需人工确认后才启用 selector 语义 |
| legacy | 两者都不匹配（含大写/中文/空格/超长） | 按**精确字面量**匹配（与今天一致），落审计告警，禁止保存修改直到迁移 |
| **invalid_json**（v0.3 新增） | `conditions_json` 不是合法 JSON / 数组元素缺 `sensor_name` | **单列一类**，不得混入以上三类（否则会被"0 个 sensor_name"掩盖）；M1 把 `ParseConditions` 前置到保存期 |

**分类口径（窄复核 M0 拍板）**：`special` = **包含** `@` / `_*` / `virtual:` 任一标记（即使其余部分不合法，如 `Temperature_*`），同时另记 `syntax_ok=false`，不降级为 `legacy`——保守口径优先暴露风险。

> **v0.1 的错误**：声称"存量全是字面量所以行为不变"。评审实测本库三张表 0 行，**该断言不可证**；且其他部署可能存在特殊形态值。v0.2 用 M0 分类替代假设。

## 5. Selector 语法与语义（核心契约）

### 5.1 文法与边界（v0.2 修订：补齐全部未定义行为）

```ebnf
selector      = literal | family | semantic | virtual ;
literal       = physical-name ;
family        = prefix , "_*" , [ ":" , aggregate ] ;
semantic      = "@" , semantic-name ;
virtual       = "virtual:" , virtual-name ;

physical-name = lower , { lower | digit | "_" } ;     (* ASCII only: ^[a-z][a-z0-9_]*$ *)
prefix        = lower , { lower | digit | "_" } , lower-or-digit ;  (* 不得以 _ 结尾 *)
aggregate     = "min"|"max"|"avg"|"sum"|"any"|"all" ;  (* 全小写 *)
```

**通用规则（v0.2 新增；v0.3 勘误）**：
0. **prefix 允许 1 个字符**（`a_*` 合法；只有 `_*` 非法，因为 prefix 必须以字母开头）。M0 扫描脚本按此口径实现（窄复核 M0 提出需拍板，此处拍板）。
1. **先 `strings.TrimSpace` 再解析**；trim 后为空 ⇒ `empty_selector`。
2. **长度上限 64 个 Unicode 字符**（DB `VARCHAR(64)` 按字符计，非字节）；超限 ⇒ `selector_too_long`。
3. **仅允许 ASCII**（`a-z0-9_` 与 `@:*`）；出现其它字符 ⇒ `invalid_selector_syntax`。
4. 大小写敏感：`MAX` / `@SOC` 一律非法（不做静默小写化）。

**边界用例表（v0.2 新增；评审要求逐条定义）**

| # | 输入 | 解析结果 | 错误码 |
|---|---|---|---|
| 1 | `*` | 非法（prefix 需 lower 起始） | `invalid_selector_syntax` |
| 2 | `_:x` | 非法 | `invalid_selector_syntax` |
| 3 | `temperature_*:` | 非法（冒号后空） | `invalid_selector_syntax` |
| 4 | `@` | 非法（语义名至少 1 字符） | `invalid_selector_syntax`（**不是** `unknown_semantic`） |
| 5 | `virtual:` | 非法 | `invalid_selector_syntax`（**不是** `unknown_virtual`） |
| 6 | `a_*:any:max` | 非法（只允许一个聚合） | `invalid_selector_syntax` |
| 7 | `temperature_*:MAX` | 非法（大小写） | `unsupported_aggregate` |
| 8 | `温度_*` | 非法（非 ASCII） | `invalid_selector_syntax` |
| 9 | `` / `   ` | 非法 | `empty_selector` |
| 10 | 64 字符 literal | 合法 | — |
| 11 | 65 字符 | 超限 | `selector_too_long` |
| 12 | `temperature_*:max ` | 合法（trim 后） | — |
| 13 | `virtual`（无冒号） | literal | — |
| 14 | `cell_voltage_10` | literal（不走 family） | — |
| 15 | `@unknown` | 语法合法、语义未定义 | `unknown_semantic`（400） |

### 5.2 四类选择器

| 形态 | 例子 | 解析结果 |
|---|---|---|
| literal | `rsoc` | 恰好该物理名（**与今天 `matchField` 逐字节相同**） |
| family | `temperature_*:max` | `^temperature_[0-9]+$` 匹配的**本帧**字段集合，按聚合求值 |
| semantic | `@soc` | 别名表顺序中**第一个该设备已知**的物理名（单值） |
| virtual | `virtual:cell_delta` | 按定义计算本帧值 |

### 5.3 聚合语义的前置定义（v0.2 重写，处置 C1）

**先定义三件事，再谈聚合**：

**定义 1（有效值）**：某字段的取值是**有限数**（`!NaN && !Inf`）时算"有值"。非有限、非数值（`bitmask/enum/string/raw`）、缺失 ⇒ 该字段视为**本帧缺失**。

**定义 2（本帧集合与已知集合）**：
- `F_now` = family 在本帧解析出的有效字段集合；
- `F_known` = 该设备**已知集合**中满足 family 的字段（解析期由 snapshot 得出）。
- 规则：`F_now ⊆ F_known`。
- **缺员判定（v0.3 方向性修订，窄复核 Q3）**：`missing = F_known \ F_now ≠ ∅` 时按聚合方向分别处理：

| 聚合 | `missing ≠ ∅` | 理由 |
|---|---|---|
| `any` | 按 `F_now` 正常求值 | 存在性语义不受缺员影响 |
| `all` | **unbound** | 缺员时无法断言"全部满足"，放行方向不安全（如"全部温度正常才允许充电"） |
| `min` / `max` | **按 `F_now` 求值** + `degraded=true` + `partial_frame` 指标 | 极值保护必须继续工作：**永不触发**比"用可见探针触发"更危险（单探头缺失会静默废掉过温/欠压保护） |
| `avg` / `sum` | **unbound** | 缺员使统计量失真（分母变小/总和偏小），无安全解释 |

> `Verdict.Reason` 必须区分 `partial_frame(missing=[...])`（degraded）与 `unbound_partial_avg`，审计要能分辨"没数据"与"数据不满足"。

**定义 3（空集；v0.3 统一口径，窄复核 Q1）**：`F_now = ∅` ⇒ **六个聚合一律 unbound（不触发）**，包括 `any`/`all`/`sum`。
- 理由：`sum=0` 会让 `sum < 10` 在无电芯设备上**反向触发**；`min=+Inf` 会让 `min > t` 恒真；`all` 空真会让"设备换型/族消失"变成**条件恒成立**（危险方向）。
- ⚠ **空集不产生 true/false，只产生 unbound**。本文件定义 4 表、§7.2.2、§12.1 已按此统一（此前 12 格表述互相矛盾，见 §20 N-13）。

**定义 4（reducer 与比较符的语义）**：

| 聚合 | 语义 | 备注 |
|---|---|---|
| `any`（默认） | `∃ f∈F_now : cmp(v(f), t)` | 空集 **unbound**（不产生 false） |
| `all` | `∀ f∈F_now : cmp(v(f), t)` | 空集 **unbound**；有缺员亦 unbound |
| `min`/`max` | 先归约 `F_now`（缺员时仍归约 + degraded），再 `cmp(reduced, t)` | 空集 unbound |
| `avg`/`sum` | 先归约 `F_now`（有缺员即 unbound），再 `cmp` | 空集 unbound |

**`reducer + neq` 是语义陷阱**（评审反例：F={5,7}, t=5 ⇒ `min neq 5` = false，而直觉上"有值不等于阈值"应为 true）：
- **保存期**：`min/max/avg/sum` + `neq` ⇒ 返回 `warnings[]`（不阻塞），UI 红字说明"几乎恒真"。
- 文档明确：这是**允许但强烈不推荐**的组合。

**真值表测试要求**：`any/all/min/max/avg/sum` × 6 比较符 × {空集, 单元素, 多元素齐全, 多元素缺员, 含 NaN, 含非数值} = **216 格**逐格断言（v0.1 只要求 36 格，覆盖不够）。

### 5.4 解析优先级与歧义

1. 语法层互斥（`@`、`virtual:`、`_*`）；literal 仅当整串匹配 `^[a-z][a-z0-9_]*$`。
2. **语义名与物理名同名**：`@x` 按语义，裸 `x` 按物理名。**不做猜测**。
3. 别名多候选：按配置顺序取第一个"该设备已知"的；若解析结果**不是首候选**或**多候选同时存在** ⇒ 指标 + **一次性通知**（不是只在触发时记审计）。
4. family 与 literal 不可能冲突。

### 5.5 版本与兼容

- `selector_version = 1`（当前）。未来只加不改。
- 存量值按 §4.4 三类处置（literal / special-needs-review / legacy）。
- **特殊形态默认不生效**：升级后存量里若出现 `temperature_*`，一律按 §4.4 标 `needs_review`，**不自动按 family 求值**（v0.1 的 fail-open 行为变更被评审否决）。

## 6. 别名与派生

### 6.1 别名表（唯一一份，v0.2 修订，处置 C4/F3）

```yaml
# config/field_aliases.yaml —— 唯一默认表（v0.1 的 §6.1 示例与 §18.1 两份表合并为此一份）
# 每个语义词声明期望单位类；候选单位类不一致 ⇒ 启动失败（防"作用于错误物理量"）
soc:               { expected_unit: "%",  candidates: [rsoc, battery_capacity, bms_soc, soc] }
total_voltage:     { expected_unit: "V",  candidates: [total_voltage, battery_voltage, bus_voltage] }
charge_current:    { expected_unit: "A",  candidates: [battery_charge_current, charge_current] }
discharge_current: { expected_unit: "A",  candidates: [battery_discharge_current, discharge_current] }
net_current:       { expected_unit: "A",  candidates: [current] }   # JBD 带符号（充正放负）
dc_power:          { expected_unit: "W",  candidates: [output_active_power] }
```

**规则（v0.2 明确）**：
1. **配置合并语义**：配置**按 key 整体替换**，不追加（避免重复候选）。
2. **冲突检测（启动期 fail-closed）**：同一物理名出现在**多个语义名**下 ⇒ 拒绝启动；除非该物理名所在项显式 `allow_overlap: true`。
3. **单位类校验（v0.2 新增）**：候选的 `unit` 与 `expected_unit` 不同类（如 `V` vs `A`）⇒ 拒绝启动。这防的是评审指出的最坏场景：`@current` 在 Techfine 上只解析到充电电流而漏掉放电电流 ⇒ 过流保护失效。
4. **运行期多候选/非首候选**：允许（fail-open），但必须 ①按 `(device, semantic)` **冻结首次解析结果**并在 UI 展示；②产生**触发前**的一次性通知；③高风险动作在语义未确认前要求重新确认。
5. 已删除 v0.1 的死候选（`battery_soc`/`bms_power`——全仓无产出）。
6. **`current` 必须拆分（v0.3 勘误，窄复核 H1）**：原先 `current: [current, battery_charge_current, battery_discharge_current]` 的三候选**单位都是 A**，单位类校验对"放电电流被漏掉"这一最坏场景**完全无效**；Techfine 同帧同时产出充/放两个字段 ⇒ 冻结首候选 = 充电电流 ⇒ **放电过流保护静默失效**。拆分后 `charge_current` / `discharge_current` 各自单候选，语义不再被"取第一个"掩盖；`net_current` 仅覆盖 JBD 的带符号单字段，**不得**用于过流保护（符号语义跨厂商不一致）。
7. **`soc` 候选保留**（v0.3 勘误）：删"死候选"的判据漏了 simulation / ConfigParser 路径——`simulation` 场景直接构造 `DeviceConfig.Parser.fields` 并产出物理名 `soc`，删除会使 `@soc` 在仿真/配置解析设备上 unbound。

### 6.2 派生字段（受限函数式）

```yaml
virtual:
  dc_power:      { fn: product,  args: ["@total_voltage", "@net_current"] }   # v0.3：@current 已拆分为 charge/discharge/net，必须用 net_current
  max_temperature: { fn: max_of, args: ["temperature_*"] }
  cell_delta:    { fn: diff,     args: ["cell_voltage_max", "cell_voltage_min"] }
  soc_gap:       { fn: abs_diff, args: ["@soc", "bms_soc"] }
```

**函数集（唯一一份，两处必须一致）**：

| fn | 参数 | 说明 |
|---|---|---|
| `product` / `sum` | ≥2 | 数值运算 |
| `diff` | ≥2 | a−b−c… |
| `abs_diff` | 2 | \|a−b\| |
| `ratio` | 2 | a÷b |
| `scale` | 1 + `scale` | a×scale |
| `sum_of` / `max_of` / `min_of` | 1，必须是 **family selector**（不带聚合后缀） | 族归约 |

**统一不变量（v0.2 修订）**：
1. **任何输入缺失 ⇒ 整体 unbound**（不 fallback 到 0）。
2. **任何输出非有限（NaN/±Inf）⇒ unbound + `virtual_undefined_total{reason}`**（不再只对 `diff` 特例）。
3. `ratio` 分母为 0 或负数 ⇒ unbound（**负数分母也拒绝**，避免符号歧义）。
4. 参数个数/类型非法 ⇒ **启动失败**（配置随镜像分发，不是用户输入）。
5. 嵌套深度 ≤ `max_virtual_depth`（默认 4）；环 ⇒ 启动失败。
6. **命名规范**：语义/派生名必须带物理限定（`dc_power` 而非 `power`），避免"交流/直流/总功率"歧义（v0.1 的 `power` 示例被评审否决）。
6.1 **派生引用的语义名必须存在**（v0.3 勘误）：`@current` 在 current 拆分后已不存在，引用它会在 `SetVirtuals`/`Validate` 以 `ErrUnknownSemantic` **拒绝启动**——这是 fail-closed 的正确行为，示例已改为 `@net_current`（JBD 带符号电流）。
7. `max_of/min_of/sum_of` 的参数**只接受 family**，不接受 `@semantic` / `virtual:` / 带聚合后缀（消除双重归约）。

## 7. 解析算法与缓存

### 7.1 控制面

```go
func (r *Registry) Resolve(deviceID uint, sel string) (Resolved, error)
```
纯内存，`O(#fields)`；语法错误返回 400 类错误；语法合法但无匹配返回 `Status=unbound`（不是错误）。

### 7.2 数据面（v0.2 修订，处置 H-1）

**编译产物不放 `models.AutomationRule`**（否则 `models → sensorfield → models` 成环），放在消费包内的**旁路 map**：

```go
// internal/automation
type rulePlan struct {
    selectorHash uint64
    deviceID     uint
    epoch        uint64
    plan         sensorfield.Plan
}
// v0.3 勘误（窄复核 R1）：key 必须是三元组，单 ruleID 装不下
type ruleKey struct {
    ruleID   uint
    slot     uint8   // 0=trigger；1..N=conditions_json 第 N 项
    deviceID uint    // = Evaluate(edgeDeviceID) 入参，不是 rule.TriggerEdgeDeviceID
}
evaluator.plans map[ruleKey]compiledPlan
```

**缓存键有效性**（v0.3 勘误）：`(ruleID, slot, deviceID, selectorHash, epoch)` 任一变化即重编译。
- **不用 `rule.UpdatedAt` 当版本**：planner 的 `last_triggered_at` 簿记会 bump UpdatedAt（GORM AutoUpdateTime），它是"触发计数器"不是内容版本，会导致每次触发都重编译。
- **slot 的必要性**：一条规则有 trigger + N 个 conditions ⇒ 多个 selector，必须分开缓存（窄复核 R1 反例）。
- **deviceID 语义（勘误 R3）**：一律取 `Evaluate(edgeDeviceID, ...)` 的**入参**，不是 rule 上的设备字段。理由：规则可绑**逻辑设备**（merge 链解析），用逻辑 ID 查"已知字段"会恒空 ⇒ 特殊 selector 恒 unbound。
- **epoch 读取顺序（勘误 K1）**：调用方必须**先读 `Epoch()` 再 `Compile()`**（或使用 `Compile` 返回的 epoch），否则存在"新 epoch 配旧 plan"的竞态（fail-open 方向：新字段永久进不了该 plan）。

**失效时机**：`LoadRules()`/Invalidate（30s 兜底刷新）后 **清空 plans**；`epoch` 变化时惰性重编译。
**Eval 前检查**：`enabled` 从 snapshot 读（原子），关闭 ⇒ 特殊 selector 直接不触发并落审计（kill switch 生效，v0.2 修复）。

### 7.2.1 规则内容变更必须清求值状态（v0.3 勘误 R2，安全项）

**问题**：plan 会因 selectorHash 变化而重编译，但求值器的**窗口状态**（`windows` / `triggered` / 条件求值历史）缓存的是**旧阈值下算出的 satisfied 布尔**。`sameWindowStateFields` 白名单（`automation/evaluator.go` 末尾）只覆盖 time_window/sun 字段，**不含 comparator/threshold/duration/conditions** ⇒ 改阈值后最长 `DurationSec` 内仍按旧历史判定，可**误触发或漏触发**。

**修法（两包同改）**：
1. 扩展 `sameWindowStateFields` 白名单：加入 `TriggerSensorName/TriggerComparator/TriggerThreshold/TriggerDurationSec/ConditionsJSON`。
2. 内容变化 ⇒ 清 `windows`/`triggered`（automation）或 `windows`/`firing`/`lastNotifyAt`（alert），并清该 rule 的全部 plan 槽。
3. 加回归测试：改阈值后首次求值不受旧窗口影响。

### 7.2.2 比较必须走 `EvalPredicate`（v0.3 契约扩展）

`Plan.Eval(frame)` 无比较符参数，**数学上无法实现 any/all（∃/∀ 需要 cmp）**。因此解析层新增：

```go
type CmpOp string   // gt gte lt lte eq neq，与 models.AlertComparator* 同值
type Verdict struct { OK, Satisfied bool; Value float64; Reason string }
func EvalPredicate(p Plan, frame []Reading, op CmpOp, threshold float64) Verdict
```

- literal/semantic/virtual：`OK`=找到有效值，`Satisfied`=Compare(op,Value,t)
- family reducer（min/max/avg/sum）：先归约（受空集/缺员约束），再比较
- family `any`：∃ 有效成员满足（不受缺员影响；**空集 unbound**）
- family `all`：∀（**空集 unbound**；缺员/未知成员 ⇒ unbound）
- family `min/max`：缺员时按 `F_now` 求值 + `degraded=true`（§5.3 定义 2）
- family `avg/sum`：缺员或空集 ⇒ unbound
- `Plan.Eval` 对 family any/all 返回 unbound + reason（fail-closed，防静默错语义）

**literal 快速路径**：
```go
for i := range fields { if fields[i].Name == plan.literal { return fields[i].Value, true } }
```
与今天 `matchField` 逐字节相同（含"取第一个同名"语义）；基准门禁 ≤ +5%。

**缓存 miss 不查 DB**：用当前 snapshot 即时编译；滞后上限 = 投影间隔（60s），由 `snapshot_age_seconds` 指标暴露。

| Y2 | 日配额/日熔断计数 | `automation_events`（当日 executed 计数） | 清了 = 绕过日上限 | 改阈值后 count 不重置、仍 `suppressed_daily_limit`；日切恢复；`pending_confirm` 不占额度 |
| Y3 | 已发送通知/历史告警 | `notifications` / `alert_events` | 历史不可改写 | 改规则前后历史行字节不变 |
| Y4 | 在途 `TriggerEvent` | 事件内 `ev.Rule` 拷贝 | 半新半旧执行比旧值执行更危险 | 阻塞分发中并发改规则 → 本次严格用触发时拷贝、`-race` 干净、下一帧用新内容 |
| Y5 | pending confirmation 的动作快照 | **需新增** `automation_events.action_hash` | 见下 | confirm 时 hash 不匹配 ⇒ `ErrConfirmActionChanged` 拒绝执行 |

**Y5 是 v0.3 发现并修复的现存 TOCTOU（安全）**：现状 `ConfirmEvent`（planner.go:1153）重读 DB 规则并用**当前**动作集合执行，而 `automation_events` 无动作快照——pending 期间改动作 ⇒ 执行的是**用户没确认过的新动作**。修法：pending 落 `action_hash`（动作集合规范化哈希），confirm 比对不一致即拒绝并落审计；删除规则 ⇒ `ErrConfirmRuleMissing`；超时 ⇒ `ErrConfirmEventExpired`；成功时冷却锚点用 `ev.TriggeredAt` 而非 now。

## 11. 配置与生效方式（v0.2 修订，处置 F7）

```yaml
field_resolver:
  enabled: false
  aliases_file: "config/field_aliases.yaml"
  virtual_file: "config/virtual_fields.yaml"
  observe_interval: "60s"
  snapshot_ttl: "10m"
  max_selector_chars: 64
  max_family_size: 64
  max_virtual_depth: 4
  preview_max_samples: 5000
  never_resolved_hours: 24
```

**生效方式（v0.2 明确）**：仓库**没有配置热加载机制**（`config.Load()` 仅启动调用一次，依赖里无 fsnotify/viper）。因此：

> **所有 `field_resolver` 配置（含 `enabled`）变更需重启进程生效。** 不新增 watcher（"少造机制"）。
> 灰度用 `EHOME_FIELD_RESOLVER_ENABLED` 环境变量 + 重启。

**Kill switch 语义（v0.3 精确化，窄复核 N-2）**：

| 场景 | 行为 |
|---|---|
| `enabled=false` + 纯字面量规则 | **完全照旧**（literal 的 Compile 不查 enabled、不返回 ErrNotReady；字面量路径不依赖 registry） |
| `enabled=false` + 含特殊 selector 的规则 | 该规则**整条 fail-closed**（不触发）；即使只有 conditions 是特殊 selector、trigger 是 literal，也整条不执行（不能"跳过条件只跑 trigger"——那会执行未经条件校验的动作） |
| `enabled=false` 的**混合**规则审计 | automation ⇒ `automation_events(result=field_resolver_disabled)`，按 `(ruleID, selectorHash)` **5 分钟去重**（否则 30s×规则=2880 条/日/规则）；alert ⇒ **只记日志+指标**（`alert_events.State` 仅 firing/resolved，不新增事件类型） |
| 运行期翻转（不重启） | **不可用**：无配置热加载。`SetEnabled` 仅供测试/运维注入，生产以"改配置 + 重启"为准 |
| 不自动降级为字面量 | 是（会把 family 当不存在的物理名，静默失效） |

**启动顺序（v0.3 新增）**：① `RegisterDeclarations`（逐设备型号）→ ② `SetDeviceType`（逐设备）→ ③ 冷加载观测 → ④ `Validate()`（仅配置内部矛盾 Fatal；数据依赖问题只 WARN）→ ⑤ 启动 evaluator/projector。**literal Compile 在任何阶段都必须可用**。

> 已入库 selector 在完全回退代码后仍是死规则 ⇒ 回退预案必须包含 §12.3 门禁 #11 的盘点脚本。

## 12. 失败语义、红线与门禁

### 12.1 失败矩阵（v0.2 补空行）

| 场景 | 行为 | 方向 |
|---|---|---|
| 语法非法 / 未知语义 / 未知派生 | 保存期 400 | fail-closed |
| `unbound`（语法合法、当前无匹配） | 保存允许（warnings）；求值不触发 + 计数 | 软校验 |
| **规则启动期编译失败**（v0.2 补） | 该规则不参与求值 + 审计 + 指标；不影响其它规则 | fail-closed |
| 运行期解析不到（换型/族消失） | 不触发 + 审计（5 分钟节流） | fail-closed |
| 本帧缺员（已知有、本帧无） | `all/min/max/avg/sum` unbound | fail-closed |
| 空集 | 全部 unbound | fail-closed |
| 非有限值（NaN/Inf） | 视为缺失 | fail-closed |
| 非数值 value_type 参与比较 | 视为缺失 + 指标 | fail-closed |
| 别名多候选 / 非首候选 | 允许 + 冻结 + **触发前**通知 | fail-open + 可观测 |
| 观测投影不可用 | 降级"仅声明" + 指标 | fail-open |
| 数据库不可用 | 解析层用内存快照继续工作 | — |
| 配置无效（冲突/环/单位类不符/参数非法） | **启动失败** | fail-closed |

### 12.2 红线（v0.2 修订，处置 B-2）

1. **固件零感知**（协议零变更）。
2. **数据面零 import**：`internal/databus` 不得 import `sensorfield`；`unified_data` 不得新增列/FK。
   - 注意：`automation` / `alert` / `api` **允许** import（控制面编译/校验）。v0.1 把这条写成"全包禁止"，与自己的改造清单冲突。
3. **解析层不承载业务语义**（不放阈值/级别/优先级/动作映射）。
4. **求值路径零 DB**；literal 路径零分配。
5. **允许未知 selector 存在，但执行期不猜测**：解析不到 ⇒ 不触发 + 审计。
6. **新增字段不改中心端代码**（声明或观测自动发现）。
7. **可回滚（限定语义）**：见 §11。
8. **领域包不依赖 `internal/api`**（防包环）。
9. **literal 求值路径不得为「统一入口」付税**（v0.3 新增，实测教训）：特殊选择器检测必须是**字节级短路**（首字节 `@` / 前缀 `virtual:` / 扫描 `_*`），且 plan 在 **LoadRules 期预编译**。禁止在每帧 hot path 上做 hash / RWMutex / 统计写入。实测反例：无条件注入 provider ⇒ literal 58ns（基线 1ns，+5700%）。

### 12.3 门禁（v0.2 重写，处置 B-2 / F1）

| # | 门禁 | 判定方式 |
|---|---|---|
| 1 | 数据面零 import | `cd backend && set -o pipefail && go list -deps ./internal/databus \| grep -q '^ehome/backend/internal/sensorfield$' && exit 1`。**必须 `pipefail` + 行锚定**（否则 `go list` 失败会变成"失败即绿"） |
| 2 | 领域包零 internal 依赖 | `go list -deps ./internal/sensorfield` 中 `^ehome/backend/` 只允许 `pkg/logger`、`pkg/metrics`（与 doc.go 红线 2 等价；v0.2 只禁 4 包，判据不完备——窄复核 N-1） |

| 4 | 声明自洽 | `GetSensorDefinitions()` 声明并集 ⊆ 产出可达集。**必须用 `go/ast` 解析，不能用 grep**（实测 grep 只抓到 13/104 个字面量）；不写死分母 |
| 5 | 产出可寻址 | 所有 `SensorData{Name:...}` 字面量匹配物理名文法（同上，AST）；`*_ack` 伪量列入例外清单 |
| 6 | 别名一致 | 配置可加载：无冲突（或显式 allow_overlap）、单位类匹配、无**格式**错误。⚠ "候选是否在声明/观测中"属**数据依赖**，只 WARN 不阻断（新部署无观测，见 §11） |
| 7 | 派生无环 | 拓扑排序通过；参数个数/类型合法 |
| 8 | 语法表驱动 | `go test ./internal/sensorfield -run 'TestSelector' -v` 且**断言输出含 `=== RUN` 与至少 N 个用例计数**（避免"无测试文件时 exit=0"的假绿——窄复核 N-1 实测） |
| 9 | 变异自证 | 改默认聚合 / 去掉缺员方向规则 / 去掉空集 unbound ⇒ 对应测试必须红（"legacy 分支"改为具体变异点：M0 分类的 special→literal 降级） |
| 10a | **生产求值链路**（硬判据，**绝对预算 + 端到端**） | ① `BenchmarkAutomationLiteralPath` / `BenchmarkAlertLiteralPath` 单次 literal 求值**新增 ≤ 10ns 且 0 alloc**；② 端到端 `BenchmarkEvaluateFrame`（一帧多字段、含 literal 规则）相对基线 **≤ +5%**。⚠ 不采用「单次 literal ≤ +5%」：main 基线 1ns 级 ⇒ 预算 0.05ns，任何包装层必红。<br>**10ns 预算的来源（v0.3 修订，含自我更正）**：初版我拍 3ns；实测短路后 9.13ns、条件注入前 58.6ns。诚实修正理由——① 绝对量级：9ns/选择器/帧 × 1Hz × 10 规则 = 90ns/s，占 1ms 帧预算 **0.009%**；② 门禁目的是**捕捉数量级异常**（58ns 那种无条件付税），不是逼近基线；③ 压到 3ns 需改装载路径/内联，**用架构妥协换 6ns 是坏交易**。故 10ns + 端到端 5% 双硬判据 |
| 10b | **新层抽象成本**（观测值，不阻断） | `BenchmarkLiteralEval`（新层 `Plan.Eval` 3.6–4.0 ns / 0 alloc）只 WARN，阈值 ≤10ns 且 0 alloc。**必须打印说明**：生产 literal 按 G-6 走 legacy `matchField`，新层成本不计入回归判据 |

| 11 | **回滚盘点** | `backend/scripts/check_field_selectors.sh` 可列出库中所有非字面量 selector 值；**无该脚本不得执行代码回退**（窄复核 N-1：v0.2 只有要求没有交付物） |
