## 一、前端验收

### 1.1 Login 页面

- [ ] 打开 `/login` 页面正常显示品牌区 (logo+名+描述)
- [ ] 用户名/密码为空时点击登录 → 提示 "请输入..."
- [ ] 用户名/密码错 → 错误提示 "用户名或密码错误，还剩 N 次机会"
- [ ] 5 次连续失败 → 锁定 5 分钟, 按钮 disabled, 倒计时显示
- [ ] "记住我" 勾选 → localStorage 存 token
- [ ] 不勾 → sessionStorage 存 token
- [ ] 登录成功 → 跳到 `?redirect` 参数或 `/dashboard`
- [ ] 登录成功 → 顶栏显示当前用户名 + 角色标签
- [ ] "忘记密码" 链接 → 弹出对话框说明联系管理员

### 1.2 顶栏下拉

- [ ] 点击 "A admin" 头像 → 弹出下拉 (个人设置/用户管理-仅 admin/退出登录)
- [ ] 点击 "个人设置" → 跳 `/profile`
- [ ] 点击 "用户管理" (仅 admin) → 跳 `/admin/users`
- [ ] 点击 "退出登录" → 二次确认 → 清 token + 跳 login
- [ ] 退出后刷新页面不自动登录

### 1.3 个人设置页

- [ ] 显示当前用户头像 + 用户名 + 角色 + 邮箱
- [ ] 改密表单: 当前密码 + 新密码 + 确认新密码
- [ ] 两次输入不一致 → 错误提示
- [ ] 新密码 < 6 位 → 错误提示
- [ ] 改密成功 → "请重新登录" → 1.5s 后跳 login

### 1.4 用户管理页 (仅 admin)

- [ ] 列表显示: ID/用户名/邮箱/角色/状态/创建时间/最后登录
- [ ] 顶部 4 个统计卡 (admin/operator/viewer/总数)
- [ ] 关键词搜索 (用户名/邮箱)
- [ ] 角色筛选下拉
- [ ] "新建用户" → 弹对话框 (用户名+密码+邮箱+角色+启用)
- [ ] "编辑" → 弹对话框 (预填)
- [ ] "重置密码" → 弹对话框 (新密码)
- [ ] "删除" → 二次确认 (禁用删除自己)
- [ ] 操作列对 viewer 角色用户不可见 (v-permission)

### 1.5 403 页面

- [ ] 普通用户访问 admin 专属路由 → 跳 `/403`
- [ ] 403 页显示当前用户名 + 角色标签
- [ ] "返回首页" / "切换账号" 按钮正常

## 二、后端验收

### 2.1 端点

- [ ] `POST /api/v1/auth/login` (body: username+password) 返回 200 + token+user
- [ ] 错密码返回 401 + error 字段
- [ ] `GET /api/v1/users` 需要 admin token, 否则 403
- [ ] `GET /api/v1/users` 返回 list + total 信封
- [ ] `GET /api/v1/users?keyword=...&role=...` 过滤
- [ ] `POST /api/v1/users` 创建 (admin)
- [ ] `PUT /api/v1/users/:id` 更新
- [ ] `DELETE /api/v1/users/:id` 删除
- [ ] `POST /api/v1/users/me/change-password` 改密 (任意登录)
- [ ] 错密码改密 → 400

### 2.2 鉴权

- [ ] 任何需鉴权的端点无 token → 401
- [ ] 错 token → 401
- [ ] 过期 token → 401
- [ ] admin 端点被 operator 调 → 403
- [ ] middleware 解析 token 后 ctx.Set("user_id", ...)

### 2.3 安全

- [ ] 密码 bcrypt 存储, 数据库中无明文
- [ ] 登录失败统一返回 "invalid username or password"
- [ ] 错误信息不暴露用户存在与否
- [ ] JWT exp 24h (生产) / 7d (开发)
- [ ] 中间件不 panic 即使 token 错乱

### 2.4 模型

- [ ] users 表 7 字段 + 索引 (username unique, role)
- [ ] AutoMigrate 自动建表
- [ ] 软删除 (未实现 P2)

## 三、节点端验收

> 节点 (ESP32) 不直接调用 auth 端点, 但需遵循以下约定:

### 3.1 MQTT ACL

- [ ] ESP32 用 node-specific username/password 认证 broker
- [ ] ACL 限制只能 pub `nodes/{自己的_id}/up`
- [ ] ACL 限制只能 sub `nodes/{自己的_id}/down`
- [ ] 跨节点 topic 访问被 broker 拒绝

### 3.2 Token 不下沉

- [ ] ESP32 不持有 JWT
- [ ] 后端用 node_id 而非 JWT 鉴权 MQTT 消息
- [ ] MQTT 处理层不解析 Authorization header (用 broker 替代)

### 3.3 凭据管理

- [ ] ESP32 MQTT 凭据存在 NVS (加密分区)
- [ ] 出厂设置清空 NVS (含 MQTT 凭据)
- [ ] 配网模式 (SoftAP) 可重新配 MQTT 凭据

## 四、集成验收

### 4.1 端到端

- [ ] 浏览器 → 登录 → 顶栏显示 admin
- [ ] 改 URL 到 /monitor (admin only) → 正常显示
- [ ] 改 URL 到 /monitor (operator 登录) → 跳 403
- [ ] 退出 → 跳 login
- [ ] admin 在用户管理页创建新 operator → 列表立即显示
- [ ] 新 operator 登录 → 看不到 /monitor 和 /admin/users
