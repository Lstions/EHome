# 采集器 — 详细设计

> **模块**: 采集器 (Collector)
> **实现**: [实现/采集器.md](../../实现/采集器.md)
> **验收**: [验收标准.md](验收标准.md)

## 1. 功能概述

采集器是 ESP32 边缘节点的 Server 侧抽象。每个 ESP32 物理设备对应一个 Collector 记录，承担:
- 状态跟踪 (online/offline)
- 资源编排 (channels / bus / config)
- 心跳管理 (PingTracker, 60s/次)
- OTA 升级
- MQTT 消息路由

### 1.1 端点

| 端点 | 方法 | 权限 | 用途 |
|------|------|------|------|
| `/api/v1/collectors` | GET | 登录 | 列表 (分页 + 过滤) |
| `/api/v1/collectors/:id` | GET | 登录 | 详情 |
| `/api/v1/collectors` | POST | admin | 手动注册 (e.g. 配网前预占) |
| `/api/v1/collectors/:id` | PUT | admin | 编辑 |
| `/api/v1/collectors/:id` | DELETE | admin | 注销 |
| `/api/v1/collectors/:device_id/channels` | GET | 登录 | 该 collector 下 channels |
| `/api/v1/collectors/:device_id/data` | GET | 登录 | 历史数据 |
| `/api/v1/collectors/:device_id/ping` | POST | 登录 | 主动 ping |

## 2. 数据模型

```sql
CREATE TABLE collectors (
  id                    SERIAL PRIMARY KEY,
  device_id             VARCHAR(64) UNIQUE NOT NULL,  -- 物理 device id
  name                  VARCHAR(64) NOT NULL,
  model                 VARCHAR(64),
  firmware_version      VARCHAR(32),
  protocol_version      VARCHAR(16) DEFAULT '2.0',
  platform              VARCHAR(16),                  -- ESP32 / ESP32S3 / ESP32C6
  status                VARCHAR(16) DEFAULT 'offline',-- online/offline/unknown
  last_seen             TIMESTAMPTZ,
  last_ping_at          TIMESTAMPTZ,
  uptime_seconds        INTEGER DEFAULT 0,
  ping_latency_ms       INTEGER DEFAULT 0,
  mqtt_topic_up         VARCHAR(128),
  mqtt_topic_down       VARCHAR(128),
  wifi_ssid             VARCHAR(64),
  wifi_rssi             INTEGER,
  free_heap_bytes       INTEGER,
  capabilities          JSONB,                        -- max_channels / supports_ota
  hardware_info         JSONB,                        -- { uart: [{port: 1, baud: 115200}] }
  created_at            TIMESTAMPTZ DEFAULT NOW(),
  updated_at            TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_collectors_status ON collectors(status);
CREATE INDEX idx_collectors_last_seen ON collectors(last_seen);
```

## 3. 状态机

### 3.1 Collector 状态

```
   创建
    ↓
 unknown ──→ online ──→ offline
              │  ↑       │
              │  └───────┘ (心跳恢复)
              ↓
           (网络断开/Hello 重连)
```

| 状态 | 触发 |
|------|------|
| `unknown` | 创建时默认, 等待第一次 Hello |
| `online` | 收到 Hello / StatusReport (60s 内) |
| `offline` | 离线检测器判定 (last_seen > 10min) |
| `disabled` | 手动禁用 (admin 操作, P3 计划) |

### 3.2 离线检测

```
[PingTracker] 每 30s 检查所有 online 的 collector
  ↓
若 last_seen > 10min:
  - status = offline
  - 推 collector_status 事件到前端
  - 触发 notifications 表新增 (level=warning, msg="Collector xxx went offline")
```

## 4. 关键流程

### 4.1 Hello 握手 (type=0x01, ESP→SVR)

详见 [总体设计 §2.1](../总体设计.md#21-设备接入流-hello-握手)

```
ESP32 → mqtt.up: {device_id, firmware_version, model, channel_count, hardware_types}
  ↓
[server/collector/handler_hello.go]
  1. 校验 device_id 格式 (UUID/短 ID)
  2. UPSERT collectors 表
  3. 写 last_seen = NOW(), status = online
  4. 触发 HandleHelloOTACompletion (OTA 自动完成)
  5. 发 HelloAck (type=0x12) 含 ConfigManifest
  6. 推 collector_status 事件
  7. 推 notification 事件 (仅首次上线)
```

### 4.2 心跳 (type=0x02, StatusReport)

```
ESP32 → mqtt.up: {device_id, uptime, free_heap, wifi_rssi, status_flags}
  ↓ (60s 间隔)
[server/collector/handler_status.go]
  1. 更新 last_ping_at, uptime, free_heap
  2. 重置 last_seen
  3. 推 collector_status 事件
```

### 4.3 配置下发 (HelloAck 内 type=0x04, ConfigManifest)

```
[server] 计算 config_hash (SHA256 of current config JSON)
  ↓
[server] 查询 collector 当前 hash (from Redis cache)
  ↓
若 hash 不一致:
  发 ConfigManifest (type=0x04) → 完整 config JSON
  ↓
[ESP32] 收到 → 写 NVS → 发 ConfigResult (type=0x05)
  ↓
[server] 写 collector.config_hash = new_hash
```

### 4.4 主动 Ping

```
前端 → POST /api/v1/collectors/:device_id/ping
  ↓
[server] 发 Ping (type=0x08) 到 mqtt.down
  ↓
[ESP32] 收到 → 发 Pong (type=0x09) 含 timestamp
  ↓
[server] 收到 Pong → 计算 RTT → 更新 collector.ping_latency_ms
  ↓
推 collector_status 事件 (含新 RTT)
  ↓
前端 → 显示 RTT (e.g. "23ms")
```

## 6. 容错设计

| 场景 | 行为 |
|------|------|
| Hello 重复 device_id | UPSERT (不报错) |
| 设备断电 (无离线信号) | last_seen 超 10min 自动 offline |
| ConfigManifest 发送失败 | 3 次重试, 失败进 notifications |
| 心跳超时 | 30s 检测, 10min 阈值 |
| MQTT 断 | 客户端自动重连, 不影响数据流 |

## 7. 可观测性

| 事件 | 字段 |
|------|------|
| `collector.hello.received` | device_id, firmware_version |
| `collector.status.changed` | device_id, from_status, to_status |
| `collector.ping.sent` | device_id |
| `collector.pong.received` | device_id, rtt_ms |
| `collector.offline.detected` | device_id, last_seen_age |

| 指标 | 类型 | 标签 |
|------|------|------|
| `ehome_collector_online_count` | gauge | - |
| `ehome_collector_total_count` | gauge | platform |
| `ehome_ping_rtt_ms` | histogram | device_id |
| `ehome_hello_received_total` | counter | - |

## 8. 安全

- MQTT topic ACL: 设备只能 pub/sub 自己的 topic
- HTTP API 端点: 任何操作需 admin (POST/PUT/DELETE) 或登录 (GET)
- ConfigManifest 不含敏感凭据 (MQTT password 在 NVS, 不在 manifest)
