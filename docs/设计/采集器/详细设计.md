## 1. 功能概述

采集器是 ESP32 边缘节点的 Server 侧抽象。每个 ESP32 物理设备对应一个 Collector 记录，承担:
- 状态跟踪 (online/offline)
- 资源编排 (channels / bus / config)
- 心跳管理 (StatusReport, 60s/次 + v2.1 epoch 上报)
- OTA 升级 (HTTPS + SHA256, v2.1)
- **多通道配置同步 (v2.1, SyncGate)**
- **Config Epoch 持久化 (v2.1)**
- MQTT 消息路由

### 1.1 端点 (不变)

| 端点 | 方法 | 权限 | 用途 |
|------|------|------|------|
| `/api/v1/collectors` | GET | 登录 | 列表 (分页 + 过滤) |
| `/api/v1/collectors/:id` | GET | 登录 | 详情 |
| `/api/v1/collectors` | POST | admin | 手动注册 |
| `/api/v1/collectors/:id` | PUT | admin | 编辑 (v2.1: 触发 ConfigChange) |
| `/api/v1/collectors/:id` | DELETE | admin | 注销 |
| `/api/v1/collectors/:device_id/channels` | GET | 登录 | 该 collector 下 channels |
| `/api/v1/collectors/:device_id/data` | GET | 登录 | 历史数据 |
| `/api/v1/collectors/:device_id/ping` | POST | 登录 | 主动 ping |

> **v2.1 新增**: 所有 PUT/POST/DELETE 必须 `defer EmitConfigChange()` (通过 CRUD helper 强制)

## 2. 数据模型

```sql
CREATE TABLE collectors (
  id                    SERIAL PRIMARY KEY,
  device_id             VARCHAR(64) UNIQUE NOT NULL,
  name                  VARCHAR(64) NOT NULL,
  model                 VARCHAR(64),
  firmware_version      VARCHAR(32),
  protocol_version      VARCHAR(16) DEFAULT '2.1',  -- v2.1 升级
  platform              VARCHAR(16),
  status                VARCHAR(16) DEFAULT 'offline',
  last_seen             TIMESTAMPTZ,
  last_ping_at          TIMESTAMPTZ,
  uptime_seconds        INTEGER DEFAULT 0,
  ping_latency_ms       INTEGER DEFAULT 0,
  mqtt_topic_up         VARCHAR(128),
  mqtt_topic_down       VARCHAR(128),
  wifi_ssid             VARCHAR(64),
  wifi_rssi             INTEGER,
  free_heap_bytes       INTEGER,
  capabilities          JSONB,
  hardware_info         JSONB,
  -- v2.1 新增字段 ↓
  config_epoch          BIGINT DEFAULT 0,           -- 采集器当前 epoch
  last_manifest_id      VARCHAR(64),                 -- NVS 中 manifest_id
  config_sync_state     VARCHAR(16) DEFAULT 'unknown',-- in_sync/syncing/lag/error
  last_sync_at          TIMESTAMPTZ,                 -- 上次同步时间
  last_sync_id          VARCHAR(64),                 -- 上次 sync_id
  created_at            TIMESTAMPTZ DEFAULT NOW(),
  updated_at            TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_collectors_status ON collectors(status);
CREATE INDEX idx_collectors_last_seen ON collectors(last_seen);
CREATE INDEX idx_collectors_config_epoch ON collectors(config_epoch);  -- v2.1
```

**v2.1 新增**:
- `config_epoch`: 采集器当前 epoch (Hello 上报,ConfigManifest 同步)
- `last_manifest_id`: 最近应用的 manifest_id (Hello 上报)
- `config_sync_state`: in_sync / syncing / lag / error (前端可视化)
- `last_sync_at` / `last_sync_id`: 同步审计

**v2.1 新增 config_meta 表** (全局 epoch):

```sql
CREATE TABLE config_meta (
  id        INTEGER PRIMARY KEY DEFAULT 1,
  epoch     BIGINT NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 启动时 init
INSERT INTO config_meta (id, epoch) VALUES (1, 0) ON CONFLICT DO NOTHING;
```

### 3.1 Collector 状态 (不变)

```
   创建
    ↓
 unknown ──→ online ──→ offline
              │  ↑       │
              │  └───────┘ (心跳恢复)
              ↓
           (网络断开/Hello 重连)
```

### 3.2 离线检测 (不变, Redis TTL 15s + DB 90s)

### 3.3 同步状态 (v2.1 新增)

**新增** `config_sync_state` 字段, 表示当前配置同步状态:

```
                ┌──────────┐
                │ unknown  │ (新设备, 等待首次同步)
                └─────┬────┘
                      │ 收到 ConfigManifest
                      ↓
                ┌──────────┐
                │ syncing  │ (ConfigResult 尚未回, 或 Apply 进行中)
                └─────┬────┘
                      │ 收到 ConfigResult success
                      ↓
            ┌──────────────────┐
            │     in_sync      │ ◄─────┐
            └────────┬─────────┘       │
                     │                  │ (ConfigResult success)
                     │                  │
       (ConfigChange / Restart)         │
                     ↓                  │
            ┌──────────────────┐       │
            │       lag        │ ──────┘
            └──────────────────┘
                     │
                     │ 错误 (NVS 写失败 / Manifest 解析失败)
                     ↓
            ┌──────────────────┐
            │      error       │ (告警 + 进入离线状态等)
            └──────────────────┘
```

**状态转移触发**:

| 从 | 到 | 触发 |
|----|----|----|
| unknown | syncing | 收到 ConfigManifest (从无 → 有) |
| syncing | in_sync | 收到 ConfigResult success |
| syncing | error | 收到 ConfigResult fail / NVS 写失败 |
| in_sync | lag | 收到 ConfigChange / Server restart / epoch bump |
| lag | syncing | 收到 ConfigManifest |
| error | syncing | 重试 1 次, 收到新 ConfigManifest |

## 4. 关键流程

### 4.1 Hello 握手 (type=0x01, ESP→SVR, v2.1)

```
ESP32 → mqtt.up: {                          // v2.1 扩展字段
  device_id, firmware_version, model, channel_count,    // 已有
  config_epoch, nvs_has_config, last_manifest,          // v2.1 新增
  protocol_version="2.1"                                // v2.1 新增
}
  ↓
[server/collector/handler_hello.go]
  1. 解析 v2.1 字段 (老固件缺失字段用默认值)
  2. UPSERT collectors 表 (含 config_epoch, last_manifest_id)
  3. 写 last_seen = NOW(), status = online
  4. **SyncGate.OnHello(deviceID, hello)** (v2.1 决策)
     ├─ nvs_has_config=false → 强制下发 (修复 G3)
     ├─ hello.config_epoch < server.epoch → 强制下发
     ├─ hello.last_manifest != server.manifest_id → 强制下发
     └─ 否则 dedup 决定
  5. 决策结果 → sendConfigManifestWithDecision(decision)
     - decision.sync_id 贯穿全链路
     - decision.reason 进日志
  6. 触发 HandleHelloOTACompletion
  7. 推 collector_status 事件
  8. 推 collector_config_synced 事件 (含 sync_id)
  9. 推 notification 事件 (仅首次)
```

### 4.2 心跳 (type=0x02, StatusReport, v2.1)

```
ESP32 → mqtt.up: {                          // v2.1 扩展
  uptime_sec, status, channel_count,        // 已有
  config_epoch, sync_state                  // v2.1 新增
}
  ↓ (60s 间隔, 可配置)
[server/collector/handler_status.go]
  1. 更新 last_ping_at, uptime, free_heap
  2. 更新 config_epoch (采集器上报)
  3. 更新 config_sync_state
  4. **SyncGate.OnStatusReport(deviceID, rpt)** (v2.1, 修复 G5)
     ├─ rpt.config_epoch < server.epoch → 推 ConfigManifest
     └─ 否则 in_sync
  5. 推 collector_status 事件
  6. **新**: offline→online 时强制 sync (旧只 init, 不 sync)
```

### 4.3 配置下发 (type=0x04, ConfigManifest, v2.1)

**触发源** (v2.1 多通道):
- Hello (device 主动)
- StatusReport (周期上报发现 epoch 落后)
- ConfigChange (服务端 CRUD 触发)
- ServerStartup (服务端启动)
- ConfigQuery (采集器主动)

**流程**:
```
[SyncGate] 决策 SyncDecision{Action: Full, Reason: ..., SyncID: uuid}
  ↓
[Manager.sendConfigManifestWithDecision(deviceID, decision)]
  1. 读 templates + channels (DB)
  2. 编码 ConfigManifest (含 config_epoch + sync_id + sync_reason)
  3. MQTT publish
  4. DB update: config_sync_state = 'syncing'
  5. log: [sync_id=xxx] action=full reason=xxx
  6. metrics: ehome_sync_decisions_total{reason=xxx,action=full}++
  ↓
[ESP32] 收到 → config_mgr_apply_manifest
  ├─ 解析 (含 epoch, sync_id)
  ├─ 写 NVS (cfg_epoch, manifest_id)
  ├─ 启动/更新 scheduler
  └─ 发 ConfigResult (含 success/error)
  ↓
[Server] 收到 ConfigResult
  ├─ success: config_sync_state = 'in_sync', last_sync_at = NOW()
  └─ fail: config_sync_state = 'error', alarm
  ↓
  推 collector_config_synced { sync_id, result }
```

### 4.5 同步流程 (v2.1 多通道统一入口)

**所有同步入口走 SyncGate**:

```go
// 入口 1: Hello → SyncGate.OnHello()
func (m *Manager) handleHello(deviceID string, payload []byte) {
    // ... 解析 + upsert
    decision := m.syncGate.OnHello(deviceID, hello)
    if decision.Action != SyncActionNone {
        m.sendConfigManifestWithDecision(deviceID, decision)
    }
}

// 入口 2: StatusReport → SyncGate.OnStatusReport() (v2.1 新增)
func (m *Manager) handleStatusReport(deviceID string, payload []byte) {
    // ... 解析
    decision := m.syncGate.OnStatusReport(deviceID, rpt)
    if decision.Action != SyncActionNone {
        m.sendConfigManifestWithDecision(deviceID, decision)
    }
    // 保留: offline→online 触发 triggerDeviceInit
}

// 入口 3: ConfigChange → SyncGate.OnConfigChange() (v2.1 新增, 修复 G1)
func (m *syncGate) OnConfigChange(evt ConfigChangeEvent) {
    // 影响范围分析
    affectedCollectors := m.analyzeImpact(evt)
    for _, c := range affectedCollectors {
        decision := SyncDecision{
            Action: SyncActionFull,
            Reason: fmt.Sprintf("config_change:%s:%s", evt.Type, evt.Action),
            SyncID: uuid.New().String(),
            ...
        }
        m.sendConfigManifestWithDecision(c.DeviceID, decision)
    }
}

// 入口 4: ServerStartup → SyncGate.OnServerStartup() (v2.1 新增, 修复 G2)
func (m *syncGate) OnServerStartup() {
    var collectors []models.Collector
    m.db.Where("status = ?", "online").Find(&collectors)
    for _, c := range collectors {
        decision := SyncDecision{
            Action: SyncActionFull,
            Reason: "server_startup_reconciliation",
            SyncID: uuid.New().String(),
            ...
        }
        m.sendConfigManifestWithDecision(c.DeviceID, decision)
    }
}

// 入口 5: ConfigQuery → SyncGate.OnConfigQuery() (v2.1 新增)
func (m *Manager) handleConfigSyncRequest(deviceID string, payload []byte) {
    decision := m.syncGate.OnConfigQuery(deviceID, q)
    if decision.Action == SyncActionNone {
        m.sendConfigSyncResponse(deviceID, inSync=true)
    } else {
        m.sendConfigManifestWithDecision(deviceID, decision)
    }
}
```

## 6. 容错设计 (v2.1 强化)

| 场景 | 行为 | 修复 GAP |
|------|------|---------|
| Hello 重复 device_id | UPSERT (不报错) | - |
| 设备断电 (无离线信号) | Redis TTL 15s + DB last_seen 90s | - |
| ConfigManifest 发送失败 | 退避重试 3 次 + 失败进 notifications | - |
| 心跳超时 | 30s 检测, 10min 阈值 (老规范) | - |
| MQTT 断 | 客户端自动重连, 触发新 Hello | - |
| **服务端重启丢内存态** | **启动 5s 后 push 所有 online collector** | **G2** |
| **采集器恢复出厂 (NVS 空)** | **SyncGate 检测 nvs_has_config=false 强制下发** | **G3** |
| **服务端改配置不通知** | **ConfigEventBus 自动发出事件 → SyncGate 推送** | **G1** |
| **ConfigEventBus 满** | **drop + alarm, 不阻塞 CRUD** | - |
| **同步失败兜底** | **30s 后周期 sync 兜底, MQTT 断自动重连** | - |
| **OTA 证书不匹配** | **HTTPS TLS 验证失败, 拒绝升级** | - |
| **OTA SHA256 不匹配** | **拒绝刷写, 上报 fail 状态** | - |

## 8. 安全 (v2.1 强化)

- MQTT topic ACL: 设备只能 pub/sub 自己的 topic
- HTTP API 端点: 任何操作需 admin (POST/PUT/DELETE) 或登录 (GET)
- **v2.1**: ConfigEventBus 事件包含 `actor` 字段, 审计"谁改了什么"
- **v2.1**: OTA HTTPS + CRT bundle 验证, 不允许 HTTP 明文下载
- **v2.1**: WS 事件名通过 const 共享, CI 校验 union match, 防"幽灵订阅"
