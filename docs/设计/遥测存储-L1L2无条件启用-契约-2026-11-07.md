## 1. 用户裁决

> 完成并打开遥测存储的 L1 、L2 帧级编码，同时删除开关

拆解为四条硬要求：

1. **L1 无条件启用**：不再有影子模式，值不变且未到心跳 ⇒ 直接不写 `unified_data`
2. **L2 无条件启用**：双写 `telemetry_frame` 成为主路径（不是影子）
3. **删除开关**：`EHOME_TELEMETRY_WRITE_ON_CHANGE` / `EHOME_TELEMETRY_DUAL_WRITE` / `EHOME_TELEMETRY_ROLLUP_WRITE` 三个环境变量与对应 config 字段全部删除，不是「默认改 true」
4. L3 rollup 写入侧无条件常驻；**读侧开关 `EHOME_TELEMETRY_ROLLUP_READ` 保留**（读切换有风险，用户只要求 L1/L2）

## 2. 为什么必须同时改读路径（否则会出事）

L1 打开后 `unified_data` 不再是完整 1 Hz 序列。以下读路径必须同步改口径：

| # | 读路径 | 现在的语义 | L1 后的 bug | 必须改成 |
|---|---|---|---|---|
| **D1** | `agg=avg` 降采样（`history_points.go:historyAvgSQL`） | `avg(value)` 按桶平均 | 恒定值段只有 1 行（心跳），阶跃段有 N 行 ⇒ **平均值偏向变化频繁的段**（实测电流最大偏差 0.17 A） | 桶内**最后值**（PG: `(array_agg(value ORDER BY timestamp DESC))[1]`），实测偏差恒 0 |
| **D2** | `/overview` 的 `data_count_today`（`handler_overview.go:145`） | 今日 `unified_data` 行数 | 行数降到 17.7%，**用户会以为数据丢了** | 改口径为「今日写入的采样帧数」并改前端文案 |
| **D3** | `/metrics/summary` 的 `points_stored`（`handler_metrics.go:119`） | `unified_data` 总行数 | 同上 | 同上 |
| **D4** | `/sensor-fields/preview` 按 timestamp 分帧（`handler_sensor_fields.go:382`） | 一帧 = 同一 timestamp 的多行 | 帧变稀疏（60s 心跳才一帧） | 分帧窗口改为「同一 sensor 相邻行」或显式标注 |
| **D5** | `agg=change` | 相邻值变化点 | **无需改**（变化点全保留） | 不动 |

### 2.1 D1 的具体实现（PG / SQLite 双方言）

```sql
-- 现状（错）
avg("value") AS "value"

-- 改后（桶内最后值，PG）
(array_agg("value" ORDER BY "timestamp" DESC))[1] AS "value"
```

SQLite 用子查询或 `MAX(...) FILTER` 等价形态；**必须保留 SQLite 路径可测**。
**硬验收**：恒定段的 avg 与桶内最后值必须相等。

### 3.4 失败语义裁决

| 场景 | 启用后必须 |
|---|---|
| L1 写库失败 | **状态不得推进**（否则变化永久丢失）—— 已实现，保留 |
| L2 编码/写库失败 | **只 Warn + 计数，绝不影响主写入** |
| L2 表不存在（迁移未跑） | **启动期 Fatal**（不允许主写成功但帧表没建这种半残状态） |
| L3 rollup 写失败 | 只 Warn（派生数据） |

- L1 删 policy 分支判断
