## 1. 概念关系总图

```
                    ┌──────────────────────────────────┐
                    │        中心端 (Center)             │
                    │  Go 后端 + Vue 前端                │
                    │  权威源：节点/通道/设备配置/         │
                    │  边缘设备/逻辑设备/数据              │
                    └──────────────┬────────────────────┘
                                   │ MQTT (帧协议 0x01-0x1D)
                                   │ + HTTP REST + WebSocket
        ┌──────────────────────────▼───────────────────────────┐
        │  节点 (Node) ──── 1:N ────► 通道 (Channel)             │
        │  ESP32-S3/C6 物理整机       UART/I2C/SPI/ADC 物理端点   │
        │  node_id / firmware_ver    (GPIO/PWM 不走通道)         │
        │        │                        │ 1:N                 │
        │        │                        ▼                     │
        │        │           边缘设备 (EdgeDevice)               │
        │        │      = Node + Channel + DeviceConfig         │
        │        │        + hardware_id 的实例化                 │
        │        │                        │ N:1                  │
        │        │                        ▼                     │
        │        │           设备配置 (DeviceConfig)             │
        │        │           型号级协议无关定义                   │
        │        │                                             │
        │   GPIO/PWM 直控 ◄──── PeriphCmd/PeriphRsp (0x1B/0x1C) │
        └───────────────────────────────────────────────────────┘
                                     │
                                     ▼
                    逻辑设备 (LogicalDevice)   ← 数据身份层
                    数据血缘与身份解耦（v3.3）
```

## 2. 实体关系（E-R 摘要）

| 实体 | 关键字段 | 关系 |
|------|---------|------|
| nodes | id, node_id(唯一), model, firmware_version, status, last_seen, config_epoch | 1:N channels; 1:N edge_devices |
| channels | id, node_id(FK), hardware_type, bus_config, hardware_id | N:1 nodes; 1:N edge_devices |
| device_configs | id, name, device_type, vendor, connection, parser, init_flow | 1:N edge_devices |
| edge_devices | id, node_id, channel_id, device_config_id, hardware_id, interval_ms, enabled, status, logical_device_id | N:1 三者; 1:1 logical_devices |
| logical_devices | id, identity_key(唯一), name, device_type, retention_days, merged_into, merge_status | 1:N edge_devices; 1:N unified_data(归属) |
| unified_data | id, edge_device_id(血缘), logical_device_id(归属), sensor_name, value, unit, timestamp | 纯追加时序表，无软删 |

核心不变量：

1. **节点不感知 EdgeDevice/DeviceConfig**：协议只下发 Channel + Template + 外设配置。EdgeDevice 身份（id/device_config_id）是中心端内部信息。
2. **三元组唯一性**：同 (channel, hardware_id, type) 不可重复；不同从机地址允许（I2C 多地址/SPI 多 CS 合法）。
3. **GPIO/PWM 剥离**：只有可数据交互的协议总线入通道；GPIO 引脚直控、PWM LEDC 直控走 PeriphCmd/PeriphRsp。
4. **数据血缘与身份分离**（v3.3）：unified_data.device_id 记物理采集来源（永不改写）；logical_device_id 记数据归属身份（可合并迁移）。合并是 UPDATE logical_device_id 原地改写，不是 INSERT 搬迁。
5. **资源上报制**：硬件资源只来自 ResourceReport(0x19) 上报，中心端零硬编码型号资源。

## 3. 拓扑示例

### 3.1 简单 1:1（SPI）

```
节点: esp32c6_001
├─ 通道 1: SPI2 (mosi=11, miso=13, sck=12, cs=10, 10MHz)
│   └─ 边缘设备 10: BMP280 (SPI), hardware_id=0, interval_ms=1000
└─ 通道 2: I2C0 (sda=8, scl=9, 400kHz)
```

### 3.2 共享总线多从机（UART 多地址，v3.3 合法形态）

```
节点: esp32s3_002
└─ 通道 3: UART1 (tx=20, rx=21, 4800 8N1)
    ├─ 边缘设备 11: BMS 嘉佰达, hardware_id=0x01, interval_ms=5000
    └─ 边缘设备 12: SN-3001 雨量, hardware_id=0x02, interval_ms=1000
```

### 3.3 GPIO/PWM 直控（不入通道）

```
节点: esp32c6_001
├─ 通道 1: UART0（传感器数据总线）
└─ 外设直控（非通道）:
    ├─ GPIO5: 继电器（PeriphCmd SET_HIGH/LOW/READ）
    └─ PWM0 (LEDC ch0): 风扇调速（freq/duty 可调）
```

### 3.4 逻辑设备身份与合并（v3.3）

```
边缘设备 11 (BMS #1, UART0) ─┐
                              ├─► 逻辑设备 L1 (identity_key="bms_jbd:0x01")
边缘设备 33 (BMS #2, 更换后) ─┘      │ retention=90d
                                     ▼
                            unified_data 行同时持有:
                            edge_device_id=11/33（血缘）
                            logical_device_id=L1（归属，可 merge 追溯）
```

## 4. 关键解耦决策（架构评估确认正确、不应动的部分）

| 决策 | 为什么对 |
|------|---------|
| 三层模型：中心端持有全部状态、节点无业务逻辑 | 节点可替换、协议演进可控——全系统最重要抽象 |
| 二进制帧协议（自研，protobuf-wire 兼容） | ~50B vs ~150B（-67%）、~200ns vs ~10μs（-50x）、hex 可调试、C/Go 共享语义头文件 |
| SyncGate + Epoch + manifest hash 三重兜底 | 配置最终一致：Hello 决策 + 中心端重启 push + 节点周期 sync |
| 资源全部来自 ResourceReport | 新硬件型号零后端改动（通用性原则） |
| Driver Registry + ConfigTemplate + 逐指令 Manifest | 新设备 = 配置 + parser + 动作定义，多数不改代码 |
| DataEventBus 进程内分片 | 单二进制内 ingest→persist→push 扇出（10000 events/s），不引入网络 MQ |
| OTA：HTTPS + SHA256 + A/B + 30s mark-valid | 帧丢失→Hello 补完成；并发→supersede |

## 5. 明确不做（产品决策，v3.x 持续有效）

- 多用户/多角色管理界面（单主体模式）；RBAC 仅保留 API 层语义
- GPIO/PWM 走通道系统（已裁决，见 GPIO与PWM外设控制.md）
- 中心端硬编码任何 ESP32 型号资源
- 微服务/服务网格、protobuf/gRPC、多租户、Kubernetes
