# 认证与账户运维指南

> **状态**: 已实现（单用户/单管理员认证现行运维流程）
> **版本**: v1.0
> **日期**: 2026-08-22
> **关联**: [../设计/认证授权.md](../设计/认证授权.md) | [../设计/总体设计.md](../设计/总体设计.md)

## 目标

覆盖单主体认证模式的日常运维：管理员初始化、密码重置、事故排查。系统只有一个可登录主体（system_admin），禁多用户 CRUD。

## 1. 管理员初始化

**首次部署（空库）**：

1. 后端启动后数据库为 `auth_states` 无行 → 前端登录页显示"迁移未完成/初始化引导"。
2. 生成一次性初始化凭据：
   ```bash
   ehomectl auth create-initialization-token
   ```
3. 前端"首次运行设置"表单粘贴凭据 + 填写管理员用户名/密码（≥8 字符）。
4. 初始化成功后该入口永久关闭（AuthState 从 uninitialized 转变）。

**开发环境速通**：`make auth-bootstrap` 重新生成凭据；`make up` 自动执行 bootstrap（v2.2+）。

## 2. 密码重置

```bash
EHOME_NEW_ADMIN_PASSWORD='<≥12字符新密码>' ehomectl auth reset-password
```

注意：

- 重置密码会使 session_version 自增 → 所有已签发 JWT 立即失效（登录页 401 属预期）。
- 若想保留会话，别重置；若想踢出所有会话，重置密码是有效手段。

## 3. 登录排障速查

| 症状 | 诊断 | 处置 |
|------|------|------|
| 登录 403 且 body 为空 | CORS 白名单不匹配（前端从局域网 IP 访问，Origin 不在白名单） | `EHOME_ALLOWED_ORIGINS=*` 或加入实际 Origin |
| 403 且有 JSON envelope | 业务拒绝（recent_auth_required / 密码修改要求重认证） | 按 envelope 提示操作 |
| 401 所有 token 都失效 | 密码被重置 / session_version 变化 | 重新登录 |
| 429 | 登录限流（解析 Retry-After） | 等窗口过期 |
| 初始化后仍显示"迁移未完成" | auth_states 行缺失（make clean 删卷后） | bootstrap-database + create-initialization-token + POST /api/v1/auth/initialize |
| dev 环境 token 一直 401 | 运行进程 JWT secret 是 Makefile 硬编码值而非 .env | 检查进程 environ（`/proc/<pid>/environ` 的 EHOME_JWT） |

## 4. API 变更清单（单主体迁移后）

- 用户列表/创建/编辑/删除、角色选择、他人密码重置端点 → **410 Gone**。
- /account/password（改自己的密码）、/account/reauthenticate、/account/logout-all 保留。
- JWT 有效载荷含 session_version（sv），改密/重置自增。

## 5. 安全边界

- 公开白名单仅：登录、初始化状态查询/提交、/health（部署边界决定 /metrics 是否公开）。
- 其余 REST/WS（业务、终端 WebSocket）全部要求有效会话。
- 凭据、一次性初始化 token、JWT 不得出现在日志/截图/测试产物中。
- 生产模式禁止默认口令（admin/admin123 仅限显式开关的开发环境）。

## 6. 回滚

- 无需回滚（单主体迁移是单向决策）；如需临时多用户，历史 RBAC 版本见 archive/（不支持混合运行）。

## 7. 验证

```bash
curl -s http://localhost:8082/api/v1/auth/initialization   # 返回 authState
curl -s -X POST http://localhost:8082/api/v1/auth/login -d '{"username":"admin","password":"..."}' -H 'Content-Type: application/json'
```
