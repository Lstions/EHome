# 环境变量收敛：只保留部署身份（2026-11-14）

> **状态**：已实施
> **触发**：2026-11-14 生产 BMS 页报「温度趋势加载失败：查询窗口 24h0m0s 超过帧表单次解码上限 1h0m0s」
> **关联**：[长窗图表全坏事故分析](../分析/长窗图表全坏事故分析-2026-11-11.md)、[复盘-日出日落BMS-MOS验证](../分析/复盘-日出日落BMS-MOS验证-2026-11-13.md)

## 1. 规则（一条，可执行）

**环境变量只回答「连哪里、用什么身份」；行为与调参写死为代码常量。**

| 放在 env | 不放在 env |
|---|---|
| 数据库地址/账号、JWT 密钥、mTLS 证书路径、监听地址、静态资源目录、对外 host、保留期、初始管理员 | 「是否启用某路径」「窗口多大」「队列多深」「tick 多快」「灰度开关」 |

配套三条：
1. 测试用显式注入（`SetFrameDecodeMaxWindow` / `DualWriterConfig`），**不读 env**；
2. 仿真用 `//go:build simulation` + `EHOME_SIM_*`，生产二进制里不存在这些变量；
3. 新增 env 必须登记白名单，门禁 `backend/internal/config/env_surface_gate_test.go` 会扫源码。

## 2. 事故链（为什么必须做）

2026-11-14 09:53（UTC）生产重部署，`/srv/ehomesystem/docker-compose.yml` 被仓库模板覆盖，两个遥测变量丢失：

- `EHOME_TELEMETRY_ROLLUP_READ`（代码默认 **false**，生产靠 env 打开）⇒ 长窗不再走分钟聚合；
- `EHOME_TELEMETRY_FRAME_DECODE_MAX_WINDOW`（代码默认 **1h**，生产靠 env 设 6h）⇒ 帧表也拒解 >1h。

结果：24h/7d 图表全部报错（新容器启动后 14 秒出现第一条），而**数据完全正常**
（`telemetry_frame` 86,400 帧/天、`telemetry_rollup_1m` 1,436 桶/24h、coverage complete）。
报错文案还把原因写成「尚未被分钟聚合覆盖」，把排查引向数据侧。

三个结构性缺陷：
1. 「关闭态」不是降级而是故障（关掉帧表读 = 全站 500）；
2. 默认值 ≠ 生产值，且启动日志从不打印生效配置；
3. 两次分界（帧窗 1h / rollup 短窗 6h）可各自漂移 ⇒ `(1h, 6h]` 两个源都不服务的死区。

## 3. 保留清单（生产环境变量面）

| 变量 | 用途 |
|---|---|
| `EHOME_SERVER_ADDR` / `EHOME_ENV` / `LOG_LEVEL` / `GIN_MODE` / `CONFIG_PATH` | 进程身份 |
| `EHOME_DB_HOST/PORT/USER/PASSWORD/NAME/SSLMODE` | 数据库连接 |
| `EHOME_JWT_SECRET` | 令牌签名 |
| `EHOME_ALLOWED_ORIGINS` / `EHOME_STATIC_DIR` / `EHOME_EXTERNAL_HOST` | 对外身份 |
| `EHOME_DEVICE_ADDR/CERT_FILE/KEY_FILE/CLIENT_CA_FILE` | 设备 mTLS 连接材料 |
| `EHOME_ADMIN_USERNAME/PASSWORD/EMAIL` | 初始管理员种子 |
| `EHOME_DATA_RETENTION_DAYS` | 产品策略 |
| `EHOME_NEW_ADMIN_PASSWORD` | `ehomectl` 一次性 CLI 入参 |

> 配套 compose 变量 `EHOME_HTTP_PORT` / `EHOME_DEVICE_PORT` 只在 docker compose 插值，进程不读。

## 4. 删除清单（28 个）与替代行为

| 变量 | 原语义 | 替代 |
|---|---|---|
| `EHOME_TELEMETRY_FRAME_READ` | 帧表读开关（默认 true） | **常开**（unified_data 已 DROP，它是唯一源） |
| `EHOME_TELEMETRY_ROLLUP_READ` | 长窗读 rollup（默认 false） | **常开**，覆盖判据 `RollupWindowCovered` 是唯一闸门 |
| `EHOME_TELEMETRY_FRAME_DECODE_MAX_WINDOW` | 短窗分界（默认 1h） | 常量 **6h**（21,600 帧 ≤ MaxDecodeFrames 32,768） |
| `EHOME_TELEMETRY_ROLLUP_SHORT_WINDOW` | rollup 分界（默认 6h） | 与帧窗**同源**（`rollupShortWindow()`），死区消失 |
| `EHOME_TELEMETRY_ROLLUP_BACKFILL` | 回填开关（默认 true） | **常开**（幂等，跳过已验证单元） |
| `EHOME_TELEMETRY_ROLLUP_BACKFILL_BATCH_SECONDS` / `_SLEEP_MS` | 回填限速 | 常量 3600s / 50ms |
| `EHOME_TELEMETRY_HEARTBEAT_SECONDS` | 关键帧/心跳间隔 | 常量 60s |
| `EHOME_TELEMETRY_DUAL_WRITE_QUEUE` | 双写队列深度 | 常量 4096 |
| `EHOME_DEVICE_ENABLED` | 设备监听开关（默认 false） | 由「证书三件套齐全」推导 |
| `EHOME_DEVICE_CONTROL_V2_ENABLED` | 命令分发急停阀 | 恒开（急停改为改代码发版） |
| `EHOME_RAW_DIAGNOSTICS_ENABLED` | 未审计 raw 读写闸门 | 收敛为 `api.ControlPolicy` 代码字面量 |
| `EHOME_FIELD_RESOLVER_*`（10 个） | 字段解析层灰度/参数 | config.yaml 默认值 |
| `EHOME_STARTUP_MAINTENANCE_PAGE` | 启动维护页回退 | 恒开 |
| `EHOME_STARTUP_FAIL_FAST_SECONDS` | 启动看门狗 | 删除（默认本就关闭） |
| `EHOME_LATEST_WARMUP_LOOKBACK` | 最新值预热窗口 | 常量 24h |
| `EHOME_WINDOW_TICK_INTERVAL` | 自动化 tick | 常量 1m；仿真用 `EHOME_SIM_WINDOW_TICK` |
| `EHOME_COMMAND_DEADLINE` | 命令超时 | 常量 2m；仿真用 `EHOME_SIM_COMMAND_DEADLINE` |
| `EHOME_PARSER_SHARDS` | 解析分片数 | 常量 8（DefaultParserShards） |

## 5. 部署影响（升级本版本时）

1. **不需要再设置任何遥测变量**：24h/7d/30d 图表开箱即用；
2. 旧 `.env` / compose 里残留的被删变量是**无操作**（不报错、不生效）——建议顺手删掉，避免误以为它们还在起作用；
3. `EHOME_DEVICE_ENABLED` 删除后，只要 CertFile/KeyFile/ClientCAFile 三件套齐全就会监听：升级前请确认生产 compose 确实挂载了 `./certs`（当前 `docker-compose.30.yml` 已挂载）；
4. `EHOME_RAW_DIAGNOSTICS_ENABLED` 的取值固定为「开启」（与生产现状一致）；
5. 回滚：单次 revert 即恢复到「可配」形态，无数据迁移。

## 6. 验证

```bash
go build ./... && go vet ./...
go test ./internal/config/ ./internal/telemetry/ ./internal/api/ ./internal/datalifecycle/
```

门禁（可失败）：
- `TestProductionEnvSurfaceIsWhitelisted`：源码里出现白名单外的 `EHOME_*` 字面量即红；
- `TestTelemetryHasNoEnvSurface`：遥测重新引入 env 即红；
- `TestFrameDecodeMaxWindowIsSixHours`：帧窗与 rollup 分界必须同源且满足帧数上限；
- `TestRollupAndFrameAreComplementary`：任意窗口恰好一个源服务（死区即红）。

生产验收：升级后打开 BMS 页 24h/7d 与 Dashboard 7d，应无「超过帧表单次解码上限」；
`docker logs --since 10m ehome-prod-web | grep 超过帧表` 应为 0。
