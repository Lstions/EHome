## 5. 部署方式的一个意外（**下次部署要注意**）

生产容器 `ehome-prod-web` 是历史某次用 **`docker run` 直接创建的**，不带
`com.docker.compose.*` labels。因此：

```
docker compose up -d ehome
→ Conflict. The container name "/ehome-prod-web" is already in use
```

**处置**：改用与旧容器**逐项等价**的 `docker run`（端口 18090/8443、同一 network
`ehomesystem_ehome-internal`、同一组 20 个环境变量、同两个 volume 挂载），
并把旧容器 `docker rename` 成 `ehome-prod-web-rollback-20261106-144328` 保留（可秒级回滚）。

⚠ 这意味着 `/srv/ehomesystem/docker-compose.yml` 与**实际运行的容器已经脱节**
（compose 文件里的 `image` 走 `${EHOME_IMAGE}`，实际容器是 run 出来的）。
**建议后续统一**：要么把容器纳入 compose 管理（`docker rm -f ehome-prod-web` 后
`docker compose up -d`），要么在文档里明确「本机用 docker run」。本次没做这个统一
（属于运维形态变更，超出部署范围），只记录事实。

   所以 L2/L3 的容量收益尚未兑现；按保留期 90 天滚动，202611 分区增长会继续吃盘。
5. **遥测存储的三个开关全部默认关闭**（`EHOME_TELEMETRY_WRITE_ON_CHANGE` /
   `EHOME_TELEMETRY_ROLLUP_WRITE` / `EHOME_TELEMETRY_DUAL_WRITE`）——
   本次部署**只上线了骨架与门禁**，行为与部署前逐字节相同（除索引变化）。
   灰度开启前需先裁决评审报告 D1~D8（见 docs/设计/遥测存储-阶段0与L1实现记录-2026-11-06.md §3.5）。

## 8. 复现命令

```bash
# 构建
cd /mnt/storage/WorkSpace/EHome
export DOCKER_CONFIG=$PWD/.docker-config
SHA=$(git rev-parse --short HEAD)
DOCKER_BUILDKIT=1 docker build --build-arg GOPROXY=https://goproxy.cn,direct \
  --build-arg GIT_COMMIT=$SHA -t ehome-new:main-$SHA .

# 传输

  sshpass -e ssh root@192.168.20.6 'cat > /srv/ehomesystem/ehome-$SHA.tar.gz'

# 生产侧（脚本见 .tmp-telemetry/remote_*.sh）
docker load < /srv/ehomesystem/ehome-$SHA.tar.gz
```
