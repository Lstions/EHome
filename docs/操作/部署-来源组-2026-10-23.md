## 二、构建（本机）

~~~bash
COMMIT=$(git rev-parse HEAD)                    # e416931b
git archive "$COMMIT" | tar -x -C .deploy-src   # 干净树，不含工作区未提交改动
DOCKER_BUILDKIT=1 docker build \
  --build-arg GOPROXY=https://goproxy.cn,direct \
  --build-arg GIT_COMMIT="$COMMIT" \
  -t ehome-new:sg-e416931b .deploy-src
~~~

**为什么用 git archive 而不是直接 docker build .**：2026-10-21 事故的根因就是「部署了不是从 main 构建的产物」。直接 docker build . 会把工作区未提交改动一起打进去 —— 本次工作区恰好有 3 个**他人并发 WIP** 文件（inverter 功率流向），若直接构建就会把别人的半成品带上线。已实测导出树不含这些改动。

## 六、回滚

~~~bash
ssh $SSH 'cd /srv/ehomesystem
  cp .env.pre-roll-<ts> .env       # 或直接改回 EHOME_IMAGE=ehome-new:ui-fix15
  docker compose -f docker-compose.yml up -d ehome'
~~~

若要连数据回滚：

~~~bash
ssh $SSH 'docker exec -i ehome-prod-postgres pg_restore -U ehome -d ehome \
  --clean --if-exists < /srv/ehomesystem/backups/ehome-pre-sg-20261023-002911.dump'
~~~

**回滚前必读**（合并可行性审查 C3 实测的两个陷阱）：

1. **DROP INDEX IF EXISTS ux_ds_one_active;** —— 旧二进制的 Deactivate 是「先升新、再降旧」，在存在 active 行时会撞这个新的部分唯一索引 ⇒ 停用活跃来源报 UNIQUE 冲突。生产 data_sources 当前 0 行，暂不触发，但一旦有人创建过来源就必须先删索引。
2. **清理 pending_confirm 且 source_hash 非空的事件** —— 旧二进制不比对 source_hash，回滚后确认会按旧来源执行（用户看到 A、实际用 B）。
3. 组规则在旧二进制下会退化为「只按 trigger_edge_device_id（锚点成员）触发」，需人工确认锚点仍权威。

用脚本自查这三项：

~~~bash
./backend/scripts/check_source_group_rollout.sh --rollback
~~~
