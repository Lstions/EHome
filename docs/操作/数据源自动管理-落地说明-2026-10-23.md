# 数据源自动管理 —— 落地说明（2026-10-23）

> 对应设计：[数据流架构与数据源统一接入-方案](./数据流架构与数据源统一接入-方案-2026-10-23.md)
> 接口契约：[数据流架构-接口设计](./数据流架构-接口设计-2026-10-23.md)

## 一、用户看到什么变化

| 之前 | 之后 |
|---|---|
| 菜单「数据源」+「来源组」两个入口 | 一个「数据来源」入口，两个 Tab |
| 数据源页面**永远是空的**（纯人工配置表，生产 0 行） | **来源总览**自动显示系统里所有数据来源，无需手工维护 |
| 用户困惑：设备在传数据，为什么没来源？ | 打开就能看到「哪台设备的哪个字段是谁在供数」 |

## 二、只读 vs 可写的边界（重要）

| 页面 | 可写？ | 说明 |
|---|---|---|
| Tab1「来源总览」 | **否** | 自动派生。三层保证：组件契约无写能力 / 前端测试断言 / 后端写方法返 405 |
| Tab2「来源组」 | **是** | 唯一可写入口。主备/复合配置都在这里，由用户手动创建 |

**为什么总览必须只读**：它是设备与采集数据的**事实投影**。允许写入就等于允许"手工伪造事实"，
而页面又会被自动派生覆盖 —— 用户改完发现变回去，比不能改更糟。

## 三、数据从哪来（来源总览的派生规则）

```
输入：edge_devices（已绑逻辑设备）+ sensor_field_obs（实际观测过的字段）
     + source_groups（用户建的组，enabled）

判定：
  1. 每个 enabled 来源组 ⇒ 一个来源（Kind=primary_backup/composite）
  2. 未被任何组覆盖的 (逻辑设备, 字段) ⇒ 一个直连来源（Kind=direct）
  3. 同一 key 同时有组和直连 ⇒ **组优先**（不覆盖用户的显式配置）
```

## 四、自动管理的三条纪律（为什么可以放心）

1. **只碰自动行**：`managed_by='auto'` 才会被收敛器修改。
   人工创建的（`manual`）**永不覆盖** —— 有测试 + 变异测试双重保证。
2. **不删除，只 disable**：设备下线/字段消失时置 `disabled` 保留血缘。
   删掉会丢失"这台设备曾经供过这个字段"的历史。
3. **幂等**：派生可重复调用任意次，结果一致。启动一次 + 每 60s 对账。

## 五、为什么不在采集热路径写库

生产实测：`unified_data` 每 10 分钟约 **1.9 万行**。
任何在采集 sink 回调里写 `data_sources` 的设计都会反压 ingest。
因此派生走**冷路径**（启动 + 60s ticker），从 `sensor_field_obs` 读而不是扫 3000 万行的 `unified_data`。

## 六、当前生产的实际情况（诚实说明）

| 项 | 值 | 含义 |
|---|---|---|
| `edge_devices` | 10 | 有设备 |
| `unified_data` | 3000 万+行 | 有数据 |
| `data_sources` | 部署前 0 行 | 本次上线后会被自动填充 |
| `source_groups` | 0 | **用户还没建过组** |
| `automation_rules` / `alert_rules` | 0 / 0 | 还没配规则 |

**这意味着**：上线后来源总览会显示设备与字段（自动派生），但「主备/复合」
要等用户手动建来源组后才出现。这是设计如此 —— 用户明确要求来源组手动创建。

## 七、一次上线后的自查清单

```bash
# 1) 来源总览有数据（不再是空表）
curl -s -H "Authorization: Bearer <token>" \
  http://<host>:18090/api/v1/data-sources/overview | jq '.data.total'

# 2) 只读保证：写方法必须 405（不是 404、更不是 200）
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  http://<host>:18090/api/v1/data-sources/overview
# 期望 405

# 3) data_sources 被自动填充且标记来源
docker exec ehome-prod-postgres psql -U ehome -d ehome -At -c \
  "SELECT managed_by, count(*) FROM data_sources GROUP BY 1"
# 期望看到 auto 行（数量 = 设备数 × 各设备观测字段数）

# 4) 派生器在跑（derived_at 应在 60s 内刷新）
docker exec ehome-prod-postgres psql -U ehome -d ehome -At -c \
  "SELECT max(derived_at), now() FROM data_sources"

# 5) 启动日志应有一行对账结果
docker logs ehome-prod-web 2>&1 | grep source_projection
# 期望：source_projection: 启动对账完成 sources=N created=N ...
```

## 八、回滚

代码回滚：`git revert` 对应提交即可，无 DB 破坏性变更。

本次只**新增**了两列（`managed_by`、`derived_at`，都有默认值），
不删列、不改既有列语义 ⇒ 回滚旧二进制后新列被忽略，数据仍可用。

```bash
# 若需要把自动派生的行清掉（不想保留台账）
docker exec ehome-prod-postgres psql -U ehome -d ehome -c \
  "DELETE FROM data_sources WHERE managed_by='auto'"
# 注意：不要删 manual 行
```
