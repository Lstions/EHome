# 部署 EHome 3.0 到生产服务器（192.168.20.6）

> 2026-10-18 首次完整执行并验证通过。本文是可复现的操作手册。

## 0. 前置事实（每次部署前先确认）

| 项 | 值 |
|---|---|
| 服务器 | `192.168.20.6`（PVE 上的 Debian 13 VM） |
| 凭据 | 仓库 `.secrets/prod.env`（gitignored） |
| 部署目录 | `/srv/ehomesystem` |
| Web 端口 | **18090**（8080 被 sub2api 占用） |
| 设备端口 | **8443**（mTLS） |
| 数据库 | `ehome-prod-postgres`，bind mount `./data/postgres` |

⚠ 服务器上还跑着 sub2api / 3x-ui / nginx-proxy-manager / ddns-go —— **不要动它们**。

## 1. 构建（本机）

### 1.1 后端镜像

```bash
cd /mnt/storage/WorkSpace/EHome
export DOCKER_CONFIG=/mnt/storage/WorkSpace/EHome/.docker-config   # 宿主 ~/.docker 只读
DOCKER_BUILDKIT=1 docker build --build-arg GOPROXY=https://goproxy.cn,direct \
  -t ehome-new:v2 .
```

⚠ **不要用 GHCR 的 `main`/`latest`** —— 实测它们是 2026-10-05 的旧镜像，
连 `device transport` 符号都没有，不含任何 3.0 修复。

### 1.2 固件（host 必须编译期指定）

```bash
cat > .fwbuild-conf/prod_host.defaults <<EOF
CONFIG_EHOME_DEVICE_LINK_HOST="192.168.20.6"
CONFIG_EHOME_DEVICE_LINK_PORT=8443
EOF

export IDF_TOOLS_PATH=/home/sun/.espressif
. /mnt/storage/env/esp/v6.1/esp-idf/export.sh > /dev/null   # 提供 riscv32-esp-elf-gcc
export PATH=/mnt/storage/WorkSpace/EHome/.tools/cmake-3.30.5-linux-x86_64/bin:$PATH  # export.sh 不含 cmake
export BUILD_ROOT=/mnt/storage/WorkSpace/EHome/.fwbuild-prod
export EXTRA_SDKCONFIG_DEFAULTS=/mnt/storage/WorkSpace/EHome/.fwbuild-conf/prod_host.defaults
cd esp32-collector && ./build_firmware.sh c6-n8 && ./build_firmware.sh s3p-n16
```

⚠ `EHOME_DEVICE_LINK_HOST` 是**编译期常量**（`device_link_wiring.c:1289`），
manifest 不下发 host。默认值 `192.0.2.1` 是 RFC 5737 占位符（故意不可达）。
**换服务器 IP = 必须重编 + 重刷所有设备。**

## 2. 证书

设备证书的 CN **必须等于 node_id**（后端 `transport/server.go:299-324` 强制）。

```bash
cd .secrets/pki
# 每个 node_id 一份
openssl req -newkey rsa:2048 -sha256 -nodes \
  -keyout dev-$NODE.key -out dev-$NODE.csr -subj "/CN=$NODE/O=EHomeSystem-Device"
openssl x509 -req -in dev-$NODE.csr -CA ca.pem -CAkey ca.key -CAcreateserial \
  -out dev-$NODE.crt -days 3650 -sha256 -extfile client.cnf
```

生成设备 NVS 镜像（工具自带读回校验）：

```bash
python3 esp32-collector/tools/nvs_certs_gen.py generate \
  --ca ca.pem --cert dev-$NODE.crt --key dev-$NODE.key --out nvs-$NODE.bin
```

## 3. 部署到服务器

### 3.1 传镜像

```bash
docker save ehome-new:v2 | gzip -1 | $SSH "cat > /srv/ehomesystem/ehome-30.tar.gz"
$SSH "docker load < /srv/ehomesystem/ehome-30.tar.gz"
```

### 3.2 传证书

```bash
$SSH "mkdir -p /srv/ehomesystem/certs && chmod 700 /srv/ehomesystem/certs"
cat ca.pem   | $SSH "cat > /srv/ehomesystem/certs/ca.pem"
cat server.crt | $SSH "cat > /srv/ehomesystem/certs/server.crt"
cat server.key | $SSH "cat > /srv/ehomesystem/certs/server.key"
$SSH "chmod 600 /srv/ehomesystem/certs/server.key"
```

### 3.3 备份（**必做**）

```bash
$SSH "docker exec ehome-prod-postgres pg_dump -U ehome -d ehome -Fc \
  > /srv/ehomesystem/backups/ehome-pre30-$(date +%Y%m%d-%H%M%S).dump"
$SSH "cp /srv/ehomesystem/docker-compose.yml /srv/ehomesystem/docker-compose.yml.mqtt-bak"
$SSH "cp /srv/ehomesystem/.env /srv/ehomesystem/.env.pre30-bak"
```

### 3.4 切换 compose

用 `deploy/prod/docker-compose.30.yml`（见仓库），关键差异：

```yaml
  ehome:
    image: ${EHOME_IMAGE:-ehome-new:v2}
    ports:
      - "${EHOME_HTTP_PORT:-18090}:8080"
      - "${EHOME_DEVICE_PORT:-8443}:8443"          # 新增：设备 mTLS
    environment:
      EHOME_DEVICE_ENABLED: "true"                  # 新增
      EHOME_DEVICE_ADDR: ":8443"
      EHOME_DEVICE_CERT_FILE: /certs/server.crt
      EHOME_DEVICE_KEY_FILE: /certs/server.key
      EHOME_DEVICE_CLIENT_CA_FILE: /certs/ca.pem
    volumes:
      - ./certs:/certs:ro                           # 新增
```

```bash
$SSH "cd /srv/ehomesystem && docker compose -f docker-compose.30.yml up -d"
```

### 3.5 验证

```bash
curl -s http://192.168.20.6:18090/health          # → {"status":"ok"}
nc -z 192.168.20.6 8443 && echo "8443 OPEN"
nc -z 192.168.20.6 1883 && echo "1883 仍在（异常）" || echo "MQTT 已移除"
```

## 4. 刷设备

### 4.1 先确认启动槽（**最容易踩的坑**）

```bash
# 看串口日志的第一行 boot 信息
grep "Loaded app from partition at offset" 串口日志
# 0x10000 = ota_0 ；0x390000 = ota_1
```

**烧错槽不会有任何报错**，固件照旧运行（Compile time 不变）。

### 4.2 烧固件 + 证书

```bash
docker run --rm --device=/dev/ttyACM0 \
  -v .fwbuild-prod/c6-n8:/fw:ro -v .secrets/pki:/pki:ro python:3.12-slim sh -c \
  "pip install -q esptool; \
   esptool.py --port /dev/ttyACM0 flash_id; \
   esptool.py --port /dev/ttyACM0 write_flash --flash-size 8MB 0x390000 /fw/ehome_collector.bin; \
   esptool.py --port /dev/ttyACM0 write_flash --flash-size 8MB 0x9000 /pki/nvs-$NODE.bin"
```

⚠ 烧 `0x9000` 会覆盖**整个 NVS 分区**（含 WiFi 凭据）。因为 host 是编译期常量，不影响连接。
⚠ 烧前必须 `flash_id` 确认容量（C6=8MB / S3P=16MB）。

## 7. 已知的配置归属问题

刷成 3.0 后设备会用 **base MAC 派生的 node_id**（如 `F0F5BD02F35C`），
而历史配置可能挂在旧 id（如 `F0F5BDFFFE02`，由 USB-JTAG MAC 派生）。

后端的 `MigrateNodeIDFromJTAGMAC` 会自动修，但**只在旧节点未被软删除时生效**。
生产中 `F0F5BDFFFE02` 已于 2026-10-06 被软删 ⇒ 迁移跳过 ⇒ 新 id 拿到 `channels=0`。

**排查方法**：

```sql
select node_id,count(*) from channels group by node_id;
```

若新 node_id 没有通道，需手工把配置改绑（或重新建）。本机台架的对照配置：

```
channels:    bus_config=1415000012C008010000  (UART1 4800 8N1)
             config={"baud_rate":4800,...,"device_type":"sn3001_rain"}
edge_devices: type=sn3001_rain, hardware_id=1
```
