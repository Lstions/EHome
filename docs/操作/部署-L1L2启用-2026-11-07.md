## 1. 用户裁决与实现

> 完成并打开遥测存储的 L1 、L2 帧级编码，同时删除开关

| 项 | 实现 |
|---|---|
| L1 | 值不变且未到心跳 ⇒ 不写 `unified_data`。影子模式删除，`filter()` 只返回真正要写的行 |
| L2 | `telemetry_frame` 从影子变主路径，`NewDualWriter` 恒构造，表缺失 ⇒ 启动 Fatal |

| 保留 | `EHOME_TELEMETRY_HEARTBEAT_SECONDS`（参数）、`_DUAL_WRITE_QUEUE`（参数）、`_ROLLUP_READ`（读侧开关，风险独立） |

## 2. 读路径口径配套（不改会出用户可见 bug）

| # | 路径 | 改动 |
|---|---|---|
| D1 | `agg=avg` 降采样 | `avg(value)` → **桶内最后值**（PG `array_agg(...)[1]` / SQLite `ROW_NUMBER()`）。实测：旧口径下恒定桶与阶跃桶的均值最大偏差 5.75A，新口径恒定桶 100% 相等（差 <1e-9，纯浮点噪声） |
| D2 | `data_count_today` | 行数 → 今日**采样帧数**（`COUNT DISTINCT device_id,timestamp`） |
| D3 | `points_stored` | 行数 → **帧数** + 60s 懒加载缓存（全表帧数查询实测 19.8s，前端 10s 轮询会拖垮连接池） |
| D4 | `/sensor-fields/preview` | 新增 `sparse_frames`/`frame_semantics` 标注，不补全缺失字段（补全会造出没发生过的求值） |
| D5 | `agg=change` | 未动（L1 只在「值不变」时跳过，变化点全保留） |

前端文案跟随：「今日数据」→「今日采样帧（全局）」、「已存储」→「已存储帧数」+ tooltip「差额是压缩，不是丢失」。
（「已采集」**保持不加**「帧」后缀 —— 它数的是采集事件，与收窄后的帧数不可比，加后缀会制造「两侧应该相等」的错误预期。）

## 3. 生产 P0：L3 rollup 全线失败（已修复）

### 3.1 现象

部署 `c27caa23` 后每分钟：
```
ERROR: column "updated_at" of relation "telemetry_rollup_1m" does not exist (SQLSTATE 42703)
[0.253ms] [rows:0] INSERT INTO telemetry_rollup_1m (device_id, bucket, payload, updated_at) VALUES ...
```
`telemetry_rollup_1m` **一行都写不进去**。

### 3.2 根因

`telemetry_rollup_1m` 的分区母表由 `partitionParentDDL` 裸 DDL 建（**三列**），
而 `models.TelemetryRollup1m` 多一个 `UpdatedAt`，`upsertRollupRow` 的 INSERT 带了它。

**为什么单测全绿**：SQLite 走 `AutoMigrate`（列来自 model）⇒ 一定有该列；
PG 走裸 DDL（列来自模板）⇒ 没有。**两条建表路径互不相交，交叉点上从没有过用例。**

### 3.3 止血与根治

| 阶段 | 动作 |
|---|---|
| 止血（19:42） | 手工 `ALTER TABLE telemetry_rollup_1m ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ NOT NULL DEFAULT now()` —— PG 元数据操作，自动传播到 5 个分区，实测下一步 `L3` 即恢复写入 |
| 根治（`d7ccd294`） | ① DDL 补列 ② 新增 `ensurePartitionParentColumns`：真源 = `partitionParentDDL`，逐列对比 `information_schema.columns`，缺失发 `ADD COLUMN IF NOT EXISTS`，挂在 `finalizePartitionParentIndexes` 首步（四张分区表全部受益，存量库启动自愈） |

### 3.4 三层防线

1. **开发期**：`TestPartitionDDLMatchesModels` 纯源码门禁，DDL ↔ model 双向断言（不需要 PG）
2. **集成期**：`TestPGRollupUpsertAgainstBareDDL` 走真 `partition_mgr` 建表 + upsert，复现生产同样的 42703
3. **运行期**：`ensurePartitionParentColumns` 存量库启动自动补列（Warn 不阻断）

**变异验证**（两次都真做）：删掉 DDL 的 `updated_at` 后，源码门禁报「model 有而 DDL 没有的列: [updated_at]」，
PG 用例报「SQLSTATE 42703」—— 与生产错误完全一致；恢复后均绿。

## 8. 已知遗留

1. **L3 读路径仍未接入**（`EHOME_TELEMETRY_ROLLUP_READ` 默认 false）：rollup 表在写但没人读，
   长窗图表仍走原表。接入需单独评估（评审 B-8 提到 `latest-values` 生产实测 210,997 ms 也是相关欠账）。
2. **合并历史的帧表有损窗口**：源设备合并后其 slot 最多等一个关键帧周期（≤60s）才对齐，
   这期间解码查询返回上一关键帧的值。影响有界、源设备已软删。
3. **detached 分区不会被自动补列**：见 `docs/操作/分区表列一致性与detached分区-运维手册-2026-11-07.md`。
4. **D1 语义变更需要用户理解**：图表 avg 现在是「桶内最后值」而不是算术平均。
   对恒定段无差异，对阶跃段语义不同（这正是修复的目的）。
