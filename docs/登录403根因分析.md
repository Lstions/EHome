# 登录 403 根因分析报告

## 结论（TL;DR）

**登录 403 的根因是 CORS 白名单不匹配**，不是密码/账号/JWT 问题。

- 通过 `http://localhost:5174` 访问前端 → 登录 **成功（200）**
- 通过 `http://192.168.20.3:5174`（本机局域网 IP）访问前端 → 登录 **失败（403）**，页面提示 `Request failed with status code 403`

## 复现步骤（浏览器实测）

| 访问地址 | 登录结果 | 页面提示 |
|---|---|---|
| `http://localhost:5174/login` | ✅ 成功进入 dashboard | 无 |
| `http://192.168.20.3:5174/login` | ❌ 403 停留在登录页 | `Request failed with status code 403` |

## 根因链路

```
访问 http://192.168.20.3:5174            ← 前端可以被访问（vite 监听 0.0.0.0）
  └─> 浏览器发出 POST /api/v1/auth/login
       └─> 请求头携带 Origin: http://192.168.20.3:5174   ← 浏览器自动加
            └─> 后端 CORS 白名单只允许 http://localhost:5174
                 └─> gin-contrib/cors 直接返回 403 Forbidden（不放行）
```

### 证据

1. **curl 实测**（后端直连，Origin 不同结果不同）：
   - `Origin: http://localhost:5174` → **200**，正常返回 token
   - `Origin: http://192.168.20.3:5174` → **403 Forbidden**（Content-Length: 0，无 body）

2. **后端 CORS 配置**（`backend/cmd/server/main.go:255-279`）：
   ```go
   allowedOrigins := []string{}
   for _, origin := range strings.Split(os.Getenv("EHOME_ALLOWED_ORIGINS"), ",") { ... }
   // 只有 len(allowedOrigins) > 0 时才会挂 CORS 中间件
   ```

3. **Makefile 写的白名单**（`Makefile:102` 等 3 处）：
   ```
   EHOME_ALLOWED_ORIGINS=http://localhost:$(FRONTEND_PORT)
   ```
   debug 环境产生 `http://localhost:5174`，不含局域网 IP。

4. **前端 vite 监听 0.0.0.0**（`frontend-shared/vite.config.ts:41` `host: '0.0.0.0'`）—— 所以局域网 IP 能打开页面，但 API 请求被 CORS 拦。

5. **浏览器实测网络日志**：从 `192.168.20.3:5174` 登录时只有一条 `POST /api/v1/auth/login` 请求，随后报 403，没有任何后续 API 请求 —— 中间件在 `JWTAuth` 之前就 abort 了。

## 为什么 localhost 没问题

浏览器从 `http://localhost:5174` 发请求时 `Origin: http://localhost:5174`，恰好命中后端白名单，所以一切正常。用户实际打开的地址可能是 `192.168.20.3:5174`（局域网/手机访问），于是踩中 CORS 403。

## 解决方案（二选一）

### 方案 A：修改 Makefile，白名单加局域网 IP（推荐，开发环境）

`Makefile` 3 处 `EHOME_ALLOWED_ORIGINS=http://localhost:$(FRONTEND_PORT)` 改为同时包含本机 IP：

```makefile
EHOME_ALLOWED_ORIGINS=http://localhost:$(FRONTEND_PORT),http://192.168.20.3:$(FRONTEND_PORT)
```

### 方案 B：使用 `*` 通配符（不推荐，后端会 Fatal 拒绝）

后端 `main.go:268-270` 明确禁止 `*`：
```go
if strings.TrimSpace(origin) == "*" {
    logger.Fatalf("EHOME_ALLOWED_ORIGINS must not contain '*' when AllowCredentials=true; use explicit origins")
}
```

## 备注

- 本问题与账号密码、JWT secret、认证状态均无关（`POST /api/v1/auth/login` 直连 200）。
- 若用户访问的是 **localhost** 但仍然 403，则需另查（如旧 token、限流 429 被误读为 403），但本次复现明确指向 CORS。
