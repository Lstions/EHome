## 四、评审独立发现的**我自己代码的缺陷**

这一节单独列，因为评审确实抓到了我看不到的东西：

1. **全链路 E3 断言无效**（实现 H-5）：我用「通知数不变」判定 unbound，但当时处于 300s 冷却内 —— 通知不出现既可能因 unbound、也可能因冷却。若把 fail_closed 误实现为 use_available（单边出值 + Degraded），健康行照样写、冷却照样掩盖 ⇒ **测试仍绿**。正确做法是断言审计语义（`result=source_degraded` + detail 含 reason + `Degraded=false`）+ 加同输入的 use_available 正向对照（两个方向误实现都能抓）。
2. **全链路 E1/E2 用 DB 直写绑定规则**（实现 H-4）：8 处 `Updates(source_kind/source_group_id/...)` 绕过 POST/PUT 保存期校验（V-8 cooldown floor / V-9 锚点 / SG-01 一致性）。若 API 绑定路径坏了，这些 e2e 仍全绿。

**未修复原因（如实说明）**：这两条属测试加强，不影响生产正确性；已写入本次交付的遗留项，列为「合并后 P1」。

## 五、门禁抓到的**真实性能回归**（本批最有价值的发现之一）

终审后跑完整门禁，`check_field_semantics.sh #10a-2`（端到端求值开销 ≤ 基线 +5%，**硬判据**）FAIL：

```
基线 7bc63e3f : 788.7 ns/op   1600 B/op   4 allocs/op
修复前 HEAD  : 973-1013 ns/op 1888 B/op   4 allocs/op   ⇒ 1.24x / +288B
```

**根因**：`Evaluate` 每帧做 `make([]models.AutomationRule, 0, len(e.rules))` + 逐条值拷贝。本批给 `AutomationRule` 加了 4 个来源字段，结构体 **352 → 448 字节**，3 条规则 × 96B = 288B/帧，与实测差量精确吻合。

**这不是「新功能必然更慢」**，而是每帧为读取**不变数据**重建了一次拷贝 —— 白花的。

**修法**：规则快照 + `atomic.Pointer`。`LoadRules` 锁内构建一次并 Store，`Evaluate` 只 `Load()` + 解引用（无 RLock、无拷贝、无分配）。alert 同款。

```
修复后：458-477 ns/op   480 B/op   3 allocs/op
对比基线：0.59x 时间（-40%）、-70% 字节、少 1 次分配
```

**结果比基线还快 40%** —— 说明原来的每帧拷贝本来就是浪费。

## 八、过度设计裁剪（v0.4，提交 `3d8f09c5`）

终审通过后做了收益-代价评估，结论：**能力是真的（②③ 以前产品上无路径），但当前兑现值 0**
（生产 `automation_rules=0`、`data_sources=0`、无任何同类传感器第二实例），
而部分"保险"反而引入新风险。据此砍掉 8 项。

### 8.1 裁剪清单

| # | 砍掉 | 为什么 | 规模 |
|---|---|---|---|
| 1 | **S8 窗口 gap 上限**（整块） | 用**配置** `IntervalMs` 判实际 gap；稀疏上报时反复截断窗口 ⇒ 存量 `DurationSec>0` 规则**可能永不触发**且无指标。风险 > 收益。删后跨长断流仍由 `durationSec` cutoff 自然截断。**附带：热路径彻底零 DB**（`deviceIntervalFn` TTL-miss 查库消失） | 两引擎 + helper + 测试 |
| 2 | **combine `max`/`min`/`first_available`** | 每多一算子要同步 5 处，后端只多 6 行；`first_available` 与 `on_degrade` 语义重叠（N-8）。生产 0 行无历史兼容负担 | 3 算子，跨 5 处 |
| 3 | 结果码 `source_resolver_not_configured` | 是"上线顺序错了"的运维态，非业务结果 → 映射 `unresolved_selector`，原因留在 detail | 1 码 |
| 4 | 结果码 `source_group_shadow` | **死常量**，全仓无产出点（灰度 G1 从未实现） | 1 码 |
| 5–7 | 门禁 SG-21 / SG-11 / SG-02 | 分别为代码风格强制（两次误报）、与单测重复、已废弃占位 | 3 条 |
| 8 | 门禁 SG-06/17/19 合并 | 三条都是依赖边界断言，合并后**断言一条不少** | 3 → 1 |

**保留不动的四条安全底线 + 八条核心不变量**，见新增 ADR
`docs/设计/来源组-核心不变量-ADR-2026-10-22.md`（把代码里 376 条执行性注释收敛成 12 条）。
