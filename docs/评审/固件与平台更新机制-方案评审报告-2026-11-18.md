## 1. 总体结论

### 1.1 三问裁决

| 维度 | 三位评审均分 | 裁决 |
|---|---|---|
| 设计合理性 | 3 / 3 / 3 | **方向正确，局部自相矛盾**：L1 身份 → L2 决策的主线成立，但「PSRAM 档位」「回滚时机」「闸门与自动回滚」「灰度与验收」四处互相打架 |
| 可落地性 | 2 / 2 / 2 | **不能按现稿开工**：5 处会直接导致启动失败/返工/验收假绿的阻塞项，21.4 人日低估约 20–45% |
| 过度设计 | 2 / 3 / 2 | **中等冗余**：核心（身份 + 闸门 + 票据）站得住；外围（0x1A、compat 端点、清单 CLI、多处字段）约 4–5 人日可删 |

### 1.2 一句话结论

> **问题找得准、主线对，但现稿有三处「设计层面就会失败」的硬伤：固件档位无法从二进制推导出 PSRAM、回滚开关属于 bootloader 而非 app、以及唯一索引在存量数据上会阻塞启动。**
> 必须先修订为 v1.1 再排期；建议按 §8 的收窄范围重估，交付工期从 21.4 调整为 **18.5 人日（app 侧）+ 一次现场 bootloader 重烧窗口**。

### 1.3 评审一致项与分歧

| 项 | 三人是否一致 | 说明 |
|---|---|---|
| 镜像头偏移/芯片常量/帧 fail-closed 等事实引用 | 一致且均核对成立 | 方案的事实基础是可靠的 |
| `/ota/compat` 冗余 | A/B/C 一致 | 应删，保留 `GET /firmwares?node_id=` |
| `nodes.model` 扩宽无必要 | A/B/C 一致 | 12 字符 < 20，省掉唯一的 ALTER TABLE |
| 迁移必须同时覆盖测试库 | A/B 一致（C 未涉及） | 否则部分唯一索引只在生产存在，验收假绿 |
| **PSRAM 能否由 model_key 推导** | **B 认为可（`profileHasP`），A 证明不可** | 主评审采纳 A：镜像头无 PSRAM 位，`s3-n16` 与 `s3p-n16` 实测同键（§2.1） |
| release 清单是否值得做 | C 认为可整体删除，B 认为保留但补 compose 改造 | 主评审折中：降级为「部署脚本一行校验」，不建 `ehomectl` 子命令 |

## 2. 五个必须知道的关键结论

### 2.1 固件档位无法从二进制推导（**最高优先级**）

方案把 `model_key` 定义为 `chip + flash`，并据此建唯一索引、生成 `psram_required`。但 **ESP 应用镜像头没有 PSRAM 位**：

```text
s3-n16   chip=0x0009 flash=4 -> esp32s3-n16
s3p-n16  chip=0x0009 flash=4 -> esp32s3-n16   ← 同键（实测，见 §10 证据 E-1）
```

后果连锁：

1. 两档固件推导出同一 `model_key` + 同为 `2.8.0` + 同为 `stable` ⇒ **`CREATE UNIQUE INDEX` 必然失败**；
2. 迁移失败会触发 `abortStartup`（`cmd/server/main.go:150-153`）⇒ **服务起不来**；
3. `AC-1` 要求上传后 `model_key = esp32s3p-n16`，**不可达**；
4. 闸门分支 3 只比 chip、分支 5 只拦「固件要 PSRAM 而节点没有」⇒ **s3 镜像刷进 s3p 板的方向无人拦**，与方案 §2.1「s3↔s3p 100% 被拒」矛盾。

**修订要求**：
- PSRAM 来源改为构建期旁挂（`build/<profile>/config/sdkconfig.json` 已含 `"SPIRAM": true/false`，主评审已核实 E-2），由 `build_firmware.sh` 产出 `<profile>.meta.json`；
- 上传接口要求 sidecar，缺失时 `psram_required = unknown`（**三态**，不能用 bool 默认 false）；
- 唯一键改为 `elf_sha256`（每个构建唯一），`(model_key, version, channel)` 降为普通索引；
- 闸门分支 3 改为「档位全等（chip+flash+psram）」，并补 `PSRAM_MISMATCH` 反向分支。

### 2.2 回滚开关不属于 app，OTA 下发不了

`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` 定义在 `components/bootloader/Kconfig.app_rollback`，编译进 **bootloader.bin**（23KB，独立分区）；
OTA 只写 `ota_0/ota_1` 应用分区。因此：

- 存量设备**无法通过 OTA 获得回滚能力**，必须串口/产线重烧 bootloader；
- 方案把 T3.4 估为 0.8 人日并当作普通任务，**低估了一个现场作业窗口**。

**修订要求**：M3 拆为两段——「app 侧判据与验证逻辑」（可 OTA）与「bootloader 重烧」（现场作业、需排窗口、仅覆盖可接触设备）；
若无法重烧，则明确「回滚仅覆盖新出厂设备」，并把自动升级永久保持在默认关。

### 2.3 闸门会掐断自动回滚

`AutoRollback` 的目标是**更旧**的稳定版本，且它直接调用 `CreateTask(nodeID, firmwareID)`（`ota.go:290-330`）。
若闸门放在 `CreateTask` 内，回滚任务必然命中 `NOT_AN_UPGRADE` ⇒ **每天静默失败**。

**修订要求**：闸门入参增加来源与开关（`Source=user|system`、`Force`），系统回滚只校 chip/flash/psram、不校版本方向，并写审计。

### 2.4 `0x1A` 已被占用，「硬件档案」已有既有通道

- `MSG_QUERY_RESOURCES = 0x1A`（下行，`frame_codec.h`），方案的「可选 HwInfo 0x1A」是编号冲突；
- 已有 `MSG_RESOURCE_REPORT = 0x19` 上报硬件资源，并已落 `nodes.platform` 与 `nodes.hardware_info`（jsonb）、`resource_reported_at`。

**修订要求**：删除 HwInfo 方案；如确需 flash/psram，优先扩展 0x19（服务端对未知字段静默忽略，可向后兼容）或继续用 Hello model。

### 2.5 迁移与索引必须双库同源

测试库（SQLite）**不走** `database.AutoMigrate`，只走 `AutoMigrate(models)` + 若干 `dbschema.Ensure*`（`testutil/db.go:127-141`）。
方案把回填与索引只挂在生产迁移里 ⇒ 单测库不存在该索引 ⇒ **AC-3 等验收假绿**。仓库已有同坑先例与明确纪律（`dbschema/source_group.go:20-23`）。

**修订要求**：把 `EnsureFirmwareIdentityIndex` 与回填放进 `internal/dbschema`，`database/gorm.go` 与 `testutil/db.go` 各调一次；
建索引前先 `GROUP BY ... HAVING count(*)>1` 预检并 fail-closed 报出冲突键（对齐 `source_group.go:62-84` 范式）。

## 5. 过度设计裁定

| 项 | 判定 | 理由 |
|---|---|---|
| `GET /ota/compat` 端点 | **删** | 与 `GET /firmwares?node_id=` 的 `compatible/reasons` 完全重复 |
| `firmware_changed` WS 事件 | **删** | 单认证主体，多标签页场景前端动作后自行 refetch 足够 |
| `0x1A HwInfo` | **删** | 编号冲突且 0x19 已覆盖 |
| `nodes.model` 20→32 | **删** | `esp32s3p-n16` 仅 12 字符，省掉全方案唯一的 ALTER TABLE |
| `hw_chip` / `hw_profile_raw` / `hw_reported_at` | **删** | 复用 `platform` / `hardware_info` / `resource_reported_at` |
| `channel='withdrawn'` 枚举值 | **删** | 与 `withdrawn_at` 双表达，且撤回后会丢失原渠道 |
| `identity_source` + `identity_mismatch` | **合并** | 用 `identity_source` 一个枚举（`upload`/`backfill`/`backfill_mismatch`/`unknown`）表达 |
| `psram_required` 列 | **保留为三态** | 驳回「由 model_key 推导」：model_key 无 PSRAM 位；改为 `model_key` 不含 `p`、PSRAM 单独三态列，避免两处表达 |
| `ota_tasks.firmware_checksum` / `target_model_key` + 回填第 5 步 | **删** | Hello 无法比对；详情已有 `firmware_id`/`to_version` |
| `uploaded_by` / `requested_by` | **删** | 审计已记 actor |
| release 清单全套（`release.json` + schema + `ehomectl` 子命令） | **降级** | 保留 `release.json` 与一行脚本校验；不建子命令、不写 schema，省约 1.2 人日 |
| `UpdateBanner` 6 态 | **收为 3 态** | `checking`/`current`/`error` 无可观测 UI，收为 `same`/`stale`/`dismissed` |
| `RK-6` 多副本抖动 | **删** | 与「单实例」前提矛盾，且单端点响应内无法实现「两次一致」 |
| M1 单期 | **拆两期** | M1a（闸门+审计+Hello 加固）可第 2 周独立上线；M1b（列表/撤回/置灰/对话框）随后 |
| 附录 A/B 与正文重复 | **删重复** | 保留 §6.3 码表 + §5.6 迁移编排，附录各留一处索引即可 |
| 12 项「待裁决」 | **收敛为 3 项** | 其余 9 项各已有明确推荐，属决策记录；真未决仅：M3 实机窗口、0x1A（已删）、gateMode 观察期 |

## 13. v1.2 技术更正（评审之外的补充）

评审结论未覆盖**设备回滚的引导器语义**。依据 [ESP-IDF OTA 文档](https://docs.espressif.com/projects/esp-idf/zh_CN/stable/esp32/api-reference/system/ota.html) 与 `bootloader_support/src/bootloader_utility.c:393-400`：

- 使能回滚后，新镜像首启为 `PENDING_VERIFY`；**只要复位前没有 mark_valid，下一次启动引导器就把该镜像置 `ABORTED` 并自动退回旧分区**，不需要应用调用 `mark_app_invalid_rollback_and_reboot()`；
- 因此 mark-valid 判据必须**纯本地可达成**，不能依赖 StatusReport / 联网；
- 方案据此把判据改为「uptime ≥ N 秒 + 关键子系统就绪 + 非安全模式」（§6.6），并新增「设备自动回滚的服务端记账」，避免服务端 `AutoRollback` 再次下发导致「回滚的回滚」。

**影响面**：仅 §3.4 判断 2、§6.6（新增）、§8.2 T3a、§10 RK-10/RK-12、§11 D-3、AC-15；不影响 12 项 P0 的结论，也不需要重开全量评审。

## 14. v1.3 需求强化（用户补充）

用户明确「前端更新后，正在使用旧页面的用户要被提醒刷新」为一等需求。v1.2 的做法只有 30 分钟轮询 + WS 重连，对**活跃用户**太慢，且 chunk 加载失败时只收敛进度条、不提示。v1.3 改为四通道检测：

| 通道 | 延迟 | 覆盖 |
|---|---|---|
| 响应头 `X-EHome-Build` + axios 拦截器 | 下一次 API 响应（秒级） | 正在操作的标签页 |
| WebSocket 重连成功 | 1 次重连 | 部署后自动触发 |
| 轮询 + 可见性 | ≤30 分钟 | 纯浏览/空闲 |
| `vite:preloadError` / `router.onError` | 立即 | 懒加载 chunk 404（页面已不可导航） |

状态机由 3 态扩为 4 态：`same` / `stale`（可推迟横幅）/ `blocked`（不可推迟模态）/ `dismissed`；并明确「稍后」不压制 `blocked`。
**影响面**：§4.3 新增响应头契约、§6.4 重写、§8.2 M2 由 8 任务扩为 10 任务（4.2–5.8 人日）、AC-13 量化 + 新增 AC-16、附录 D 新增 3 条 e2e。不影响 P0 结论。

## 15. v1.4 开发原则对齐（用户补充）

用户提出项目开发原则：**允许破坏性更新；涉库变更必须在程序启动时完成迁移适配；能不负债就不写兼容代码。** 复核后发现 v1.3 有三处正是「为旧数据写兼容代码」，v1.4 据此收紧：

| 项 | v1.3 | v1.4 |
|---|---|---|
| 无 sidecar 的固件 | 入库为 `psram=unknown`，闸门可 force | 上传必填 sidecar（`FW_META_REQUIRED`）；存量用 `meta-gen` 补后重传，补不齐标 `legacy` 不可选 |
| 固件 PSRAM | 三态 | 两值 + `identity_state`（`legacy` 行不可选） |
| `stable` / `target_model` | 保留列、不再写入、读时派生 | 迁移中 DROP COLUMN，调用点与测试一并删除 |
| 闸门 | 11 分支，unknown 均可 force | 10 分支，硬件类不可 force |
| 运行模式 | `gateMode` warn/enforce | 删除，改 `ehomectl ota gate-check` 只读预检 |

**新增边界**：破坏性只适用于平台自身；**在网设备的固件帧结构不可破坏**（fail-closed 解码 + 设备无法回滚升级），帧零变更属硬件约束，不是技术债。
**代价（已接受）**：删列后不能回退镜像，回滚改为 `pg_dump` + 单事务 + 前滚修复（新增 RK-13）。
**收益**：方案新增 §2.5，给出 H1–H4 口径、收益 A–E 与回本点（拦截 1 台误刷即可覆盖增量成本）。不影响 P0/P1 结论。

## 16. v1.5 A 档：更新内容可见（用户选择）
