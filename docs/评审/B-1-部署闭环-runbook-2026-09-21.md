## 2. 提交（按文件粒度拆分，避免一个巨型提交）

建议 5 个提交，顺序如下（每步 `git add <显式文件>`，**禁止 `git add -A`**）：

1. `fix(api): 设备地址/型号门禁收敛到单一真值源（G1/G2/G6/G7）`
   `backend/internal/api/handler_{device,edge_device,node}.go` + `backend/internal/api/routes.go` + `backend/cmd/server/main.go`
2. `fix(commandexec): 派发拒绝原因可诊断 + 下沉 attempt 级（G5/M-3）`
   `backend/internal/commandexec/{dispatcher,inbox,channel_cmd_v2_transport}.go` + `backend/internal/models/command_execution.go`
3. `fix(ota): 取消窗口收敛为下载阶段 + 409（含已知缺口记录）`
   `backend/internal/ota/ota.go`、`backend/internal/api/handler_ota.go`、`docs/设计/固件OTA.md`
4. `fix(frontend): 会话失效自证 + 地址口径按驱动能力分流 + UI 真值源`
   `frontend-shared/src/**`（含新增 utils 与 spec）
5. `chore(ci+sim): 仿真标签进常态门禁 + 能力窗口进仿真 + 注释债/卫生`
   `.github/workflows/test.yml`、`.gitignore`、`backend/simulation/**`、`scripts/esp32_simulator.py`

> 所有新增测试文件（`*_test.go` / `*.spec.ts`）与上面各自的主题一起提交。

## 7. 回滚

```bash
PREV=$(cat /tmp/prev-image.txt)
docker tag $PREV ghcr.io/lstions/ehome:rollback-$(date +%s)   # 便于追溯
docker compose -p ehomesystem -f deploy/prod/docker-compose.prod.yml \
  up -d --no-deps --force-recreate ehome                        # 用上一个 tag 重建
curl -s localhost:8080/health
```

数据库回滚：`make restore DUMP=backups/<本次备份> DB=<临时库>` 先验，**生产库恢复需 FORCE=1 且另取得授权**。
