# 缺陷 2 修复方案（已独立核实：部分属实，需重新定级）

## 核实结论（verify-silent-swallow，task-8）

| Lead 原断言 | 裁定 | 依据 |
|---|---|---|
| A. CMD_SAMPLE 用 bus_dma_transact，`rl==0` 静默 | **证伪** | uart_cmd_loop 里 transact 调用数=0；UART 走 bus_dma_write（fire-and-forget），根本不产生 rl |
| B. 静态统计假 100% | **部分属实** | `rate=(txn-errs)*100/txn`（bus_worker.c:971）确实不含 RX 超时；但 0x01 上报由 rx_task 独立发出（:1417-1426），上报链是通的 |
| C. CMD_WRITE 同样问题 | **证伪** | UART CMD_WRITE 走 bus_dma_write（:917），无 rl；带 rl 空洞的是 SPI/I2C 分支，而 SPI 恒 rx_len==rx_size，暴露面仅 I2C |
| D. 现场证据因果 | **不成立** | 「已上报失败(0x01)」与「同一事务又计入成功」并存，不是「既不报错也不上报」 |

## 真正的缺陷（比原断言更实在）

### 现象：设备完全读不到传感器，却向服务端上报「通道健康」

1. `uart_cmd_loop` 的 CMD_SAMPLE 分支（bus_worker.c:949-955）在 **TX 被接受**时就调用
   `scheduler_notify_channel_success()`，与 RX 结局无关。
2. `scheduler_notify_channel_success()`（scheduler.c:432-441）会 **递减** `error_count`。
3. 而 `error_count == 0` 时，`handler_data.c:146` 会 **整条跳过 EdgeDeviceHealth 子帧**：

   ```c
   if (!cmd->enabled || cmd->error_count == 0) continue;   // ← 健康 = 不上报
   ```

⇒ **每次采样都失败（全部 RX 超时）时，error_count 反而被清零，服务端看到的是「无异常」。**

### 影响面（已确证）

- 服务端 `ChannelHealth.comm_status`（0=OK/1=TIMEOUT/3=FAULT）永远为 0；
- 运营侧无法从设备健康上报发现「传感器完全无应答」；
- 本次事故中，故障持续 7 小时，服务端侧**没有任何**来自该通道的健康告警。

## 最小充分修法（可破坏性更新）

### 修改 1：成功判定从 TX-accept 改为 RX-complete

删掉 bus_worker.c:955 的 `scheduler_notify_channel_success()`（TX 成功不再算成功）；
改由 rx_task 在**收到完整响应**时上报成功（`handle_uart_event`/`complete_idle_response` 的完成点）。

### 修改 2：超时补记错误

bus_worker.c:1417-1426 的 RX 超时路径补 `scheduler_notify_channel_error(rt->bus_ch[i])`。

### 修改 3：错误码 owner 唯一化（防重复计数）

0x01/0x02/0x03 三类错误**只由 rx_task 上报**（它已有 s_rx_timeout_count/s_rx_error_count 计数器）；
`uart_cmd_loop` 只负责 **TX 失败**（bus_dma_write != ESP_OK）这一类。
明确写入注释：`scheduler_notify_channel_*` 的 owner 是 rx_task，cmd_task 不得再调 success。

### 修改 4：统计口径迁移

`txn/errs` 的成功率统计（:971）改为由 rx_task 维护（txn=发出的请求数，errs=超时+错误数），
或直接把 Stats 行改为分别打印 `tx` 与 `rx_ok/rx_timeout/rx_err`，不再输出单一的「成功率」。

## 测试缺口（必须补）

- 全目录 **0 处**引用 `uart_cmd_loop`；
- `host_tests/bus_worker_rx_tests.c:69-70` 把 `scheduler_notify_channel_success/error` 打成**空桩**
  ⇒ 现有测试**结构上不可能**发现该缺陷。
- 需补：host 测试断言「TX 成功但 RX 超时」时 `error_count` **递增**而非递减；
  以及「error_count>0 时 EdgeDeviceHealth 子帧**必须出现**」。

## 与缺陷 1 的关系

两者独立：缺陷 1（若成立）导致字节进不了 rx_task；缺陷 2 让「进了 rx_task 但没数据」在健康面上不可见。
**缺陷 2 单独就足以让本次事故静默 7 小时**，无论缺陷 1 是否成立。
