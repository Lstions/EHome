## 4. 事实核对：评审纠正了方案哪 8 处（最高价值部分）

| # | 方案 v0.1 声称 | 独立核对结果 | 影响 |
|---|---|---|---|
| F1 | "驱动代码里 **169 个**字段名" | 实测 **170**（基线 `dea94e4d`）；且**混入 18 个动作参数名**（`ControlParameter{Name:...}`）与 6 个 `*_ack` 回读伪量 | 门禁 3 与 M4 分母失效；v0.2 改为**不写死数字**，由脚本按 §12.3 口径推导 |
| F2 | `GetSensorDefinitions` 声明并集 ≈ 全部字面量 | 声明并集实测 **91**；"169/170 全在声明内"恒假 | 门禁 4 口径改为"声明 ⊆ 产出可达集"（反向校验，防幽灵声明） |
| F3 | 门禁 #1 可执行 | 与 §3.2/§9.2 自身设计互斥（automation 必然 import） | 见 B2 |
| F4 | 投影表主键 `edge_device_id` | `unified_data.edge_device_id` 生产 **179,532/179,532 全 NULL** | 见 B3 |
| F5 | "存量全是纯字面量，行为不变" | 本库 `alert_rules/automation_rules/data_sources` **均 0 行** ⇒ 该断言不可证 | 改 M0 扫描 + 三类处置 |
| F6 | §5.1 "见 §10.6" | **该章节不存在**（幽灵引用） | 已删 |
| F7 | §16 R-5 "CI 跑 bench" | §12.3 门禁表无 bench 项 | 门禁 10 已补 |
| F8 | M1 顺带覆盖 DG-05（category 32→64） | M1 清单**未含** | 已补入 M1 |

**另有三条结构性问题被评审发现（方案未提）**：
- `sensorfield` 若同时含 HTTP handler 并复用 `internal/api` envelope ⇒ **包环**（`sensorfield → api → automation → sensorfield`）。v0.2 已把 handler 移到 `internal/api`、GORM 模型移到 `internal/models`。
- `rule.compiled` 挂在 `models.AutomationRule` 会破 `models` 叶子性并成环。v0.2 改为包内旁路 map。
- `unified_data.edge_device_id` 全 NULL 是**未修复的 P1 缺陷（DS-14）**，任何"按 edge_device_id 聚合"的新设计都会静默为空。
