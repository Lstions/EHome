# 前端设计风格基线

> **状态**: 提案（约束 NodeOverview 等新页面的风格决策；监控持续推进）
> **版本**: v1.0
> **日期**: 2026-08-17
> **关联**: [../规范/前端开发与UIUX设计规范.md](../规范/前端开发与UIUX设计规范.md) | [前端页面功能基线-节点页.md](前端页面功能基线-节点页.md)

## 1. 风格定位：双体系并存（现状事实）

- **Platform 原生体系**（Element Plus + 项目 theme.css token）：管理页面主体。
- **BMS 页设计 DNA**（2026-08-13 生产升级沉淀）：紧凑运维密度、分区卡片、特化行容器。

新页面设计统一以"BMS 页 DNA 模式语言"为参照，而不是另起炉灶。

## 2. BMS 页设计 DNA（可复用模式）

1. **布局骨架**：实体身份/状态/操作 → 概览指标区 → 领域分区（可折叠区段）。
2. **关键设计决策**：
   - 信息密度高但可扫描：数值 + 单位紧跟，标签清晰。
   - 分区卡用标题 + 行列表，不用"折叠面板→卡片头→灰面板→行卡"多层套娃。
   - 状态用文字 + 颜色双重表达。
3. **交互与工程纪律（与视觉同等重要）**：
   - 加载/空/错误/离线/禁用五态各可辨，未知显示"—"不伪造。
   - 图表色值走 getThemeColors() 主题解析。
   - 单元分工：shared 组合 + 类型特化卡，禁止页面级复制。

## 3. 双体系关系

| 体系 | 适用范围 | 规则 |
|------|---------|------|
| Platform（theme.css token + PageHeader/StatCard/EmptyState） | 管理页通用 | 全部 MUST 遵守前端规范 |
| BMS DNA 模式语言 | 设备详情类、高密度资源面板 | 作为结构参照，不新增风格体系 |

## 4. 历史背景（防止回退）

- 指标卡曾经有渐变底风格 → MetricStatCard 统一（透明底 + tone 语义色 + 方向色只在文字上表达"放电中/充电中"）。
- 移动端 2×2 卡片曾回退损坏 → 现在单行 4 列紧凑（≤768px）。
- rebase 事故曾丢失响应式增量 → 风格规范与验收一起合入，防约定漂移。

## 5. 约束与监控

1. 新页面（如 NodeOverview 各 TAB）须在实现前 vision 提取设计稿完整色板并声明风格体系。
2. 改动后按前端规范 §5 验收矩阵走查（1440/768/390 视口 + 亮暗主题）。
3. 风格问题统一归入前端规范，本文档只留风格基线与 DNA 描述。
