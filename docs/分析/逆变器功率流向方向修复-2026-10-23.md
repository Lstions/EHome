# 逆变器功率流向「方向指向电池」修复（2026-10-23 第八轮）

## 0. 用户诉求（原话）

> 「逆变器功率流向的方向不对，明明电池放电，方向却指向电池」

截图证据：电池节点橙色、标签「放电 6.0A」，但逆变器与电池之间的连线箭头指向**电池**。

## 1. 根因（不是判定表写错，而是箭头写死 + 判定分散）

改前的实现有两处独立判定，彼此没有任何约束：

| 位置 | 做了什么 |
|---|---|
| `batteryClass` / `batteryLabel`（脚本） | 读 `battery_charge_current` / `battery_discharge_current` **两个独立寄存器**，正确判出「放电」 |
| 电池连线（模板） | 一条静态 `<path d="M358,140 … 530,200" marker-end="url(#pf-arrow)">` —— 起点固定在逆变器、终点固定在电池 |

于是 `marker-end` **恒落在电池端**：无论充电还是放电，箭头都指向电池。放电时画面
「文字说放电、箭头指电池」自相矛盾，正是用户报障的那一帧。

窄屏（≤768px）DOM 版是同一个缺陷的另一种形态：两行之间各只有一个**写死的「↓」**，
与电池实际充放方向完全无关。

顺带发现两处「方向信息最弱」的问题：
1. SVG 的箭头头部只有一个灰色 `marker`，而连线是绿/蓝/橙 —— 方向信息里最关键的「箭头」反而最不显眼；
2. 窄屏箭头 14px/400 + `--el-text-color-placeholder`（实测对白底 **2.3:1**，低于 WCAG 1.4.11 图形对象 3:1）。

## 2. 改法

### 2.1 方向判定收口成一个纯函数模块（单一事实源）

新增 `views/edge-device/inverter/powerFlow.ts`：`pvFlow / gridFlow / loadFlow / batteryFlow`，
全部返回「**相对逆变器**的方向」：

| dir | 含义 |
|---|---|
| `in` | 能量从该支路节点**流入逆变器** |
| `out` | 能量从逆变器**流出到该节点** |
| `none` | 无可判定流动（**不画箭头**，绝不猜方向） |

组件里的标签、节点配色、SVG 连线方向、SVG 箭头颜色、窄屏箭头，**全部由这一个结论派生** ——
两套判定之间再没有可漂移的空间。

各支路的知识边界（决定能否判定、是否要标「推定」）：

- **光伏 / 负载**：`pv1_power + pv2_power` 与 `output_active_power` 是实测功率 ⇒ 可判定；
- **电池**：HBAT 的充/放电流是两个独立寄存器（不是带符号单量）⇒ 谁 > 0 就往哪走；
  两者同时 > 0 属读数矛盾 ⇒ `none`，标签把两个数都列出来，**不猜方向**；
- **电网**：协议只给 HGRID 电压/频率，**没有任何市电功率传感器** ⇒ 方向无法实测。
  仍画「电网 → 逆变器」，但标 `inferred=true`，并在图例显式写
  「电网方向为推定（协议只提供电压/频率，无市电功率）」，不再与实测支路混为一谈。

脏数据（负值 / NaN / 越界：功率 > 50kW、电流 > 1000A、市电电压不在 50~600V）一律 `none`。

### 2.2 箭头方向由方向决定

- **SVG**：电池连线的 `d` 按方向**互换起终点**（放电 `M530,200 … 358,140`，充电反过来），
  `marker-end` 自然跟着反转到正确一端。
- **窄屏**：把原来整行一个写死的「↓」改为 `pfm-arrow-row` 两列独立箭头，
  方向 `in` ⇒ ↑、`out` ⇒ ↓、`none` ⇒ ·（中性点）。两行各有 `aria-label`
  读成「上排连接方向：光伏流入逆变器，电网流入逆变器」，不会只念「↓ ↓」。

### 2.3 让「方向」真正可读

- 箭头头部按语义分色（`pf-arrow-flow` 绿 / `pf-arrow-charge` 蓝 / `pf-arrow-discharge` 橙），
  与连线同色 —— 不再出现「彩色连线 + 灰箭头」；
- 窄屏箭头 18px / 700 + 语义色，实测对比度：flow 3.45:1、charging 4.20:1、discharging 3.35:1、
  静止中性点 3.08:1，全部 ≥ WCAG 1.4.11 图形对象 3:1 要求（判据用 1.4.11 而非 1.4.3：
  方向另有「放电 6.0A」文字与节点配色承担，箭头是图形指示符）。
- 每条连线带 `<title>`（悬停可读方向说明），外层 `svg` 带 `role="img" + aria-label` 汇总四支路方向；
- 暗色主题下语义色自动反向（实测 success-dark-2 on #29292b 正常，无需另写规则）。

## 4. 遗留与说明

1. **电网方向仍是推定值**：协议没有市电功率字段（HGRID 只有电压/频率，HOP 的功率是**输出**侧），
   要真实测「倒送电网」需要驱动与固件新增字段。当前已用 `inferred` + 图例声明把不确定性摆在界面上，
   而不是假装它是实测。
2. 本机开发库的是 8 天前的快照（含 `ehome-postgres` 与本轮报障设备不同源），
   真机页面级回归受登录限流（429）与设备数据缺失影响，未在本机完成；
   方向逻辑的验证全部走「纯函数 + 组件渲染 + 四工况离线页」三层，覆盖了缺陷本身的全部形态。
