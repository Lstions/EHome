## 2. 任务 A【F10 移动端导航位置感丢失】

**判断**：选"恢复页内面包屑并压缩为两段"，不选"新增返回列表按钮"。理由：
1. 面包屑的「节点管理」段**本身带 `:to` 链接**——同一元素既表达层级又提供返回入口，
   不必在 390px 已极紧张的页头再塞一个按钮（规范 §4.1.4 顶部至多一个 primary 主操作）。
2. 规范 §4.1.2 MUST 要求"面包屑至少表达列表 -> 当前实体"；恢复面包屑直接命中该条，
   而加返回按钮只是兜底，不满足"表达层级"。
3. 原「返回列表」按钮在 `NodeOverview.vue:598` 的 `v-else` 错误分支里，
   正常渲染路径上根本不出现，复用它会引入新的分支耦合。

**改法**：
- 移动端（<=768px）不再 `display:none`，改为 `display:flex` 两段式；
  用 `:deep(.el-breadcrumb__item:first-child){display:none}` 裁掉根级「首页」。
- 用 flex 而非 Element Plus 默认的 `float:left`：float 不参与父容器 overflow 计算，
  横向溢出会顶破页面。
- 兜底：`min-width:0` + `overflow-x:auto` + 隐藏滚动条；当前实体段 `flex:0 1 auto`
  可收缩加省略号，防止长名把胶囊撑成逐字竖排。
- **MainLayout 顶栏面包屑：结论是"维持隐藏"**。390px 下顶栏已被移动端抽屉按钮、
  logo、通知、主题、头像占满；顶栏面包屑横向仅 92px（1440px 实测），在 390px
  无可用空间。页内面包屑已提供层级线索，顶栏重复显示属规范 §4.1.5 禁止的重复容器。
  故本次**不改 MainLayout**（也不在白名单内）。

**实测（全部在 390/360/768/1440 四档）**：见第 5 节。

## 3. 任务 B【F14 统计卡无范围标注】

**/data（DataPanel.vue）**——关键发现：该卡片组混用**两种范围**，故必须逐卡标注，
不能共用一句页脚说明：
- 「数据点总数」= `total.value`，服务端按设备+时间范围筛出的**全量** → 标 `当前筛选`
  （改前叫「本次数据点」，实测 3797 而分页器也是「共 3797 条」，值本身是全量）
- 「采集覆盖时长」= `calculateStats()` 只遍历 `historyData`（当前页 20 条）→ 标 `本页`
  （实测"9分钟"确实只由 20 行算出）
- `dynamicStats` 的「最新<指标>」取自当前页最新一条 → 标 `本页`

**/monitor（Monitor.vue）**——同族问题，且口径更微妙（三页均无范围标注）：
- 「HTTP 请求总数」「数据点采集总数」= Prometheus Counter（`handler_metrics.go:82/106`
  `readCounterTotal`），**进程启动以来累计，重启归零** → 标 `进程启动以来`
- 「设备在线状态」「节点在线状态」= 直接 `COUNT` 全表 → 标 `全局`

未改 /dashboard（不在白名单）。

## 4. 任务 C【§3.4.5 '-' 统一为 '—'】

**高杠杆点**：在 `utils/format.ts` 定义 `export const UNKNOWN = '—'`，
让 `formatTime`、`formatObjectData`、`metricOrDash` 三处返回它。

白名单内逐页替换（`|| '-'` / `return '-'` / `? '-' :` 形态）：
- NodeOverview.vue：6 处模板占位 + 1 处注释
- DataPanel.vue：4 处（`formatTime`/`formatData`×2/`formatRawData`）+ 表格空值单元格
- Monitor.vue：`lastUpdateTime` 的 `'--'` → `UNKNOWN`

### 我**跳过**的 `'-'` 及原因

| 位置 | 形态 | 跳过原因 |
|---|---|---|
| `ChannelTerminal.vue:486` | `replace(/[:.]/g,'-')` | **正则替换串**，是时间戳文件名分隔符，非占位符 |
| `NodeDetail.vue:117,118` | `sessionDuration !== '-'` / `=== '-'` | **字符串比较**，与同文件 530-544 行的返回值配对；该文件不在白名单，改它必须两侧同改 |
| `NodeOverview.vue:875` 等 | `1900-01-01` / `0001-01-01` | **哨兵日期字面量**，参与 `isNaN` 判断，非显示占位 |
| `styles/theme.css` 等 | CSS 值、`var(--x)` 连字符 | CSS 语法，非 UI 文案 |
| 其余 40+ 处 | 分布在 `NodeDetail/NodeList/Dashboard/DeviceInfoCard/...` | **不在白名单**（任务书要求只改白名单内文件） |

> 全仓 `'-'` 实测 64 处（非测试文件）。其中白名单内 10 处已改；
> 白名单外按任务书要求**未动**，建议另立任务统一收敛。

## 6. 我额外发现并修复的**自己引入**的缺陷

加范围词后，390px 下「采集覆盖时长」折成末行只剩 1 个「长」字（§4.2.5 禁止的逐字竖排）。

**A/B 实验定性**：隐藏范围词后孤字换行**仍复现** → 该换行是**改前既有**问题，
但我的 chip 使其更明显。既然触及该区域（规范 §6「触及相关区域时应按风险渐进收敛」），
一并修掉。

**根因（实测尺寸）**：165px 卡 - 图标48 - gap12 - 内边距40 = 标签仅 63px，
而「采集覆盖时长」6 字需 72px。

**修法（在浏览器里逐个候选实测选定，非猜测）**：图标 48→32px、间距 12→8px、
内边距 20→16px，**字号保持 12px 不变**（拒绝"缩小到不可读"，§4.4.1）。
实测 360/390/414/768 四档全部单行显示。
