4. 暗色主题必须同时成立（规范 §4.5.1）。
5. **不做过度设计**：用户明确反对为「好看」增加装饰、步骤、术语。

## 1. 侧边栏滚动条样式异常

**根因**：全局 `theme.css:707-723` 的 `::-webkit-scrollbar` 用 `--bg-color`(#fff) 作 track、
`--scrollbar-thumb`(#c1c1c1) 作滑块 —— 都是亮色，而侧栏是**深色渐变**
(`--sidebar-bg-gradient`)。矮视口（实测 620px 高，菜单 892px）滚动时出现浅色滚动条压在深底上。

**目标**：侧栏内滚动条改为深色适配（细、低对比、悬停提亮），**只作用于侧栏**，
不得影响全局其它滚动区。移动端抽屉同理。

**验收**：视口高度 620px 截图侧栏，滚动条与深色底协调；亮/暗主题各一张。

## 2. DMA 绑定样式与页面整体不符

**根因**：DMA 绑定是「可写配置」，用 `el-select`（`size="small"`）直接塞进
①总线表格单元格（`NodeOverview.vue` ~437 行）②「资源详情」描述列表行（~575 行）。
而描述列表其余行都是**右对齐纯文本**，一个带边框/聚焦蓝框的下拉破坏了整列节奏；
表格里又因单元格窄（~138px）显得局促。

**目标**：让 DMA 绑定在两种位置都**读起来像同一套语言**：
- 描述列表：默认呈现为与其它行一致的「值 + 轻量编辑入口」，不常驻大边框；
- 表格单元格：紧凑、与行内其它控件（tag/开关）同一视觉重量；
- 保留「已绑定/未绑定/不可用」三态文字（规范 §4.2.2 要求文字表达）。

**验收**：总线配置 tab 与资源详情卡各一张截图；亮/暗主题。

## 3. 外设控制 UI 设计水平差

**根因**：`components/periph/PeripheralControl.vue` 只有
`<section><h4>GPIO 硬件资源</h4>…`，无卡片容器；`GPIOResourceList.vue` 的行是
`grid-template-columns: 1fr auto auto`，信息列吃满 `1fr` ⇒ 实测出现
「GPIO 1 可用 …………………………… [配置 GPIO]」的大片空白（截图已复现）。

**目标**（对齐同页「总线配置」tab 的成熟形态）：
- 用卡片/区段容器承载，标题层级与页面一致；
- 行内容**按信息聚拢**，消除跨屏空白：引脚标识 + 状态 + 配置摘要相邻，操作区贴右侧但不过度拉伸；
- 复用既有筛选条（`全部/已配置/未配置`）与空态；
- GPIO 与 PWM 两个列表风格统一。

**验收**：外设控制 tab 截图（亮/暗、桌面/375px 窄屏）。

## 4. BMS 页面 UI 设计水平差

**根因**（`views/edge-device/bms/`）：
- `BmsDetailPage.vue`「温度探头」4 个探针用大间距平铺，卡片内出现大片留白；
- `BmsMosStatus.vue` 用 `el-tag effect="dark"`（视觉过重）+ Open/Lock 图标，与页面其它指标表达不统一；
- `BmsProtectionGrid.vue` 在无保护时渲染一个**居中大绿 tag**「保护状态正常 (bitmask=0)」，
  上下各留一大片空白（截图已复现）。

**目标**：
- 温度探针：紧凑排布（grid，窄屏 2 列），数值 + 状态在同一阅读路径；
- MOS 状态：改用与页面一致的轻量表达（文字 + 语义色，不堆深色 tag）；
- 保护状态：无保护时**不要大留白**，用紧凑的一行摘要；有保护时才展开明细网格。

**验收**：BMS 详情页全页截图（亮/暗、桌面/375px 窄屏）。
