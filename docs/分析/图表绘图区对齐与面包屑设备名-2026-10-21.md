# 图表绘图区对齐 + 面包屑显示设备名（2026-10-21）

用户反馈两条：
1. 「图表长度显示参差不齐」
2. 「顶部面包屑不应该显示『边缘设备详情』，应该显示边缘设备名称」

---

## 一、图表「参差不齐」的真实成因

先说结论：**不是容器高度问题**。6 个 `.chart-sub-section` 实测高度全部 314px、
内部 canvas 全部 260×1124px —— 一眼看不出差异，所以容易被误判成「感觉问题」。

差异藏在 **ECharts 的 grid（绘图区）** 里。用组件暴露的真实 rect 测出来：

| 分组 | 改前 plot 宽 | 改前 plot 高 |
|---|---|---|
| PV输入 | 615px | 139px |
| 电网 | 688px | 122px |
| 输出 | 555px | 159px |
| 电池 | 628px | 148px |
| 温度 | 723px | 100px |
| 发电量 | 622px | 159px |

**两个成因**：

1. `containLabel: true` —— ECharts 先按左/右边距起算，再按**本图标签的实际宽度**往里收。
   左轴刻度「300.0」（5 字符）与「54.9」宽度不同；右轴 1 根（15%）与 3 根（29%）预留不同，
   于是每张图的绘图区左右边界都不在同一竖线。
2. `grid.top` 未设置 —— 交给 ECharts 自动布局，而自动 top 随「轴名个数 + 图例行数」变化。

## 二、修法

常规图（桌面 260px）改为**像素边距 + `containLabel: false`**，让 plot rect 只由常量决定：

```js
grid: {
  top: 56,                                  // 图例一行 + 轴名一行
  left: 64,                                 // Y 轴刻度最宽约 5 字符
  right: 24 + max(本图右轴数, 父级预留) × 64, // 右轴按 offset 60px 递进
  bottom: 46,                               // X 轴单行时间刻度
  containLabel: false,
}
```

「父级预留」由 `HistoryChartSection` 传入：它算出**组内最大右轴数**（`maxReserveRightAxes`），
每张图都用这个数算右边距 ⇒ 组内宽度严格相等，而不同页面仍按各自需要留白。

**窄桌面夹取**：769px 视口下画布只有约 453px，若仍按 24+3×64=216 预留，绘图区只剩 173px。
所以右边距夹到画布宽度的 34%（`RIGHT_MAX_RATIO`），下限 48px。

紧凑图（窄屏 150px 高）**保持原样**（百分比 + containLabel:true）——
小图里写死像素会切标签，且窄屏同时只显示一张图，没有「对齐」需求。

### 改后实测

| 视口 | plot 宽 | plot 高 |
|---|---|---|
| 1440 | 844 ×6（完全相等） | 158 ×6 |
| 1024 | 428 ×6（完全相等） | 158 ×6 |
| 769 | 235 ×5，输出 221（差 14px） | 158 ×6 |

769px 的 14px 差异来自「输出」有 4 根 Y 轴（3 根右轴），ECharts 在边距被夹到 154px 后
仍会为最后一根轴的标签让位；1440/1024 无此现象。该宽度已接近移动断点（≤768 走单图布局），
不影响实际使用。

## 三、面包屑末段显示设备名称

### 问题

顶部框架面包屑末段是按**路由段**推导的抽象称谓：`/edge-device/14` → 「边缘设备详情」。
但用户要看的是**具体是哪台设备**。

### 为什么不能用路由 meta

设备名称是**异步**取到的（详情接口返回后才知道），路由 meta 在导航时就固定了；
而且同一路由不同 id 切换时也要跟着变。所以做成一个轻量 store，由页面登记：

- `src/stores/breadcrumb.ts`：`leafLabel`（空串 = 不覆盖）+ `setLeafLabel` / `clearLeafLabel`；
- 三个详情页 `watch(() => device.value?.name)` 登记，`onBeforeUnmount` 清空（避免串到别的页面）；
- `MainLayout` 只把它用在**最后一段** —— 中间段必须保持模块名，因为它的语义是「点回列表」。

### 实测

| 页面 | 改前 | 改后 |
|---|---|---|
| `/edge-device/14` | `/ 边缘设备管理 / 边缘设备详情` | `/ 边缘设备管理 / **bms**` |
| `/edge-device/15` | `/ 边缘设备管理 / 边缘设备详情` | `/ 边缘设备管理 / **inter**` |
| `/node/3/overview` | `/ 节点管理 / 节点详情 / 节点总览` | 不变（该页末段本就是具体视图名） |

## 四、验证方式（可复现）

「对齐」这类几何问题不能靠肉眼比划，也不能靠截图像素扫描（曲线/面积填充会干扰）。
本轮给 `LineChart` 增加了 `defineExpose({ getPlotRect })`，探针直接读 ECharts 真实
`grid.coordinateSystem.getRect()`，于是对齐可以被**断言**：

```js
// frontend-shared/.tmp-probe/r7shot.mjs
for (const sec of document.querySelectorAll('.chart-sub-section')) {
  // 从 DOM 拿到 LineChart 组件实例，读它暴露的 getPlotRect()
}
// 输出：w=1440 widths=[724,724,724,724,724,724] heights=[158,158,158,158,158,158]
```

新增契约 `src/components/charts/__tests__/ChartPlotAlignment.spec.ts`（10 tests）锁死：
常规图必须 `containLabel:false` + 像素常量、上边距不得交给自动布局、
右边距取「本图轴数 vs 父级预留」的较大者、窄桌面夹取、`reserveRightAxes` 变化触发重绘，
以及面包屑 store 的 set/clear 语义与三页登记/清空契约。
