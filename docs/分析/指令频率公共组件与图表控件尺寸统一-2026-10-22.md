# 指令频率公共组件 + 图表卡控件尺寸统一（2026-10-22 第七轮）

## 0. 本轮用户诉求（原话）

1. 「按钮大小比例与图表的相比大太多了，按钮大小没有统一的规范。」
2. 「指令频率内容显示不全，一些内容被覆盖遮挡。」
3. 「指定频率应该抽一个公共组件出来，大家一起通用。」

截图（Screenshot_20261022_071143 / 071148，真机 393 宽分屏窗口）分别对应：
逆变器详情页的「指令频率」卡（多条指令的名称被右侧输入框压住）与「历史数据」卡
（时间档 / 导出 / 分组 tab 三类控件高矮不一，控件块比图表还高）。

## 1. 诊断（先量化再动手）

### 1.1 指令频率：窄容器下「名称被输入框覆盖」的结构性根因

真实设备页 `/edge-device/15`（泰琪丰逆变器，11 条指令）多视口实测
（`frontend-shared/.logs/ui-fix/round7/before-summary.json`，fine + coarse 各一遍）：

| 视口 | 文字×控件矩形相交的行数 | 最大重叠面积 | 说明 |
|---|---:|---:|---|
| 320 | **9 / 11** | 659 px² | 名称整段压在输入框下 |
| 360 | **6 / 11** | 139 px² | 同上 |
| 393 及以上 | 0 | — | 恰好放得下，所以一直没被发现 |

根因不是某条 CSS 写错，而是 ≤768px 的两列网格：
`grid-template-columns: minmax(0, 1fr) auto` —— 右列是 `auto`（输入框 104 + ms + 开关 ≈ 161px，
由内容决定、不可收缩），左列 `1fr` 的最小值是 0 ⇒ 窄容器下左列被压到 19px；
而 `.cmd-name` 用 `word-break: keep-all`（规范 §4.2.5 防逐字竖排）且**没有** `overflow-wrap` 兜底
⇒ 名称画到格子外，被后绘制的输入框盖住。**页面级 scrollWidth === clientWidth 恒等于 0**，
只看横向溢出的探针永远发现不了，必须量「文字矩形 × 控件矩形」的交集。

### 1.2 历史数据卡：同一张卡里三档控件高度 + 控件块高过图表

| 视口 | 时间档按钮 | 导出按钮 | 分组 tab | 卡头 | controlsH/chartH |
|---|---|---|---|---|---:|
| 320 fine | 48.5×40 (13px) | 108.8×36 (15px) | 32 (12px) | 142px（折 4 行） | **1.10** |
| 320 coarse | 48.5×44 | 108.8×44 | 32 | 154px | **1.20** |
| 393 fine | 48.5×40 | 108.8×36 | 32 | 96px | **0.90** |
| 393 coarse | 48.5×44 | 108.8×44 | 32 | 100px | **0.90** |
| 900 | 64.5×36 | 104.8×32 | 30 | 73px | 0.30 |

同一容器里并存 40/36/32（coarse 44/32）三种高度、13/14/15 三种字号 ⇒ 用户说的
「按钮大小没有统一的规范」；而控件块比图还高 ⇒ 「按钮比图表大太多」。

### 1.3 顺带发现的真机缺陷（本轮一并修）

- `el-input__inner` 在 ≤768px 实测 12px：Element Plus `size="small"` 的特异性压过了
  App.vue 的全局 16px 规则 ⇒ 违反规范 §4.4.4「≤768px 输入控件字号 ≥16px」（真机点输入框会触发缩放）。
- 桌面 `.cmd-desc` 用 nowrap + ellipsis，900px 实测 6 条指令描述被截断 19px（与「内容显示不全」同类）。

## 3. 共享组件设计（诉求③）

`CommandFrequencySection.vue` 现在是**全站唯一实现**，合并了两套实现各自的独占行为：

## 4. 容器感知布局（诉求②）

- 名称：`word-break: keep-all`（防逐字竖排）+ `overflow-wrap: anywhere`（实在放不下必须断行，不许画出格子）。
- 行：默认两列 `name | ctl` + 描述独占整行；`@container (max-width: 262px)` 整行降级为
  `name / ctl / desc` 单列（容器查询与视口解耦：分屏窗口、折叠面板内嵌、页面缩放都按真实容器宽降级）。
- 控件：`.cmd-controls` 可换行，输入框 `flex: 0 1 104px; min-width: 84px`（单列档 96px）⇒ 任何宽度都不横向溢出。

## 5. 控件尺寸档位（诉求①，已写入规范）

| 场景 | 桌面 fine ≥769 | ≤768 或 coarse | 字号 | 圆角 |
|---|---|---|---|---|
| 图表卡工具条（时间档 / 导出图标 / 分组 tab） | 32px | 36px | 12px | 6px |
| 正文输入控件 | 32px | 44px | 继承 | 4px |
| 页头图标按钮 | 44px | 44px | — | 50% |
| 表格行内操作 | 36×36 | 36×44 | 12px | 4px |

36px 的依据：§4.4 第 5 条允许「极高密度、非主要任务的工具栏」降到 36px，
前提是 **每个控件有可访问名称**（导出按钮给了 aria-label + title + tooltip 三通道）
+ **相邻间距 ≥6px**（分组 tab 6px、分段与导出 8px）。正文输入/页头/表单主操作仍走 44/32 档，未被降级。

## 7. 已知渲染细节（不作为缺陷）

`PV2 电压、电流与功率（可选硬件；PV1-only 机型恒为 0）` 在 414px 恰好落在单行临界：
Chrome 允许行末**收尾全角标点悬挂**（`）` 11.02px 悬挂到内容盒外 3.72px），
所以 `scrollWidth` 比 `clientWidth` 大 4px。实测文本右缘 349.72 < 下一列控件 x≥358、
自身 overflow=visible、无裁切祖先 ⇒ 用户看到的是完整的一句话，**不是截断**。
独立验证用「自身裁切 + 有裁切祖先 + 越界且非悬挂」三条判据把关，并单独记录悬挂处数（inform）。

## 7.1 过程中额外修掉的一处回退风险（D6）

`App.vue` 有一条 `@media (max-width: 480px) { .el-button { font-size: 15px } }` 的移动端全局缩放规则。
导出按钮改图标化后文字被 `el-icon` 取代、没有文字受它影响，但**只要按钮里有文字**（或将来加回文字），
≤480px 就会出现「工具条里三件控件两种字号」——正是本轮要根治的问题。
处理：`.hist-export` 显式写 `font-size: var(--control-font-toolbar, 12px)`（scoped 0,2,0 压过 0,1,0），
并在 `ChartCardToolbarSizing.spec` 里加反向断言（含对 App.vue 那条规则的在场证明）锁死。
实测 320/393/414 coarse + 900 fine：字体集合 `{12px}`、高度集合 `{36}`/`{32}`。

## 8. 遗留

1. BMS 的历史趋势卡仍是 `BmsChartsPanel`（电芯/温度/SOC 专用多图），本轮只统一「指令频率」，未与逆变器 `HistoryChartSection` 合并。
2. 指令频率卡在 ≤360px 容器下为「名称 / 控件 / 描述」三行式，行高比两列式高约 30px —— 这是保证不覆盖的代价，未再做更激进的压缩。
3. 图表卡工具条 36px 档低于正文控件的 44px 档，属规范例外；若后续把图表筛选视为主操作，应回到 44px 并同步调整图高比例门禁。
