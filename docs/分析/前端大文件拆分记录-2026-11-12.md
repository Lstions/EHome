## 2. 拆法（按优先级）

1. **脚本状态与逻辑 → composable**：按「一次查询/一次推送会同时改哪几处」整体搬，不按行数切。例：`useNodeOverviewData` 承载同一 `watch(route.params.id)` 驱动的五份数据（一起清空、一起递增代际）。
2. **自包含模板片段 → 子组件**：props 进、emit 出；破坏性写动作留在页面（需要页面级会话/事务代际）。
3. **纯映射/纯函数 → 独立模块**：展示口径、编码、分组、地址判定等，可单独单测且被页面与子组件共用，避免「同一口径两处写法」。
4. **共享样式 → 共享 css**：当多个子组件需要同一套窄屏规则时，抽 `*.shared.css` 由各引入方以 `<style scoped src>` **放在最后一个 style 块**引入（复现原层叠次序）。代价：该文件被编译多份（NodeOverview 那份 gzip 约 +5KB）。

## 3. 门禁处理：三级分类

### A. 零改动（真·未碰门禁）
`MainLayout`、`DataPanel`、`Dashboard`、`ChannelManager`、`HistoryChartSection`、`SensorFieldPicker` —— 拆的都是源码文本门禁射程之外的部分。这几个最有复用价值：它们证明「门禁最密的文件」也能拆，只要切开点选在断言对象之外。

### B. 只改读取路径（断言文本一字未改）
把「读一个 SFC」改成「读页面 + 读子组件拼接」，例如 `FixedColumnOcclusion` 把两张表的 `<template>` 合成一份源码，使「响应式取消固定的列」与「静态豁免列」两条断言都仍有对象（只指向其中一个会让另一条分母变 0）。

这类改动必须满足：
- 断言文本、条数、豁免一字不改；
- 拼接串真的包含子组件源码（不许指向空壳）；
- 页面级约定仍单独用页面源码断言（`PageHeader`、`<el-pagination>` 绑定、`feedback.confirmDanger(`、`listPageConventions` 路径登记）。

### C. 改变了断言性质（必须记录）
| 位置 | 变化 | 影响 |
|---|---|---|
| `AutomationRules.spec` 的 `mediaBlock()` | 从「取首个同宽度媒体块」改为「合并所有同宽度媒体块」 | 从「这些规则在同一块里」弱化为「存在于某个同宽度块中」。原因是同断点声明现在分布在页面与子组件的 scoped 样式里 |
| `EdgeDeviceList.spec` 的计数类断言 | 计数范围从「页面」变为「三段拼接」 | `await fetchDevices(true, true)` 恰 2 处、`invalidateLists()` ≥2 仍成立，但「恰好只在页面」的隐含语义放宽 |
| 同上 `not.toContain` 类断言 | 覆盖范围扩大到三段 | 属**收紧**（新文件里也不能出现），逐条 grep 确认 |

## 4. 被门禁钉住、因此没拆的典型段落

这些不是「懒得拆」，拆了会让门禁**失去对象**（分母为 0）或产生**假绿**：

1. **BMS 的 MOS 卡与保护卡必须同文件相邻**：门禁用 `indexOf('class="card mos-card"')` → `indexOf('class="card protect-card"')` 做源码切片，拆成两个组件会切出空串。
2. **MainLayout 顶栏按钮**：44px 触控目标靠页面 scoped 的 `.main-header .el-button.is-circle{min-width:44px}`。按钮进子组件后规则的 `data-v` 落在子组件根节点、按钮在内部 DOM ⇒ 规则失效、触控目标回退 32px（**真实行为回归**）。而 `TouchTargets.spec` 读页面文本，加 `:deep` 会打断其字面量正则。
3. **MainLayout 主滚动容器**：`MainScrollAnchoring.spec` 用 `@vue/compiler-sfc` **只编译 MainLayout.vue** 的 scoped 样式，拼接读取救不了。
4. **Monitor 统计卡 / 页头**：`compiledScopedCss('Monitor.vue')` 断言编译产物里的 `.stat-content[data-v-*]`。父 scoped 样式不进子组件内部 DOM，改 `:deep` 会改变编译后选择器文本导致正则失配。
5. **DataPanel 本地切片 + 两个分页器**：`listPageConventions` 以「路由页模板含 `el-pagination`」定分母，且 `EXEMPT_LOCAL_SLICE` 有「必须仍有事可免」的腐烂检查。
6. **ChannelList 整张表**：其 spec 的 `TableStub` 依赖 `<el-table>` **直接列组件**的作用域插槽（`col.children.default`），列搬进子组件则所有行断言失效——改夹具不属于「机械改读取路径」。
7. **MainLayout / Dashboard 的零散卡**：异常摘要卡的两条 `IconActionAccessibilityGate` 登记带「失效即报红」的反向守卫，搬走等于改豁免。

## 7. 经验（可复用）

1. **门禁靠 grep 时，注释也会被算进去**：`MobileTableWrapper.spec` 的分母是 `grep -rl '<el-table' src --include=*.vue`，新组件注释里写出该标签就会被误收，然后因「0 张表」报红。拆出的组件里不要出现该字面量。
2. **「页面文件里必须有 X」类断言，X 就别搬**：分页器、PageHeader、loader 命名、`confirmDanger` 调用点。搬走不是让门禁变严，而是让它**失去对象**。
3. **scoped 样式是拆分的隐形边界**：父组件样式只作用于子组件**根节点**，内部 DOM 全部失效。看到「某个 class 在门禁里被按行号/正则定位」时，先确认它迁走后是否还有人测它。
4. **计数类断言最容易被拆分悄悄放宽**：`恰好 N 处` 在多文件拼接后通常仍成立，但「只在页面里」的语义已经变了——这类变化必须在提交说明与文档里写明。
5. **拆完留证据**：DOM 多重集比对、CSS 规则计数、逐字节 diff，比「测试还是绿的」更能证明「只是搬移」。
