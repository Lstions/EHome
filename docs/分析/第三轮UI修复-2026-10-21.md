## 1. 图表显示错乱（图例画到画布外）—— 根因已定性

### 现象

/edge-device/15「发电量 (kWh)」卡：图例没出现在顶部，而是**一个巨大的序列名「总发电量 (kWh)」**
压在曲线和 x 轴刻度上（用户截图 1）。实测 3 个时点（4s/8s/14s/20s）稳定复现，不是加载瞬间。

### 定位过程（关键，避免以后再踩）

| 步骤 | 结果 |
|---|---|
| 找 DOM 元素 | `main` 内没有字号 >18px 的「总发电量」节点 ⇒ 文字画在 canvas 里 |
| 遍历 zrender display list | 所有 text 的 `fontSize` 都是 12，没有大字 ⇒ 不是「字号被放大」 |
| `legend.show=false` | 文字消失 ⇒ 确认是图例 |
| 把 `getOption()` 原样丢进**空白容器**的新图 | **同样错位** ⇒ 与容器/时序无关，是 option 自身 |
| 删掉 `grid` / 删掉多轴 | 恢复正常 ⇒ 需要 grid 才触发 |
| `legend.top=100` | 图例出现在 y=100 ⇒ `top` 生效，但配默认 `bottom` 时被夹在 top..bottom 之间布局，最终落到画布外 |
| 只把 `legend.bottom='auto'` | **恢复正常** |

### 根因（两处，都在 `LineChart.vue`）

1. **ECharts 6.1.0 的 legend 默认值带 `bottom`**（`LegendModel.defaultOption` 里 `bottom: tokens.size.m`）。
   我们只写 `top`，于是图例被放进 `top..bottom` 的垂直盒子布局 —— 实测画到画布顶部之外（文字 bbox y ≈ -9），
   只露出下边缘。**必须显式 `bottom: 'auto'`。**
2. 我们给 `itemWidth/itemHeight/textStyle.fontSize` 写了 **`undefined`**（`isCompactChart ? 值 : undefined`）。
   ECharts 把它当作「已提供」参与行高计算；隔离实验：同一份 option 只要 JSON 序列化（丢掉 undefined 键）就能正常渲染，
   直接传对象就错位。**改成按需展开**（只有紧凑图才补这几个键）。

顺带修掉两处同类缺陷：

- 桌面图例 `type:'scroll'`：会翻页隐藏序列（违反「不拿信息换对齐」），且在本例中与上述错位叠加。统一改 `type:'plain'` 自动换行。
- 多轴轴名重复：实测「发电量」组有 3 根 kWh 轴，顶部挤成 `(kWh) (kWh)` 并压住刻度。改为**同单位只在第一根轴显示轴名**（单位仍由图例后缀表达）。

### 修复后实测（dev + 生产一致）

- 图例：4 项 `日/月/年/总发电量 (kWh)` 完整显示在顶部，居中，无遮挡；
- 轴名：只剩左侧 1 个 `(kWh)`，右侧两根轴只有刻度；
- 5 张分组图（PV输入/电网/输出/电池/温度/发电量）逐一截图核对。

## 2. 逆变器温度「有问题」—— 两个独立缺陷

### 2.1 温度卡片把正常温度标成警告色（P1）

`InverterTempCard.vue` 原分级：`>60℃ 危险 / >40℃ 警告`。而逆变器正常工作时
PV/逆变/升压温度本来就在 40~55℃ —— 生产实测 **PV 41℃、逆变 45℃ 全被涂成黄色**，
用户第一反应就是「逆变器温度有问题」（截图里 PV温度 41.0°C 是黄色卡片）。

改为行业惯例分档：`≤60℃ 正常 / 60~75℃ 偏高 / >75℃ 危险`（只影响配色，不参与告警判定），
并把两个阈值提为 `TEMP_WARN_C / TEMP_DANGER_C` 常量。

### 2.2 两路「温度」根本不是温度（P1，数据面）

`unified-data/historical-batch` 近 3 小时 362 个采样点实测：

| 传感器 | 取值特征 | 判定 |
|---|---|---|
| pv_temp | 38~42℃，连续 | 正常 |
| inverter_temp | 36~43℃，连续 | 正常 |
| boost_temp | 31~38℃，连续 | 正常 |
| transformer_temp | 32~39℃，连续 | 正常 |
| max_temp | 38~43℃，连续 | 正常 |
| **pv2_temp** | **只有 3 个取值：30 / 50 / 100**，mean 90.52，04:01~05:01 之间反复跳变 | **不是温度** |
| **dc_rectifier_temp** | 与 pv2_temp **完全同步**（同一组 30/50/100） | **不是温度** |

处理（前端先行，可随时恢复）：

- 历史趋势「温度」组不再请求/绘制这两路 —— 否则会出现一条 100℃ 假尖峰，把真实的 30~43℃ 曲线压扁（用户截图 2）；
- 温度卡片不再显示这两项 —— 显示恒定 30℃ 的「温度」比不显示更糟；
- 驱动侧 `parseHTEMPCompact` 对这两位的归属**原本就写了「无法用数据自证」**（厂商位序约定）。
  现在有了反证（枚举式跳变），位序需厂商文档确认后再恢复；数据仍在库里。

### 修复后实测（393 / 1440，dev + 生产）

- 温度图：5 条真实曲线（PV/逆变/升压/变压器/最高），y 轴 20~54.6℃，图例完整；
- 温度卡：只剩 5 项，41℃ / 45℃ 为**中性色**，不再误标黄；
- 契约测试同步：`HistoryChartSectionMobile.spec`（温度组类别）、`InverterTempCard.spec`（边界 60/75、5 项）。

> 遗留观察（数据面，非本次修复）：温度曲线在 00:00~08:00 出现锯齿振荡，属设备上报数据本身在两组帧之间交替，
> 需要固件/驱动侧确认帧顺序，已记录待办。

## 3. 页面偶发自动向下滚动 —— 浏览器 scroll anchoring

### 根因（已定性，非 JS）

主滚动容器 `main.el-main.main-content` 被**浏览器的滚动锚定**改写了 `scrollTop`：
页面进入后图表/表格/折叠块**分批渲染**，视口上方内容高度变化时 Chromium 为「保住视口内的锚点节点」
静默改写滚动位置。它不经过 `scrollIntoView` / `focus` / `scrollTop` setter，也不发 focus 事件，
所以表现为「用户没操作，页面自己往下滚一段」。

### 排除项（都有实测依据）

| 候选 | 依据 |
|---|---|
| `scrollIntoView()` / `focus()` | 4 个目标页（BMS/逆变器/逻辑设备/数据面板）× 桌面+移动视口，插桩 `Element.scrollIntoView/scrollTo/scrollBy` + `HTMLElement.focus` + scrollTop setter：**JS 程序化滚动 0 次、main 内 focus 0 次** |
| `router` scrollBehavior | `router/index.ts` 未配置 scrollBehavior；全仓无 `history.scrollRestoration`、无 `window.scrollTo` |
| SPA 切换沿用上一页滚动 | 4 组长页↔长页/短页实测切页后 `top` 一律归 0 |
| el-collapse 动画 | 自增发生在**无任何交互**的静默渲染窗口 |

### 修复与实测

- `MainLayout.vue` 的 `.main-content` 增加 **`overflow-anchor: none`**（唯一滚动容器本体；保留 `overflow-y:auto`，没有禁用滚动）。
- 改前/改后同场景采样：dashboard 异步沉降期 **2 次自增（+60 / +76px）** → 改后 **0 次**；
  移动视口 **3 次（+76 / +60 / +136px）** → **0 次**；4 个目标页 × 明暗视口复跑 **0/0/0/0**。
- 新增 `src/layouts/__tests__/MainScrollAnchoring.spec.ts`（4 条，含「删声明必红」的反证）。

### 顺带收掉的重复实现

侧栏折叠也曾用「420ms 临时关闭锚定」处理同一类跳动（实测 inverter@1024 scrollTop −147/−249px）。
既然根因是**任何内容高度变化**都会触发，永久关闭已覆盖侧栏场景 ⇒ 移除临时窗口/定时器/class 绑定，
只保留永久一条规则（单一实现），并把原 spec 收窄为「永久规则 + 反向守卫（不得改回临时窗口）」。
侧栏折叠实测：scrollTop 2000 → 2000，**900ms 内自增 0 次**。

## 4. 分段控件文字未居中（用户截图：实时数据流 明文 / 16进制）

### 根因

`theme.css` 的「分段控件」规则**只加了 `min-height: 36px`（触摸目标），没有改 `display/line-height`**。
EP 默认 `.el-radio-button__inner` 是 `display:inline-block` + 自身行高 12~14px ⇒ 盒子被撑到 36/44px，
文字按行盒贴在顶部。

全站实测（1440 全路由 + 节点详情 8 tab + 通道弹窗）：23 个分段控件中 **16 个不居中**，集中在 4 处 —
逆变器「显示模式」、节点详情「外设控制」筛选、通道终端 HEX/ASCII、通道编辑弹窗（偏移 −2 ~ −11.5px）。
`TimeRangeSelector` 不在名单里（组件内已自带收口）。

### 修复

`theme.css` 统一声明（**不逐页 :deep 覆盖**，历史教训是各页覆盖导致同一控件三档不同高）：

```css
.el-radio-group .el-radio-button__inner,
.el-checkbox-group .el-checkbox-button__inner {
  display: inline-flex; align-items: center; justify-content: center; line-height: 1;
}
```

选择器必须带祖先前缀（0,2,0）：EP theme-chalk 是**按组件懒注入**的，`el-radio-button.css` 在 dev 下排在
theme.css 之后，同特异性 (0,1,0) 会被它的 `display:inline-block` 按顺序盖掉（第一版实测仍没生效）。

### 改后实测

- 全站 39 个分段控件 **不居中数 = 0**，偏移全部 **0.00px**（1440 与 393 各场景）；
- 盒子高度不变（桌面 36 / 窄屏 44），容器几何改前改后完全一致；`TimeRangeSelector` 无回归。

## 5. BMS 首屏「加载中」被伪装成「空数据 / 正常 / 关断」

### 改前实测（1440，模拟首屏慢接口）

4 个采样点（0.5 / 1.5 / 3 / 6s）全部是：指标卡 `—% / —Ah / —V / —A`、
保护状态卡「暂无数据」+ **12 个绿色「正常」徽标**、MOS「关断 / 关断」+「尚无 fet_status 数据」，
而同屏下方「保护触发历史」却写着「正在加载保护历史...」—— 加载中被表达成空数据，
更严重的是**把「未知」表达成「正常」**（安全隐患）。

### 修复

- 新增 `bms/realtimeViewState.ts`：纯函数四态 `loading / error / empty / data`（+ 首帧 12s 宽限期），可测；
- `MetricStatCard.vue` 新增可选 `loading`（默认 false，其它页面零变化）：加载时渲染骨架 + `aria-busy`，
  **不再把「—」当值显示**；
- `BmsDetailPage.vue`：指标卡/MOS/保护卡按四态渲染；保护状态未知时显示中性「未知」而不是 12 个绿色「正常」；
  加载/失败/空态三套文案互斥，失败态独立错误条 + 重试（重试入口 ≥3）；
- 新增 `BmsLoadingStates.spec.ts`（15 tests，含「loading 不得判成 empty/error」「未知≠正常」的反向守卫）。

### 改后实测（1440，拦截 latest-data 挂起）

0.5 / 1.5 / 3 / 6s 全部骨架（4 张指标卡骨架、MOS/保护骨架 + 「未知不等于关断/正常」提示、电芯「正在加载单体电压…」），
**9.18s settled 自动收敛为真数据**（不卡死）；失败态独立错误条 + 重试且不伪装成数据/空态。
