## 1. 绝对红线（违反 = 任务失败）

1. **禁止执行任何 `git` 命令**（包括 status/diff/add/log）。提交由主控统一完成。
2. **禁止连接/修改 `ehome`、`ehome_test` 或任何非 `ehome_sim_*` 数据库**。
   harness 在建立连接前必须用正则 `^ehome_sim_[a-z0-9_]+$` 校验库名，不合规直接拒绝启动。
3. **禁止向 `nodes/` 下非 `sim-*` 的节点发布 MQTT 消息**（同网段有真实设备）。
   仿真器在 `Connect`/`Publish` 前校验 NodeID 前缀，不合规返回 error。
4. **禁止修改白名单之外的文件**（见每期任务的白名单）。
5. **禁止**：`as any`、`@ts-ignore`、`t.Skip`、空断言（`if true`）、`_ = x` 式规避、
   删除或弱化任何既有断言、`// TODO` 占位后不实现。
6. 禁止把 `time.Sleep` 当作断言同步手段（仅允许在仿真器"模拟上报节奏"处）。
7. 不得为了通过而放宽门禁阈值（≥50 场景、ID 唯一、域 ≥10 等）。

## 2. 验收标准（主控会独立复核，且会做变异测试）

| 项 | 要求 |
|---|---|
| 编译 | `go build -buildvcs=false ./...` 与 `go vet -tags=simulation ./simulation/...` 零错误 |
| 格式 | `gofmt -l` 对新增文件为空 |
| 常规测试不受影响 | `go test ./...`（不带 tag）与改动前同样全绿 |
| 仿真套件 | `go test -tags=simulation -count=1 ./simulation/...` 全绿，场景 ≥50，0 skip |
| 变异验证 | 主控会**故意注入缺陷**（如删掉一处业务校验、关掉一个 sink 注入），套件必须变红 |
| 结构 | 无重复实现：帧编解码复用 `pkg/frame`；启动复用真实 `cmd/server` |
| 文档 | 新增文件有中文注释说明"为什么"，关键断言注明其守护的不变量 |
