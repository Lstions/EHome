## 二、图表量纲混用（举一反三的重点）

### 2.1 根因

`LineChart.vue` 的多 Y 轴只按 **unit 字符串**分轴：

```ts
const unit = s.unit || ''
const existingIdx = unitGroups.indexOf(unit)   // ← 只看单位，不看量级
```

而 `HistoryChartSection.vue` 的 BMS 分组把三者放进同一组：

```ts
{ title: '电压 (V)', categories: ['total_voltage', 'cell_voltage_max', 'cell_voltage_min'] }
```

总电压 ~50V 与单体电压 ~3.2V **单位相同**，于是共用一根 Y 轴；
轴上下界被 50V 撑到 ~60，两条 3.2V 曲线被压成贴底直线 —— **数据在，图上看不见**。

### 2.2 修复（两层，缺一不可）

**第一层 `LineChart.vue`：分轴判据加入量级**

```ts
const MAGNITUDE_SPLIT_RATIO = 10   // 量级差 ≥10 倍不再共轴
const MAX_Y_AXIS = 4               // 轴数上限，触顶则并入最接近的量级
```

- 只有 **单位相同 · 且量级可比** 才共用一根轴；
- 自定义范围（`yAxisMin/Max`）只在**单轴**时生效 —— 它是"整图一个范围"的旧契约，
  多轴时套到每根轴会给出错误上下界；
- 右侧轴数量动态决定 grid 右边距（原先固定 8%，多轴会把轴标签挤出画布）；
- 只有第一根轴画 splitLine，避免多条网格线互相干扰。

**第二层 `HistoryChartSection.vue`：自适应范围尊重量级**

```ts
// 组内量级差 ≥10 倍时不指定范围，交回 LineChart 分轴
if (max / min >= 10) return {}
```

并拆分 BMS 分组：

| 改前 | 改后 |
|---|---|
| `电压 (V)` = total + max + min | `总电压 (V)` = total |
| | `单体电压 (V)` = max + min |

> 逆变器分组**只加注释、不改分组** —— 它的组内单位差异（V/A/W/Hz/%）已由
> LineChart 多轴解决，量级差异由量级判据解决。若在那里按单位拆成十几张图，
> 页面会被拉得极长，是**过度修复**。

### 2.3 取证（生产真实数据）

修复前：单体电压两条曲线贴在 X 轴上，几乎不可见。
修复后：Y 轴自动缩放到 **3.06 – 3.28 V**，两条曲线完整可读（见附件截图）。

## 三、资源表"一片白"

### 3.1 根因（计算样式实测）

```
--no-border-light: #F0F2F5   ← 行分隔线
卡片背景:          #FFFFFF
```

`#F0F2F5` 与 `#FFF` 的对比度约 **1.06:1**，肉眼几乎不可辨 —— 表头、表行、行间
三层结构全部糊成一片白。

### 3.2 修复

- 新增页面级 token `--no-bg-subtle`（亮 `#F7F8FA` / 暗 `rgba(255,255,255,.04)`）；
- 表头加浅底色带；
- 正文行分隔线由 `--no-border-light` 改为 `--no-border`（`#E8EBF0`，对比度约 1.13:1）；
- 最后一行不画线，避免"半截线"。

> `--no-border-light` 在页面里有 **22 处**用途，因此**没有全局改它** ——
> 只改表格这一处，其余更轻的分隔保持不变。

## 四、总线工具未按 TAB 隔离

### 4.1 根因

模板里两块工具组**都无条件渲染**，只在按钮 `disabled` 上用
`activeBusType !== 'i2c'` 兜底 ⇒ 在 I2C TAB 上同时看到
「I2C 总线工具」和「快速操作 **UART 专属**」。

### 4.2 修复

- 工具组标题跟随当前 TAB：`{{ activeBusTab.label }} 总线工具`；
- 「地址扫描」`v-if="activeBusType === 'i2c'"`；
- 「修改波特率」`v-if="isUartTab"`（`isUartTab` 为新增 computed）；
- 「资源刷新」对所有总线通用，与地址扫描并列放在当前 TAB 组内；
- 只剩一组时 `.single-group` 占满整行，避免右侧留白。

### 4.3 逐 TAB 取证（实测）

| TAB | 工具组 |
|---|---|
| I2C | `["I2C 总线工具"]` |
| UART | `["UART 总线工具"]` |
| SPI | `["SPI 总线工具"]` |
| ADC | `["ADC 总线工具"]` |
| GPIO | `["GPIO 总线工具"]` |
| PWM | `["PWM 总线工具"]` |

—— **每个 TAB 只显示自己的工具，"UART 专属"字样已彻底移除**（它本是多余的，
既然只在 UART 出现，就不需要额外声明）。

## 五、可编辑性（人机交互优化）

### 5.1 资源详情：区分"物理事实"与"可写配置"

| 字段 | 可编辑 | 理由 |
|---|---|---|
| 资源名称 / 引脚 / 工作模式 / 关键参数 | ❌ 只读 | 设备上报的**物理事实**，改了只是本地假象，下次上报即被覆盖 ⇒ 制造第二真相 |
| **DMA 绑定** | ✅ 可编辑 | **真正可写的配置**（走节点配置下发）。此前只有资源表那个窄选择器能改 |
| 已挂载通道 | 只读计数 + 「查看」入口 | 省一次跳转 |

### 5.2 UART 波特率：内联替代弹窗

最高频场景是"只改一条通道"，弹窗要多两次点击且遮住整页。现在：

- 通道行内直接出 `el-input-number`，**Enter 提交 / Esc 取消**；
- 失败**就地**显示并可继续改（保持编辑态），不用重新找入口；
- 弹窗**保留**，用于"按资源批量改多条"这种确实需要确认范围的场景。

## 六、文案 / 大小写 / 分隔符统一

| 项 | 改前 | 改后 | 理由 |
|---|---|---|---|
| DMA 能力位 | `TX, RX, Burst` | `发送 · 接收 · 突发` | 前两个缩写、第三个英文单词，同文档内语言与粒度都不一致；同卡片「最大突发」本是中文 |
| DMA 绑定值 | `i2c/i2c0`（后端内部键） | `i2c0（I2C）` | 同一资源在资源表里是 `i2c0`，DMA 卡里却是 `i2c/i2c0`，用户会以为是两个东西 |
| 列表分隔符 | 混用 `, ` 与 ` · ` | 统一 ` · ` | 同页两种并列符是纯噪声 |
| DMA 卡字段名 | `类型 / 能力 / 绑定 / 兼容总线` | `通道类型 / 支持能力 / DMA 绑定 / 可服务总线` | 与页内其它字段命名对齐 |
| 工具组标题 | `快速操作` + `UART 专属` 徽标 | `{总线} 总线工具` | 各 TAB 命名一致，徽标已无必要 |

### DMA 选择器宽度问题（实测发现）

- 选择器写死 `width: 200px`，而该列只有 **~81px** ⇒ 溢出并盖住右侧「操作」列
  （实测单元格 `scrollWidth=206 > clientWidth=81`）；
- 已改为 `width: 100%`，并重新配比 8 列宽度（把宽度让给「DMA 绑定」「操作」，
  它们要放下选择器和两个入口；「引脚」「状态」内容很短）；
- 修复后 **8 列全部 `scrollWidth === clientWidth`，零溢出**；
- 表内绑定值显示**紧凑名**（`GDMA_CH0`，126px 放得下），完整文案
  （`GDMA_CH0（#0 · UART · I2C · SPI）`）保留在下拉选项与 `title` 提示里；
  资源详情卡有 365px，显示**完整**文案。

## 七、顺带修好的一个假失败

`NodeOverview.spec.ts` 断言：

```ts
expect(source).toContain('.btn {\n  height: 36px; ...')
```

本仓 Windows 检出为 **CRLF**（`core.autocrlf=true`，实测 3068 CRLF / 0 LF-only），
而断言里写的是 **LF** ⇒ 该用例在 Windows 上**恒失败**。断言意图是"字号/字重/行高成体系"，
与换行符无关，已改为正则 `/\.btn \{\s*height: 36px; .../`。

## 十、未做的部分（附理由）

- **逆变器分组不拆**：见 §2.2，属过度修复。
- **`--no-border-light` 不全局提升**：22 处用途，只改表格这一处。
- **`i2c0` 与 `I2C0` 的大小写未统一**：这是**后端数据**的大小写
  （fixture 用 `i2c0`、生产上报 `I2C0`）。前端统一会掩盖后端不一致，
  应由后端规范化，不宜在前端贴补丁。
