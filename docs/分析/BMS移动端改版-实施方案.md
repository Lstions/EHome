## 0. 先说清楚一个范围修正（重要）

初版验收标准「页面总高 ≤3200px」引用的是 demo B 的 3190px，但 **demo B 遗漏了 4 个真实区块**。
实测真实页面（393×875，fixture 回放）：

```
真实页面 mainScrollH = 6325px = 7.23 屏

   row mos-protect         1050   （MOS 364 + 保护状态 670）
   row cell-chart-row       535   （电芯电压分布）

   row charts-row          1085   （电芯电压历史趋势 592 + 运行趋势 1435 的合计）
```

下面所有目标数字都**覆盖全部 16 个区块**，不再用不完整范围的数字。

## 2. 两个最难压缩项的具体做法

### 2.1 运行趋势 1435 → 320px

**现状**：`BmsChartsPanel.vue` 内部 `trend-grid` 恒定渲染 5 个子图槽位（总电压/单体电压/电流/电池状态/温度），每个 200px 图 + 标题 = 1435px。

**做法**：
- 改为**单图 + 量纲切换器**：`el-radio-group`（或 `el-select`）选一个量纲，只渲染 1 张图
- 图高 200px，标题行 44px → 卡片约 320px
- **保留 5 个量纲的全部数据维度**，只是不同时渲染（数据仍一次拉取，切换不重新请求）
- 记住用户上次选的量纲（localStorage）

**为什么不是简单调小图高**：5 × 120px = 600px 仍需 0.7 屏，且手机 120px 高的折线图基本读不出趋势。

### 2.2 电芯电压历史趋势 592 → 300px

**现状**：`BmsCellVoltageHistoryChart.vue` 有 16 个 `el-checkbox` 平铺（占约 160px），图 280px。

**做法**：
- 16 个 checkbox 收进「选择电芯」`el-popover` / `el-dialog`，触发器显示「已选 16/16」
- 图上默认画全选折线
- 图高 280 → 160px（保留 tooltip 与图例）
- 卡片约 300px

## 3. 折叠策略

### 3.1 哪些默认折叠

**默认折叠**（8 项）：保护触发历史、温度趋势、SOC 与电流、电芯电压历史趋势、运行趋势、轮询间隔分布、实时数据流、操作历史

**始终可见**（8 项）：页头、指标卡、保护状态、MOS、电芯电压分布、温度探头、轮询指令配置、受控操作

### 3.2 折叠态必须带摘要

折叠不是隐藏信息，标题栏要保留**一行关键结论**：

| 区块 | 折叠态摘要 |
|---|---|
| 保护触发历史 | 近 30 天 6 次 |
| 温度趋势 | 当前 28.1℃ |
| SOC 与电流 | SOC 7.0% |
| 电芯电压历史趋势 | 压差 11mV |
| 运行趋势 | 总电压 51.76V |
| 轮询间隔分布 | 7 条轮询中 |
| 实时数据流 | 实时 · 548 条 |
| 操作历史 | 最近 0 条 |

### 3.3 折叠状态持久化

`localStorage['bms-collapse:<deviceId>']` 存展开过的区块 id 数组。
- 用户展开某区块后，下次进入保持展开
- 按 deviceId 隔离（不同设备各自记忆）

## 4. 图表降级策略（硬要求）

**任何一张图坏了都不能让整页白屏或报错。**

| 图表 | 数据源 | 失败/空数据时 |
|---|---|---|
| 电芯电压分布 | `latest-values` 的 `cell_voltage_1..16` | 显示「暂无单体电压数据」（现有行为） |
| 温度趋势 | `historical-batch?categories=temperature_1,2,3` | 空态 + 保持 217px 骨架，不塌陷 |
| SOC 与电流 | `historical-batch?categories=rsoc,current` | 同上 |
| 电芯电压历史趋势 | `historical-batch?categories=cell_voltage_1..16` | 同上 |
| 运行趋势 | `historical-batch` 5 组 | 同上 |
| 保护触发历史 | `historical-batch?categories=protection_status` | 「近 30 天无保护触发记录 ✓」（绿勾） |
| 轮询间隔分布 | `commands` 的 `interval` | 「暂无轮询指令」 |

**实现约束**：
- 每个图表独立 `try/catch` + 独立 loading/empty 状态，**不得用整页级 error boundar**
- 图表请求用 `Promise.allSettled`，**并发上限 2~3**（不要一次 6 个）
- 每个图表 `ResizeObserver` + 卸载 `dispose()`（照抄 `BmsCellVoltageChart.vue`）
- 单次 `max_points ≤ 500`

### 4.1 保护触发历史的口径（必须用跃变，不能求和）

实测数据（设备 14）：
```
近 7 天   5142 点  非零 0    唯一值 [0]
近 30 天 20520 点  非零 1239 唯一值 [0, 1]
近 90 天 20521 点  非零 1239 唯一值 [0, 1]
```

- 非零值**恒为 1** ⇒ 是状态位，不是计数。**直接求和得到的数字是错的**
- 正确算法：`0→1` 跃变 = 一次触发；`1→0` = 结束；持续时长 = 区间时长之和
- **默认时间范围必须 30 天**（7 天全 0，会让用户以为功能坏了）
- 只画**触发过的位**，其余收敛成一行「其余 11 项近 30 天未触发」

## 5. 桌面端策略（风险最高，必须明确）

**决策：桌面端（>768px）结构完全不动，只新增/调整 `@media (max-width: 768px)` 内的规则。**

理由：现有 5 个契约测试、141 个断言锁定桌面结构。移动优先改造只加媒体查询，141 个断言基本不受影响，风险最低。

**唯一例外**：新增图表的媒体查询要保证桌面也正常（桌面仍显示，只是不加移动端紧凑样式）。

| 步 | 内容 | 改动面 | 风险 | 验证 | 回滚 |

## 9. 已确认决策（2026-10-20 用户拍板）

1. **运行趋势的量纲切换器**：用 **`el-select` 下拉**（省宽度，移动端友好）
2. **保护触发历史时间范围**：**让用户可切 7 / 30 / 90 天**
   - 默认 **30 天**（实测近 7 天非零点为 0，默认 7 天会让用户以为功能坏了）
   - 切到 7 天若全空：显示「近 7 天无保护触发记录 ✓」+ 提示「可切到 30/90 天查看更多」
3. **折叠默认值**：执行 §3.1 —— 8 项诊断类默认折叠
