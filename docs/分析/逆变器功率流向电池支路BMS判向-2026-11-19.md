# 逆变器功率流向「电池静止」误判修复 —— 逆变器读 0 时由同节点 BMS 判向（2026-11-19）

> **状态**: 已实现 + 离线视觉验证通过（待生产部署）
> **范围**: 逆变器详情页「功率流向」电池支路 + 顶部电池指标卡；不改协议 / 不改后端
> **证据**: [桌面第⑨工况](../验证/证据-2026-11-19-逆变器BMS判向/desktop-bms-fallback.png) · [窄屏第⑨工况](../验证/证据-2026-11-19-逆变器BMS判向/mobile-bms-fallback.png) · [量化报告](../验证/证据-2026-11-19-逆变器BMS判向/visual-report.json)

## 0. 用户诉求

> 「BMS 都在放电了，INV 流向图还显示电池静止，不对！」

截图工况（逆变器页 / BMS 页同屏对照）：

| 来源 | 电压 | SOC | 电流 | 图上结论 |
|---|---|---|---|---|
| 逆变器 device 15（techfine_inverter） | 53.1V | 89% | 充电 0A · 放电 0A | **「静止」**（错） |
| 同节点 BMS device 14（jiabaida_bms） | 53.15V | 99% | **-1.96A** | 放电中（正确） |

## 1. 结论

**逆变器的 0A 不等于「电池静止」**，它只是「这台逆变器没有测到电池电流」。

改前电池支路只消费逆变器自己的两个寄存器（`battery_charge_current` / `battery_discharge_current`），
两路都为 0 就断言「静止」并停画箭头；而同节点 BMS 的直接测量显示电池正在放电约 2A。

现在：**逆变器任一路有读数 → 用逆变器自己的测量；两路都为 0 且有新鲜的同节点 BMS →
用 BMS 的有符号电流判向，并在标签 / 图例里注明来源；两源方向相反 → 仍不猜方向。**

## 2. 根因

### 2.1 数据侧（生产库实测，2026-11-19 16:00–16:20 CST）

| 时刻（UTC） | 逆变器 放电电流 | 逆变器 充电电流 | 逆变器 容量 | 同节点 BMS 电流 |
|---|---|---|---|---|
| 08:05:01 | **0** | 0 | 89% | （区间内 -1.88） |
| 08:06:21 | **0** | 0 | 89% | -1.88 |
| 08:07:31 | **0** | 0 | 89% | （区间内 -2.17） |
| 08:09:11 | **0** | 0 | 89% | -2.17 |
| 08:10:50 | **0** | 0 | 89% | （区间内 -2.13） |
| 08:11:40 | 2 | 0 | 88% | -3.42 |
| 08:12:30 | 3 | 0 | 88% | -3.97 |

即：逆变器 HBAT 的放电电流**连续 6 分钟读 0**，而 BMS 稳定在 -1.88 ~ -2.17A；
同一时段逆变器 `battery_voltage=53.1`、`battery_capacity=89` 与截图的「53.1V · 89%」逐字段吻合 ——
截图那一帧就是这段窗口。

### 2.2 为什么逆变器读 0 是「能力边界」而不是「电池静止」

- 逆变器**没有接 BMS 通讯**：`/latest-values` 里没有任何 `bms_*` 字段（`bms_comm_ok` / `bms_soc` 全缺），
  它的 89% 是**自己按电压估算**的容量（一小时从 100% 掉到 88%，而 BMS 一直是 99%~100%）；
- 泰琪丰 HBAT 的充 / 放电电流是**两个独立寄存器**、整安培分辨率，实测会整段读 0；
- 因此「逆变器两路都 0」同时兼容两种事实：「电池真的静止」与「逆变器没测到」。
  把后者显示成前者，是一次**错误断言** —— 用户看到的矛盾正是由此而来。

### 2.3 代码侧

| 层 | 改前行为 | 问题 |
|---|---|---|
| 纯函数 | `batteryFlow(charge, discharge)` 只看逆变器两路 | 没有第二个数据源，0A 就是「静止」 |
| 数据层 | 页面只订阅**当前设备**的 WS / 只拉当前设备 `/latest-values` | 同节点 BMS 的电流根本没进页面 |
| 卡片 | 详情页自己写了一份方向判定（只读两路电流） | 与流向图两处判定，可以分别说错话 |
| 视觉 | 标签「静止」+ 无箭头，与 BMS 页的 -1.96A 直接冲突 | 用户无从知道「两处读数不同源」 |

## 3. 改动

### 3.1 `powerFlow.ts`：判定单一事实源增加第三个输入

[`batteryFlow`](../../frontend-shared/src/views/edge-device/inverter/powerFlow.ts#L221) 新增可选参数
`bmsCurrent`（**有符号**：正 = 充电，负 = 放电，与 BMS 页「放电中（电流为负）」同口径），
判定顺序：

| # | 条件 | 结论 |
|---|---|---|
| 1 | 逆变器两路都 > 0 | 自相矛盾 ⇒ 不判方向（原有规则保留） |
| 2 | 逆变器方向与 BMS 严格相反 | 两源冲突 ⇒ 不判方向，两个数都摆出来 |
| 3 | 逆变器任一路 > 0 | 用逆变器自己的读数（`source='inverter'`） |
| 4 | 逆变器两路都为 0、BMS 有净流动 | **用 BMS 判向**（`source='bms'`，本次修的缺陷） |
| 5 | 都没有 / BMS 在死区内 | 静止 |

- 死区 `BMS_CURRENT_DEADBAND_A = 0.1`：JBD 电流分辨率 0.01A，静置抖动不应翻箭头；
- `BatteryFlow` 新增 `amps`（实际用于判定的电流大小，卡片复用）与 `source`；
- 脏数据（NaN / 越界 / 负数）依旧不产生方向。

### 3.2 新增 `useSiblingBattery.ts`：同节点 BMS 电流

[`useSiblingBattery`](../../frontend-shared/src/views/edge-device/inverter/useSiblingBattery.ts#L61)：

- `GET /edge-devices?node_id=…` 找**同节点**的 BMS（类型白名单 `BMS_DEVICE_TYPES = ['jiabaida_bms']`）；
- 首屏用 `/edge-devices/:bmsId/latest-values` 取 `current` 快照，随后由 WS 实时推送接管；
- **新鲜度闸门 `BMS_FRESH_MS = 120s`**：过期读数返回 `null` —— 离线 BMS 不得点亮箭头；
  闸门需要一个"会走的现在"（15s ticker），否则 BMS 掉线后 computed 不会重算、箭头会一直亮着；
- 失败只记日志，判向自动退回逆变器自身读数。

### 3.3 组件与页面

- [`InverterPowerFlow.vue`](../../frontend-shared/src/views/edge-device/inverter/InverterPowerFlow.vue#L216) 新增 prop `batteryBmsCurrent`；
  用 BMS 判向时标签追加 `· BMS`（[`batteryLabel`](../../frontend-shared/src/views/edge-device/inverter/InverterPowerFlow.vue#L269)），
  图例追加「电池电流取自 BMS（逆变器电池电流寄存器读 0A）」，aria-label 同步。
- [`InverterDetailPage.vue`](../../frontend-shared/src/views/edge-device/inverter/InverterDetailPage.vue#L344) 的电池指标卡与流向图
  **共用同一个 `batteryFlow` 结论**（卡片方向 / 副文本「放 2.0A·BMS」与图上标签必然一致）。
- [`MockPowerFlowPanel.vue`](../../frontend-shared/src/dev/MockPowerFlowPanel.vue) 增加第 ⑨ 工况（复刻本次报障），供离线验收。

## 4. 行为矩阵

| 工况 | 逆变器读数 | BMS 读数 | 电池支路 |
|---|---|---|---|
| 用户报障 | 充电 0 / 放电 0 | -1.96A | 橙色箭头指向逆变器，「放电 2.0A · BMS」 |
| 逆变器在测 | 放电 3A | -3.97A | 用逆变器读数「放电 3.0A」（不抢权威、不标 BMS） |
| 充电 | 充电 5.5A | +5.4A | 「充电 5.5A」指向电池 |
| 真静止 | 0 / 0 | 0.00A | 「静止」，不画箭头 |
| BMS 死区 | 0 / 0 | -0.05A | 「静止」，不画箭头、不加 BMS 标注 |
| 两源冲突 | 充电 2A | -1.5A | 不画箭头，「充电 2.0A / BMS 放电 1.5A」 |
| 无 BMS / BMS 离线 / 读数过期 | 0 / 0 | — | 静止（行为与改前一致）；有读数则照旧用逆变器 |
| 无 BMS 安装 | 放电 6A | — | 放电 6.0A（行为完全不变） |

## 6. 遗留（本次刻意不改）

1. **电压 / SOC 仍取逆变器自己的读数**（53.1V · 89%），与 BMS 页的 53.23V · 99% 不同源。
   这是逆变器**自己的估算**（无 BMS 通讯时按电压折算，实测 1 小时从 100% 掉到 88%）。
   是否在电池节点改用 BMS 的 V/SOC 是产品决策（会影响"逆变器自己的低电保护阈值"的理解），
   本次只标明了**电流**来源，未改 V/SOC。
2. **后端字段未改**：`battery_discharge_current` 仍是逆变器原始读数 0A，HA / 自动化 / 告警
   若消费该字段，仍会看到 0。要做统一口径需要后端增加"节点级电池电流"派生字段。
3. **多 BMS 节点**：同节点存在多台 BMS 时当前取列表第一台（不求和、不猜并联）；
   真实多包并联场景需要产品先定义口径。
4. **BMS 类型白名单**目前只有 `jiabaida_bms`；新增 BMS 驱动必须同步 `BMS_DEVICE_TYPES`。
