## 1. 为什么需要这份契约

UI/UX 审计最大的失败模式不是"看不出来"，而是**用印象代替事实**：
「这个间距有点挤」「配色不太协调」既无法复核、也无法验收、更无法判断改完是否真的变好。

规范 §5.2 已经给出答案：**视觉结论用 DOM 事实复核**（`location.pathname`、`getComputedStyle`、
`getBoundingClientRect`、`scrollWidth/clientWidth`），截图只作为**发现问题的辅助证据**。

本契约把这条要求固化成可机械执行的三合一取证：**截图 + DOM 度量 + 代码锚点**。
三者必须同时给出一条结论，缺任何一项该结论视为未验证。

## 2. 三轮证伪（写进来是为了让子代理不重犯）

本节全部是主控 Agent 在建立探针时**亲自踩到并证伪**的，不是推测。

### 2.1 截图会骗人：必须用 DOM 度量复核

`node-list` 在 mobile-390 的截图里，第二张卡的「设备ID F0F5BDFFFE02」看起来被横向切掉。
实测该 SPAN 的 `getBoundingClientRect().right = 341`，而 `viewport = 390` —— **它没有被横向裁切**，
只是卡片落在视口**高度**之外（第 844px 处被屏幕底边截住）。

> **推论**：任何"看起来被截断/重叠/压扁"的结论，必须先用 `getBoundingClientRect()` 与
> `scrollWidth/clientWidth` 复核。仅凭截图的结论一律视为未验证。

### 2.2 探针会误报：可滚动容器不是裁切

首版探针沿祖先链找 `overflow != visible` 就判为"内容被裁切"，在 `automation` 页报出 10 处。
逐条核实后全部是 Element Plus 的 `el-table__header-wrapper` / `el-table__body-wrapper` ——
它们 `overflow-x:hidden` 且 `scrollWidth(930) > clientWidth(310)`，是**宽表格的横向滚动容器**，
在内部滚动是设计允许的（规范 §4.3 表格条款要求的是"操作列可达 + 横滚提示"）。

> **推论**：判定裁切前必须排除「祖先自身可横向滚动」的情况，否则会把正常横滚报成缺陷。
> 修正后 automation 归零 —— **归零不是"没问题了"，而是误报被消除了**。

### 2.3 文档与实现不一致时以源码与运行时为准（规范 §8.2）

规范 §6「当前整改基线」的 7 条存量偏差是**历史快照**，不是当前事实。
审计必须逐条实测复核，已修复的标注"已闭环"，仍存在的补当前证据。

## 5. 审计维度（每页逐条过，共 7 维）

每条结论必须标注**规范条款号**，否则视为个人偏好，不予采纳。

| 维 | 关注点 | 规范条款 | 必须产出的证据 |
|---|---|---|---|
| **D1 布局与排版** | 间距节奏、对齐、层级、留白、容器套娃（禁止"折叠面板→卡片头→灰面板→行卡"）、圆角 ≤8px（统计卡/指标卡 12px 例外） | §4.1、§4.2.3-4、§4.4 | `getBoundingClientRect()` 的间距实测值 + 截图 |
| **D2 配色与主题** | 语义色正确（LOW/OFF/停止/未选中**不得**用 danger）、亮暗双主题可读、无硬编码 hex、图表色走 token | §4.2.1、§4.5、§3.6 | `getComputedStyle` 的实际色值（亮/暗两组）+ 对比度计算 |
| **D3 人机反馈** | 加载/空/错误/离线/权限/禁用六态可辨、禁用给出原因、破坏性操作二次确认含对象身份与影响、未知显示 `—` | §4.3、§3.4 | 触发各状态的 DOM 快照 + 文案原文 |
| **D4 动效与过渡** | 过渡时长/缓动一致、无布局抖动、骨架屏与内容结构相近、无长时间无反馈 | §4.3.3 | 过渡前后 `getBoundingClientRect` 差 + 时序 |
| **D5 业务完整交互流程** | 创建/编辑/删除/启停/筛选/分页/批量/跳转是否闭环；编辑不得展示创建专属字段；筛选变化重置分页 | §4.1、§4.3.2、§3.3.6 | 真实点击走完整流程 + 每步的 DOM/网络事实 |
| **D6 响应式与触控** | 360px 可完成核心操作、44x44 触控区（工具栏最低 36）、≤768px 输入框 ≥16px、页头换行不逐字竖排 | §4.4 | `getBoundingClientRect()` 尺寸 + 溢出/裁切度量 |
| **D7 可访问性与文案** | 可点击非原生容器有 role/tabindex/aria-label、状态不只靠颜色、术语正确（节点/边缘设备/通道）、无旧称 | §1、§3.1.3、§4.2.2 | DOM 属性原文 + 术语 grep 结果 |

## 6. 证据格式（每条问题一行，缺字段视为无效）

```
[编号] 页面 | 视口 | 主题 | 维度
现象:   <一句话，可复核>
证据DOM: <getComputedStyle / getBoundingClientRect / scrollWidth 的原始值>
证据截图: <文件名，如 mobile-390-light-node-list.png>
证据代码: <文件:行号 + 关键代码原文>
规范条款: §x.y.z（引用规范原文关键词）
严重度: 阻断 / 高 / 中 / 低
建议:   <可执行的最小改动方向，不写"优化一下"这类空话>
```

**严重度判据**（避免主观分级）：
- **阻断**：核心任务无法完成，或数据/术语误导用户做出错误判断
- **高**：违反 MUST 条款，或在常用视口下明显影响可用性
- **中**：违反 SHOULD 条款，或一致性问题（同类元素在不同页面表现不一致）
- **低**：打磨项，不影响任务完成

## 7. 绝对红线（违反 = 本次审计作废）

1. **禁止执行任何 git 命令**（包括 status/diff/add/log）。提交由主控统一完成。
2. **禁止修改 `frontend-shared/src/` 下任何文件**。本轮只审计、不改代码（改代码会污染后续证据）。
   唯一例外：可在 `frontend-shared/tools/` 下新增你自己的取证脚本。
3. **禁止连接或修改 `ehome`、`ehome_test`** 数据库；只允许 `ehome_uiux`。
4. **禁止编造证据**：没跑出来的 DOM 值不许写；截图文件名必须真实存在。
5. **禁止用主观词代替事实**："美观""优雅""体验差"必须转成可度量的现象。
6. **禁止只审桌面**：§4.4 的触控与 360px 是硬要求。
7. **禁止把规范 §6 的历史偏差当现状**：必须实测复核，已修复的标"已闭环"。
8. 报告里**必须**包含"我未能验证的部分"与"我原本的判断被证据推翻的部分"（诚实性要求）。

## 8. 交付物

1. 本域全部页面的 `dom-facts.json`（探针产出，原样保留）+ 截图目录清单。
2. 按 §6 格式的问题清单（markdown 表或结构化列表）。
3. 每个问题在源码里的**根因定位**（文件:行号 + 为什么会导致该现象）。
4. **优化方案**：按严重度排序，每条给出最小改动点与验收方法（改完用什么度量证明变好）。
5. 「未能验证的部分」与「被证据推翻的初判」两节。

## 9. 主控会独立复核的事项

- 抽查至少 20% 的 DOM 度量复跑，**数值必须一致**；不一致的结论直接作废。
- 抽查截图是否真实存在、是否对应所声称的 页面×视口×主题。
- 对每条"严重度高/阻断"的问题，独立用探针复现一次。
- 检查是否有把"设计允许的横滚容器"误报成裁切（§2.2 的坑）。
