# BMS 页面重设计需求（2026-10-15）

> 本文档是**隔离子代理的唯一输入**。它没有本次会话的上下文，所有必要信息都在这里。
> 目标：重新设计一个 BMS（电池管理系统）设备详情页 demo。

## 1. 项目背景

EHomeSystem：**ESP32-S3 采集器 → 3.0 TCP+TLS(mTLS) → Go 后端 → Vue3 + Element Plus 前端**。
前端仓库根：`frontend-shared/`（Vue 3 + TypeScript + Element Plus，Vite）。

BMS 设备通过 **UART 总线**接在采集器上，协议为 **jiabaida（嘉佰达/JBD）**。
一个采集器（节点）可挂多条总线通道，每条通道最多 5 个边缘设备。

### 现有页面（被重设计的对象）
- 路由：`/edge-device/:id`，BMS 分支渲染 `src/views/edge-device/bms/BmsDetailPage.vue`
- dev 演示页（可参考其"理想态"骨架）：`src/dev/BmsDemoPage.vue`，路由 `/dev/bms-demo`
- 参考 mock：`src/dev/MockBmsPanel.vue`，路由 `/dev/mock-bms`

## 2. 设备上报的数据（27 个字段）

```
cell_count            电芯数量
cell_voltage_1..16    单体电压 V（实际只用前 cell_count 个）
temp_1..4             温度探头 °C
total_voltage         总电压 V
current               电流 A（正=充电，负=放电）
soc / rsoc            剩余电量 %
remaining_capacity    剩余容量 Ah
nominal_capacity      标称容量 Ah
cycle_count           循环次数
fet_status            MOS 状态位（见 §3）
protection_status     保护状态位掩码（见 §4）
software_version      固件版本
```

上报频率：默认约 1 次/秒（可配置轮询间隔，见 §5）。

## 3. MOS（场效应管）状态 —— 本轮重点

BMS 有两个受软件控制的 MOS 开关：

| 名称 | 作用 | fet_status 位 |
|---|---|---|
| 充电 MOS | 控制是否允许充电 | bit0（1=导通，0=关断） |
| 放电 MOS | 控制是否允许放电 | bit1（1=导通，0=关断） |

**控制动作**：`set_mos_policy`（风险等级 elevated / "风险"），
参数为两个布尔（充电/放电目标状态）。后端执行是**带回读校验**的：
写 0xE1 帧 → 回读 0x03 帧 → 比对 `fet_status` 的 bit0/bit1 是否与目标一致，
不一致则判 FAILED 并给出"检查 protection_status 是否有硬件保护覆盖"的提示。
执行耗时约 1~2 秒（两次串口往返）。

**用户诉求（本轮）**：
> "MOS 状态完全可以做成开关，而不是放在什么受控操作里面"

即：MOS 应当像"电灯开关"一样直接呈现在 BMS 页面主要位置，
**不应该**让用户去 26 项「受控操作」清单里找 `set_mos_policy` 再走表单+二次确认。

注意：它是风险动作，现有安全模型要求风险动作经二次确认（确认/取消两键弹窗）。
请设计：**直接开关的交互 + 仍满足风险确认**的形态（例如开关切换时弹一个极简确认）。

## 4. 保护状态（protection_status 位掩码，12 位）

| bit | 含义 | bit | 含义 |
|---|---|---|---|
| 0 | 单体过压 | 6 | 放电过温 |
| 1 | 单体欠压 | 7 | 放电低温 |
| 2 | 整组过压 | 8 | 充电过流 |
| 3 | 整组欠压 | 9 | 放电过流 |
| 4 | 充电过温 | 10 | 短路保护 |
| 5 | 充电低温 | 11 | 前端 IC 错误 |

位=1 表示该保护**已触发**。全部为 0 表示正常。

## 5. 轮询指令（5 条，可单独设间隔；0=禁用）

| id | 名称 | 说明 |
|---|---|---|
| `read_basic_info` | 读取基本信息 | 总压/电流/容量/SOC/温度/FET |
| `read_cell_voltage` | 读取单体电压 | 各串电芯电压 |
| `read_hardware_version` | 读取硬件版本 | |
| `read_comprehensive` | 读取综合信息 | |
| `read_protection_count` | 读取保护历史次数 | 12 种保护触发次数统计 |

**硬约束**：**同时可轮询的指令条数上限 = 3**（固件静态数组 `MAX_COMMANDS_PER_DEVICE`，
后端 `MaxCommandsPerEdgeDevice` 镜像它）。超过则保存整单被拒（HTTP 400）。
设计时**必须**体现这个约束（例如：已启用 N/3、超限时明确提示要禁用哪几条），
不要让用户"改完保存、刷新没变化"。

## 6. 受控操作目录（26 项，含风险等级）

风险项需二次确认；非风险项可直接执行。

| id | 名称 | 风险 |
|---|---|---|
| `read_basic_info` | 读取基本信息 | 否 |
| `read_cell_voltage` | 读取单体电压 | 否 |
| `read_hardware_version` | 读取硬件版本 | 否 |
| `read_comprehensive` | 读取综合信息 | 否 |
| `read_protection_count` | 读取保护历史次数 | 否 |
| `read_custom_attributes` | 读取自定义属性（F0 读 3 个 uint16） | 否 |
| `read_test_mos_status` | 读取 MOS 测试状态（0C 读） | 否 |
| `read_protection_parameters` | 读取 BMS 保护参数（需进厂模式） | **是** |
| `read_system_parameters` | 读取 BMS 系统参数（需进厂模式） | **是** |
| `set_mos_policy` | 设置充放电 MOS 软件策略 | **是** |
| `force_balance` | 强制均衡（F5 + 回读 0x03 均衡态） | **是** |
| `clear_alarm` | 清除告警状态（E6 固定数据） | **是** |
| `find_car` | 寻车（蜂鸣器，F1 开/关，最长 30s 自动关闭） | 否 |
| `test_charge_mos` | 测试充电 MOS | 否 |
| `test_discharge_mos` | 测试放电 MOS | 否 |
| `auto_test_edv` | 自动测试 EDV（0D 设置静止时间，需 SOC>95%） | **是** |
| `bms_restart` | 重启 BMS（需观察离线窗口，不能以 ACK 判成功） | **是** |
| `write_protection_parameters` | 写入 BMS 保护参数 | **是** |
| `write_system_parameters` | 写入 BMS 系统参数 | **是** |
| `write_custom_attributes` | 写入自定义属性 | **是** |
| `write_internal_resistance` | 写入电芯内阻 | **是** |
| `write_sn` | 写入 SN 码 | **是** |
| `set_static_correction_time` | 设置静态修正时间 | **是** |
| `set_report_interval` | 设置上报时间间隔 | **是** |
| `set_charge_time_window` | 设置充电时间窗 | **是** |
| `set_discharge_time_limit` | 设置放电时限 | **是** |

操作执行有状态机：`QUEUED → DISPATCHED → DEVICE_ACCEPTED → VERIFYING → SUCCEEDED/FAILED/UNKNOWN/CANCELLED`。
UI 必须把这些映射成**中文可读文案**（已发送/执行中/校验中/成功/失败/结果未知/已取消），
**禁止**直接显示英文枚举。操作历史是审计线索。

## 7. 现有页面的已知缺陷（本轮要解决/规避）

1. **实时数据流抢滚动**（严重）：新数据到达时强制 `scrollTop = 0`，
   高频上报时用户**根本无法滚动**查看历史帧（"一直输出数据，滚动页面功能不能正常使用"）。
   日志类视图的标准做法：跟随模式 + 用户上滚即暂停 + "回到最新"入口。
2. **布局失衡**：底部两列（左"实时数据流" vs 右"指令频率配置+受控操作"）高度差极大，
   被 flex 等高拉出大片空白（已修，但设计时应避免同类结构）。
3. **MOS 藏在受控操作里**（§3）。
4. **轮询容量约束不可见**（§5）。

## 8. 设计约束（项目规范，必须遵守）

- **视觉**：Element Plus 组件库 + 项目 token（`var(--el-*)` / 项目语义 token）。
  圆角 ≤ 8px；卡片用既有 `.card` / `el-card` 语言；图标统一来自 `@element-plus/icons-vue`。
- **状态表达**：必须"文字 + 颜色"双通道，不能只靠颜色。
  **禁止**把正常工况（关断/停止/未选中/OFF）标成危险色 —— 关断不是故障。
- **中文优先**：界面上不出现英文枚举、内部键名、原始 bitmask 作为主文案
  （可作辅助信息小字）。
- **响应式**：1440px 桌面优先；≥768px 双列，<768px 单列堆叠；
  移动端可点击区 ≥44px。
- **信息密度**：首屏呈现"当前最需要知道的"。不要把所有 26 个操作平铺在一屏；
  分组 / 折叠 / 按使用频率排序都可以。
- **可行动**：任何被拒绝的操作都要在页面上留下**常驻**原因，不能只弹 toast。
- **不要过度设计**：不加不必要的步骤、必填项、术语。
  用户明确反对"二次确认里还要填操作理由"这类多余环节。
