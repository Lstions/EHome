# 边缘设备页头统一 + 面包屑收敛（2026-10-21）

用户反馈两条：
1. 「边缘设备的顶部头没有统一，应该使用统一的组件」
2. 「边缘设备中不应该再增加面包屑，要使用最上方框架的面包屑进行返回或跳转上层」

---

## 一、页头「没统一」的真实原因

排查发现：三个设备页**都已经在用同一个 `DeviceHeader` 组件**，但**传进去的内容不同**：

| 页面 | 标题 | 状态/类型标签 | 副标题 | 1440 高度 |
|---|---|---|---|---|
| BMS `/edge-device/14` | ✅ | ✅ 在线 / jiabaida_bms · 16S | ✅ 节点·通道·设备号·固件·轮询 | **100px** |
| 逆变器 `/edge-device/15` | ✅ | ❌ | ❌ | **57px** |
| 通用 `/edge-device/16` | ✅ | ❌ | ❌ | **57px** |

**这就是「用了统一组件但看起来没统一」** —— 组件相同、信息维度不同，视觉上仍是两种页头。
用户截图里 BMS 页两行、逆变器页一行，正是这个差异。

> 教训：契约只锁「用了哪个组件」是不够的，必须锁「传了哪些维度」。
> 本轮新增的 `DeviceHeaderUnified.spec.ts` 就是锁 props 维度而非组件名。

## 二、修复

三页统一到同一组维度（`title` + `tags` + `subtitle` + 完整操作组）：

- `InverterDetailPage.vue` / `GenericDeviceDetail.vue` 新增 `headerTags`（状态 + 设备类型）与 `headerSubtitle`（节点 · 通道 · 设备号 · 固件）；
- 副标题**缺失项跳过、不输出占位符**（页头是身份区，`—` 只会制造噪声）；
- 状态文案统一三档：在线 / 离线 / 状态未知（与 BMS 页同口径，不自造第四种）；

## 三、面包屑收敛到顶部框架

### 改前（用户截图即此形态）

- 顶部框架面包屑：`/ 边缘设备管理` —— **只到模块名，没有当前页**；
- 页面内又画一套：`边缘设备管理 / BMS 设备详情` —— 同一屏**两条面包屑**；
- 逆变器页没有页面内面包屑，但顶栏同样只到模块名 ⇒ 三个页面的层级表达也不一致；
- 更实际的问题：**「返回列表」的能力被从顶栏剥离**，只能点页面内那条。

### 修复

`MainLayout.vue` 的 `breadcrumbs` 从「按一级路径 push 一个字符串」改为**按路径分段展开、每级带可点目标**：

| 路径 | 面包屑 |
|---|---|
| `/edge-device` | 边缘设备管理 |
| `/edge-device/14` | 边缘设备管理(→列表) / 边缘设备详情 |
| `/node/3/overview` | 节点管理(→/node) / 节点详情(→/node/3) / 节点总览 |

- 中间项可点，**末项不可点**（当前页不该是可返回链接，EP 的 `:to` 会给末项渲染成链接，属误导）；
- 新增 `BREADCRUMB_SUB_LABELS` 解决三级路径退化 —— 改前 `/node/3/overview` 显示成「节点详情 / 节点详情」（第二段之后的未知段都 fallback 到详情称谓）；
- 同时移除 `DeviceHeader` 的 `breadcrumb` prop、`dh-crumb*` DOM/CSS、`goCrumb()`，以及 BMS 页的 `headerBreadcrumb`；
- 一并移除 `NodeOverview.vue` 的页内面包屑（`no-breadcrumb`，DOM + 全部响应式 CSS）—— 同类详情页统一收敛。

### 改后实测

| 验证 | 结果 |
|---|---|
| 三设备页页内面包屑 | **全部为 0**（`pageCrumb: false`） |
| 顶栏面包屑（设备页） | `/ 边缘设备管理 / 边缘设备详情` |
| 顶栏面包屑（节点总览） | `/ 节点管理 / 节点详情 / 节点总览` |
| 点击「边缘设备管理」 | `/edge-device/14` → **`/edge-device`**（真实跳转） |

## 四、本轮踩到的一个坑（记录）

用正则批量删除 CSS 时，把 `/* 面包屑… */` 注释块的**结尾 `*/` 一起删掉了**，
留下一个孤立 `/*` ⇒ PostCSS 报 `DeviceHeader.vue:36:1: Unexpected }`，
整个 `DeviceHeader` 编译失败，三个设备页全部白屏（ErrorBoundary 捕获 `Failed to fetch dynamically imported module`）。

**教训**：用正则删 CSS 块必须同时处理注释边界；改完立刻 `curl` 一下模块是否 200，
比跑完整测试快得多。已在本轮验证流程里固定为第一步。
