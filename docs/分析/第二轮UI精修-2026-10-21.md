# 第二轮 UI 精修（2026-10-21 用户真机反馈）

用户反馈三点：
1. 图表右上角时间档样式不对 —— 文字没居中、字号大小不一。
2. 边缘设备顶部「实时连接 / 刷新数据」那里样式不对，且应当**统一为一个组件**。
3. 自动化规则/策略引擎相关页面也要截图精读、找出问题并修复。

---

## 1. 时间档选择器（TimeRangeSelector）

### 实测根因（393×851 生产）

| 现象 | 实测 | 成因 |
|---|---|---|
| 文字没居中 | `.el-radio-button__inner` 高 36px 但文字贴上沿 | 全局 theme.css 只抬了 `min-height:36px`（触摸目标），没有 `display/line-height` |
| 四段长短不齐 | 宽度 53 / 59 / 41 / 58px | 窄屏 `flex: 1 1 auto` 按**内容**分配 |
| 大小不对 | 字号 12px，与相邻正文 13px 不一致 | EP `size=small` 默认，调用处各自 `:deep` 再改成 24px |
| 同一控件多处不同高 | 图表卡 24px / 诊断卡 36px | 每个调用页各自 `:deep(.el-radio-button__inner)` 覆盖 |

### 修复（组件内一次收口）

- `TimeRangeSelector.vue` 重写样式：`inline-flex + align-items:center + justify-content:center`、统一 13px、`line-height:1`；
  窄屏四段 `flex: 1 1 0` **等宽铺满**（实测 74/74/74/74 × 40px 高）、粗指针 44px；
- 新增 `dense` 档（卡片头右上角与 small 按钮同高 24px）与 `showCustom` 档（仪表盘只有 1h/24h/7d）；
- 删除 `BmsChartsPanel.vue` 里两处本地 `:deep` 覆盖 —— 各页各自覆盖正是「同一控件三处不同高」的根因；
- 仪表盘趋势卡不再自写 `el-radio-group`，改用同一个共享组件（实测等宽 101×3、40px 高、13px 居中）。

### 顺带修掉的两个图表问题（同一屏暴露）

- 仪表盘趋势图内还有 canvas 大标题「<类别>趋势」，与卡片头重复且挤占 60px 绘图区 → 去掉 canvas 标题；
- 默认趋势类别会落到 `alarm_*` 状态位（0/1 直线，看起来像没数据）→ 改为优先连续物理量（total_voltage / battery_voltage / soc / current …）。

## 2. 设备页头统一为一个组件（DeviceHeader）

### 实测问题（320 / 360 / 393 三档真机宽度）

| 宽度 | 改前 | 说明 |
|---|---|---|
| 320px | 页头 101px、标题 `int` `er` **折成 3 行**（16px 宽）、「⋯」掉到第三行（y=134）、按钮被压到 28px | 单行 flex 挤压 |
| 360px | 同上（标题 27px 宽 2 行、⋯ 掉行） | |

而且 BMS 详情页是**另一套自建页头**（`.page-head` + 面包屑 + 自绘操作组），与逆变器/通用设备页的 DeviceHeader 并存 —— 同一产品里三种设备页头三种样式。

### 修复

- `DeviceHeader.vue` 重写为统一页头：
  · 窄屏**确定性两行**：行1 = 返回 + 名称/标签 + ⋯，行2 = 「刷新数据」独占整行（实测 320/393 都是 105px、名称 35px 宽不折行、刷新按钮 313×36）；

- 三个设备详情页（BMS / 逆变器 / 通用）统一使用该组件（BMS 由子代理接入，见下）。

## 3. 自动化策略 / 告警规则页（截图精读 + 修复）

### 发现的问题（393×851 真机数据 + mock 数据两种态）

| P1 | 触发历史表固定「操作」列压住「规则」列文字（有数据后确认，此前无数据被标「待确认」） | 截图可见「客厅高…」「开窗通…」「作日白…」被竖线截断 |

### 修复

1. **ElMessage CSS（P0，入口级）**：`main.ts` 补 `import 'element-plus/theme-chalk/el-message.css'`。

2. **/automation 与 /alerts 窄屏改卡片列表**（`v-if="!isMobile"` 表格 / `v-else` 卡片）：
   规则卡 = 名称（完整换行）+ 触发器类型徽标 + 动作数徽标 + 需确认徽标 + 触发条件 + 动作 + 冷却/熔断 + 触发/编辑/删除；
   事件卡 = 结果徽标 + 时间 + 触发方式 + 规则名 + 触发值 + 命令 ID + 查看 + 详情。
   桌面 1440 保持原表格与固定列不变。
3. **F26 固定列契约同步**：卡片化后窄屏不再渲染固定列表格，判据改为「窄屏渲染卡片列表、不渲染带 fixed 的表格」，桌面 fixed 断言保留。
4. 创建抽屉窄屏字段布局与日期选择器宽度按媒查体收紧（细节见 findings）。
### 追加发现：对话框超出视口 + 轻提示不可见（都是「用户根本用不了」，功能测试查不出）

| 级别 | 现象 | 实测 |

### ⑤ 的连带影响（重要）

这个问题比它报出的数值更严重：**任何在 dev 上做的颜色对比度审计都会失真**。
上一轮复核员报的「23 处主色文字不达标」与之无关（那是另一条已修的暗色规则），
但本轮它报的 6 页 tag 低对比度全部落在这个陷阱里 —— 生产一直是达标的。
已加契约测试 `Round2ReviewFixes.spec.ts` 锁住「亮色基色必须 !important」，防止再退化。
