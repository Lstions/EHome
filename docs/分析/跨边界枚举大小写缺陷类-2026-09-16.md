# 跨边界枚举值大小写：一个缺陷类的根因与成员（2026-09-16）

> 本文记录一个**已造成 3 个用户可见缺陷、并仍在别处潜伏**的根因。
> 所有事实均带可复跑命令；判定区分「可达缺陷 / 死代码 / 假阳性」，避免误报占排期。

## 1. 根因：同名 `hardware_type` 在两张表里有**相反**的大小写约定

| 模型 | 位置 | 注释/声明 | **生产库实测** |
|---|---|---|---|
| `Channel.HardwareType` | `backend/internal/models/models.go:158` | `SPI/I2C/UART/ADC`（大写） | `channels` → **`UART`** |
| `DeviceConfig.HardwareType` | `backend/internal/models/models.go:213` | `uart / i2c / spi / gpio / adc (legacy)`（小写） | `device_configs` → **`uart`** |

```bash
# 复跑（只读）
docker exec ehome-postgres psql -U ehome -d ehome      -tAc "SELECT DISTINCT hardware_type FROM channels"
docker exec ehome-postgres psql -U ehome -d ehome_uiux -tAc "SELECT DISTINCT hardware_type FROM device_configs"
# ⇒ UART   /   uart
```

**同一列族内约定相反**（实测，不只 hardware_type）：

| 列 | 实测值 | 约定 |
|---|---|---|
| `channels.hardware_type` | `UART` | 大写 |
| `command_executions.status` | `UNKNOWN` / `FAILED` / `SUCCEEDED` | 大写 |
| `nodes.status` | `offline` | 小写 |
| `edge_devices.status` | `offline` | 小写 |
| `automation_events.result` | `executed` / `expired` | 小写 |
| `security_audit_events.result` | `queued` / `issued` / `success` | 小写 |

## 2. 写入侧不统一（**这是缺陷会复发的机制**）

后端**只归一 bus_type，不归一 hardware_type**：

| 位置 | 行为 |
|---|---|
| `handler_device.go:73` | `busType := strings.ToUpper(strings.TrimSpace(ch.BusType))` ← **归一了** |
| `handler_device.go:687` | `tx.Create(&ch)` ← hardware_type **原样落库** |
| `handler_device.go:755 / :774` | `candidate.HardwareType = *dto.HardwareType` ← **原样** |
| `handler_device.go:66` | `strings.EqualFold(hardwareType, busType)` ← 校验**大小写不敏感** |

⇒ 前端下发 `hardware_type='uart'` + `bus_type='UART'` 时：
**校验通过**（EqualFold）→ **原样落库** → 同一列里出现两种大小写。

前端确实在下发这种混合（`ChannelManager.vue:563-568`）：
```ts
hardware_type: form.hardware_type,            // 小写
bus_type: form.hardware_type.toUpperCase(),   // 大写
```
可达性：`ChannelManager` 被 `ChannelPanel.vue:15/98`、`NodeOverview.vue:661` 使用 —— **正常功能入口**。

## 4. 潜伏（语义同错，当前被逻辑吞掉 —— 一旦条件变化即变可达）

`ChannelPanel.vue:759` `getChannelsByBusType: ch.hardware_type === busType`（busType 小写）：
模板 `:32` 的用法是 `getChannelsByBusType(busType).length > 0 || hardware[busType]?.length > 0`，
生产 `hardware.uart` 非空 ⇒ **被 OR 吞掉**，当前不影响渲染。

## 5. 纪律产出（比单个缺陷更重要）

1. **枚举值的「约定」必须单点声明 + 有真实数据支撑**。本次两张表约定相反，靠模型注释就判错
   （`device_configs` 的注释确实写小写，但要连库才知道它是对的、而 `channels` 是大写）。
2. **区分「当前失效」与「约定脆弱」**。前者要修，后者要立约定 + 门禁；混为一谈会做出
   **无证据的改动**（例如去改一个当前能命中的精确匹配）。
3. **`EqualFold` 校验 + 不归一落库 = 允许混合入表**。校验的不敏感与存储的不归一必须成对决策。
4. **门禁建议（主控尚未裁定）**：只做后端一条 —— 「枚举列进 `c.Query(...)` 后直接进 `Where` 且未过
   `UPPER/LOWER` 归一 ⇒ 红」。判据纯机械、命中即真缺陷（`/channels` 曾是这样、已修），
   假阳性近零。**前端「字段×字面量」全量扫描不建议上** —— 它靠变量名猜来源
   （`form.x` 与 `ch.x` 文本同形、语义相反），误伤成本高于收益。
