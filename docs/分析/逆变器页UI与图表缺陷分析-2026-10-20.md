## 0. 一句话结论

整页 **9471px ≈ 11.1 屏**（桌面 6596px）。三类问题叠加：
① **语义错判**把「有输出」状态位当成告警，页面报假警；② **图表尺寸与容器不匹配**，
277px 宽的画布里塞 5 系列 + 双 Y 轴，图例分页、X 轴刻度挤成乱码；
③ **移动端仍是桌面布局**，固定高度/竖排列表/桌面尺寸 SVG 直接套到 345px 宽的卡片里。

## 1. P0「假告警」：`alarm_output` / `alarm_pv_to_load` 是状态位，不是告警

实测数据：`work_mode=2`（市电 Line）、`fault_code=0`、`alarm_output=1`、其余 10 个 alarm_* 全 0。

页面表现（截图 `inv-light-card2-状态与告警*.png`）：

- 卡片头：**「1 条告警」红色标签**
- 列表第 2 行：**「有输出 / 异常」红色高亮**（其余 11 项「正常」绿）

根因链：

1. 后端 `inverter_techfine.go:663-676` 把状态串 `S[1:13]` 的 12 个标志位一律映射成 `alarm_*` 字段
   （协议原文里这 12 位叫 alarm flags，但其中 pos0/pos1 的语义是「PV 馈能负载」「有输出」）；
2. 前端 `InverterStatusGrid.vue:83-96` 直接把 12 个 `alarm_*` 当告警展示，`active` 即「异常」；
3. `InverterDetailPage.vue:209-222` 的 `alarmCount` 用 `key.startsWith('alarm_') && val > 0` 计数 ⇒ +1。

⇒ 只要逆变器在带载工作（绝大多数时间），页面就常驻一条假告警。**这是本次最该先修的缺陷**：
它会让真告警失去可信度（狼来了）。

**修法（不改后端、不改协议映射）**：

- 把 `alarm_output`、`alarm_pv_to_load` 从「告警」移到「运行标志」，用中性色 + 双态文案
  （`有输出/无输出`、`PV馈能负载/未馈能`），不参与告警计数；
- 剩余 10 个真告警位维持 正常/异常；
- 单测锁住「状态位不得进入告警计数」。

## 2. P0 图表：277px 画布 + 260px 高 + 5 系列双轴 ⇒ 读不出数

历史数据卡 393px 下 **2441px**，内部是 **7 个子图**（PV输入/电网/输出/电池/温度/发电量/BMS），
每个画布实测 **277×260**。

实测症状（截图 `inv-light-card8-历史数据*.png`）：

| 症状 | 证据 |
|---|---|
| 图例溢出成翻页器（`◀ 1/5 ▶`），当前只显示 2~3 条 | 「输出」组图例是 `输出电压(V)` `输出频率(Hz)` + 1/5 |
| X 轴刻度重叠成乱码 `20?D?A?D?A?D?A` | 「电池」「输出」组 X 轴 |
| Y 轴左侧塞 2~3 根轴（250/60/1500 三个量纲并排） | 「输出」组 |
| 轴名 `(V)` `(Hz)` `(W)` 压在图例上 | 三张图都有 |

根因：`HistoryChartSection.vue` 对每个分组渲染 `height="260px"` 的 `LineChart`，**不看视口宽度**。
260px 高 + 277px 宽 ⇒ 图例区（top:30）与绘图区几乎等高，5 个图例项放不下、X 轴刻度间距 < 40px。

**修法**：

- 窄屏（≤768px）改「**单图 + 分组下拉**」：`el-select` 选分组（PV输入/电网/输出/…），只渲染 1 张图，
  高度 150px（自动进入 LineChart 的 `isCompactChart` 分支 ⇒ 不画轴名、图例贴顶、`axisLabel.hideOverlap`）；
  2441 → 约 260px。桌面保持 7 子图平铺逐像素不变。
- 复用 BMS「运行趋势」已验证的同一套交互（用户已拍板 el-select）。

## 3. P0 功率流向：640 固有宽塞进 345px 卡片

实测（截图 `inv-light-card1-功率流向*.png` + DOM）：

- SVG `viewBox="0 0 640 260"`，容器 345px，`@media (max-width:1100px)` 把它钉成 **640×260 + 容器 `overflow-x:auto`**；
- 结果：**右侧「负载」「电池」两个节点在屏幕外**，用户必须横向拖动才能看到一半内容；
- 节点坐标实测 x = 80 / 320 / 560，画布 640 ⇒ 560+76 > 345，必然出屏；
- 明暗两套配色下节点/连线都正常（这一项无缺陷）。

**修法**：窄屏不再用桌面 SVG 坐标，改**竖向 2×2 布局**（PV / 电网在上排，逆变器居中，负载 / 电池在下排，
用 CSS grid + 短箭头连接），字号用正常 DOM 文本（12/14px），完全自适应宽度、零横滚；桌面继续用现有 SVG。

## 5. P1 设备列表卡：`techfine_inverter` 类型漏判导致显示内部字段名

截图 2（暗色）：逆变器卡片三个读数显示 **「电池低电·」「电池未接」「电池电·」= 0.0**，标签被省略号截断。

根因：`utils/deviceReadings.ts:59-64` 的 `readingPriorityFor()` 只匹配 `t === 'inverter'`，
而真实 `device_type = 'techfine_inverter'` ⇒ 落到 `GENERIC_PRIORITY` ⇒ 取数据里字母序最靠前的字段，
正好是 `alarm_*`。**与之前 HistoryChartSection 漏 `_inverter` 后缀是同一类缺陷**（第二次犯）。

**修法**：改成 `t.includes('inverter')`（并同样的 `includes('bms')` 已正确），补单测覆盖
`techfine_inverter` / `inverter` / `generic_inverter` 三种写法。
