#### 2.1.1 回归结果（效果层）

这次解冻**不是**改一个布尔值就完事。真正的缺陷在传输层，且已定位到根因并修复：

1. **根因**：单步 ChannelCmdV2 命令在节点侧一律映射为 `CMD_WRITE`（`bus_manager.c:1064`）。该路径下：
   - `read_size > 0` 且回复短于它 ⇒ `complete_idle_response()` 判为 **error 0x03**（`bus_worker.c:1345`）；
   - `read_size == 0` ⇒ L985 `complete_control(&cmd, true, 0, NULL, 0)`，**成功但零字节**。
   GB3024 回复是一行约 15~40 字节的 ASCII、长度随命令与固件版本变化 ⇒ **两种取值都必然失败**。这才是"11 个动作全都没启用/用不了"的完整答案：即使把 `Enabled` 改成 true，不修传输层仍然无法工作。
2. **修复**：节点对 ChannelCmdV2 改为「行空闲即帧边界」（`bus_worker.c` 的 "short-read rule"）：短回复照原样投递，由服务端 `VerifyControlAction` 做权威校验；**遗留写响应路径的短读仍判 error**，规则未被放宽。
3. **测试**：
   - `esp32-collector/host_tests/bus_worker_rx_tests.c` 新增 `test_v2_short_read_delivers_partial_payload`（断言 V2 短回复必须成功投递原始字节），并保留 `test_short_read_reports_command_error`（遗留路径仍须报错）。
   - **变异自证**：把 V2 豁免去掉（恢复修复前规则）⇒ 新用例 3 条 CHECK 全红；恢复后文件 md5 一致。
   - 后端 `definition_test.go` / `inverter_techfine_test.go` 的断言同步翻转，并新增 `TestAvailabilityCodeActionsStayDisabled` 证明 fail-closed 未被放宽。
4. **诚实的边界**：**未做 GB3024 实机验证**（本机无该硬件）。上述结论的可信度来自：帧字节被逐字节钉死、固件行为有 host 测试与变异自证、且默认失败方式是超时而非静默成功。首次实机接入时应按 `docs/验证/证据/GB3024-<动作>-<日期>.md` 登记回读结果。

## 三、诚实声明（本文档的证据等级）

1. **无实机证据**：本次解冻的两个设备（Techfine GB3024、PRS-3001）在本机都没有实机；`/dev/ttyUSB*` 与 `/dev/serial/by-id/` 均不存在。台账的 `证据路径` 字段**如实留空**，没有用"代码论证"冒充"硬件证据"。
2. **因此状态是 `enabled` 而非 `reviewed`**：按 §4.2 流程，`reviewed` 需实机回归矩阵背书。本次以"只读 + 无副作用 + 运行期 gate 仍在"为放行理由，首次实机接入时**必须**补登记回读证据。
3. **写门禁未被削弱**，§2.3 两行是回归护栏的锚点。
