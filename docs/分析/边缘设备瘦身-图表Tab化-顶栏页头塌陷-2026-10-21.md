## 2. 页头塌陷（诉求 2）：两处根因，同一类错

### 2.1 设备页头（DeviceHeader）

- 现象：视口约 900px（内容区 652px）时设备名 inter 竖排 5 行、副标题竖排 40+ 行，页头占满一屏。
- 根因：`.dh-main` 是单行 flex，`.dh-actions` 为 flex:0 0 auto（内容宽 547px、不收缩也不换行）⇒ 放不下时只能压 `.dh-ident`（唯一可收缩项且 min-width:0 允许压到 0）。
- 实测（`header-sweep.json`，改前）：ident 宽 1160→261、1024→125、980→81、940→41、900→**1**、880~769→**0**；页头高 75 → 137 → 163 → 217 → 307 → **897px**。
- 修法：允许 `.dh-main` 换行（放不下时操作组整体到第二行）+ `.dh-ident` 给硬下限 360px + `.dh-actions` 可收缩/可内部换行；769~900 再把按钮间距 12→8、内距收到 10px，让操作组单行放下。
- 修后（`header-sweep2.json`）：1440/1280 单行 75px；1160~780 两行 **119px**；769 159px；≤768 走既有移动两行布局（112~172px，未改）；全程 overflowX=false。

### 2.2 应用顶栏（MainLayout）—— 视觉复核才暴露

- 现象：769~900 顶栏面包屑「边缘设备管理 / inter」被压成 2 行(900) → 3 行(860) → 4 行(820) → 6 行/114px(769)，文字竖排并溢出 60px 高的顶栏；769 还有 9px 横向溢出，「在线」徽标被压成两行。
- 根因：left / center / right 三段都没有可收缩项 —— center 的输入框有 min-content 下限、right 的图标组是固定内容，于是唯一能被压的 left（面包屑）被压穿，而 EP 的 breadcrumb 默认允许换行。
- 修法：`.header-left { min-width:0; flex:0 1 auto }`；`.breadcrumb` 本体（它同时就是 el-breadcrumb 根元素）设 flex-wrap:nowrap / white-space:nowrap / overflow:hidden，末级 crumb 可收缩并 text-overflow:ellipsis；`.header-right { flex:0 0 auto }` + `.ws-status { white-space:nowrap }`；769~1024 隐藏搜索框（Ctrl+K 仍可用）。
- 修后（`r6-appbar.mjs`）：769~1440 全部「面包屑 1 行 / 顶栏 60px / ovf=0」。
- 踩坑记录：第一版把「不换行」写成 `.breadcrumb :deep(.el-breadcrumb)`（后代选择器），但模板 `<el-breadcrumb class="breadcrumb">` 的 `.breadcrumb` 就是 `.el-breadcrumb` 根元素 ⇒ 空操作，769 仍折行。已在 spec 里加反向断言锁死。

## 4. 风扇转速百分比（诉求 4）

## 5. 图表文字重叠（诉求 5）

- 根因一：图例 top:30 + plain 折行，而 grid.top 是常量 56 —— 「输出」组 6 条序列 5 种单位在 844px 画布实测折 2 行，图例底边 ≈66px > 56px ⇒ 压住绘图区与轴名。
- 根因二：多右轴（offset 60/120/180）时每个轴名都画在顶部同一带 ⇒ (V)(Hz)(VA)(W)(%) 糊成一团。
- 修法：computeChartTopLayout（每项宽 = 标记 30 + 文字宽×1.12 + gap 10，贪心折行；grid.top = max(56, 30 + rows×20 + 6)）+ shouldShowYAxisName（右轴≥2 清空轴名，单位由图例承担）。单行图例仍是 56 ⇒ 与改前逐像素一致；紧凑图 grid 分支仍不写 top。

| 用例 | legendRows | gridTop |
| --- | ---: | ---: |
| 6 条 / 5 单位 @844（逆变器「输出」组） | 2 | 76 |
| 2 条单行 @844 | 1 | 56（=改前） |
| 同 6 条 @400 | 3 | 96 |
| 未挂载（canvasWidth=0） | 1 | 56 |
| height=150（紧凑） | — | 60（仅报告，不写入 option） |

## 8. 生产部署记录

> 本轮纠正了一个流程问题：**不要**再用「ehome-new:v8 + COPY dist」的 UI-only 构建 —— 那会产生 ui-fix12/13 式的后端回退（见 `docs/分析/生产镜像事故与部署校验-2026-10-21.md`）。本次按事故后约定，用仓库 Dockerfile 对 **git 归档的完整树** 做多阶段构建（Go 后端 + Vite 前端）。

1. `git archive <commit> | tar -x -C /tmp/ehbuild6`（干净树，不含工作区其它改动）
2. `docker build -t ehome-new:ui-fix15 /tmp/ehbuild6b --build-arg GOPROXY=https://goproxy.cn,direct`
3. `tools/deploy/verify_image.sh ehome-new:ui-fix15` → 5/5 代码标记通过（本地与服务器各跑一次）
4. `docker save | gzip -1 | scp` → 服务器 `docker load`
5. 备份 `/srv/ehomesystem/.env` → `backups/env-<stamp>.bak`；`EHOME_IMAGE=ehome-new:ui-fix15`、`EHOME_IMAGE_TAG=sha-db873985`
6. `docker compose up -d ehome` → 容器 healthy、`/health` 200、容器内 index-DyoRuZ3Q.js 与本地 dist 一致
7. 生产探针（`r6-prod2.mjs`，1440/900/769/393）：应用顶栏恒 60px、面包屑恒 1 行(16px)；设备页头 75/119/159/172px 全单行；tab 6 组、canvas 恒 1 个、风扇 30%；两页均无「实时数据流」「轮询间隔分布」；文档级横向溢出 0、控制台 0 错误
