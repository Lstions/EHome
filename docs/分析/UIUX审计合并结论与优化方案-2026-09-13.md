## 2. 三个阻断项（P0，主控全部独立复现）

### U-1 接口失败伪装成"一切正常"（D1 域，主控复现）
拦截 `/api/v1/overview` 返回 500 → `/dashboard` 4 个 KPI 全渲染 **0**，异常摘要卡显示
**绿色对勾 +「运行正常」+「节点与设备均在线，暂无采集错误。」**，无任何错误态。
`alertOkIconColor=rgb(103,194,58)`、`kpiValues=["0","0","0","0"]`、`elResult=0`。

**同族已在 6 个页面复现**（D2 域）：node-list / edge-device-list / device-configs 的 4 个 KPI 全 0 +
空态冒充；logical-device / channel 空态冒充。**D2 域实测 `okWordHits=[]`、`greenSummaryEls=[]`** ——
即"绿色对勾"是 dashboard 独有，其他页是"0 指标 + 正常空态"，**同因不同形**。

**对照组（同仓已有范式）**：`/node/1` 显示「节点不存在或加载失败」+ 重试；
`/edge-device/:id` 有 `errorStateCount=1` + el-result + 重试；**data-sources 是唯一正确处理错误的列表页**
（顶部 el-alert + 重试、KPI 显示 `—`）→ **修法已有现成参照，不需要新设计**。

根因模式三件套（D2/D3 逐页核实）：
1. `|| 0` 数值回退把"未知"写成 0（`NodeList.vue:371-376`、`DeviceConfigList.vue:316`）
2. `v-else` 无条件渲染"正常/无异常"摘要（`Dashboard.vue:98-101`）
3. `catch` 只弹 `ElMessage` 不置错误态（`LogicalDeviceList.vue:308-317`、`stores/alert.ts:27-35` 只有 finally 没有 catch）

### U-2 固件「目标型号」编辑静默失效（D3 域，主控真实 API 闭环）
前端发 `target_model`，后端 `handler_ota.go:220` 读 `node_model`，`ShouldBindJSON` 返回值被丢弃 → 返回 200 但数据未变。
主控实测：A 发 `target_model` → 200 且值仍为 `MODEL-ORIG`；B 发 `node_model` → 值变为 `MODEL-VIA-NODE-MODEL`。
**截图/DOM/控制台全部看不出异常** —— 只有真实 API 闭环能抓到。

### U-3 自动化触发历史显示裸主键（D3 域）
`AutomationRules.vue:76` 用 `prop="rule_id"` → 显示 `1`/`3`，而上方规则名为「S2-低电强制断充」「S1-SOC低开灯」。
**同页筛选下拉已经用 `r.name`**（`:63-65`），即页面早有映射能力。

## 8. 主控裁决记录（自主决策，2026-09-13 第八轮）

按"当作未发布产品开发"与"设计最先"原则，对 §7 的四项待裁决**由主控自主裁决**如下：

| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 对比度（F4） | **修，且必须走 token 层** | 对比度不达标是**可访问性缺陷**而非审美偏好（WCAG AA 是硬标准）。D2 域明确警告"逐页修会漂移"，故只改 `theme.css` 的语义 token，不动各页面。视觉变化可接受——未发布产品，且变化方向是"更可读"。**但不得引入装饰性渐变/新配色体系**（规范 §4.2.7）。 |
| 2 | 分页（F3） | **改为真分页** | `Limit(500)` 硬截断导致用户**只看到一半数据且不知情**——这比"看不到"更危险（会基于不完整数据做判断）。提上限只是把问题推迟。已派发实施任务，要求沿用 NodeList/EdgeDeviceList 的既有分页契约。 |
| 3 | 触控（F6） | **只扩热区，不改行高** | 规范 §4.2.3 要求"保持紧凑运维密度"，§4.4.5 允许高密度工具栏降到 36px。故：用 padding / `::after` 扩大**点击热区**至 ≥36px（页头图标 ≥44px），**视觉密度不变**。验收必须用 `elementFromPoint`（`getBoundingClientRect` 测不出伪元素热区）。 |
| 4 | 76 条的处置 | **先做 P0+P1，P2/P3 随触及面渐进** | 规范 §6 明示"存量偏差不要求在无关功能改动中顺带重构"。P0+P1 已派发 5 个并行任务；P2/P3 记入方案等后续。**但新增代码不得复制这些模式**（规范 §6 硬要求）。 |
| 5 | 审计断言沉淀（D3 域提出） | **沉淀为 CI 门禁，但只收可机械判定的** | 规范 §7.6「只有可自动判断、影响面明确且已经证明能防真实回归的规则，才进入强制门禁」。故只沉淀：DOM 溢出/裁切、触控热区尺寸、对比度阈值、关键元素存在性。**主观项（美观/间距节奏）不入门禁。** 已单独派发。 |
