本文档记录前端数据通道统一性评估（F9）的发现与清理任务清单，作为后续清理任务的设计输入。

## 1. 结论摘要

前端存在两类通道冗余：

1. **unifiedDataApi 双重死代码**：该 API 模块在首屏链路中已无调用方（部分方法还是旧实现的别名），是三详情页改造后的遗留。
2. **历史数据查询 7 处重复 client.get**：DataPanel / 设备详情页各自直连 `/unified-data/historical` 系列端点，没有统一 API 模块封装。
3. **WS 双事件载荷级重复**：`channel_data` 与 `data_update` 两个事件由后端同一条已解析采样发布（双消费者），前端双订阅同一 payload 语义重叠。

## 2. 现状盘点（评估时证据）

| 项 | 证据 |
|----|------|
| 三详情页实际数据通道 | BMS/逆变器/通用详情均走 edgeDeviceApi + WS，unifiedDataApi 不在首屏链路 |
| unifiedDataApi 现状 | 部分方法无调用者（死代码），部分与 edgeDeviceApi 重复 |
| 历史查询 7 处 | 分散于 DataPanel.vue 与各详情页的 client.get('/unified-data/historical'...) |
| 双事件 | consumers_heavy 同一条数据同时 publish channel_data 与 data_update |

## 3. 清理任务台账

| # | 任务 | 目标 | 备注 |
|---|------|------|------|
| C1 | 删除 dead unifiedDataApi 方法 + 收敛历史查询到统一模块 | edgeDeviceApi / unifiedDataApi 二选一收编 | 需先跑全量 TS 依赖分析确认零调用 |
| C2 | WS 事件归一 | 只订阅 data_update，channel_data 保留为兼容/终端专用 | 确认 channel_data 无其他语义（如终端 raw 数据）再动手 |
| C3 | API 返回形状统一 | 消 `res.data \|\| res` 类兼容代码到 API 模块层 | 见前端规范 §3.2.9 |
