## 2. 页头窄桌面塌陷：根因与修法

### 现象
用户截图：视口约 900px（内容区约 652px）时，设备名 `inter` 竖排成 5 行、副标题「节点…·通道…·设备…·固件…」竖排 40+ 行，页头占满一屏。

### 根因（宽度扫描实测，`header-sweep.json`）
- `.dh-main` 是**单行** flex；`.dh-actions` 为 `flex: 0 0 auto`，内容宽 547px 且不收缩、也不换行到第二行。
- 放不下时 flex 只能压 `.dh-ident`（它是唯一可收缩项，且 `min-width: 0` 允许压到 0）。
- 实测 ident 宽度随视口递减：1160→261、1080→181、1024→125、980→81、940→41、900→**1**、880~769→**0**；页头高度 75 → 93 → 137 → 163 → 217 → 307 → **897px**。

### 修法
- `.dh-main { flex-wrap: wrap }`：放不下时让**操作组整体换到第二行**，而不是压身份信息。
- `.dh-ident { min-width: min(360px, 100%) }`：360px 是「名称 + 2 个标签一行放得下」的实测下界（本页 39+151+8≈198，留余量给更长的设备名与 BMS 的 3 个标签）。用 `min-width` 而非 `flex-basis`，因为前者是硬下限、不会被 shrink 压穿。
- `.dh-actions { flex: 1 1 auto; min-width: 0; max-width: 100% }`：换行后独占一行时右对齐；769~800 这类「比操作组自身还窄」的视口下由操作组**内部**换行，不溢出页头盒。

### 修后（`header-sweep2.json`）
- 1440/1280：单行 75px（与改前一致）；1160~880：两行 119px；840~769：两行 163px（操作组内部换行）；≤768：走既有移动两行布局（112~172px，未改）。
- 任一宽度都不再出现竖排文字；`overflowX=false`（页头无横向溢出）。

## 3. 历史数据：桌面平铺 / 窄屏下拉 → 分组 tab + 单图

### 改前的问题
- 桌面把 7 个分组纵向平铺：`7 × 260px ≈ 1900px`，要看全得滚三屏；也是「图表长度参差不齐」的结构性来源（同屏对比 ⇒ 每张图 plot 必须逐像素相等）。
- 窄屏是一个 `el-select`：换分组要点两下（展开 + 选择），且 393 下时间档位被 CSS 拉成整行 4 段、比图还高，「按钮与图表大小对比比例异常大」。

### 改后
- **两种视口同一结构**：`role=tablist` 的分组 tab（原生 button，`aria-selected`）+ 单张 `LineChart`；同屏只建 1 个 echarts 实例（不再为 7 张图各建一个）。
- tab 用 `flex-wrap` 而不是 `el-tabs`/横向滚动：7 个分组在 769~900 的卡片里会溢出，横向滚动或「◀ ▶ 翻页器」等于默认隐藏分组；折行保证**永远全部可见**。
- 切换只改 `activeGroupTitle`，不调用 `fetchHistoryData`（数据已在内存）。
- 图高：桌面 320px（单图给足高度）、窄屏 200px（≤220 才进 LineChart 紧凑分支：不画轴名/图例贴顶/axisLabel.hideOverlap）。

### 实测（`hist-tabs.json`）
| 视口 | 卡片高 | 卡头 | 时间档 | 导出按钮 | tab 行 | 图高 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1440 | 477px（原约 2000+） | 36px | 258×36 | 105×32 | 1 行 30px | 320px |
| 1024 | 477 | 36 | 258×36 | 105×32 | 1 行 | 320 |
| 900 | 477 | 36 | 258×36 | 105×32 | 1 行 | 320 |

卡片高度从「滚三屏」降到 477px；时间档位在 393 下由「铺满 319px」收到 194px，与 200px 高的图比例正常。

## 5. 图表文字重叠（图例压绘图区 / 多轴轴名互压）

### 根因
- 图例 `top: 30`、`type: plain` 在宽度用尽时自动折行，而 `grid.top` 是常量 56（只够 1 行图例 + 轴名）——「输出」组 6 条序列 5 种单位在 844px 画布**实测折 2 行**，图例底边 ≈66px > 56px ⇒ 压住绘图区与 Y 轴名。
- 多右轴（offset 60/120/180 递进）时，每根轴的 `name`（`nameLocation:'end'`）都画在顶部同一带内 ⇒ `(V)(Hz)(VA)(W)(%)` 糊成一团。

### 修法（收敛成可单测的纯函数）
- `computeChartTopLayout({ canvasWidth, items, height })`：每项宽 = 标记 30 + 文字宽（全角=字号、半角=0.6 字号）× 1.12 安全系数 + itemGap 10，对 `canvasWidth − 12` 贪心折行；`grid.top = max(56, legendTop + rows×20 + 6)`。
  - 1.12 的标定依据：844px 实测折 2 行；取 1.08 会估出 818 < 832 而误判 1 行（假绿）。
- `shouldShowYAxisName({ compact, index, unit, priorUnits, totalAxes })`：右轴数 ≥2（总轴数 ≥3）时**所有轴名清空**（单位由图例项承担）；右轴 ≤1 保留原行为；紧凑图一律不画。
- 单行图例时 `grid.top` 仍为 56 ⇒ 与改前逐像素一致；紧凑图 grid 分支仍不写 `top`（其它组件按 60 画 45℃ 告警线的契约未动）。

### 硬断言（`ChartPlotAlignment.spec.ts`，19 条）
| 用例 | legendRows | gridTop |
| --- | ---: | ---: |
| 6 条 / 5 单位 @844（逆变器「输出」组） | 2 | 76 |
| 2 条单行 @844 | 1 | 56（=改前） |
| 同 6 条 @400 | 3 | 96 |
| 未挂载（canvasWidth=0） | 1 | 56 |
| height=150（紧凑） | — | 60（仅报告，不写入 option） |
| height 220 / 221 边界 | — | 220 紧凑 / 221 常规 |

## 8. 已知遗留（本轮未做，记录口径）

1. 「输出」组 `视在功率 (VA)` 与 `有功功率 (W)` 量级相同（都到 1500）但单位不同 ⇒ 各自一根右轴，看起来像两列重复刻度。合并会让单位与数值语义含糊，本轮未动；如需要可改为「同量级且功率类单位共用一根轴 + 图例标注单位」。
2. 窄屏紧凑图轴数上限 2（`MAX_Y_AXIS_COMPACT`）⇒ 「输出」组 5 种单位在 393 下合并到 2 根轴，`输出电压 250V` 在 1500 量程轴上偏低。这是既有取舍（保证绘图区宽度），本轮未改。
3. `pv2_temp` / `dc_rectifier_temp` 仍不在温度图与温度卡中（该机型实测只有 30/50/100 三档跳变，疑非温度，见上一轮分析文档）。
4. `RealtimeDataList` 组件仍保留并由通用设备页（`GenericDeviceDetail.vue`）使用 —— 用户本轮只要求 BMS 与逆变器两页不显示。
