## 二、协议层 — 详细分析

### 2.1 二进制帧协议

#### Go 实现 (`backend/pkg/frame/frame.go`)

| 需求 | 实现状态 | 代码验证 |
|------|----------|----------|
| 1字节 type 分派 | ✅ | `MsgHello=0x01` ~ `MsgScanReq=0x0D` |

| varint 编码整数 | ✅ | `appendVarint()` / `readVarint()` |
| length-delimited bytes/string | ✅ | `EncodeBytes()` / `EncodeString()` |
| 可选字段零开销 | ✅ | 不编码默认值即为零开销 |

**测试覆盖:**
- `frame_test.go`: Hello/DataReport 编解码、varint 边界值、跨语言兼容性
- `frame_codec_test.go`: 额外测试场景

#### ESP32 C 实现 (`esp32-collector/components/frame/frame_codec.c/h`)

| 需求 | 实现状态 | 代码验证 |
|------|----------|----------|
| 零分配栈式编码 | ✅ | `frame_encoder_t` 使用外部缓冲区 |
| 零分配栈式解码 | ✅ | `frame_decoder_t` 直接引用原始缓冲区 |
| 错误码定义 | ✅ | `FRAME_OK` / `FRAME_ERR_OVERFLOW` / `FRAME_ERR_UNDERFLOW` / `FRAME_ERR_INVALID_TAG` / `FRAME_ERR_INCOMPLETE` |

**关键差异:**
- C 实现使用外部缓冲区（零拷贝设计）
- Go 实现使用内部 `[]byte`（方便性优先）
- 两者 wire 格式完全兼容 ✓

## 九、主要问题汇总

### 9.1 严重问题

1. **ConfigManifest 编码不完整**: 缺少 templates 和完整的 channel 配置
2. **WriteResponse 未路由**: `handleWriteResponse()` 未调用 `PendingWriteManager.HandleResponse()`

4. **WiFi 配网未实现**: BLE/SoftAP/Serial 配网均未实现

### 9.2 中等问题

1. **三层离线检测不完整**: L1/L2 未实现，仅 L3 DB fallback 可用
2. **config_hash 未使用**: ConfigHashManager 存在但未集成
3. **worker pool 未使用**: 当前同步处理，未使用异步 worker pool
4. **LED 硬件驱动未实现**: 仅日志输出，无实际 GPIO 控制

### 9.3 轻微问题

1. **部分模型未使用**: users/vendors/operation_logs 等定义存在但无业务逻辑
2. **前端部分页面缺失**: 驱动管理/厂商管理/数据源管理等页面未找到
3. **Python 参考实现缺失**: 需求中提到但未在代码中找到
