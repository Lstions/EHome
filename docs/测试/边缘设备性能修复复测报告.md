## G2 方案文档修订点

方案 C3 用例将 `EHOME_PARSER_SHARDS=999`（env）与 `parser_shards: 100000`（yaml）并列描述为
"生效值被夹到 64"——实测两者语义不同：
- env 路径（config.go:212-216）：Atoi 后要求 0≤n≤64，999 不满足 → **忽略回落默认 8**
- yaml 路径（config.go:258-266）：ParserShards() 夹取到 [1,64]，100000 → **64**
两路径都是 fail-closed 安全行为，但文档需区分表述（env 是"越界忽略"而非"夹取"）。

## 发现项

1. **P1 Terminal WS 死代码 WARN 刷屏 — 已修复（见下）**
2. **P2 prepare_bench_data.sh 的 device-base 易漂移**：DELETE 不重置 id 序列，每次重跑 prepare 后

## P1 修复记录（2026-08-15 复测后）

- **根因**：`terminal.Manager.record()` 的 `wsCh`（chan TerminalEvent, 缓冲 256）**无生产消费者**
  ——`Events()` 仅 terminal_test.go 使用；真实终端事件走 websocket hub 的 channel_data 广播
  （ws_handler.go:90 Subscribe→dispatchEvent）。通道填满后每事件触发 default 分支打 1 条 WARN
- **修复**：删除 `wsCh`/`TerminalEvent`/`Events()`/record() 中 WS 广播段（terminal.go），
  删除测试 TestManagerEvents（terminal_test.go）。ring buffer 历史记录（RecordTX/RecordRX/GetHistory）
  与 ws_handler（hub 订阅）完全不受影响
- **验证**：go build/vet 通过；terminal+databus 包 -race 全 PASS；全量 test-backend 29 包 ok
  覆盖率 62.7%（terminal 77.8%）
- **S1 档复测**：WARN 计数 0；整档日志 1,119 行/106KB（修复前同档 5,133 行 WARN 刷屏），
  丢弃率仍 0%（23,958 发送 → 47,916 入库）
