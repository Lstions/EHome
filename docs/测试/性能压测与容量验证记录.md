## 1. 压测方法与对账

- 模拟器架构：MQTT 级（非串口级），模拟器直发 DataReport 帧。
- 负载模型：S1 单设备高频 / S2 多设备 / S3 混合 / S4 峰值。
- 度量与对账：入库 SQL 计数 vs 发送计数（丢率）、CPU（/proc/<pid>/stat 差分 100Hz）、RSS、日志。

## 2. 修复前基线（2026-08-15 压测）

| 指标 | 结果 | 判定 |
|------|------|------|
| S1 高频单设备丢率 | 84% | CRITICAL |
| sensor_parser 单消费者串行吞吐 | ≈64 evt/s | 系统容量天花板 |
| db_persist 独立饱和 | ≈188 evt/s | 次瓶颈 |
| databus fanout 静默丢弃 | 无日志 | 可观测性缺口 |
| 日志 | 每消息 ≥2 行 Info，S4 峰值 28k 行/s | 日志爆炸 |

## 3. 修复动作摘要（2026-08-15）

修复链路（多轮审查闭环后的实施）：

1. DataEventBus 分片化（数据通道），解析/persist 消费者均可纵向扩展。
2. 消费者独立邮箱 + 背压（丢弃/重试策略显式化）。
3. 死代码日志源清理（GORM record not found 打印、wsCh 无消费者 WARN 刷屏）。
4. 高频路径降噪。

## 4. G5 复测结果（2026-08-15 复测）

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| S1 丢率 | 84% | **0%** |
| 处理量 | 基线 | **5.2–6.8×** |
| PG 写入 | 基线 | **8.3×** |
| RSS | — | 52MB（稳定） |
| 30min soak | — | 零丢失 |

## 5. 容量天花板与提容方向

- 修复后单机有效容量已覆盖"家庭规模 + 高频 BMS/雨量"需求。
- 会有新的天花板来源：parser 深度、单消费者热点、PG 写入放大（长期 → v3.4 数据层时序化：月分区 + rollup）。
- 故障定位经验：压测对账先看 device-base 是否匹配实际 id 区间；"全丢"先查数据路由，不先怀疑代码回归。
