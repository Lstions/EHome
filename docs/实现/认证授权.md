# 认证授权

当前系统采用唯一管理员主体认证，不再提供多用户 CRUD 或角色权限矩阵。

## 身份模型

- 唯一活动主体：`subject_key=system_admin`。
- `AuthState` 是系统认证状态权威：`uninitialized / initialized / migration_required / disabled`。
- `User.Enabled` 只在 AuthState initialized 时决定该主体能否登录。
- retired 历史账户保留审计关联，但不能登录。

## JWT

Token 固定使用 HS256，包含 `sub/iat/exp/jti/sv/iss/aud`。REST 和 WebSocket 均检查数据库中的 AuthState、唯一主体、Enabled 和 session_version。旧格式 Token 统一失效。

密码修改、logout 和 logout-all 原子增加 session_version，因此全部旧 Token 立即失效。

## API

公开端点仅包括健康检查和登录/受控初始化。其余 `/api/v1` 路由使用权威数据库认证中间件。

账户接口：

- `GET/PATCH /api/v1/account`
- `POST /api/v1/account/password`
- `POST /api/v1/account/logout-all`

旧 `/users` 接口兼容期在认证后返回 410。

## WebSocket

通用和终端 WebSocket 使用同一唯一主体会话语义，不再读取 role。连接记录 subject ID、session version、Token expiry 和 JTI；发送敏感命令前复核会话，撤销后按主体断开。

## 初始化

系统仅支持全新数据库，不提供旧数据库升级兼容。生产环境不 seed 默认账户；全新数据库由 `ehomectl auth bootstrap-database` 创建认证状态，再通过一次性初始化凭据完成管理员设置。完整步骤见 `单用户认证迁移与运维指南.md`。
