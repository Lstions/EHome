## 1. 目录结构（唯一定义）

```
docs/
├── README.md                    # 文档中心索引（★ 唯一导航入口，任何增删必须同步）
├── 规范/                        # 文档治理规范 + 前端开发规范（★ 强制）
├── 设计/                        # ★ 权威设计（当前架构，每主题一份）
├── 协议/                        # ★ 通信协议规范（权威，只读约束）
├── 实现/                        # 跨模块实现记录（模块实现已并入设计，仅存索引）
├── 操作/                        # 运维操作指南
├── 测试/                        # 性能测试方案与复测报告
├── 验证/                        # 实机验证与功能验收留档
├── 评审/                        # 评审报告（设计/架构/UI 审计）
├── 发布/                        # 版本发布报告
├── 分析/                        # 探索性分析、功能基线与技术债台账
└── archive/                     # ★ 历史归档（按主题/版本分目录，只进不出）
```

### 1.1 目录职责边界

| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| 规范/ | 文档治理规范、前端开发规范 | 业务设计 |
| 设计/ | 每主题一份权威文档（模块文档 = 详细设计 + 验收 + 实现记录三合一；跨模块方案） | 历史方案、过程性计划、报告 |
| 协议/ | 帧协议、厂商协议与门禁 | 协议分析过程 |
| 操作/ | 面向人的操作步骤 | 设计原理 |
| 测试/ | 性能测试方案 + 复测报告（成对出现） | 功能验收（去 验证/） |
| 验证/ | 实机验证、功能验收留档 | 设计稿 |
| 评审/ | 评审报告 | 设计正文 |
| 发布/ | 版本发布报告 | — |
| 分析/ | 未定稿分析、功能基线、技术债台账 | 定稿设计 |
| archive/ | 已归档历史（标记归档，不再更新） | 当前有效文档 |

## 2. 命名规范

### 2.1 文件名

1. **统一中文**：文件名只用中文，禁止英文词、下划线、空格、括号。
   - ✅ `边缘设备数据生命周期.md` ❌ `edge-control分析报告.md`
2. **技术缩写例外**：ESP32、GPIO、PWM、DMA、UART、SPI、I2C、OTA、BMS、SN3001 等 + README.md。
3. **连接符**：中文名之间需要分隔用 `-`；缩写与中文之间不加分隔。版本后缀 `-v<版本>`。
4. **排序前缀**：需要固定排序的概念类文档用 `NN-` 前缀（仅 README 索引和同级类目下可用）。
5. **同主题唯一**：一个主题只允许一份文档；发现重复立即合并，旧版归档。

### 2.2 目录名

统一中文，禁止英文目录名（archive/ 是唯一例外）。模块子目录中文名与模块名一致。

### 2.3 文档内部标题

1. 一级标题与文件名一致。
2. 二级标题 `## 1.`、`## 2.` 数字编号；三级 `### 1.1`。
3. 所有锚点/相对链接必须相对路径，禁止绝对路径（`/home/...`）。

## 3. 文档元信息与模板

### 3.1 头部元信息（所有文档强制）

```markdown
> **状态**: 提案 | 评审中 | 已实现 | 已归档 | 生效中
> **版本**: vX.Y（发布/规范/方案类必填；报告类可省略）
> **日期**: YYYY-MM-DD（最后实质更新日）
> **关联**: [<文档名>](<相对路径>) | ...
```

状态语义：
- `提案`：未评审未实施（分析/评估类可用）
- `评审中`：已提交评审等待结果
- `已实现`：功能已合入 main，文档作为现状权威
- `已归档`：仅出现在 archive/ 内
- `生效中`：规范类文档

### 3.2 模块文档结构（设计/ 下每个模块）

```markdown
# <模块名>

## 1. 功能概述与端点        # 职责、API 端点表、权限
## 2. 数据模型              # 当前表结构/字段（与代码一致）
## 3. 状态机                # 状态 + 转移表（如适用）
## 4. 关键流程              # 流程图 + 步骤说明
## 5. 协议与外部契约        # WS 事件、MQTT topic、帧字段（如适用）
## 6. 实现记录              # 三端代码位置 + 已实现清单
## 7. 验收标准              # 前端/后端/节点/集成 四段 checklist
## 8. 已知限制与债务        # 当前未实现/已知问题
```

### 3.3 跨模块方案结构

```markdown
# <主题>方案

## 1. 背景与需求
## 2. 目标与非目标
## 3. 架构/方案设计
## 4. 协议/接口契约
## 5. 数据模型
## 6. 状态机（如适用）
## 7. 验收标准
## 8. 实施记录与评审闭环（如已实施）
```

### 3.4 报告类（测试/验证/评审）

- 测试方案：目的、范围、步骤、通过标准；复测报告必须成对引用方案。
- 验证报告：对象、环境、结果记录、缺陷与修复。
- 评审报告：评审对象（版本+链接）、评审维度、发现清单（严重度）、结论。

## 4. 文档生命周期

```
分析/（未定稿）
   ↓ 结论收敛
设计/（状态=提案）
   ↓ 评审通过
设计/（状态=评审中 → 已实现）
   ↓ 验证完成
测试/验证/（报告留档）
   ↓ 发布
发布/（发布报告）
   ↓ 被取代或过时
archive/（标记已归档，不再更新）
```

规则：
1. **设计先行**：实现代码前先有 设计/ 文档。
2. **状态同步**：功能合入 main 后，设计文档状态必须改为 `已实现`。
3. **模块三合一**：设计/ 的模块文档同时承载实现记录与验收标准（§3.2 结构），不再三处分开放。
4. **报告成对**：测试方案与复测报告成对出现。
5. **归档**：文档被取代后移入 archive/，并在 docs/README.md 变更清单登记。

## 5. 维护规则

1. **索引强制**：新增/移动/删除任何文档，必须同步 `docs/README.md`（目录树 + 变更清单）。
2. **链接检查**：每次移动/改名后运行链接检查脚本（`scripts/check_doc_links.py docs`），非 archive 文档 0 断裂。
3. **版本基线**：docs/README.md 顶部版本号 = 当前代码版本；版本变更时登记变更清单。
4. **禁止重复**：同主题只保留一份；发现重复立即合并并归档旧版。
5. **术语一致**：遵循 设计/术语表.md 权威术语；禁止旧名（采集器、设备模板等）。
6. **临时文件**：AI prompt、草稿、未整理笔记禁止提交到 docs/。

- [ ] 文件在正确目录（§1.1 职责边界）
- [ ] 头部元信息完整（状态/版本/日期/关联）
- [ ] 无重复主题文档
