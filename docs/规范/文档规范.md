## 2. 命名规范

### 2.1 文件名

1. **统一中文**：文件名使用中文，禁止英文词、下划线、空格、括号。
   - ✅ `边缘设备数据生命周期管理方案.md`
   - ❌ `edge-control-13commit分析报告.md`、`MemOS知识库_EHomeSystem.md`
2. **允许保留的例外**：技术缩写（ESP32、GPIO、PWM、DMA、UART、SPI、I2C、OTA、BMS、SN3001、BMP280 等）与 README.md。
3. **连接符**：中文名之间如需分隔使用 `-`；缩写与中文之间不加分隔。版本后缀用 `-v<版本>`（如 `-v1`、`-v2`）。
4. **排序前缀**：目录内需要固定顺序的概念类文档使用 `NN-` 前缀（如 `00-术语表.md`）；模块设计不强制前缀。
5. **同主题多版本**：保留最新定稿版，旧版合并或归档，禁止 `xxx-v1.md`、`xxx-v2.md` 并存于同一目录。

### 2.2 目录名

1. 统一中文单层命名（见 §1 目录结构），禁止英文目录名。
2. 模块子目录 = 模块中文名（如 `docs/设计/边缘设备/`、`docs/设计/固件OTA/`）。

### 2.3 文档内部标题

1. 一级标题与文件名一致（`# 边缘设备数据生命周期管理方案`）。
2. 二级标题用 `## 1.`、`## 2.` 编号（章节编号），三级 `### 1.1`。
3. 所有锚点链接使用相对路径，禁止绝对路径（`/home/...`）。

## 3. 文档类型与模板

### 3.1 头部元信息（所有文档必须）

```markdown
> **状态**: 提案 | 评审中 | 已实现 | 已归档
> **版本**: vX.Y
> **日期**: YYYY-MM-DD
> **关联**: [00-术语表.md](../设计/00-术语表.md) | [<相关文档>](<相对路径>)
```

状态语义：
- `提案`：设计未评审、未实施
- `评审中`：已提交评审，等待/正在评审
- `已实现`：功能已落地（代码合入 main），文档保留作为权威设计
- `已归档`：文档描述的历史方案/报告，不再作为开发依据（移入 archive/ 或原地标记）

### 3.2 设计文档结构

```markdown
# <主题>设计
> 元信息（§3.1）

## 1. 背景与需求
## 2. 目标与非目标
## 3. 架构/方案设计
## 4. 协议/接口契约
## 5. 数据模型
## 6. 状态机（如适用）
## 7. 验收标准
```

### 3.3 实现文档结构

```markdown
# <模块>实现记录
> 元信息（§3.1）

## 1. 模块职责
## 2. 代码位置（后端/前端/固件）
## 3. 关键流程
## 4. 测试覆盖
## 5. 已知限制
```

### 3.4 验证/评审/发布文档

- 验证方案：目的、范围、步骤、通过标准、结果记录
- 评审报告：评审对象（版本+链接）、评审人、发现清单（严重度）、结论
- 发布报告：`v<版本>-发布报告.md`，变更清单、迁移步骤、回滚方案

## 4. 文档生命周期

```
分析/（未定稿）
   ↓ 结论收敛
设计/（状态=提案）
   ↓ 评审通过
设计/（状态=评审中 → 已实现）
   ↓ 功能落地
实现/（实现记录，与设计文档互链）
   ↓ 验证完成
验证/（验证报告）
   ↓ 发布
发布/（发布报告）
   ↓ 过时
archive/（标记已归档）
```

规则：
1. **设计先行**：实现代码前先有 设计/ 文档（即使为简化描述）。
2. **状态同步**：功能合入 main 后，设计文档头部状态必须改为 `已实现`，并在 docs/README.md 变更清单登记。
3. **实现记录**：每个模块在 实现/ 有对应记录，与 设计/<模块>/详细设计.md 互链。
4. **验证闭环**：验证方案与验证报告成对出现，报告引用方案。
5. **归档**：仅当文档描述的内容已被取代或确认不再需要时移入 archive/；归档前在 docs/README.md 登记。

## 5. 维护规则

1. **索引强制**：新增/移动/删除任何文档，必须同步更新 `docs/README.md`（目录结构表 + 变更清单）。
2. **链接检查**：文档间链接必须相对路径且指向存在的文件；移动文件后检查引用。
3. **版本基线**：docs/README.md 顶部版本号 = 当前代码版本（以 git tag / 最近发布报告为准），版本变更时登记 `## 变更清单`。
4. **禁止重复**：同主题文档只保留一份（设计/ 权威 + 实现/ 记录 + 验证/ 报告），发现重复立即合并。
5. **术语一致**：使用 设计/00-术语表.md 的权威术语，禁止旧名（采集器、设备模板等）。
6. **临时文件**：AI prompt、临时笔记、未整理草稿禁止提交到 docs/，应放仓库外或删除。

## 6. 执行检查（文档提交前）

- [ ] 文件名符合 §2 命名规范（中文、无下划线/空格）
- [ ] 文件位于正确的目录（§1 职责边界）
- [ ] 头部元信息完整（状态/版本/日期/关联）
- [ ] 无重复主题文档（同主题唯一）
- [ ] docs/README.md 索引与变更清单已更新
- [ ] 所有相对链接有效
- [ ] 状态与代码实现一致（已实现 → 状态=已实现）
