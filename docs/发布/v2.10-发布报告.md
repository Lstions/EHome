## 2. 破坏性变更（必须知道）

1. **旧的 `BIN`+`META` 上传被拒**：服务端返回 400 `FW_PKG_REQUIRED`，文案含打包器用法。存量固件必须重新打包：
   ```bash
   ./esp32-collector/tools/pack_firmware.py --bin ehome_collector.bin \
     --sdkconfig build/c6-n8/sdkconfig --profile c6-n8 --version 2.9.0 --out x.ehfw
   ```
2. **缓存了旧页面的浏览器**仍显示「两个文件框」；服务端 message 已带「请刷新页面」提示。
3. **数据库自动迁移**：新增 2 列、`identity_state` 默认 `legacy→verified`。空库无感；从备份导入的旧行需显式带 `legacy` 才会被 `BackfillFirmwareIdentity` 接管。

## 4. 已知问题（不阻塞本次发布）

| # | 问题 | 说明 |
|---|---|---|
| 1 | **节点「型号」显示 `esp32c6`** | 该值来自 Hello 的 `CONFIG_IDF_TARGET`，语义是**芯片族名**而非产品型号；建议先改文案（「芯片」），另立产品型号字段。详见 [分析/节点型号语义-待评估](../分析/节点型号语义-待评估-2026-11-19.md) |
| 2 | **OTA 需先有节点硬件档案** | 新装设备只上报 `model/platform`，缺 `hw_flash_mb`/`hw_psram`，OTA 下拉会置灰。部署后按需执行 `ehomectl node hw set -id <node> -flash-mb N -psram yes\|no` |
| 3 | `EHOME_ADMIN_USERNAME/PASSWORD` 是死配置 | 真实建号路径为启动日志的一次性 initialization credential + `POST /api/v1/auth/initialize` |
| 4 | `.dockerignore` 未排除大目录 | 构建 context 可达 5.7 GB，低带宽环境会像卡死 |
