## 1. 部署形态（一次性沙箱）

| 项 | 值 |
|---|---|
| 镜像 | `ehome-verify:fw` = `sha256:78fd58b3…6c84`（153 MB，源 = 当前工作树 `bd0ac37` + 48 个未提交文件） |
| 栈 | `docker compose -p fwverify`：`postgres:18-alpine` + `ehome`（后端 + 前端静态，三阶段构建） |
| 端口 | `18080→8080`（UI/API）、`18443→8443`（设备 TCP+TLS mTLS） |
| 隔离 | 独立容器名 `ehome-fwverify*`、匿名卷、独立网络；既有 `nginx`/`ddns-go`/`ehome-postgres` 全程未动 |
| 外部地址 | `EHOME_EXTERNAL_HOST=192.168.20.3:18080`（设备下载固件用） |

**设备链路是 mTLS**，三条代码事实来自本次部署：
1. `EHOME_DEVICE_ADDR` 单独给**不启动监听**——由「证书三件套齐全」推导；
2. 设备身份取自**客户端证书 CN**（`transport/server.go: nodeIDFromCert`），不是协议里的 `node_id`；
3. 仓库 `.secrets/pki/` 是现成 PKI（CA `EHome-Prod-CA`、各设备证书、以及预生成的 `nvs-*.bin`）。

原 `server.crt` 的 SAN 只有 `192.168.20.6`，与宿主 `192.168.20.3` 不符 ⇒ 用**同一 CA** 重签 `server-203.crt`（SAN: `.3/.6/127.0.0.1/localhost`）。`.secrets/pki` 只读挂进容器，未进镜像。

## 2. 真机

| 项 | 值 |
|---|---|
| 板子 | `/dev/ttyACM0` = **ESP32-C6**，MAC `f0:f5:bd:02:f3:5c`，`flash_id` = **8MB** ⇒ `c6-n8` |
| 旁证 | `/dev/ttyUSB0` = ESP32-S3 16MB（`30:ed:a0:a9:a8:08` ⇒ `s3p-n16`），本次未用 |
| 烧录 | 2.8.0 基线 `bootloader@0x0 / partition-table@0x8000 / ota_data_initial@0xd000 / app@0x10000`，写入后 Hash verified |
| 证书 | `.secrets/pki/nvs-F0F5BD02F35C.bin` → `0x9000`（nvs 分区 16KB），Hash verified |
| 联网 | 固化 SSID/PSK 生效，ARP `192.168.20.56 → f0:f5:bd:02:f3:5c REACHABLE` |

> 关键：当前仓库构建出的镜像 `EHOME_DEVICE_LINK_HOST` 默认是 `192.0.2.1`（TEST-NET 占位），**真机永远连不上**。本次用 `EXTRA_SDKCONFIG_DEFAULTS` 覆盖为 `192.168.20.3:18443` 重新构建（产物落 `dist-dev/`，不动已验证的 `dist/`）。

## 5. 本次发现的问题（真实、可修）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | **OTA 被硬件档案拦住**：节点由 Hello 注册，`platform/model` 有、`hw_flash_mb`/`hw_psram` 为空 → 下拉里固件置灰「节点硬件档案不完整」 | 新装设备无法直接 OTA，必须先 `ehomectl node hw set` | 部署文档补一步；或让 Hello 带容量/PSRAM（设备本来就知道 `spi_flash_get_chip_size()` 与 `esp_psram_is_initialized()`） |
| 2 | `EHOME_ADMIN_USERNAME/PASSWORD` **是死配置**（config 接收、全仓无消费者） | 按 `.env.example` 配管理员会以为生效，实际没有账号 | 要么接上、要么从 `.env.example` 删掉，实测路径是 initialization credential |
| 3 | `.dockerignore` 未排除 `.worktrees/.logs/.gocache/.pnpm-store/.fwbuild*` | legacy builder 要发 **5.7 GB** context（3 分钟没发完） | 补 `.dockerignore`；否则任何离线/低带宽环境构建都像卡死 |
| 4 | `.secrets/pki/server.crt` 的 SAN 只有 `192.168.20.6` | 换机器部署即 TLS 校验失败，且报错在设备侧很难看 | 生成脚本把「当前部署 IP」作为参数；或文档写明必须重签 |

**非问题但值得记**：OTA 同版本会被闸门拦住（`to_version <= current`），本次 2.8.0→2.9.0 天然满足；若做回滚演练需 `force_reason`。

## 7. 复跑

```bash
# 1) 构建镜像（HOME 只读 + .dockerignore 漏斗的规避法）
export DOCKER_CONFIG=$PWD/.dsbx-evidence/fwverify/docker-config
DOCKER_BUILDKIT=0 docker build --network=host \
  --build-arg http_proxy=http://192.168.20.6:10808 \
  --build-arg https_proxy=http://192.168.20.6:10808 -t ehome-verify:fw .

# 2) 起栈
docker compose -p fwverify -f .dsbx-evidence/fwverify/docker-compose.fwverify.yml up -d
sh .dsbx-evidence/fwverify/bootstrap-admin.sh      # 建管理员（fwadmin）

# 3) 烧设备（C6）
BUILD_ROOT=$PWD/esp32-collector/build-dev \
EXTRA_SDKCONFIG_DEFAULTS=$PWD/.dsbx-evidence/fw-device/device-link.defaults \
DIST_ROOT=$PWD/esp32-collector/dist-dev FW_VERSION=2.8.0 make fw-package PROFILE=c6-n8
docker run --rm --device /dev/ttyACM0 -v $PWD/esp32-collector/dist-dev/2.8.0/c6-n8:/fw \
  -v $PWD/.secrets/pki:/pki:ro ehome-esptool:fw esptool --port /dev/ttyACM0 --chip esp32c6 \
  write_flash 0x0 /fw/bootloader.bin 0x8000 /fw/partition-table.bin 0x9000 /pki/nvs-F0F5BD02F35C.bin 0x10000 /fw/ehome_collector.bin

# 4) 视觉流程
PLAYWRIGHT_BROWSERS_PATH=... node .dsbx-evidence/visual/visual-flow.mjs
```
