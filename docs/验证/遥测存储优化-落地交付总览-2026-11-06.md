## 2. 已落地代码（53 文件，+12,438 / −20）

### 阶段 0（无损项，风险最低）
- `partition_mgr.go`：删除 4 条死索引模板
- `retireDeadTimeseriesIndexes`：生产存量库按 `pg_get_indexdef` **列清单完全相等**判据 DROP（唯一索引/主键排除，失败只 Warn）
  —— 方案原文只写"删模板"，但 `ensurePartitionParentIndexes` **只补不删**，删模板拿不到 1.35 GiB 空间
- `finalizePartitionParentIndexes`：先补建后删，避免"该建的没建、旧的已删"空窗
- ⚠ **保留** `device_sensor_ts_idx` / `device_ts_idx`：方案 §1.3「5 条索引」摘要滞后于 2026-10-24/25 的 F-10 修复，删了等于回滚 P1 性能修复

### L1 写入收窄（`databus/`）
- 逐字段「值不变且未到心跳 ⇒ 跳过入库」，**状态表仅写库成功才推进**
- `latestSink` 提到 INSERT **之前**且不受写库结果门控（否则跳过会冻结缓存）
- 默认 **影子模式**：只统计"本可跳过多少行"并打 metrics，不真跳

### L2 帧级增量编码（新增包 `internal/telemetry`，20 文件 / 4,506 行 / 38 测试）
- `spec.go` 量化规格 · `codec.go` 1B flags + mask + LSB 位打包 · `slot.go` 签名字典（7 种帧类型）
- `encoder.go` 增量状态机 · `decode.go` 累积/断链恢复 · `store.go` DecodeRange/LatestSnapshot
- `telemetry_frame` 表：月分区 PK(device_id,ts,seq)，2 条索引

### L3 分钟级 rollup（`datalifecycle/telemetry_rollup.go` + `api/rollup_read.go`）
- `telemetry_rollup_1m` 宽行表 + `RollupCollector` 旁路聚合 + 读路径分派（fail-open）
- **重建**了被 `bb19ee30` 整文件删除（490 行 → 0）的 rollup 退役门禁，新增 3 条断言

### 接线（三层 sink 均接在**解析成功路径**，默认全关）
`consumers_heavy.go` → `nodemgr/manager.go` → `cmd/server/main.go`（独立 60s flush ticker）
