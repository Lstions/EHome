## 3. GPIO（PASS）

步骤：

1. 创建输出配置：POST /nodes/F0F5BD02F35C/gpio {pin:0,direction:1,initial_level:0,enabled:true}
   → 201；设备 PeriphRsp action=3 success=true；ConfigResult success=true。
2. 写高/低：POST /nodes/F0F5BD02F35C/gpio/0/set level=1 / 0
   → {code:200,data:{action:1,request_id:...}}；PeriphRsp success=true value=1/0。
3. 创建输入上拉：pin:7,direction:2 → 201；POST /gpio/7/read → PeriphRsp success=true value=1。
4. 负例：
   - level=2 → 400 "level must be 0 or 1"
   - 未配置 GPIO3 set → 404 "GPIO config not found"
5. UI：GPIO0 开关切到 HIGH，行文本由「未知」变「HIGH」，无「正在写入」；GPIO7 「读取」后显示 HIGH。

证据：

    SendPeriphCmd: type=1 resource_id=0 action=1 ... reqID=1051666790
    PeriphRsp: request_id=1051666790 success=true value=1
    SendPeriphCmd: type=1 resource_id=7 action=2 ... reqID=1051666791
    PeriphRsp: request_id=1051666791 success=true value=1

## 4. PWM（控制 PASS，状态读取受限）

步骤：

1. 创建 PWM0：pin4、1000Hz、duty=5000、resolution=10 → 201；ConfigResult success=true。
2. POST /pwm/PWM0/start → PeriphRsp action=2 success=true。
3. POST /pwm/PWM0/duty {duty:7500} → PeriphRsp action=0 success=true value=7500。
4. POST /pwm/PWM0/stop → PeriphRsp action=3 success=true。
5. UI：PWM0 行显示 1000Hz/10bit/75%；点「启动」→「运行中/停止」；点「停止」→「已停止」。

发现：

GET /pwm/PWM0/state 返回 200（数据库快照），但设备 PeriphRsp action=4 success=false error_code=5。
即固件不支持 PWM READ；修复前 UI 因此永久停在「等待状态」且没有启动按钮。已改为「状态未知」时仍允许启动（启动后由 ACK 回填 running）。

## 5. ADC（FAIL：固件没有 ADC 总线执行路径）

步骤：

1. POST /channels：
   {hardware_type:"ADC",bus_type:"ADC",hardware_id:"ADC1_CH1",config:"{\"attenuation\":3,\"bit_width\":12}"}
   → 201，数据库有通道。
2. 设备收 manifest：ConfigManifest ... 1 channels
3. 设备回执：ConfigResult success=false，StatusReport 始终 ch=0；前端通道状态仍显示「正常」（仅按 enabled 判断）。
4. 删除该通道后 ConfigResult success=true，设备恢复 ch=0。

根因证据：

固件 config_mgr 能解析 bus_type=5（ADC），但 bus_dma/bus_manager 只实现 UART/I2C/SPI/USB，没有 ADC 总线初始化/采样；仓库内也没有 esp_adc/adc_oneshot 驱动调用。
→ ADC 作为通道当前不可用；应在固件实现前禁用 ADC 通道创建，或明确标注「实验/不支持」。

## 6. UART（配置/发送 PASS，回环未验证）

步骤：

1. 创建 UART0 通道：bus_config 10110000258000（TX16/RX17/9600/DMA0）→ 201；ConfigResult success=true。
2. 终端写：POST /channels/8/terminal/write {device_id:"F0F5BD02F35C",data_hex:"A55A"}
   → 200；后端 SendWriteCommand ... tx_bytes=2；设备 WriteResponse success=true。
3. UI 终端选中 UART0，输入 55AA 发送；TX 面板出现 55 AA，无错误。

限制：

没有把 TX/RX 物理短接，也没有外接从机；只验证了发送链路与设备 ACK，未验证接收数据面。
后端 terminal/write 返回裸 JSON（非统一 envelope），当前 UI 走 WS 发送路径所以未暴露；离线/无 WS 时可能拿到 undefined，属于待统一项。

## 7. I2C（通道 PASS，扫描 FAIL/桩）

步骤：

1. 创建 I2C0 通道：SDA21/SCL22/0x50/400kHz，bus_config 15165000061A80 → 201；ConfigResult success=true。
2. 点击「地址扫描」/ POST /nodes/.../bus/i2c/scan {hardware_id:"I2C0"}
   → 200 {devices:[], request_id:"i2c-..."}；UI 显示「扫描完成：未发现设备」。

根因：

后端 scan handler 是桩：只返回空数组和合成 request_id，注释明确写「requires MQTT broadcast I2C_SCAN」，没有向设备发送 ScanReq；而设备端已有 ScanReq/ScanReport 处理。
→ 无论总线上有没有从机，UI 都只会显示「未发现设备」。I2C 通道配置本身可用，但真实设备发现未实现。

## 8. SPI（FAIL：设备拒绝配置）

步骤：

1. 创建 SPI2 通道，默认引脚：bus_config 0500000F4240171312（CS5/mode0/1MHz/MOSI23/MISO19/SCLK18）→ 201。
2. 设备 ConfigManifest ... 1 channels → ConfigResult success=false；StatusReport ch=0。
3. 变体复测，均失败：
   - 自定义引脚（CS7/MOSI22/MISO21/SCLK20）→ success=false
   - dma_enabled=true 重建 → success=false
   - 单独 SPI（删除 UART/I2C）→ success=false
4. 删除后 ConfigResult success=true。

结论：

不是引脚冲突、不是通道数量、也不是前端请求失败；设备在应用 SPI manifest 时拒绝。
由于主机没有 /dev/ttyACM*（USB 设备存在但未生成节点，无 sudo/mknod 权限），未能抓到设备串口的具体 spi_bus_initialize 错误；需固件侧用串口日志继续定位。
在修复前，SPI/ADC 的「新建通道」应至少给出明确的不支持提示，而不是后端 201 + 前端「正常」。

---

## 9. DMA（控制面 PASS，数据面未验证）

步骤：

1. PUT /nodes/F0F5BD02F35C/dma-config：
   [{"dma_id":1,"enabled":true,"bind_to":"uart/UART0"}] → 200；ConfigResult success=true；节点 config.dma_configs 落库。
2. 修复前 GET 仍返回 state=0/bound_to=""（只合并了 disabled 分支）；修复后 GET 返回：
   {"dma_id":1,"state":1,"bound_to":"uart/UART0"}。
3. UI：DMA 页 GDMA_CH1 显示「已分配 / UART0（UART）」；「解绑」弹确认，确认后变「已禁用 / 未绑定」；GET 变为 state=2。
4. 设备 ResourceReport 仍上报 state=0/bound_to=""（不回声 bound_to）；因此 UI 以配置意图为准，设备实际 DMA 数据面未通过采集数据验证。

建议：

- 固件 ResourceReport 应回显 DMA bound_to，否则 UI 与设备真实状态可能再次分叉。
- 绑定 DMA 后还应验证通道 dma_enabled 是否真正启用；本次未构造高速数据流，故数据面标记「未验证」。

## 13. 待办/阻塞

1. ADC：固件实现 ADC 总线采样（或禁止创建 ADC 通道）。
2. SPI：根据设备串口日志定位 config transaction 中 SPI init 失败原因。
3. I2C 扫描：把 API 桩改为真实的 ScanReq/ScanReport 往返。
4. PWM READ：固件 action=4 返回 error_code=5；实现读取或 UI 明确标注不可读。
5. DMA ResourceReport：回显 bound_to，避免配置意图与设备状态分叉。
6. 通道状态真实性：设备 ConfigResult false 时，通道表仍显示「正常」（按 enabled），应显示同步失败。
