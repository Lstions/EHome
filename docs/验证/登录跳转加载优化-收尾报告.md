## 3. 各阶段要点

### P0-A（预取）
- `requestIdleCallback(nextIdle)` 空闲期预取 MainLayout / Dashboard 两个懒加载 chunk；登录成功瞬间 `router.push` 命中的就是已缓存 chunk。
- happy-dom 无 requestIdleCallback → 回退 `setTimeout(prefetch, 0)`，测试环境行为可覆盖。
- **导航失败分支修正**：原实现 catch 后 re-throw，外层 catch 会用 `error.message`（如 “Failed to fetch dynamically imported module”）覆盖「页面加载失败，请刷新重试」提示；现改为直接 `return` + 固定提示，收起过渡层避免白屏卡死。
- **测试 mock 清理**：原 spec 对同一模块（MainLayout/Dashboard）多次 `vi.mock`，vitest 最后一次注册生效，把先注册工厂的副作用（importFnCalls.push）全部丢弃 → 预取断言空数组。统一为单次注册；用模块级计数器证明预取动态 import 真实执行（mock 工厂只在模块首次被 import() 解析时运行一次），计数器用例置于首条，避免注册表缓存干扰。后续 bc4f3d64 进一步抽为 `utils/prefetch.ts`，vi.mock 模块导出 vi.fn 逐次记录，用例互相独立、不依赖顺序。

### P2（element chunk 评估 + Cache-Control 核查）
- **element chunk 拆分评估结论：维持现状（不拆）**。
  - 现状 `manualChunks`：echarts / element / vue 三拆。
  - element chunk（737 KB / gzip 240 KB）由全站共享——登录页（仅用 el-alert + JS 的 ElMessage/ElMessageBox）与所有后台页面用同一份。element-plus 走 unplugin-vue-components 按需引入，但按需粒度是「按组件文件」而非「按路由」；任何路由页面都用 element，登录首屏也必然加载 element chunk，**拆小不减首屏总字节、只增请求数**，无收益。
  - 进一步拆小需引入额外 loader 层（如按路由剥离 element 样式/组件），复杂度高、收益为负，不做。
- **Cache-Control 核查 + 修复**（改动小，已动手）：
  - 原实现：`/assets`、`/favicon.svg`、NoRoute SPA 回退均无 Cache-Control 头（gin 默认不设置）。
  - 新策略（`backend/cmd/server/static.go`）：
    - `/assets/*` 与 `/favicon.svg` → `public, max-age=31536000, immutable`（Vite 产物带内容 hash，内容变文件名即变，可安全长期缓存）
    - 其余路径（history 路由回退 index.html）→ `no-cache`（每次回源校验，避免发版后命中陈旧入口 HTML）
  - 实现：`r.NoRoute` 处理器内直接设置 no-cache（gin 的 NoRoute 无法挂组中间件）；/assets 与 favicon 用 `r.Group("/", immutableStaticCache)` 挂 immutable 中间件。
  - `static_cache_test.go` 覆盖两类缓存头断言 + `EHOME_STATIC_DIR` 未设置时跳过不 panic。`go test ./cmd/server/...` 通过，gofmt/vet 干净。

#### 首屏关键路径细节
- 前：`index.html` preload 的 6 个 js 为 rolldown-runtime / element / vue / client / auth / preload-helper，但 `index-*.js` 内 **echarts 是静态依赖**，登录页首屏连 echarts（554 KB / gzip 186 KB）一起下载——登录页只显示一个表单，却背着整个图表库。
- 后：index.html preload 仍 6 个 js，index 的预取助手只把 echarts 挂在 **Dashboard/LineChart 动态导入图** 上；首屏不请求 echarts。**登录成功后由 P0-A 预取提前拉取 MainLayout/Dashboard（不拉 echarts），路由切换只等 LineChart 小 chunk，echarts 由浏览器在后台继续**。
- 首屏总字节持平的原因：element（737 KB）与 index 中的通用依赖仍是首屏必载；echarts 移出首屏的收益被 element 的体量压过（element 无法拆出首屏，见 P2 结论）。真正的体验收益在「登录成功 → 主界面首帧」路径上：不再等 186 KB gzip 的 echarts，而是等已预热的 MainLayout（P0-A）+ 4.7 KB 的 LineChart（P1），配合 P0-B 品牌过渡层掩盖剩余等待。

## 5. 遗留风险 / 注意事项

1. **LogicalDeviceList.spec.ts 失败**：main 分支已修复，本分支未合并该修复；后续把 perf/login-transition 合回 main 时自然消除。勿在本分支重写（避免与 main 冲突）。
2. **/assets immutable 缓存的前提**：Vite 产物必须带内容 hash（现状如此）。若将来关闭 hash 或产物名固定，immutable 会导致发版后浏览器加载旧文件——`vite.config.ts` 保持 `entryFileNames/chunkFileNames` 默认 hash 即可。部署新版本时无需额外操作（index.html no-cache 会回源拿到新 hash 入口）。
3. **成绩量化**：首屏字节几乎不变（+0.13%），改进集中在「登录 → 主界面」的感知延迟与体验（进度条 + 过渡层 + 预取 + echarts 脱首屏）。若后续想继续压首屏，唯一大头是 element（737 KB）：可评估按登录页实际组件（el-alert / ElMessage）进一步 tree-shake 或延迟非首屏组件样式，但属于另一轮优化，收益与风险需单独评估。
4. **`requestIdleCallback` 回退**：生产浏览器均支持；iOS Safari 也于 16+ 支持。低于该版本的 Safari 走 setTimeout 回退，功能等价（占一个宏任务，无感知影响）。
5. 本分支所有 commit 均为本地，未 push；与 main 的距离为 8 个 commit（见第 1 节），合回前建议跑一次全量 `pnpm test:run`（main 已修 LogicalDeviceList 用例，届时应为全绿）。
