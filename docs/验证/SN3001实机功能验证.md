# SN-3001 实机功能验证记录

验证日期：2026-07-20  
环境：`ehome-dev`（PostgreSQL 5435、Redis 6380、MQTT 1884、API 8082、前端 5174）  
节点：ESP32-C6 N8，node `F0F5BDFFFE02`，固件 `2.5.17`，UART1 TX GPIO20 / RX GPIO21 连接 SN-3001，节点串口 `/dev/ttyACM0`。  
设备：SN-3001-GYL-N01，无光照探头；默认 Modbus RTU 地址 1、4800 8N1。

## 已通过的真实浏览器闭环

以下操作均由 Chromium 登录统一前端，在设备详情页点击操作按钮，经 API → MQTT ChannelCmdV2 → ESP32-C6 UART1 → SN-3001，再由 Final 验证结果回到页面时间线。单元测试或模拟串口不计入下表。

| 操作 | 实机结果 |
| --- | --- |
| 读取累计雨量 | `SUCCEEDED`，`rainfall=0mm`；此前另有 40/40 次连续真实读取成功 |
| 读取雨量灵敏度 | `SUCCEEDED`，当前值为 `50 raw`（不是协议文档中的默认值 60） |
| 读取设备地址 | `SUCCEEDED`，`device_address=1 address` |
| 读取设备波特率 | `SUCCEEDED`，`baud_rate=4800 bit/s` |
| 发送雨量清零 | 真实 FC06 回显 ACK `write_ack=1`，随后读取 `rainfall=0mm` |
| 设置雨量灵敏度 | 真实写入 `50→51`，ACK 后读回 51；再次写回 50，ACK 后读回 50 |
| 设置设备地址 | 真实切换 `1→2`，广播读回 2；使用 `source_address=2` 写回 1，再读回 1 |
| 设置设备波特率 | 当前值 4800 的真实 FC06 回显 ACK，随后读回 4800 |

## 型号裁剪

该实机没有光照探头，因此 SN-3001 Action Catalog 和传感器定义不暴露光照度、光照偏差相关操作；这不是“光照读取失败”，而是按实物配置屏蔽不适用能力。协议驱动仍保留独立的 PRS-3001 光照型号入口，二者不混用。

## 尚不能称为完整放行的部分

1. `reset_rainfall` 的三步 bounded plan（读前值 → 清零 → 读回零）仍处于不可用状态。当前浏览器证据使用开发环境专用的单步 `clear_rainfall_write`，并由测试立即发起读取确认；它没有冒充生产级 bounded plan。
2. 高风险单步写入只通过 `EHOME_ENV=development` 且 `EHOME_ENABLE_HIGH_RISK_ACTIONS=true` 的显式门禁。生产默认仍拒绝，节点端 NVS at-most-once、重启恢复和丢 ACK 处理尚未放行。
3. 波特率操作已验证当前值 4800 的真实写入 ACK/读回；尚未执行 `4800→9600→4800`，因为这需要先实现服务端通道配置与 C6 UART1 的原子重配/恢复，避免设备切速率后链路丢失。
4. 这台设备没有 BMS，因此嘉佰达 BMS MOS/F2/F3/reset 不能在本次 SN-3001 实机上宣称验证。

因此，本记录证明 SN-3001 当前实机接线下的读取、清零写入、灵敏度写入恢复、地址切换恢复和当前波特率写入均可由浏览器触发并得到真实 ACK/读回；不等同于生产级高风险动作和波特率切换工作流已完成。
