# SN-3001 实机功能验证记录

验证日期：2026-07-20  
环境：`ehome-dev`（PostgreSQL 5435、Redis 6380、MQTT 1884、API 8082、前端 5174）  
节点：ESP32-C6 N8，node `F0F5BDFFFE02`，固件 `2.5.17`，UART1 TX GPIO20 / RX GPIO21 连接 SN-3001，节点串口 `/dev/ttyACM0`。  
设备：SN-3001-GYL-N01，无光照探头；默认 Modbus RTU 地址 1、4800 8N1。

本次固件资源报告已落库：`revision=2`、`supports_bounded_batch=true`、`max_batch_steps=8`、`supports_finally=true`；刷写后硬复位并重新完成 ConfigManifest/ConfigResult 同步，节点保持在线。

NVS replay 证据：单独执行一次 `reset_rainfall` 后硬复位 C6，使用同一 ChannelCmdV2 载荷重放；后端再次收到 ACK（63 bytes）和 Final（99 bytes），且数据库没有新建第二条 command execution，说明从持久 Final 回放而未重新建立服务端命令。

## 型号裁剪

该实机没有光照探头，因此 SN-3001 Action Catalog 和传感器定义不暴露光照度、光照偏差相关操作；这不是“光照读取失败”，而是按实物配置屏蔽不适用能力。协议驱动仍保留独立的 PRS-3001 光照型号入口，二者不混用。

## 尚不能称为完整放行的部分

1. bounded `reset_rainfall` 已在开发 C6/真实 SN-3001 上通过浏览器验证，并完成一次重启后的 NVS Final 回放；生产放行仍需独立的故障注入/丢 ACK 门禁证据。
2. 高风险单步写入只通过 `EHOME_ENV=development` 且 `EHOME_ENABLE_HIGH_RISK_ACTIONS=true` 的显式门禁。生产默认仍拒绝。
3. 波特率操作已验证当前值 4800 的真实写入 ACK/读回；尚未执行 `4800→9600→4800`，因为这需要先实现服务端通道配置与 C6 UART1 的原子重配/恢复，避免设备切速率后链路丢失。
4. 这台设备没有 BMS，因此嘉佰达 BMS MOS/F2/F3/reset 不能在本次 SN-3001 实机上宣称验证。

因此，本记录证明 SN-3001 当前实机接线下的读取、bounded 清零、灵敏度写入恢复、地址切换恢复和当前波特率写入均可由浏览器触发并得到真实 ACK/读回；不等同于生产级故障注入门禁和波特率切换工作流已完成。
