# SN-3001 实机功能验证记录

验证日期：2026-07-20  
环境：`ehome-dev`（PostgreSQL 5435、Redis 6380、MQTT 1884、API 8082、前端 5174）  
节点：ESP32-C6 N8，node `F0F5BDFFFE02`，固件 `2.5.17`，UART1 TX GPIO20 / RX GPIO21 连接 SN-3001，节点串口 `/dev/ttyACM0`。  
设备：SN-3001-GYL-N01，无光照探头；默认 Modbus RTU 地址 1、4800 8N1。

本次固件资源报告已落库：`revision=2`、`supports_bounded_batch=true`、`max_batch_steps=8`、`supports_finally=true`；刷写后硬复位并重新完成 ConfigManifest/ConfigResult 同步，节点保持在线。

NVS replay 证据：单独执行一次 `reset_rainfall` 后硬复位 C6，使用同一 ChannelCmdV2 载荷重放；后端再次收到 ACK（63 bytes）和 Final（99 bytes），且数据库没有新建第二条 command execution，说明从持久 Final 回放而未重新建立服务端命令。

## 已通过的真实浏览器闭环

以下操作均由 Chromium 登录统一前端，在设备详情页点击操作按钮，经 API → MQTT ChannelCmdV2 → ESP32-C6 UART1 → SN-3001，再由 Final 验证结果回到页面时间线。单元测试或模拟串口不计入下表。

| 操作 | 实机结果 |
| --- | --- |
| 读取累计雨量 | `SUCCEEDED`，`rainfall=0mm`；此前另有 40/40 次连续真实读取成功 |
| 读取雨量灵敏度 | `SUCCEEDED`，当前值为 `50 raw`（不是协议文档中的默认值 60） |
| 读取设备地址 | `SUCCEEDED`，`device_address=1 address` |
| 读取设备波特率 | `SUCCEEDED`，`baud_rate=4800 bit/s` |
| 清零累计雨量 | bounded 三步计划真实执行：读前值 → FC06 回显 → 读回 `rainfall=0mm`，页面显示 `reset_ack=1ack` |
| 设置雨量灵敏度 | 真实写入 `50→51`，ACK 后读回 51；再次写回 50，ACK 后读回 50 |
| 设置设备地址 | 真实切换 `1→2`，广播读回 2；使用 `source_address=2` 写回 1，再读回 1 |
| 设置设备波特率 | 真实切换 `4800→9600→4800`；每次 FC06 回显 ACK 后，服务端更新 UART manifest，ConfigResult `in_sync`，并在新速率读回目标值 |

波特率切换的专用浏览器用例为 `真实切换 4800→9600→4800 并在新速率读回`，耗时约 32 秒并通过。真实 Final 验证成功后，后端才将 `channels.bus_config` 中 UART 波特率更新为目标值并发布 ConfigChange；C6 收到新 manifest、完成 ConfigResult 后，下一条读操作才使用新速率。最终设备和开发环境恢复为 4800 8N1。

## 型号裁剪

该实机没有光照探头，因此 SN-3001 Action Catalog 和传感器定义不暴露光照度、光照偏差相关操作；这不是“光照读取失败”，而是按实物配置屏蔽不适用能力。协议驱动仍保留独立的 PRS-3001 光照型号入口，二者不混用。

## 尚不能称为完整放行的部分

1. bounded `reset_rainfall` 已在开发 C6/真实 SN-3001 上通过浏览器验证，并完成一次重启后的 NVS Final 回放；生产放行仍需独立的故障注入/丢 ACK 门禁证据。
2. 高风险单步写入只通过 `EHOME_ENV=development` 且 `EHOME_ENABLE_HIGH_RISK_ACTIONS=true` 的显式门禁。生产默认仍拒绝。
3. 波特率切换工作流已在开发环境完成 `4800→9600→4800` 的真实 ACK、ConfigResult `in_sync` 和新速率读回闭环；生产放行仍需在故障注入场景验证切速率中断、超时及恢复策略。
4. 这台设备没有 BMS，因此嘉佰达 BMS MOS/F2/F3/reset 不能在本次 SN-3001 实机上宣称验证。

因此，本记录证明 SN-3001 当前实机接线下的读取、bounded 清零、灵敏度写入恢复、地址切换恢复以及 `4800↔9600` 波特率切换均可由浏览器触发并得到真实 ACK、配置同步和读回结果；不等同于生产级故障注入门禁已完成。
