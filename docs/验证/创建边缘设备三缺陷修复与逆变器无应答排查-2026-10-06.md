# 创建边缘设备三缺陷修复 + 逆变器无应答排查 — 2026-10-06

> 来源：现场报告 ①选设备时名称无法辨别 ②继承方式点创建没反应 ③开关指令模板后中文名
> 创建没反应（改英文可以）；以及「C6 上 BMS 有数据、逆变器无数据」。

## 一、三个前端缺陷（已修，已部署）

### ① 候选无法辨别 —— 补主键

`LogicalDeviceCandidateSelect.vue` 只渲染 `c.name`，而 `logical_devices.name` **无唯一约束**
（唯一的是 `identity_key`，由 `type:hardware_id` 派生，与名字无关）⇒ 同名候选渲染成两行
**逐字相同**的文本。现补 `#<id>` 徽标 + 含 id 的 aria-label，与同仓另两个入口
（`QuickCreateDeviceDialog.vue` 的「p.name (p.id)」）保持一致。

### ② 点创建没反应 —— 拦截时把用户送回能修的那一步

`EdgeDeviceList.vue` 在「勾了继承但未选候选」时**只弹一条 toast 就 return**。候选选择器在
第 0 步（`v-if="inheritMode === 'inherit'"` + `v-show`），用户在步骤 3 提交时它
**不在视口** ⇒ 提示语指向一个看不见的控件，按钮不转圈、对话框不动 ⇒ 表现为「没反应」。
现显式 `createStep.value = 0` 后再提示，时长延到 6s。

### ③ 中文名 —— **已否证，不是原因**

生产库实测存在中文名 `logical_device`：**id=4 name="逆变器"**。逐层排查全部为否：
无 `binding` 标签、无 `RegisterValidation`、无自定义校验、无前端正则；真实 PostgreSQL 的
`varchar(64)` 按**字符**计（64 个汉字可存，65 字才 `22001`）。

而 id=4 **被零个 edge_device 引用、名下零条数据** —— 说明当时是
「logical_device 建成功、同请求的 edge_device 失败」，留下孤儿行；改用英文重试时
同时还改了指令模板等状态，于是显示为「改英文就好了」（**幸存者偏差**）。

最可能的真因是 `MaxCommandsPerEdgeDevice = 3`（`nodemgr/sender.go:35`，由
`api/command_intervals.go:129` 在写入时拦截 400），与「手动开关了一些指令模板」吻合。
**本轮未改配置**，需现场复现一次并看 Network 的 `POST /api/v1/edge-devices` 状态码定性。

### 放大器（本轮最有价值的一处）

`utils/feedback.ts` 的 `extractErrorMessage` 只处理 `error instanceof Error`，其余一律
`return fallback`。而 Element Plus 的 `formRef.validate()` 拒绝值是 **invalidFields 普通对象**
（非 Error）⇒ 表单校验的真实原因（如「请输入设备名称」）被替换成通用「创建失败」、5 秒后消失。
这是 ②③ 共同的「真因不可见」根因。

### 验证

- 新增回归用例：`feedbackErrorFunnel.spec.ts` 补 6 个 invalidFields 断言（含形状不符须安全回落）；
  `EdgeDeviceList.spec.ts` 的继承拦截用例补**断言 `createStep` 被重置为 0**
  （原用例只断言发了 toast，对「用户看不到提示」这一真实症状零分辨力）。
- **变异自证**：删掉 `feedback.ts` 的 invalidFields 块重跑 → 用例转红，
  报 `expected '创建失败' to be '请输入设备名称'`（正是现场症状）；还原后 md5 逐字节一致。
- `vue-tsc --noEmit` exit 0；相关 34 个测试文件 **367/367** 通过。
- 全量 `vitest run` 有 3 个失败（`FixedColumnOcclusion` / `sessionValidityGuard`），
  **与本轮无关**：spec 不 import 我改的任何模块，且**单独运行 11/11 全过** ⇒ 既有 flaky。
- CI 7/7 全绿；已部署生产（见下）。

## 三、逆变器无应答（C6 UART1）—— 已排除软件配置，未定位到根因

### 硬证据（全部实测）

| 事实 | 证据 |
|---|---|
| 固件确实发出了命令 | 终端端点发 `HSTS\r` 后 `WCMD_H: Sending WriteRsp: req=…, success=1` |
| **从未收到过任何字节** | `device_data` 中 ch11 **全时段 0 行**；`(HSTS\|HGRID\|HOP…)\` 全库 0 命中 |
| 持续 RX 超时 | `RX_TASK: RX timeout slot1 type=1` 每周期一次；`edge_devices.error_code=3` |
| 配置正确 | 波特率 2400、TX=20/RX=21，与固件 C6 UART1 表（`hw_tables.c:162`）一致 |
| 配置已下发 | `config_status=applied`、`config_sync_state=in_sync`、manifest 已更新 |
| 同机另一条 UART 正常 | BMS（ch10/UART0/slot0）持续出数，`unified_data` 有 `cell_voltage_*` |
| **同一台逆变器在 S3 上曾工作** | S3 ch9 有 1016 行，`raw_hex=28303020503030…0d` = `(00 P000000000000\r` |

### 已排除的假设（都做了实测，不是推断）

1. **命令选错** —— 原启用 `read_pv1`(HPV)，而协议文档标注 HPV 的拼写「原件写成 GBUS，需现场确认」。
   切到 S3 上**已验证可用**的 `read_status`(HSTS) 后重试：**仍然 0 字节**。⇒ 与命令无关。
2. **波特率错** —— 依次试 2400 / 9600：**均为 0 字节**。⇒ 与波特率无关。
3. **引脚/端口绑定错** —— 固件 `uart_set_pin(port, 20, 21, -1, -1)`，与 C6 硬件表一致；
   无任何 `uart_set_pin failed` / pin 冲突日志（ERROR 级日志全时段 0 条）。
4. **UART 事件队列 attach 失败** —— 该路径会打 `channel will be unreadable`，全时段 0 命中；
   且 `RX_TASK` 确实在监视 slot1（说明 slot1 已初始化并挂上事件队列）。

### 结论与下一步

故障点在**「命令已发出 → 但 RX 侧一个字节都没到」**这一段，且只在 C6 的 UART1 上出现
（同板 UART0 正常、同逆变器在 S3 正常）。软件侧配置已用实测逐项排除。

现场无法进一步观测的原因：该 C6 的 USB 不在本机（`/dev/ttyACM2` 已拔），且后端**没有重启端点**
（`grep reboot /esp_restart` 无 API），故拿不到 boot 期的 UART 初始化日志。

**建议的下一步（按性价比排序）**：

1. **给该 C6 断电重启**，并在此之前把该节点日志开到 INFO 持久化 —— boot 期会打印
   `UART1 reused/reconfigured (TX=20 RX=21 baud=2400)`；**有这行 = 固件侧引脚配置成功**，
   问题在电气/对端；**报 `uart_set_pin failed` = 固件侧问题**，可直接定位。
2. 把逆变器**临时接到该 C6 的 UART0**（GPIO16/17，已验证能收数据）—— 这是最快的 A/B：
   若 UART0 能收到，则坐实「C6 UART1 接收通路异常」而非接线/逆变器问题。
3. 台架用示波器/逻辑分析仪看 GPIO21 在逆变器应答窗口内是否有电平变化。

## 四、未改动但已发现的问题（登记备查）

- **候选排序把总线名当设备地址**：`EdgeDeviceList.vue:816-818` 把 `channels.hardware_id`（`UART1`）
  当设备地址传给 `/edge-device-candidates`，而权重比较另一侧是 `edge_devices.hardware_id`（从站地址 `1`）。
  字符串相等 ⇒ 100/80 两档**永不产生**，候选塌缩到 60/20。需复用既有 `resolveInlineDeviceAddress`
  才能与创建 payload 同源，改动面较大，未验证前未动。
- **波特率有两个来源**：`channels.bus_config`（hex，固件用它）与 `channels.config` 的
  `baud_rate`（UI 展示用）。实测改 `bus_config` 后 `config.baud_rate` 仍是 2400 —— 两者会漂移，
  建议收敛为单一来源。
- **`logical_devices` 孤儿行**：id=4「逆变器」被零个 edge_device 引用、零条数据，是 ③ 那次
  半成功创建的残留。
