## 默认安全状态

`control.device_control_v2_enabled=false` 且 `enabled_device_actions=[]`。即使
全局 V2 后续启用，任何动作也必须先以 `device_type/action_id` 进入独立灰度列表；
内置 `prs3001/read_rainfall` 当前默认禁用。

## 未通过、不得绕过的门禁

1. **普通 setter**：已取得并离线结构化原厂 `GB3024通信协议V05(外发).docx`，可核对摘录见
   [GB3024 通信协议 V0.5](../协议/GB3024通信协议V05.md)。原件确认 `V`/`F`/`PGR`/`POP` 等命令名、
   `HEEP1` 回读字段和 `\r` 终止，但没有 CRC16 算法、ASCII 表示/字节序黄金向量或真实写 ACK 捕获；
   且 `POP01` 示例与枚举表语义冲突。不能猜测 compiler 或启用 Action；回归测试同时断言 legacy
   Techfine write template 不会泄漏进 Action Catalog。
   只读 Action 的协议文本和示例解析测试已经具备，但也必须先取得真实设备响应，才可从默认禁用
   切换为目标节点的 rollout。
2. **S3 性能门禁**：S3 N8 已交叉构建，但没有 S3 板卡，无法采集 heap、worker 栈、满载
   p50/p95、丢样和 watchdog 数据。当前含 V2 control-statistics 的 S3 N8 再次脚本构建通过，
   但不能替代上述实机数据。
3. **batch/NVS/high-risk 物理动作**：方案明确要求在真实需求、步骤证据与性能余量确认后再做；
   当前不得以模拟结果替代工厂模式、NVS replay 或 destructive action 验收。
4. **嘉佰达 BMS 控制实机证据**：原始 V19 Markdown、来源路径与 SHA-256 已归档，已足够取代本机
   参考笔记作为协议来源；但没有实际 BMS 的 wake、0xE1 双 bit/优先级、ACK、`fet_status` readback 或
   恢复证据，且 F2/F3 原文存在歧义。因此仍不开放 BMS MOS、参数、reset 或其他写动作。

## 解锁所需外部输入

- CRC16 算法及完整的请求/响应黄金向量，或包含 CRC 的真实 GB3024 串口捕获；
- 目标普通 setter 的实际型号/固件/接口、readback 成功准则和测试设备；
- ESP32-S3 测试板；
- 嘉佰达实际 BMS 测试设备及 0xE1 双 bit/优先级、ACK、`fet_status` readback、恢复记录；
- 对 high/critical 动作：操作者、回退方案、观察窗口与 MQTT topic 隔离/mTLS（或等效 ACL）证据。

在这些输入到位前，保持动作默认禁用，而非以 legacy WriteCmd、raw diagnostics 或虚构的硬件
响应替代门禁。

### 首个 Techfine setter 的最小证据包

为解除第 1 项门禁，需一次性归档以下可追溯材料，并以同一设备实测闭环：

1. 原厂手册页或可校验原始串口捕获，明确命令文本、CRC 的算法/覆盖范围/ASCII 编码/字节序、`\r` 终止和 ACK 形式；
2. 一个参数的安全范围、恢复值和副作用说明（优先低影响且语义无冲突的参数，禁止 reset/开关机）；
3. 对应 `HEEP1` 或其他确定查询帧的字段位置、读回值映射和成功 predicate；
4. 目标 GB3024 型号/固件、RS232/RS485 接口与测试接线；
5. 写入、ACK、读回一致、恢复原值四段串口记录，以及操作者/观察窗口。

材料齐全后才新增一个 `set` Action；它将受现有受信任 compiler、专属 verifier、确认、审计、
Outbox/Final 和 Action 级灰度约束，且只灰度到该测试设备。
