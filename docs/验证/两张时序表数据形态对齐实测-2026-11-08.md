# unified_data 与 telemetry_frame 数据形态对齐实测（2026-11-08）

> 生产库 `192.168.20.6` / `ehome` / commit `eb3b780f`（只读 SELECT）
> 目的：DROP `unified_data` 之前，确认「帧表能承担 unified_data 的全部读语义」这件事有数据依据。

## 一、时间戳集合是否重合（最关键的一条）

帧表的 `ts` 与 unified_data 的 `timestamp` 若不完全重合，两条路的分桶边界就会错开，
「逐点相等」这个前提本身不成立。

```
设备 15，每天 00:00~01:00 UTC：
  日期          unified 独有   帧表独有   共有
  2026-11-01             0          0    2,340
  2026-11-03             0          0    2,340
  2026-11-05             0          0    2,340
  2026-11-06             0          0    2,340
```

**结论：两边时间戳集合完全重合。** 没有任何一侧存在对方没有的时刻。

## 二、同一 timestamp 是否会出现多帧

「桶内最后值」的语义依赖「同 ts 多帧时的顺序」。若生产上不存在这种情况，
实现就不依赖该顺序 —— 这比留一条无法构造的测试用例更诚实。

```
设备 15，2026-11-05 全天：
  max_slots_per_ts           = 1
  ts_with_multiple_slots     = 0
```

**结论：同一 timestamp 只有一帧（一个 slot）。**

## 三、同一 timestamp 同字段是否有重复行

```
设备 15，2026-11-05 全天：
  dup_ts_sensor_rows = 0
```

**结论：无重复行。**

