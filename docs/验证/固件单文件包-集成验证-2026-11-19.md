## 4. 六档位产物（`esp32-collector/dist/2.9.0/`）

| profile | chip | flash | psram | artifact B | 包 B | 包 sha256 前 16 |
|---|---|---|---|---|---|---|
| c6-n8 | esp32c6 | 8 | false | 1,356,912 | 1,357,764 | `5f313b86cf236f3d` |
| c6-n16 | esp32c6 | 16 | false | 1,356,912 | 1,357,765 | `5abb7756edc4ef0e` |
| s3-n8 | esp32s3 | 8 | false | 1,181,728 | 1,182,580 | `4fe20cd0106c4e64` |
| s3-n16 | esp32s3 | 16 | false | 1,181,728 | 1,182,581 | `919652c4c6deee61` |
| s3p-n8 | esp32s3 | 8 | **true** | 1,190,624 | 1,191,476 | `81a8b634b772955a` |
| s3p-n16 | esp32s3 | 16 | **true** | 1,190,624 | 1,191,477 | `f22532addb2e1750` |

**两个关键观察**：

1. **PSRAM 路径真的被走到了**：`s3p-*` 的清单是 `psram: true`，`c6-*` / `s3-*` 是 `false`。这条链路只有在有 PSRAM 档位时才会真正执行（`CONFIG_SPIRAM` + profile 名 p 位互校）。
2. **六份 artifact 的 sha256 互不相同**：`n8` 与 `n16` 的镜像头第 0x03 字节高半字节分别是 `0x3` / `0x4`（8MB / 16MB），因此同一 SoC 的两个容量档位不会撞 `uq_firmwares_elf`。验证前这是我最担心的点——两个档位只差分区表时，app 镜像可能字节相同，那样第二次上传必然 409。

## 6. 确定性（AC-P11）

同一份 artifact 独立打包两次，再与 `build_firmware.sh` 产出的那一份比对：

```text
5f313b86cf236f3d…  .logs/ac11/a.ehfw        （独立执行 #1）
5f313b86cf236f3d…  .logs/ac11/b.ehfw        （独立执行 #2）
5f313b86cf236f3d…  dist/…/c6-n8.ehfw        （构建脚本产出）
```

三方字节一致，说明：① 打包器无时间戳/随机源；② 构建脚本调用打包器的参数与手工调用等价；③ 清单里的 `build.*` 也参与确定性（同一工作树，commit/dirty/sdkconfig_sha256 相同）。

## 8. 复跑方法

```bash
# 1) 后端
GO="docker run --rm -v /path/to/EHome:/repo -w /repo/backend \
     -v ehome-go-build:/root/.cache/go-build ehome-golang-cgo:1.27.3 go"
$GO test -count=1 ./...
$GO vet ./... && $GO vet -tags=simulation ./...

# 2) 打包器与向量
UV_CACHE_DIR=$PWD/.tmp-uv/cache TMPDIR=$PWD/.tmp-uv/tmp \
  uv run --with pytest pytest esp32-collector/tools/test_pack_firmware.py -q
python3 protocol/firmware-package/vectors/gen_vectors.py --check

# 3) 六档位
source ~/env/esp-idf/export.sh
export PATH=$PWD/.tools/cmake-3.30.5-linux-x86_64/bin:$PATH
BUILD_ROOT=$PWD/esp32-collector/build-pkg FW_VERSION=2.9.0 make fw-all
(cd esp32-collector/dist/2.9.0 && sha256sum -c SHA256SUMS)

# 4) 前端
cd frontend-shared && pnpm test:run && pnpm typecheck
```

**挂载点注意**：Go 的验证命令必须挂**仓库根**。`protocol/` 在 Go 模块之外，只挂 `backend/` 时 `pkg/frame`、`pkg/protoframe`、`firmwarepkg` 的 golden vectors 全部读不到（改动前就是这样，不是本次引入）。
