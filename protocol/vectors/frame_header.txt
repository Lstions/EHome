# EHomeSystem 3.0 帧头 golden vector —— 12 B 定界头（**无分片**）
#
# 依据：用户 2026-10-06 决策「不需要分片与重组，需要的是分界」。
# 分析见 docs/设计/决策-帧格式是否需要分片-2026-10-06.md；
# 该决策同时删除了 frag_off / frag_len / MORE 与整套重组状态机。
#
#   偏移  字段          宽度
#   0     magic         2     = 0x4548 (EH)
#   2     ver           1     = 0x30 (3.0)
#   3     type          1     消息类型
#   4     flags         2     bit0 ACK_REQ / bit1 IS_ACK / bit2 IS_NAK / bit3 CRC32C
#   6     seq           4     每方向单调递增
#   10    payload_len   2     本条消息的载荷长度（**这就是分界**）
#   ---- 12 B ---- 之后 payload_len 字节载荷；CRC32C 位置位时再跟 4 B
#
# 端序：设计未规定，本实现定为**大端**（网络字节序）。理由：线路协议通行约定；
# 且与两端主机字节序无关（ESP32/C6 与常见服务器都是小端，定小端则
# 「能跑」只因双方恰好同序，换一端就静默错）。**需设计者确认。**
#
# payload_len 上界 = 16368 = MBEDTLS_SSL_IN_CONTENT_LEN(16384) - 头(12) - CRC(4)，
# 使「一条完整消息恰好放进一个 TLS 记录」这个性质**成立**。
# （上一版上界 16384 时该性质差 20 B 不成立，见决策文档 §11.2。）
#
# ⚠ wire 值【不允许手写】，由 tools/check_frame_header.py 生成并复核。
#
