⇒ **两条硬规则**：

### 规则 A：主控不在子代理跑构建/跑测期间改仓库
主控承诺：派出子代理后**不再改动 `backend/` 与 `frontend-shared/`**，直到全部代理结束。
若有紧急修复，主控会先**中断全部代理**再改。
子代理若发现仓库被改动（`md5` 变化），**立即停止并以消息告知主控**，不要基于变化中的树下结论。

### 规则 B：project / 容器名 / 库名 / 端口 **必须可覆盖**
开发期与交付期**不得共用同一个 project 名**。

| 用途 | project | 容器名前缀 | 端口 | 库名前缀 |
|---|---|---|---|---|
| **交付探针**（默认，契约值） | `ehome-bb` | `ehome-bb-*` | 18080 | `ehome_bb_*` |
| **开发/自测**（必须显式指定） | **`bbdev<代号>`**（**不得**以 `ehome-bb` 开头） | `bbdev<代号>-*` | 18091+ | `ehome_bbdev<代号>_*` |

> ️ **dev project 命名规则（2026-09-16 修正，前一版有缺陷）**：
> 初版建议 `ehome-bb-dev-<代号>` —— **这仍然会以 `ehome-bb` 开头**，
> 于是被任何「按 `^ehome-bb-` 前缀清理/检查」的工具命中。
> **实测证据**：`docker ps -aq --filter "name=^ehome-bb-"` 同时返回了
> `ehome-bb-dev-b-mcprobe` 与 `ehome-bb-dev-c-ehome`（并行代理的容器）⇒
> 代理 B 的反向对照跑到一半，容器被 D 的清理删除。
> ⇒ **dev project 必须与交付 project 无前缀关系**，故改为 `bbdev<代号>`。

**实现要求**：每个探针脚本头部必须支持环境变量覆盖，且**默认值 = 契约值**：
```bash
PROJECT="${BB_PROJECT:-ehome-bb}"
WEB="${PROJECT}-ehome"

DB="${BB_DB:-ehome_bb_$RUNID}"
```

**同理**：清理与残留检查一律以 **compose project label** 为准（精确相等），
**不得**用名字前缀作为主判据 —— 前缀匹配是本次互踩的根因。
仅在「对象无 label（孤儿）」时才用名字前缀兜底，且已在 run.sh 注释注明。
**并在证据头部打印** `BB_PROJECT=` / `BB_HOME_PORT=` / `BB_DB_NAME=`（D 的 run.sh 已这么做），
这样一看证据就知道是谁跑的。

## 5. 纪律（不可放松）

1. **缺陷先红**：断言必须先在「故意破坏」下变红，再恢复
2. **变异脚本自证落地**：改完先 grep/打印被改的行确认，再看结果
3. **分母守卫**：断言「真的扫到 N 个东西」

   > **实战教训（子代理 A 实测，2026-09-16）**：**「逐个存在」型断言会空转成绿**。
   > 产物整体缺失时，A4 报的是 `PASS: 引用的 0 个静态资源逐个存在（FOUND=0 MISSING=0）` ——
   > 「0 个都满足」被当成通过。全靠分母守卫 G1b/G1c 才变红。
   > 对**比较器**型断言（如 Q7 的两次构建比对）风险更大：两份清单都空时，
   > 朴素 `diff` 会判「一致 ⇒ 绿」（A 已实测 `diff` 对两份空文件返回 SAME）。
   > ⇒ **凡「对两个集合做一致性判断」的断言，必须额外证明「集合非空」**。

   > **并发守卫（子代理 B 的实践，2026-09-16）**：起栈前若同名容器已存在则 **ABORT 不抢占**；
   > 断言前容器 cid 变化则标 **COLLISION**（而非判红/判绿）；启动日志库名与本 run 不符亦标 COLLISION。
   > 目的：避免把「被外部删掉」误报成「功能不通」，也避免把抢占当成正常。
4. **失败可诊断**：打印原始响应/日志片段
5. **如实报告**：未做的、不确定的、与预期不符的都要写。**主动缩小结论范围优于多报结论**
6. **只经公开接口**（HTTP/MQTT/docker inspect/日志）；不读容器内私有文件、不直连其 DB 改数据
7. **结束必清理**（trap 保证异常也清），并核对零残留
