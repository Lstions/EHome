# UART1 无输出诊断 + S3 UHCI/DMA 限制登记（2026-10-05）

> 状态：**UART1 无波形已确认为未解决**；本文记录已排除项、证据与待办。
> 现场：S3 节点 `30EDA0A9A808`（固件 2.8.0，ESP-IDF 6.1），
> UART0(GPIO43/44) 接嘉佰达 BMS、UART1(GPIO4/5) 接泰琪丰 GB3024 逆变器。

---

## 1. 现象

| 通道 | 从设备 | 发送 | 接收 | 转换板指示灯 |
|---|---|---|---|---|
| ch8 UART0 (GPIO43/44) | 嘉佰达 BMS @9600 | OK | OK 有真实数据（51.49 V） | — |
| ch9 UART1 (GPIO4/5) | 泰琪丰逆变器 @2400 | 驱动报成功 | 无：`raw` 恒为空、`error_code=1` x598 | **TX/RX 全不亮** |

关键判据：**转换板的 TX/RX 灯完全不亮**。用户指出"即使接反了灯也会亮" ——
这一条决定了"引脚上根本没有电平变化"，而不是"电平对但数据错"。

---

## 2. 已排除的原因（含反证）

### 2.1 不是 UHCI/UART DMA 争用（已排除）

一度怀疑 UART0 与 UART1 同时 `dma_enabled=true` 触发 UHCI 争用。实测排除：

```c
/* IDF 6.1 components/esp_driver_uart/src/uart.c: uart_driver_install() */
/* 只做 malloc 缓冲 + uart_module_enable + 装中断，完全不触碰 UHCI */
```

- 全仓 `uhci_*` **零命中** —— 本项目对 UART 走**中断驱动**，未启用硬件 DMA。
- `dma_enabled` 对 UART 的唯一作用是选缓冲大小（`bus_dma.c:535`）：
  `rx_buffer_size = dma_enabled ? 512 : 256`。
- 反证：UART0 与 UART1 的 `dma_enabled` **都是 true**，但 UART0 正常工作 ——
  若是 UHCI 争用，两条都该失败。

### 2.2 不是配置未下发（已修复，见 §4）

### 2.3 不是引脚非法/被保留

`bus_dma.c` 的保留引脚仅 USB_D-(19)/USB_D+(20)/LED(48)；GPIO4/5 合法。

### 2.4 不是收发方向接线（用户否定）

用户明确：**接反了灯也会亮**。故"灯全灭"只能解释为**无信号**。

## 3. 尚未排除（下一步）

1. **ESP32 GPIO4 是否真有输出** —— 需示波器/万用表在发送时量 GPIO4。
   若 GPIO4 无变化 → 问题在固件侧（UART1 未真正安装成功）；
   若有变化 → 问题在转换板/逆变器侧。
2. **转换板的供电与电平**（用户已确认电源灯亮、接线正常）。
3. **逆变器从机地址/协议** —— 但即使协议不符，RX 灯也应有反应，
   故此项**不能解释"RX 灯也不亮"**。

### 一个值得注意的旁证

`deploy/prod/ESP32S3-UART0-ADUM1201通讯验证-2026-10-02.md` 已实测：
**UART0 + ADUM1201 隔离器双向均通**（9600 8N1）。即"ESP32 UART → 隔离/电平
转换 → 外部设备"这条链路在 UART0 上是被证明可行的。因此 UART1 的失败
更可能是**该路独有的差异**（引脚、转换板、或该 UART 未被真正启用）。

## 4. 本次已修复：配置因模板容量被拒

（这是 UART1 从"零记录"到"有记录"的转折）

### 现象

```
W ConfigManifest rejected: reconcile driver templates:
  template reconciliation would create 18 templates; collector limit is 16
```

`config_status=failed`，配置**从未成功下发**；UART1 因此从未被配置，
`device_data` 中 ch9 记录为 **0 条**。

### 根因（后端两处口径不一致）

| 位置 | 过滤条件 | 是否正确 |
|---|---|---|
| 编码器 `sender_snapshot.go:347-357` | `Schedulable && effectiveInterval > 0` | 正确 |
| 容量校验 `manifest_codec.go:243` | 仅 `Schedulable && WriteData != ""` | 错误，缺 interval 过滤 |

于是把"驱动声明过但永不轮询"的模板也创建进 DB 并计入容量：

| 来源 | 声明数 | 实际轮询数（interval>0） |
|---|---:|---:|
| JBD BMS | 5 | **1**（`read_basic_info` 5000ms） |
| Techfine | 11 | **1**（`read_status` 1000ms） |
| 历史残留 | 2 | 0 |
| 合计 | 18 | **2** |

### 修复

`reconcileDriverTemplates` 改用与编码器一致的谓词（`Schedulable &&
effectiveInterval > 0`，interval 取 storedIntervals 覆盖值、否则模板默认值）。
新增回归测试 `TestReconcileCreatesTemplatesOnlyForPolledCommands`，
并做**变异自证**（禁用过滤器 → 编译通过 + 测试变红 `created 3 templates, want 1` → 恢复）。

### 效果（实测）

```
config_status: failed -> applied      （配置首次成功下发）
ch9 device_data:  0 -> 598 条          （固件开始按 1s 周期发命令）
```

> 注意：**这只解决了"命令被调度并发出"**，尚未解决 §1 的"引脚无波形"。
> 两者是独立问题，不要混为一谈。

## 5. TODO：ESP32-S3 UHCI/DMA 限制（用户 2026-10-05 决定"先记 TODO"）

### 硬件事实

- ESP32-S3 的 **UART0/UART1/UART2 通过 UHCI 共享同一组 DMA TX/RX 通道**。
- `UHCI_UART_SEL` 从多个 UART 中**选择一个**接入 UHCI；
  `UHCI_UART1_CE` 决定 UHCI 是否接到 UART1。
- **任一时刻只能有一个 UART 占用这组共享 DMA 资源。**
- 官方提醒：UART DMA 与 **蓝牙 HCI 共享硬件**，不要与 BLE HCI 同时使用，
  即使使用的是不同 UART 端口。

### 对本项目的影响

**容量需求冲突**：用户要求"满配通道、每条总线 100Hz 收发"，S3 需 3 路 UART。
若三路都要 DMA，硬件上不可能。

### 目标形态（用户决定：混合模式）

> 三个串口**都支持 DMA，但同一时刻只有一个能启用**。

实现要点（待做）：
1. 在配置校验阶段**拒绝**"多个 UART 同时要求 DMA"的 manifest，
   并在错误信息中说明原因（而非运行期静默失败）。
2. 支持"分时复用"或在同一时刻只让一个 UART 真正持有 UHCI，
   其余走中断/轮询。
3. 若将来引入 BLE 配网/BLE OTA，需同时保证 BLE HCI 与 UART DMA 不并存。

固件中已在 `components/bus_dma/bus_dma.c` 的 `uart_init()` 顶部留下 `TODO(DMA)` 注释。
